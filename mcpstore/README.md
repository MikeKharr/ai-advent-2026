# Сервер MCP: хранилище файлов

Единица дней 19–20: инструменты `file.save`, `file.read` и `file.list` поверх
SQLite (`node:sqlite`, поэтому **Node 24**, а не 22). Протокол — JSON-RPC
ревизии `2025-11-25` без SDK, свой `src/rpc.js`. Решение и контракт —
`agent_docs/adr/2026-09-28-0736-days18-20-mcp-host-scheduler-orchestration.md`.

Зависимостей нет ни одной: все четыре раздела `package.json` пусты.

На хранилище держится смысл дня 19: цепочка сохраняет выжимку и читает её
обратно, а `sha256` с обеих сторон должны совпасть. Поэтому `file.read` на
пропавший файл отвечает `{found: false}` **без** `isError` — «нет файла» не
отказ, и вызывающий обязан это различать.

## Как выкатывается

Контейнером в закрытую сеть `tools` (`deploy/compose.yml`), с томом
`mcpstore_data`. **Наружу не публикуется:** опубликованного порта нет,
маршрута в `deploy/caddy/Caddyfile` нет, `caddy` в сеть `tools` не входит.
Обращается к серверу только сервис агентов, и замкнутость этого круга держит
страж `.github/scripts/compose-networks.mjs` — мутация «дать `caddy` сеть
`tools`» красит прогон.

Потолки: файл 64 КБ (единственная копия — `src/store.js:72`), 200 файлов,
срок хранения 30 часов. Тело запроса — 256 КБ, а не 64 КБ, как в ADR:
отступление записано в `agent_docs/development-history/2026-09-28-0832-mcpstore-body-limit-deviation.md`,
причина — 64 КБ содержимого дают тело 65 659 байт даже из одной латиницы.

## Локальный запуск

```sh
PORT=8085 STORE_DB=./data/store.db node server.js
```
