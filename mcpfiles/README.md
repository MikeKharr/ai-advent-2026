# Сервер MCP: ассистент над файлами проекта

Единица дня 34: четыре инструмента над файлами этого репозитория — читает
(`docs.read`), ищет (`docs.search`), выполняет одну правку (`backlog.close`) и
показывает, что можно править (`backlog.list`). Протокол — JSON-RPC ревизии
`2025-11-25` без SDK, своя копия внутри `server.mjs` (пятая в проекте — цена
границы зависимостей, ADR `2026-09-28-0736`, п. 3). Решение и контракт —
`agent_docs/adr/2026-10-18-2152-day34-in-ai-advent.md`; образец конструкции —
единица `mcpgit/` дня 31.

**Это локальный процесс.** Его запускает Claude Code на ноутбуке по записи
`mcpfiles` в корневом `.mcp.json`; транспорт — stdin/stdout. Контейнера,
порта, маршрута в `deploy/caddy/Caddyfile` и строки в `deploy/compose.yml` у
единицы нет, на VPS её нет вовсе. Зависимостей нет: `package.json` у каталога
нет, и умолчание карты в шаге «Граница runtime-зависимостей» (`ci.yml`) для
единицы вне карты — ноль.

## Инструменты

| Инструмент | Аргументы | Что делает |
|---|---|---|
| `docs.read` | `path`, `section?` | Текст файла или одного раздела по заголовку → `{path, section, from, to, truncated, text}` |
| `docs.search` | `query`, `limit?` | Подстрока без учёта регистра по всем `*.md` внутри `agent_docs/` → `{matches: [{path, line, text}], total, truncated}` |
| `backlog.list` | нет | Открытые пункты `- [ ]` всех файлов `agent_docs/backlog/` → `{items: [{file, line, text}], total}` |
| `backlog.close` | `file`, `anchor`, `note`, `date`, `kind?` | Переносит один пункт в `agent_docs/backlog-closed.md`: `- [x]` выполнено, `- [~]` снят как ошибочный |

Имена в сессии — `mcp__mcpfiles__docs_read`, `mcp__mcpfiles__docs_search`,
`mcp__mcpfiles__backlog_list`, `mcp__mcpfiles__backlog_close` (точка →
подчёркивание, как у `mcp__project__project_search`).

Потребитель — project-local skill `/backlog-close`
(`.agents/skills/backlog-close/`).

## Воспроизводимость

`backlog.close` ищет якорь сначала в архиве:

- якорь в архиве, пункта в очереди нет → `changed: false`, ни один файл не
  открывается на запись. **Второй прогон того же сценария на том же дереве
  даёт пустой `git diff`** — это проверяет тест «второй прогон того же
  сценария на том же дереве даёт пустой git diff»;
- якорь в архиве и пункт ещё открыт → отказ. Такое состояние возможно только
  после сбоя между двумя записями, и тихий повторный перенос сделал бы из
  одного пункта два.

Порядок записи — сначала архив, потом вычерк из очереди: двух файлов одной
операцией не записать, и из двух возможных последствий сбоя посередине
«пункт в обоих файлах» виден и правится, а «пункт нигде» — потерянный текст.

## Чего сервер не может по построению

- **Прочитать что-либо вне корня репозитория.** Любой путь из запроса идёт
  через `resolveInRoot`, и все три формы выхода — сегмент `..`, абсолютный
  путь и симлинк наружу — закрывает одна проверка: сверка `realpath` пути с
  `realpath` корня. Второй, лексической, проверки нет намеренно — она была бы
  той же защитой во втором месте, и снятие любой из двух оставляло бы прогон
  зелёным (I-14).
- **Прочитать секрет.** Каталог `.git/` и файлы `.env*` закрыты по имени
  РАЗРЕШЁННОГО пути, то есть после `realpath` — симлинком их не открыть (I-1,
  I-3). Правило простое, и заодно закрыт безобидный `deploy/.env.example`:
  точный список имён стоил бы здесь дороже, чем даёт, а сценарию скилла этот
  файл не нужен.
- **Записать куда-либо, кроме двух файлов очереди.** Имя файла темы сверяется
  с шаблоном `^[a-z0-9-]+\.md$` и каталогом `agent_docs/backlog/`, второй путь
  (`agent_docs/backlog-closed.md`) — литерал. Пути из запроса для записи не
  собираются.
- **Закрыть не тот пункт.** Якорь, подходящий к двум открытым пунктам, —
  отказ с номерами строк, а не выбор «какого-то из двух».
- **Залить модель выводом.** 400 строк на чтение, 256 КБ на файл, 50 находок
  поиска, 300 пунктов списка; срез помечен `truncated`.

Платного вызова единица не делает ни одного: ключей у неё нет, сети нет.

## Локальный запуск

```sh
# Обычно запускает Claude Code по .mcp.json; руками — так:
CLAUDE_PROJECT_DIR=$PWD node mcpfiles/server.mjs
```

Один объект JSON-RPC на строку в stdin, один ответ на строку в stdout.
В stdout не уходит ничего, кроме протокола.

## Тесты

```sh
node --test test/mcpfiles.test.js
```

Тесты живут в корневом `test/`: он целиком идёт шагом «Данные страницы
прогресса» в `docs-guard.yml` на каждом PR. Сервер в них поднимается
настоящим дочерним процессом во временном git-репозитории со своим
`agent_docs/` — дерево проекта не трогается ни на чтение, ни на запись.
