# День 20 — оркестрация инструментов

Тот же трейс, что у дня 19, но порядок вызовов и перенос данных между ними выбирает модель, а
инструменты приходят с трёх разных серверов MCP. Имя сервера стоит у каждого вызова — в этом
предмет дня.

Решение — ADR `2026-09-28-0736`, пп. 1, 4, 5, 9.

## Что делает единица

Создаёт запуск агента `mcp-agent` и показывает его события. Что звать и в каком порядке, решает
модель; эта единица об этом ничего не знает.

## Ручки

| Ручка | Что делает |
| --- | --- |
| `GET /healthz` | состояние настройки, суточный счётчик и статистика лимитера |
| `POST /api/runs` | `{task}` → запуск агента, `202 {runId}` |
| `GET /api/runs/:id/events` | поток событий запуска, насквозь |

## Расход

Запуск зовёт платную модель через роутер, поэтому у дня, сверх окон на адрес, есть суточный
потолок вызовов `MAX_DAILY_CALLS` 50 на всё приложение. Он не привязан к адресу и не обходится
его сменой; сутки считаются по UTC. Слот берётся **до** обращения к сервису агентов (I-4).

## Неутверждённый контракт

Форма входа агента — `input: {task}`. Она **не утверждена**: её задаёт `mcp-agent` в единице
`agents`. Место одно — `handleRun` в `server.js`.

## Окружение

`AGENT_KEY` (обязателен), `AGENT_URL`, `AGENT_ID` (`mcp-agent`), `MAX_DAILY_CALLS` 50,
`RATE_LIMIT_PER_MIN` 5, `RATE_LIMIT_PER_HOUR` 30, `PORT` 8080.

## Раскладка

Своей раскладки у дня нет. `public/style.css` — дословный срез блока `<style>` дня 16;
совпадение держит `test/style-copy.test.js`.

## Запуск локально

```sh
AGENT_KEY=dev AGENT_URL=http://127.0.0.1:8082 node server.js
node --test
```
