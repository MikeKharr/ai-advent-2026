# День 11 — профили и слои памяти агента

`https://challenge.zpq.ai/day11/`

День 10 помнил один разговор. День 11 разносит память агента на три слоя с
разной принадлежностью и разным сроком: **память персонализации** (настройки
профиля и правила, извлечённые моделью из разговоров), **память фактов** по
темам, которые человек прорабатывает, и **рабочая память** текущего диалога со
стратегиями дня 10. Первые два живут на профиле 30 дней, третий — в диалоге
30 часов. Решение — `agent_docs/adr/2026-09-15-2024-day11-profiles-knowledge-topics.md`,
раскладка — `agent_docs/design/2026-09-16-0542-day11-profiles-memory-layout.md`.
Дни 6–10 остаются в проде без изменений.

**Агент дня 11 — другой агент.** `layered-agent` в реестре сервиса: без архива
статей, без сферы, без готовых запросов и без белого списка ссылок. Инварианты
I-7–I-9 о карточках новостей к нему не относятся, и страница говорит это прямо:
ссылки и числа в его ответах ничем не подтверждены.

**Профиль ничего не защищает.** Это ярлык памяти, а не учётная запись:
любой посетитель видит все профили, выбирает любой, пополняет его память и
удаляет его целиком со всеми правилами, темами, фактами и диалогами. Экран
входа говорит об этом до выбора, а не после.

## Локальный запуск

```sh
AGENT_KEY=<ключ сервиса агентов> \
AGENT_URL=http://127.0.0.1:8082 \
COOKIE_PATH=/ COOKIE_SECURE=false \
node server.js
```

Тесты: `node --test test/*.test.js` — сервер дня против поддельного сервиса
агентов: две cookie, оба окна лимитера, ручки профиля и диалогов, создание
диалога первым сообщением, потолки профилей и диалогов, чтение переписки со
слоями, очистка, прокси потока.

## Чем отличается от дня 10

- **Экран выбора профиля** — при каждом заходе, до всего остального. Видны все
  живые профили с временем последней активности и числом диалогов; профиль из
  cookie помечен «в прошлый раз». Потолок — 5 профилей; при пяти живых форма
  создания выключена, и продукт **не предлагает** стереть чужой.
- **Выбор профиля диалог не создаёт.** Cookie диалога ставится, только если у
  профиля уже есть живой диалог; иначе чат пуст, и диалог рождается первым
  сообщением или кнопкой «Новый диалог». Иначе случайный клик постороннего по
  старому профилю продлевал бы срок чужой памяти.
- **Настройки агента — в окне** по плавающей кнопке слева, а не в панели над
  композитором, и живут за профилем, а не в `localStorage`. Закрытие окна любым
  способом пишет настройки; при отказе окно не закрывается и фокус идёт на
  поле-виновника. Полей сферы, «Статей с источника» и готовых запросов нет.
  «Лимит ответа» — 1–2048: потолок класса `layered_dialogue`.
- **Монитор состояния памяти** — окно по кнопке «Память профиля» в правой
  колонке: три раздела, у каждого подпись «кому принадлежит и когда исчезнет».
  Правила и факты помечены как записанные моделью и непроверенные; у факта —
  дата записи и имя диалога, а не издание.
- **Темы.** У диалога есть активная тема; к существующей теме агент переходит
  сам, а новую предлагает вопросом в диалоге — карточка с двумя кнопками и
  тремя состояниями. Пока ответа нет, факты этой части разговора припаркованы и
  уйдут вместе с диалогом, если не ответить.
- **Два окна лимитера на адрес.** Запуски — как в дне 10 (50 в сутки, 5 в
  минуту, 30 в час). Публичные записи профиля — создание, выбор, настройки,
  удаление, ответ о теме — под своим окном `RATE_LIMIT_WRITES_PER_HOUR` (60 в
  час): модель они не зовут, но меняют общую для всех память.
- **Свои cookie:** `day11_pid` (30 дней) и `day11_sid` (30 часов) на
  `Path=/day11/`. `localStorage` дня 10 не используется вовсе.

## Эндпоинты

| Путь | Что |
|---|---|
| `GET /api/profiles` | все живые профили, потолок и профиль из cookie |
| `GET /api/profile` | профиль из cookie со всей памятью: настройки, правила, темы, диалоги. Чтение — вне лимитера и срок памяти не продлевает |
| `POST /api/profile` | создание по имени; `409` — мест нет |
| `POST /api/profile/select` | выбор: ставит cookie профиля и, если живой диалог есть, cookie диалога |
| `DELETE /api/profile` | удаление профиля со всей памятью; свой указатель при этом стирается |
| `PUT /api/settings` | настройки профиля; отказ приходит словами агента |
| `GET /api/sessions` | живые диалоги профиля с именами и темами |
| `POST /api/session` | новый диалог с выбранной темой; `409` — 20 из 20 |
| `POST /api/session/select` | переключение на другой диалог профиля |
| `POST /api/session/topic` | ответ на предложение темы или ручная смена; `409` — идёт запуск |
| `GET /api/topic/:id` | факты темы для монитора: текст, дата записи, имя диалога |
| `POST /api/answer` | лимитер → при отсутствии диалога создаёт его → запуск у агента → `202 { runId }` |
| `GET /api/runs/:id/events` | прокси SSE потока событий агента |
| `GET /api/chat` | переписка, сумма токенов, сводка, контекст, голова ветки, активная тема и ожидающее предложение. `DELETE` — удаляет диалог и **не** заводит новый |
| `PUT /api/chat/head` | `{ messageId }` — переключение ветки |
| `GET /api/state` | описание агента, модели, умолчания, потолки, сроки хранения |
| `GET /healthz` | конфигурация цела |

Идентификаторы профиля и диалога день берёт только из cookie и подставляет сам;
принадлежность диалога профилю проверяет агент, и чужой диалог отвечает как
несуществующий.

## Переменные окружения

| Имя | Умолчание | Смысл |
|---|---|---|
| `AGENT_KEY` | — | ключ сервиса агентов, обязателен |
| `AGENT_URL` | `http://agents:8082` | адрес сервиса агентов |
| `AGENT_ID` | `layered-agent` | какой агент отвечает на этой странице |
| `COOKIE_PATH` | `/day11/` | путь обеих cookie |
| `COOKIE_SECURE` | `true` | `false` только для локального запуска по http |
| `SESSION_TTL_HOURS` | 30 | срок cookie диалога, совпадает со сроком хранения переписки у агента |
| `PROFILE_TTL_DAYS` | 30 | срок cookie профиля, совпадает с `PROFILE_TTL_DAYS` сервиса агентов |
| `MAX_DAILY_CALLS` | 50 | суточный предел запусков с этого адреса |
| `RATE_LIMIT_PER_MIN` | 5 | окно на адрес: запусков в минуту |
| `RATE_LIMIT_PER_HOUR` | 30 | окно на адрес: запусков в час |
| `RATE_LIMIT_WRITES_PER_HOUR` | 60 | окно на адрес: записей профиля в час |

Счётчик запусков считает **запуски**, а запуск дня 11 делает два вызова модели
(три при стратегии «Липкие факты»): 50 запусков в сутки с адреса — это 100–150
вызовов. Жёсткая граница расхода сверху — суточный потолок приложения `agents`
у роутера, общий с днями 6–10.

## Имя диалога

Сервер берёт SHA-256 от идентификатора диалога и выбирает из хеша два слова и
число: «синий-кит-42». Обратного пути нет. В отличие от дней 7–10 сам
идентификатор диалога странице виден: без него не выбрать другой диалог
профиля (ADR, п. 3). Профиль открыт, и защитой идентификатор здесь не был бы.
