Цепочка MCP

Четыре вызова к двум серверам MCP подряд: найти новости, сделать выжимку, сохранить её файлом, прочитать файл обратно. Порядок задаёт код, а не модель, и данные между шагами переносит тоже код — расход модели здесь нулевой. Ниже видно каждый вызов: имя сервера, метод и сырые тела JSON-RPC, как они прошли по проводу.

! Смысл последнего шага — сверка. Сервер выжимки возвращает её sha256, сервер хранилища возвращает sha256 прочитанного. Оба хеша показаны рядом: если они совпали, значит по цепочке дошли те же байты, а не похожие.

серверы mcpnews, mcpstore MCP-Protocol-Version 2025-11-25 расход модели: 0

Что здесь показано

Предмет дня — цепочка: выход одного инструмента подаётся на вход следующему. news.search находит новости — его ответ уходит аргументом в news.summarize; текст выжимки уходит в file.save; имя сохранённого файла уходит в file.read. Четыре вызова, два сервера MCP, и переносит данные между шагами код.

В конце сверяются два отпечатка: sha256, который вернул сервер выжимки, и sha256, который вернул сервер хранилища для прочитанного файла. Оба показаны рядом: совпали — значит по цепочке дошли те же байты, а не похожие.

Модель в этой цепочке не участвует: порядок шагов задан кодом заранее, решать нечего, токенов не тратится — прогон бесплатный. В консоли ниже видно каждый вызов: имя сервера, метод и сырые тела JSON-RPC, как они прошли по проводу.
