# День 19 — цепочка MCP

Экран цепочки `news.search` → `news.summarize` → `file.save` → `file.read`: каждый вызов с именем
сервера и сырыми телами JSON-RPC, две `sha256` рядом — выжимки и прочитанного.

Решение — ADR `2026-09-28-0736`, пп. 5, 8, 9.

## Что делает единица

Создаёт запуск агента `pipeline-agent` и показывает его события. Порядок шагов задаёт агент,
а не эта единица и не страница. Модель в цепочке не участвует — расход нулевой.

## Ручки

| Ручка | Что делает |
| --- | --- |
| `GET /healthz` | состояние настройки и статистика лимитера |
| `POST /api/runs` | `{task}` → запуск агента, `202 {runId}` |
| `GET /api/runs/:id/events` | поток событий запуска, насквозь |

## Неутверждённый контракт

Форма входа агента — `input: {task}`. Она **не утверждена**: её задаёт `pipeline-agent` в единице
`agents`. Место одно — `handleRun` в `server.js`.

Хеши берутся из ответов шагов `news.summarize` и `file.read`, из полей `result.sha256` или
`result.structuredContent.sha256` (`sha256Of` в `public/trace.js`). Других мест не ищется:
строка из 64 знаков, найденная где угодно, хешем не считается.

## Окружение

`AGENT_KEY` (обязателен), `AGENT_URL`, `AGENT_ID` (`pipeline-agent`), `RATE_LIMIT_PER_MIN` 5,
`RATE_LIMIT_PER_HOUR` 30, `PORT` 8080. Суточного денежного счётчика нет: модель не зовётся.

## Раскладка

совпадение держит `test/style-copy.test.js`.
