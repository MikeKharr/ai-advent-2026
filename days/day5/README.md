# День 5 — архив статей и выбор модели

`https://challenge.zpq.ai/day5/`

Приложение копит статьи восьми изданий в архиве на сервере (окно 1000 записей
с квотой на издание), под запрос отбирает из них подходящие алгоритмически и
задаёт вопрос той модели, которую выбрал пользователь. Ключей к моделям у дня
нет: он ходит в роутер (`agent_docs/adr/2026-09-08-1748-llm-router.md`) по
своему ключу приложения.

Решения: `agent_docs/adr/2026-09-09-1130-day5-article-archive.md` (архив и
отбор), `agent_docs/adr/2026-09-09-1100-explicit-model-choice.md` (выбор
модели). Эксплуатация — `agent_docs/operations.md`.

## Локальный запуск

```sh
ROUTER_APP_KEY=<ключ приложения day5> \
ROUTER_URL=http://127.0.0.1:8081 \
STORE_FILE=./data/store.json \
node server.js
```

Тесты: `node --test test/*.test.js` (35), включая интеграционные — они
поднимают сервер и проверяют лимитер целиком.

## Модули

```text
store.js   окно статей на диске: дедупликация, квота на источник, атомарная запись
select.js  отбор под запрос: основа слова, вес заголовка, добор свежими
router.js  клиент роутера: класс news_answer, явный provider, белый список ссылок
feeds.js   загрузка восьми лент (из дня 3, окно 90 суток вместо недели)
rss.js     разбор RSS и Atom (из дня 3)
env.js     разбор окружения и параметров, список моделей
limits.js  суточный предел и окна на адрес (из дня 3)
server.js  HTTP: /api/answer, /api/state, /healthz
```

## Переменные окружения

| Имя | Умолчание | Смысл |
|---|---|---|
| `ROUTER_APP_KEY` | — | ключ приложения у роутера, обязателен |
| `ROUTER_URL` | `http://router:8081` | адрес сервиса роутера |
| `STORE_FILE` | `/data/store.json` | файл архива на томе |
| `WINDOW_SIZE` | 1000 | сколько статей держим |
| `REFRESH_MIN_MINUTES` | 15 | не чаще этого опрашиваем ленты |
| `MAX_OUTPUT_TOKENS` | 2048 | потолок пользовательского max_tokens |
| `MAX_DAILY_CALLS` | 50 | суточный предел вызовов на процесс |
| `RATE_LIMIT_PER_MIN` | 5 | окно на адрес: запросов в минуту |
| `RATE_LIMIT_PER_HOUR` | 30 | окно на адрес: запросов в час |
| `MAX_AGE_DAYS` | 180 | дольше этого статьи в архиве не хранятся |

## Чем отличается от дня 3

- Статьи копятся на диске, а не живут 30 минут в памяти; перезапуск их не теряет.
- Подборка собирается отбором по словам запроса из всего архива, а не «свежее
  за неделю». При отсутствии совпадений отбор вырождается в самые свежие.
- Модель выбирается до запуска: Claude Haiku 4.5, GPT-OSS 20B или Qwen3.6 27B
  (последние две — через Groq). Подмены модели при отказе нет.
- Бюджет подборки зависит от модели и от её **живого остатка квоты**: день
  спрашивает у роутера `GET /v1/models`, берёт меньшее из своего предела,
  потолка провайдера и остатка, и режет подборку под него. Рядом с моделью
  видно, сколько статей она примет сейчас. Причина ограничения не в окне
  модели, а в пределе тарифа: Groq на `on_demand` принимает 7–8 тысяч
  входных токенов в минуту (ADR `2026-09-09-2330`).
- Ключ Anthropic дню больше не нужен: вызовы идут через роутер, который ведёт
  учёт и лимиты по приложению.
