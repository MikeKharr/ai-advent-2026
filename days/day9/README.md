# День 8 — разговор вместо темы

`https://challenge.zpq.ai/day8/`

День 7 спрашивал тему и сообщение. День 8 спрашивает только сообщение:
релевантность статей агент считает по репликам разговора, а подборку
набирает сам под предел входа модели. Решение —
`agent_docs/adr/2026-09-09-2134-day8-relevance-from-dialogue.md`,
раскладка — `agent_docs/design/2026-09-09-2133-day8-chat-refinements.md`.
Дни 6 и 7 остаются в проде без изменений.

## Локальный запуск

```sh
AGENT_KEY=<ключ сервиса агентов> \
AGENT_URL=http://127.0.0.1:8082 \
COOKIE_PATH=/ COOKIE_SECURE=false \
node server.js
```

Тесты: `node --test test/*.test.js` (12) — сервер дня против поддельного
сервиса агентов: cookie сессии, читаемое имя сессии, сумма токенов
переписки, лимитер, создание запуска, прокси потока, очистка.

## Чем отличается от дня 7

- **Поля темы нет.** Слова для отбора берутся из текущего сообщения и
  реплик пользователя, уже попавших в контекст: «а подробнее про первое»
  само по себе зацепок не содержит, а тема живёт в прошлых репликах.
- **Числа статей в параметрах нет.** Подборку ограничивают потолок на
  издание и предел входа модели. На Claude Haiku 4.5 это около 40 статей.
- **Счётчик токенов всей переписки** в шапке диалога, отдельно от числа
  одной итерации в сводке ответа. Сумму считает агент.
- **Читаемое имя сессии** в шапке страницы: «синий-кит-42». Выведено из
  идентификатора сессии необратимо, восстановить по нему переписку нельзя.
- **Настройки — панель, а не строка.** В дне 7 открытый блок сжимал лог до
  двух пикселей и уводил поле ввода за нижний край окна; здесь лог не
  опускается ниже 128 px, а тело настроек прокручивается само.
- **Умолчания:** ответ до 3000 токенов (было 600), контекст 2000 (было 3000).
- **Курсор при загрузке** стоит в поле сообщения на широком экране;
  подсказка о клавишах зависит от платформы, работают обе комбинации.

## Эндпоинты

| Путь | Что |
|---|---|
| `POST /api/answer` | лимитер → запуск у агента с идентификатором сессии → `202 { runId }` |
| `GET /api/runs/:id/events` | прокси SSE потока событий агента |
| `GET /api/chat` | переписка, сумма токенов и имя сессии; `DELETE` — удаляет переписку и начинает новую сессию |
| `GET /api/state` | описание агента, модели, готовые запросы, состояние архива, срок хранения, имя сессии |
| `GET /healthz` | конфигурация цела |

## Переменные окружения

| Имя | Умолчание | Смысл |
|---|---|---|
| `AGENT_KEY` | — | ключ сервиса агентов, обязателен |
| `AGENT_URL` | `http://agents:8082` | адрес сервиса агентов |
| `AGENT_ID` | `news-analyst` | какой агент отвечает на этой странице |
| `COOKIE_PATH` | `/day8/` | путь cookie сессии |
| `COOKIE_SECURE` | `true` | `false` только для локального запуска по http |
| `SESSION_TTL_HOURS` | 30 | срок жизни cookie, совпадает со сроком хранения у агента |
| `MAX_DAILY_CALLS` | 50 | суточный предел запусков с этого адреса |
| `RATE_LIMIT_PER_MIN` | 5 | окно на адрес: запросов в минуту |
| `RATE_LIMIT_PER_HOUR` | 30 | окно на адрес: запросов в час |

## Имя сессии

Сервер берёт SHA-256 от идентификатора сессии и выбирает из хеша два слова
и число: «синий-кит-42». Обратного пути нет, идентификатор остаётся в
cookie `HttpOnly` и странице недоступен. Словарь конечен (24 × 24 × 100),
поэтому имена у разных сессий могут совпасть: это метка для разговора о
переписке, а не ключ к ней.
