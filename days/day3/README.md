# День 3 — свой запрос к полным текстам новостей

**URL:** `https://challenge.zpq.ai/day3`
**Порт в контейнере:** 8080
**Образ:** `ghcr.io/mikekharr/advent-day3`

## Состояние

Работает. В отличие от дня 4, где модель получала заголовок и анонс, здесь в
подборку идёт **полный текст статьи** — там, где издание отдаёт его в ленту.
Поэтому запрос может быть шире тематики: «какие суммы раундов», «кто инвесторы»,
«сравни подходы» — ответ строится по текстам, а не по заголовкам.

Экран из трёх частей. В первом блоке — тематика и запрос под одной кнопкой:

| Поле | Что делает |
|---|---|
| Тематика | по чему отбираются материалы; подсказки на четырёх языках |
| Запрос и формат ответа | промпт для модели: что спросить и в каком виде ответить |

Параметры генерации — в правой панели: температура (0–1, шаг 0.1), статей
с источника (1–15), условие завершения, останов по токенам.

Запись ленты: тематика, дата-время, параметры, токены вход → выход, причина
останова, **сам запрос** и ответ. Лента в localStorage — сервер запросы
пользователей не хранит.

## Откуда берётся полный текст

Только из самой ленты: `content:encoded`, а где его нет — `description`
(так делает Entrackr). **За страницами статей приложение не ходит.** Причины
в ADR `2026-09-08-1420`: RSS издание публикует для агрегаторов само, а обход
страниц — это уже другая история и по нагрузке, и по правовой стороне, и по
хрупкости (вёрстка меняется, антибот-защита срабатывает).

Замер 2026-09-08: полный текст отдают шесть лент из восьми — Crunchbase (6.7К
символов), EU-Startups (4.2К), Entrackr (3.9К), Inc42 (2.8К), Tech.eu (2.6К),
Pandaily (2.2К). TechCrunch кладёт анонс на ~430 символов, Sifted не даёт
ничего, кроме заголовка.

В подборке различаются три состояния, и это важно: статья с текстом; статья,
которой издание текста не дало; и статья, у которой текст **есть, но не
поместился в бюджет запроса**. Второе и третье легко перепутать, и тогда
пользователю сообщается неправда про издание. Число материалов каждого вида
видно в ленте и в `note`.

## Как ограничен объём

Полный текст дороже заголовка примерно в двадцать раз, поэтому объём ограничен
в трёх местах:

- на статью — 6000 символов;
- на запрос — 120 000 символов текстов суммарно; дальше материалы идут только
  заголовком;
- статей с источника — 1–15, по умолчанию 5 (в дне 4 было 30);
- ссылка длиннее 500 символов отбрасывает запись при разборе: резать URL
  в промпте нельзя, потому что белый список сверяет его целиком.

Бюджет считает только тексты. Заголовки, анонсы и ссылки добавляют сверху
до ~50 000 символов, поэтому реальный вход — ~30K токенов при значениях по
умолчанию (~$0.033 за вызов) и до ~48K токенов при максимальных ползунках
(~$0.06). Суточный потолок дня при `MAX_DAILY_CALLS=50` — $1.7–3.3.
Без потолка пятнадцать статей с восьми лент дали бы ~220K токенов — больше
окна Haiku 4.5 и вдесятеро дороже.

## Устройство

| Файл | Что делает |
|---|---|
| `rss.js` | разбор RSS и Atom без зависимостей; извлечение полного текста |
| `feeds.js` | список лент, параллельная загрузка, лимит 2 МБ и таймаут на ленту |
| `answer.js` | фильтр по неделе, обрезка по источнику, бюджет текста, сборка записи |
| `anthropic.js` | вызов Messages API, подборка с текстами, вырезание чужих ссылок |
| `limits.js` | окно на IP и суточный предел, атомарный резерв слота до вызова API |
| `cache.js` | кэш лент вместе с текстами (ответы модели не кэшируются) |
| `env.js` | разбор окружения, валидация тематики и параметров на границе |
| `server.js` | SSE-прогресс, `/api/answer`, `/api/sources`, статика |

## API

- `GET /api/answer?sphere=fintech&prompt=…&temperature=0.7&max_tokens=600&per_source=5&stop=…` —
  SSE: события `progress`, затем `result` или `error`.
- `POST /api/answer {"sphere":"fintech","prompt":"…","perSource":5}` — один JSON-ответ.
  Принимаются оба написания ключей (`maxTokens` и `max_tokens`).
- `GET /api/sources` — список лент.
- `GET /healthz` — 200, либо 503 при неполной конфигурации.

Поле `format` дня 4 переименовано в `prompt`: теперь это не описание формата,
а сам запрос вместе с требованиями к формату.

## Тексты статей как недоверенные данные

В промпт попадают тысячи символов чужого текста, поэтому граница держится тем же
способом, что и раньше, но нагрузка на неё выше: разметка снимается до срезания
угловых скобок (`stripHtml`), подборка обёрнута в `<candidates>` с явным
указанием, что это данные, а указания внутри выполнять нельзя, а ссылки в ответе
сверяются с белым списком (`stripUnknownLinks`).

Границу этой защиты стоит назвать прямо: белый список составляется из ссылок
самих материалов, поэтому он не спасает от **враждебной ленты** — издание,
попавшее в список источников, определяет и содержание, и допустимые ссылки.
Гарантия здесь ровно одна: в ответе не появится ссылка, которой нет ни у одного
из восьми изданий.
