# День 1 — сфера → 3 главные свежие новости стартапов

**URL:** `https://challenge.zpq.ai/day1`
**Порт в контейнере:** 8080
**Образ:** `ghcr.io/mikekharr/advent-day1`

## Состояние

Работает. Пользователь вводит сферу, приложение читает восемь RSS-лент (США, Европа, Индия, Китай),
оставляет материалы за неделю, а модель выбирает до трёх релевантных **по номерам** — ссылку, дату и
издание подставляет приложение из ленты (ADR `2026-09-07-2016`).

## Устройство

| Файл | Что делает |
|---|---|
| `rss.js` | разбор RSS и Atom без зависимостей: CDATA, сущности, дедупликация |
| `feeds.js` | список лент, параллельная загрузка, лимит 2 МБ и таймаут на ленту |
| `digest.js` | фильтр по неделе, отбор по кругу источников, сборка карточек |
| `anthropic.js` | вызов Messages API, строгий JSON, санитизация номеров |
| `limits.js` | окно на IP и суточный предел, проверка до всякой работы |
| `cache.js` | кэш лент и дайджестов, одна работа на ключ |
| `env.js` | разбор окружения и валидация сферы на границе |
| `server.js` | SSE-прогресс, `/api/digest`, `/api/sources`, статика |

## API

- `GET /api/digest?sphere=fintech` — SSE: события `progress`, затем `result` или `error`.
- `POST /api/digest {"sphere":"fintech"}` — один JSON-ответ.
- `GET /api/sources` — список лент.
- `GET /healthz` — 200, либо 503 при неполной конфигурации.

## Важно про префикс

Caddy срезает `/day1` через `handle_path`, поэтому приложение видит пути от корня и остаётся запускаемым локально на `/`.

Правило: **все ссылки и `fetch` — относительные** (`./healthz`, а не `/healthz`). Абсолютный путь уедет в корень домена и вернёт лендинг вместо ответа API.

`<base href="/day1/">` **не нужен и вреден.** В `Caddyfile` есть `redir /day1 /day1/`, поэтому адрес в браузере всегда с завершающим слэшем, и относительный путь и так разрешается правильно: `./healthz` → `/day1/healthz` в проде, `/healthz` при локальном запуске. Жёстко прописанный `<base>` ломает второй случай — страница локально показывает «недоступно».
