**Порт в контейнере:** 8080

## Состояние

Работает. Функционально это день 2 плюс температура; экран переделан по
дизайн-корпусу (`agent_docs/design/corpus.md`) — день 4 первый, к кому корпус
применяется.

Параметры:

| Поле | Куда уходит | По умолчанию |
|---|---|---|
| Формат ответа | в промпт, свободным текстом | краткий дайджест по пунктам |
| Температура | `temperature` | 1.0 (0–1, шаг 0.1) |
| Статей с источника | обрезка кандидатов перед моделью | 30 (1–50) |
| Условие завершения ответа | `stop_sequences` (до 4, по одной на строку) | нет |
| Останов по токенам | `max_tokens` | 200 (1–2048) |

Запись ленты: запрос, дата-время, параметры (включая температуру), токены
вход → выход, причина останова, сам ответ. Лента хранится в localStorage —
сервер запросы пользователей не хранит.

Сфера — свободный текст на любом языке. Подсказки под полем даны на русском,
английском, китайском и хинди: ленты индийские и китайские тоже, и граница
не-латиницу не режет. Ответ при этом по-русски, как задано системным промптом.

## Про температуру и модель

`temperature` принимают не все модели Anthropic. Haiku 4.5 (модель проекта по
умолчанию) — принимает; Sonnet 5 отвергает **недефолтное** значение; Opus 4.7
и новее отвергают параметр целиком, включая дефолтное.

Поэтому параметр уходит в запрос, **только если пользователь сдвинул ползунок**
с значения по умолчанию. При положении 1.0 тело запроса температуры не содержит
вовсе, и день остаётся рабочим на любой из этих моделей; сдвинутый ползунок на
модели, которая сэмплинг не принимает, ожидаемо даст 400 — это вопрос выбора
модели, а не кода.

Значение по умолчанию — 1.0, совпадает с дефолтом API. Значения между шагами
(например 0.15) отвергаются на границе: молчаливое округление скрыло бы от
пользователя, что применён не тот параметр, который он задал.

## Устройство

| Файл | Что делает |
|---|---|
| `rss.js` | разбор RSS и Atom без зависимостей: CDATA, сущности, дедупликация |
| `feeds.js` | список лент, параллельная загрузка, лимит 2 МБ и таймаут на ленту |
| `answer.js` | фильтр по неделе, обрезка N статей с источника, сборка записи ленты |
| `anthropic.js` | вызов Messages API с `temperature`/`stop_sequences`/`max_tokens`, вырезание чужих ссылок |
| `limits.js` | окно на IP и суточный предел, атомарный резерв слота до вызова API |
| `cache.js` | кэш лент (ответы модели не кэшируются), одна работа на ключ |
| `env.js` | разбор окружения, валидация сферы и параметров на границе |
| `server.js` | SSE-прогресс, `/api/answer`, `/api/sources`, статика |

## API

- `GET /api/answer?sphere=fintech&format=…&stop=…&max_tokens=200&per_source=30&temperature=0.7` —
  SSE: события `progress`, затем `result` или `error`.
- `POST /api/answer {"sphere":"fintech","temperature":0.7,"maxTokens":200,"perSource":30}` —
  один JSON-ответ. Принимаются оба написания ключей (`maxTokens` и `max_tokens`).
- `GET /api/sources` — список лент.
- `GET /healthz` — 200, либо 503 при неполной конфигурации.

## Дизайн

Экран собран по `agent_docs/design/corpus.md`: все отступы из шкалы 4px
(значений вне шкалы — ноль), четыре размера шрифта из шести токенов, палитра
с проверенным контрастом в обеих темах, `:focus-visible` на каждом
интерактивном элементе, четыре состояния контента, `tabular-nums` для чисел,
которые сравнивают глазами, `prefers-reduced-motion`.

Известное отклонение: `[disabled]` описан только у кнопки — поля параметров
во время запроса не блокируются, поэтому состояние сегодня недостижимо.

Раскладка «работа / параметры / результат»: на экране от 64rem каждая колонка
скроллится сама, поэтому форма и параметры остаются на местах, пока листаешь
ленту. Ниже 64rem — обычный поток страницы.
