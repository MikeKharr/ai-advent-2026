# Контракт запуска `cited-agent` (день 24)

Источник истины — код: `agents/src/rag-agent.js` (`createRagAgent`, опция
`pipeline: 'cited'`) и `agents/src/rag/cited.js`. Отбор — дня 23 целиком
(`agents/src/rag/retrieve.js`, контракт `day23-rerank-contract.md`): всё, что
там сказано про нумерацию, события поиска и отказы, здесь верно без
изменений. Этот файл описывает **только добавку дня 24** — форму ответа,
сверку цитат и исходы. Решение — ADR `2026-10-05-0544`, п. 2.

## Вход

`POST /v1/runs` сервиса агентов, `agentId: "cited-agent"`, `input`:

| Поле | Значение |
| --- | --- |
| `question` | непустая строка, до 600 знаков |
| `mode` | `rerank` или `rewrite` — умолчания нет |

Режимов два, а не три: режим `rag` дня 23 — это «до» его сравнения, а день 24
строится на отборе. Какой из двух работает на странице и в прогоне, задаёт
правило ADR, п. 2.4 (`rewrite`, если MRR@10 после отбора выше `rerank` не
меньше чем на 0,02, иначе `rerank`). Числа дня 23 на момент этого PR ещё нет,
поэтому режим называет вызывающий, как и в дне 23, а страница с прогоном
пошлют один — выбранный по правилу, а не по вкусу реализации.

## Форма ответа — схемой, а не просьбой

Вызов ответа уходит в роутер с полем `schema` (`agents/src/llm.js`,
`askLayered`); роутер требует от провайдера возможность `json_schema` и
возвращает **разобранный** объект полем `json`. Схема —
`ANSWER_SCHEMA` в `agents/src/rag/cited.js`:

```json
{
  "status": "answered | unknown",
  "answer": "строка",
  "sources": [{ "n": 1, "source": "путь", "section": "раздел" }],
  "quotes": [{ "n": 1, "text": "дословно" }],
  "clarification": "строка; пусто — уточнения нет"
}
```

Все поля обязательны, лишних нет (`additionalProperties: false`). Повтора при
неразборе **нет**: роутер отдаёт `invalid_json`/`truncated`, запуск проваливается
с `paidNothing: false` — платить второй раз за ту же неудачу незачем.

**Конструкции схемы — только те, что уже ходили к живому провайдеру**: `type`
object/array/integer/string, `properties`, `required`, `additionalProperties`,
`enum` — как у схемы дня 1 (`days/day1/anthropic.js`, `SELECTION_SCHEMA`) и
реранкера дня 23. `type: ["string", "null"]` и `maxLength` в схеме **не
используются**: в строгих подмножествах JSON Schema ограничения строк обычно
не поддерживаются, а 400 от провайдера — оплаченный отказ. Поэтому
`clarification` — обычная строка, и пустая означает «уточнения нет» (наружу,
в результат запуска, она выходит как `null`), а потолок цитаты в 300 знаков
держит код, не схема.

## Сверка цитат — механическая, в коде

Каждая `quotes[].text` после нормализации (`flatten`: NFC, пробелы в один,
регистр вниз — та же, что у прогона дня 22) обязана быть **подстрокой** текста
фрагмента `n` — того, как его отдала служба (срез 2000 знаков). Несовпавшая
цитата не выбрасывается, а едет с `verified: false`, и страница показывает её
такой. Цитата с номером вне отбора, пустая цитата и цитата длиннее 300 знаков —
тоже `verified: false`: проверить их не по чему, а подстрока размером во весь
фрагмент не доказывает ничего, кроме копирования.

`sources[].n` обязаны указывать на фрагменты, **оставшиеся после отбора**.
Чужой номер — отказ формы, а не тихая строка на экране.

**Путь и раздел в результат берутся из отбора, а не из ответа модели.** Сверять
один номер мало: подтверждённая цитата могла бы стоять под выдуманным путём, и
страница показала бы «дословно из `agent_docs/выдумка.md`». Заявленное моделью
не выбрасывается — оно едет рядом полями `claimedSource` и `claimedSection`, а
расхождение видно признаком `checks.cited_exact` (сравнение путей точное, не по
подстроке — находка дня 22 про q72/q57).

## Исходы (`outcome`)

| `outcome` | Когда | Вызовов модели ответа |
| --- | --- | --- |
| `answered` | есть источники и хотя бы одна подтверждённая цитата | 1 |
| `unknown_filter` | реранкер не оставил ни одного фрагмента; модель вызвана **без блока фрагментов**, с путями и заголовками десяти отброшенных кандидатов, и формулирует «не знаю» своими словами плюс `clarification` | 1 |
| `unknown_model` | фрагменты были, модель вернула `status: "unknown"` и свой уточняющий вопрос | 1 |
| `unsupported` | `status: "answered"`, но подтверждённых цитат ноль | 1 |

Пятый случай — ответ не по форме — исход не запуска, а отказ: см. ниже.
Отличие от дня 23: при пустом отборе модель **вызывается** (решение владельца
Р5(б)), а шаблонной строки «ни один фрагмент не относится» у дня 24 нет.

## Результат успешного запуска (`result`)

Поля дня 23 — `mode`, `rewritten`, `candidates`, `sources`, `index`, `rpc`,
`tokens`, `budgetLeftUsd`, `truncated`, `model`, `durationMs` — те же и в том
же смысле. Добавка дня 24:

| Поле | Тип | Что это |
| --- | --- | --- |
| `outcome` | строка | один из четырёх исходов выше |
| `status` | `"answered"` \| `"unknown"` | поле схемы, как его вернула модель |
| `answer` | строка | текст **из поля схемы**, а не всё тело ответа |
| `clarification` | строка \| `null` | уточняющий вопрос посетителю |
| `cited` | список | `{n, source, section, claimedSource, claimedSection}` — номера, на которые сослалась модель; `source`/`section` взяты **из отбора** по номеру, `claimed*` — то, что назвала модель |
| `quotes` | список | `{n, text, verified}` — цитаты с результатом сверки |
| `checks` | объект | `sources_present`, `quotes_present`, `quotes_verbatim`, `cited_exact` — булевы |
| `refused` | булево | `status === "unknown"`; подстроку фразы день 24 не ищет |

`sources` — отобранные фрагменты с текстами, то есть **то, что ушло модели**;
`cited` — **номера, на которые она сослалась**, с путями из отбора. Два списка,
а не один: страница показывает цитату рядом с тем фрагментом, из которого её
проверяли. Подмножество это по построению: номер вне отбора не доходит сюда —
он отказ формы, а путь берётся не из ответа модели.

`checks.quotes_verbatim` истинен, только когда цитаты есть и подтверждены
**все**: признак обязан краснеть от первой же выдуманной, иначе он меряет
старательность, а не достоверность. `checks.cited_exact` истинен, когда
источники есть и у каждого заявленный моделью путь совпал с настоящим точно.
У исходов «не знаю» все четыре признака ложны по построению.

## Отказы (`status: "failed"`, поле `error`)

Все отказы дня 23 — те же (`search_unavailable`, `search_failed`,
`search_refused`, `search_empty`, `rerank_invalid`, отказы роутера). Новый
один:

| `code` | Когда | `paidNothing` |
| --- | --- | --- |
| `answer_invalid` | ответ не по форме: не разобрался (`data.reason: "unparsed"`), исход не `answered`/`unknown` (`bad_status`), источник вне отбора (`unknown_source`), ответ там, где фрагментов не было (`answered_without_fragments`) | `false` |

Отказ поиска по-прежнему наступает **до** первого вызова модели — во всех
режимах, в том числе в `rewrite`.

## События

Контракт дня 23 целиком. Отличия: у события `llm_call` вызова ответа есть
`data.schema: true` и `data.unknownBranch` (булево — шёл ли вызов без блока
фрагментов), а при неподтверждённой цитате добавляется событие стадии
`warning` «Цитата не нашлась во фрагменте» с `data.unverified` — списком
номеров.
