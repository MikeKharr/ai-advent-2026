# Логирование

Использовать, если скрипт делает сетевые запросы, работает с внешними сервисами или есть риск ошибок.

## Правила

- Использовать минимально необходимый объем данных.
- Создавать один лог на один запуск приложения.
- Путь к логу, папка `logs/run-%timestamp%`.
- В этой папке создать файл `_log.md` и вести все записи в нем.
- Использовать Markdown-разметку.
- Одна запись = одно событие; указывать время и уровень (INFO/WARN/ERROR).
- Удалять логи старше трех дней, если нет иных инструкций.
- Текст запросов скрывать под `<details>` для экономии места.
- **Никогда не логировать значение `ANTHROPIC_API_KEY`, заголовок `x-api-key` и полное тело запроса к Anthropic** (инвариант I-1).
- **Access-логи Caddy выключены намеренно и включаются только с фильтрацией query.** Со дня 2 запрос пользователя (сфера, формат ответа) уходит в query string GET `/api/answer`: access-лог с query рядом с IP стал бы хранением запросов пользователей — нарушение I-10.

## Минимальный шаблон лога

```markdown
## События
- [HH:MM:SS] [INFO] start - ok
- [HH:MM:SS] [INFO] request anthropic messages - ok (searches: 3, tokens_in: 18420)
- [HH:MM:SS] [WARN] rate limit hit ip=<hash> - refused
- [HH:MM:SS] [ERROR] <action> - <error>
- [HH:MM:SS] [INFO] finish - ok
```
