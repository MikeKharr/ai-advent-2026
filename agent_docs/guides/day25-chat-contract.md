# Контракт хода дня 25

Что сервер обещает странице дня 25 на каждый ход диалога. Решение —
ADR `2026-10-05-0544`, п. 3; код — `agents/src/rag/chat.js`,
`agents/src/staged.js`, `agents/src/rag/retrieve.js`, `agents/src/rag/cited.js`.
Этот файл — контракт, а не пересказ ADR: расхождение кода с ним — дефект.

## Что взято из дня 15 и не переписано

Профили и шесть правимых промптов, диалог с рабочей памятью, машина этапов с
паузой на границе этапа, события запуска потоком, журнал этапов CSV и текст
промпта каждого круга — всё это код дней 13–15 (`agents/src/sessions.js`,
`memory.js`, `context.js`, `staged.js`, `runs.js`, `stage-log.js`). День 25 —
та же машина с четвёртым швом `rag`; копии `staged.js` нет.

## Этапы хода — восемь

`intake → assemble → retrieve → prepare → answer → verify → replenish → deliver`
(`RAG_STAGES`). Новый — третий; остальные — таблица дня 15 (`PREPARE_STAGES`).

`retrieve` стоит **до** `prepare` и `answer`, и внутри него первым идёт поиск,
а не переписывание. Отсюда обещание «источники всегда»: хода без поиска не
бывает, а отказ поиска — отказ хода **до единого вызова модели** (I-4).
Возврат с `verify` идёт на `assemble`, значит на каждом круге проходят и
`retrieve`, и `prepare`: у круга свои фрагменты и своя строка `run_prompts`.

## Вызовы модели — шесть на ход

| № | Что | Класс | Потолок ответа | Схема |
|---|---|---|---|---|
| 1 | переписывание реплики в поисковый запрос (всегда, Р6(б)) | `summarize` | 500 | нет |
| 2 | реранкер: оценки десяти кандидатам | `layered_dialogue` | 200 | `ratings` |
| 3 | ответ посетителю | `layered_dialogue` | `maxTokens` хода | ответ дня 24 |
| 4 | проверка ответа (`kimi-k2.6`) | `layered_dialogue` | 400 | нет |
| 5 | пополнение памяти профиля | `summarize` | 400 | нет |
| 6 | состояние задачи (`stage.task`) | `layered_dialogue` | 400 | `TASK_SCHEMA` |

Седьмой вызов бывает ровно в одном случае — сжатие истории при стратегии
«сводка» и наступившем пороге; это вызов дня 11, а не дня 25. Эмбеддингов на
ход — два (исходная реплика и переписанный запрос).

## Запрос ответа

Блоки в порядке политики (`context.js`, `assemble`):
`<invariants>` → `<personalization>` → `<topic>` → блок стратегии памяти →
`<dialog>` → `<review>` → **`<fragments>`** → **`<task>`** → `<request>`.
Последние два — новые; складывает их `prepare`, и в `run_prompts` они
попадают дословно. Если отбор не оставил ни одного фрагмента, на месте
`<fragments>` стоит `<rejected>` — пути и заголовки отброшенных кандидатов без
текстов (исход «не знаю» дня 24).

Фрагменты, состояние задачи и записи памяти — **недоверенные данные**: блок
помечен сведениями, закрывающая метка обезвреживается, запрос стоит
последним. Держит это форма блока — и больше ничто (та же граница, что у дней
22–24; `agent_docs/invariants.md`, абзац о дне 22).

## Результат хода

Сверх полей дня 15 (`answer`, `summary`, `context`, `review`, `layers`,
`rounds`, `stagesPassed`, …):

| Поле | Что |
|---|---|
| `sources[]` | фрагменты, ушедшие модели: `n`, `source`, `section`, `score`, `relevance`, `text`, `truncated`. Номера те же, которыми ссылается ответ |
| `cited[]` | источники, на которые сослалась модель: подмножество `sources` |
| `quotes[]` | `n`, `text`, `verified` — дословность сверена кодом, не моделью |
| `checks` | `sources_present`, `quotes_present`, `quotes_verbatim` |
| `status` | `answered` или `unknown` (поле схемы) |
| `outcome` | `answered`, `unknown_filter`, `unknown_model`, `unsupported` |
| `clarification` | уточняющий вопрос посетителю или `null` |
| `rewritten` | переписанный запрос или `null` |
| `candidates[]` | все кандидаты до отбора: `score`, `relevance`, `kept`, `from` |
| `index` | коммит, стратегия и число фрагментов индекса |
| `task` | состояние задачи после хода: `goal`, `constraints[]`, `terms[]`, `clarifications[]`, `open[]`, `round`, `stored` |

Те же `sources`, `cited`, `quotes`, `checks`, `status`, `outcome`,
`clarification`, `rewritten` и `index` лежат в `meta.rag` **реплики агента**:
карточка показывает их и после перезагрузки, когда результата запуска уже нет.

## Состояние задачи

Таблица `task_state (session_id PRIMARY KEY, profile_id, state, round,
updated_at)`; `state` — JSON по `TASK_SCHEMA`, не длиннее 4000 знаков (потолок
держит `sessions.saveTaskState`: длиннее не пишется вовсе).

- обновляется шестым вызовом на этапе `replenish`, **целиком**, а не дельтой;
- отказ вызова и ответ не по схеме состояние **не стирают**: прежнее остаётся
  в силе, ход заканчивается ответом, в ленте — предупреждение;
- уходит в промпт переписывания **следующего** хода вместе с двумя прошлыми
  парами реплик — поэтому «а почему так?» ищется по цели разговора;
- промпт `stage.task` — шестой правимый промпт профиля (`PROFILE_PROMPT_IDS`),
  виден в `describe().extraPrompts` и правится ручкой
  `PUT /v1/profiles/:id/prompts/:promptId`;
- срок — с диалогом, три оператора: `clear` уносит, `deleteProfile` уносит,
  `sweep` снимает по сроку профиля.

## Отказы хода

| Код | Когда | Оплачено |
|---|---|---|
| `search_unavailable` | адреса сервера MCP у сервиса нет | нет |
| `search_refused` | отказ инструмента или окна лимитера службы `rag` | нет |
| `search_failed` | служба не ответила | нет |
| `search_empty` | первый поиск вернул пустую выдачу | нет |
| `rerank_invalid` | реранкер ответил не по схеме | да, вызов реранкера |
| `answer_invalid` | ответ не по форме: чужой номер источника, `answered` без фрагментов | да, вызов ответа |
| `budget_too_small` | запрос с фрагментами не влезает в потолок этапа | да, отбор |
| прочее | как в дне 15 (`router_error`, `rate_limited`, `session_gone`, …) | по отказу |

Повтора ни у одного отказа нет: оплаченный отказ формы стоил бы столько же
второй раз (развилка Р4 дня 24).

## Что держит обещания

| Обещание | Держит |
|---|---|
| у ответа хода есть источники, и они же у реплики | тест «у ответа хода есть источники и дословная цитата, вызовов модели шесть» (`agents/test/day25-chat.test.js`) |
| состояние задачи переживает ход и уходит в переписывание | тест «состояние задачи переживает ход, перезапуск и уходит в промпт переписывания» |
| отказ поиска не оплачивает ответ | тесты «отказ поиска обрывает ход: роутер не вызван ни разу, ход не оплачен» и «поиск недоступен — ход отказан до роутера» |
| фрагменты и состояние видны в журнале запуска | тест «фрагменты и состояние задачи попадают в текст промпта круга дословно» |
| шестой промпт действует | тест «шестой промпт профиля правит вызов состояния задачи» |
| состояние уходит с диалогом и профилем | тест «„очистить“ и удаление профиля уносят состояние задачи» |
| форма ответа обязательна | тест «ответ со чужим номером источника — отказ формы, повтора вызова нет» |

Чего не держит ничто: достоверность путей в тексте ответа (их не сверяет ни
один шаг — I-7 и I-9 к дням 22–25 неприменимы) и граница блока данных при
фрагменте, в котором встретился дословный шаблон блока указаний.
