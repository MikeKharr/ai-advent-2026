# Витрина решений в Google Drive

Google Drive — **витрина только для чтения**. Источник истины для решений — git (инвариант I-11). При расхождении прав git; файл в Drive перевыпускается.

## Зачем витрина

ADR и история живут в репозитории: их версионирует git, их видно в PR, их читают агенты во время сессии. Но репозиторий неудобно показать человеку, который не работает с кодом. Drive закрывает именно это — просмотр и ссылка, а не редактирование.

## Структура

```text
AI advent Dev/
├── 00-INDEX.md            Карта витрины, перевыпускается при каждой синхронизации
├── protocol/
│   └── action-log.md      Протокол действий, append-only
├── decisions/             Зеркало agent_docs/adr/
│   └── YYYY-MM-DD-HHMM-slug.md
└── history/               Зеркало agent_docs/development-history/
    └── YYYY-MM-DD-HHMM-slug.md
```

Имена файлов совпадают с именами в репозитории — так строка из Drive однозначно находится в git.

## Заголовок синхронизированного файла

Каждый выложенный в Drive файл начинается с блока происхождения:

```markdown
<!--
ИСТОЧНИК: agent_docs/adr/2026-09-07-1510-git-source-of-truth.md
КОММИТ: <git sha>
СИНХРОНИЗИРОВАНО: 2026-09-07 15:40 +07
ВНИМАНИЕ: копия только для чтения. Правки вносить в репозиторий.
-->
```

Без этого блока файл в Drive считается устаревшим и подлежит перевыпуску.

## Версионирование

Версионирование структурное, отдельных номеров версий документы не несут:

- **Событийные документы неизменяемы.** ADR и записи истории не редактируются. Исправление — новый датированный файл со ссылкой на старый; у ADR при этом статус «Заменяет ...».
- **Дата и время в имени файла** задают порядок. Сквозная нумерация не ведётся: параллельные агенты выбирают один и тот же следующий номер и конфликтуют.
- **Git несёт полную историю правок** для документов текущего состояния (`AGENTS.md`, `architecture.md`, `snapshot.md`).
- **Drive хранит собственную ревизию** каждого файла — этого достаточно, чтобы увидеть, когда витрина обновлялась.
- **`protocol/action-log.md` — append-only.** Новые записи добавляются в конец, прошлые не переписываются.

## Когда синхронизировать

- После принятия ADR.
- После записи в `development-history/`.
- После продакшн-деплоя.

Не синхронизировать: `.env`, любые секреты, содержимое `temp/` и `logs/`.

## Ответственность

Роль `docs`. Синхронизация — часть DoD задачи, в которой появился новый ADR или запись истории.
