# Бэклог

Оглавление очереди. Сами пункты живут в тематических файлах `backlog/`;
закрытые пункты переносить в `backlog-closed.md`. Лимит 300 строк **на файл**,
проверяется в CI.

- `backlog/days.md` — наследство приложений дней: находки, починка которых живёт в оставшемся коде. Самих дней, их страниц и витрины атласа больше нет (ADR `2026-10-20-0737`), пункты про них перенесены в `backlog-closed.md`.
- `backlog/infra.md` — CI, выкатка, сервер, Caddy, роутер, служба MCP.
- `backlog/rag.md` — служба `rag`, индекс, корпус, эмбеддинги, мера поиска.
- `backlog/process.md` — правила процесса, гейты, ADR, документы.

Новый пункт заводить в файл по теме того, где лежит починка. В каждом файле
свои разделы `Next` / `Soon` / `Later`; порядок приоритета — внутри темы.

Пункт «Владельцу» заканчивается меткой «проверено ДАТА: ЧЕМ» — файлом со строкой, прогоном, ссылкой; у несверенных метки нет, и это и значит «не сверено». Без метки пункт читается как сегодняшний, хотя может быть любой давности: пункт про `deploy/.env.example` утверждал «только до дня 8», когда дни 13 и 14 уже были описаны, а 9–11 — нет, и занижал срочность. Сверять по источнику, а не по тексту пункта (`guides/verification.md`).

Закрытие бывает трёх видов, и это разные вещи:
`- [x] ДАТА — …` — выполнено, работа сделана;
`- [~] ДАТА — снят как ошибочный: … опровергнуто ЧЕМ` — задачи не было;
`- [~] предмет удалён, ADR <ссылка> — …` — работа не сделана и находка не
опровергнута, но починить нечего: файл, экран или служба удалены. Третий вид
заведён 2026-10-20 при свёртывании заданий челленджа (ADR `2026-10-20-0737`):
так ушли 69 пунктов и два раздела — 59 пунктов и оба раздела из
`backlog/days.md`, 7 из `backlog/rag.md`, 2 из `backlog/infra.md`, 1 из
`backlog/process.md`. Все три вида уходят в `backlog-closed.md`; снятый пункт
не исчезает молча, иначе опровергнутая находка заводится заново.
