# Архитектура

## Обзор

Одно Node-приложение без runtime-зависимостей, за реверс-прокси Caddy, на одном VPS. Состояние — только локальный SQLite-кэш. Внешняя зависимость одна: Anthropic Messages API.

## Контекст

Пользователь вводит сферу. Приложение спрашивает у Claude свежие новости стартапов в этой сфере, Claude ищет в вебе через server-side инструмент `web_search`, приложение отдаёт браузеру до трёх карточек с источниками.

Публичный URL держит платный API-ключ, поэтому контроль расхода — часть архитектуры, а не эксплуатации.

## Ключевые компоненты

```text
      Браузер
         │  POST /api/digest  { sphere }
         │  ← text/event-stream
         ▼
 ┌─────────────────────────────────────────────┐
 │  Caddy  (:80 / :443, Let's Encrypt автоматом)│
 └───────────────────┬─────────────────────────┘
                     ▼
 ┌─────────────────────────────────────────────┐
 │  app — Node 22, без зависимостей, :8080     │
 │   server.js     маршруты, SSE, статика       │
 │   digest.js     единственная доменная операция│
 │   anthropic.js  Messages API + web_search    │
 │   cache.js      sqlite, TTL 6 ч на сферу     │
 │   limits.js     на IP + суточный предел      │
 │   public/       index.html app.js style.css  │
 └───────────────────┬─────────────────────────┘
                     │  HTTPS
                     ▼
        api.anthropic.com  /v1/messages
          model: claude-sonnet-5
          tools: web_search + publish_digest
```

- Project-local skills source: `.agents/skills/<name>/SKILL.md`.
- Platform skill mirrors: `.claude/skills/`, `.codex/skills/`, `.cursor/skills/`.

## Потоки данных

1. `POST /api/digest { sphere }`.
2. Нормализация и валидация сферы: пусто, >60 символов, управляющие символы — отказ.
3. Проверка лимитов: token bucket на IP, затем суточный предел. Проверка **до** вызова API (инвариант I-4).
4. Поиск в кэше по паре (нормализованная сфера, сутки). Попадание — отдать из кэша, API не вызывать.
5. Промах — потоковый вызов Anthropic: блоки `server_tool_use` показываются пользователю как «Ищу: <запрос>», блок `publish_digest` несёт структурированный результат.
6. Валидация результата по схеме, запись в кэш.
7. Отдача карточек в браузер.

## Технологии и зависимости

| Слой | Выбор | Почему |
|---|---|---|
| Runtime | Node 22 | `node:http`, `fetch`, `node:test`, `node:sqlite` покрывают всё; ноль зависимостей |
| LLM | Anthropic Messages API, `claude-sonnet-5` | Нужен server-side `web_search`; Sonnet 5 — баланс цены и качества |
| Свежесть данных | `web_search_20260318` | Обучающие данные не содержат новостей этой недели |
| TLS | Caddy | Сертификат выпускается сам, конфиг в пять строк |
| Хостинг | Vultr Singapore, High Frequency | ~30 мс от Бангкока, $6/мес |
| CI/CD | GitHub Actions | Деплой по push в main; из песочницы агента SSH закрыт |

## Нефункциональные требования и ограничения

- Стоимость: ≈ $0.085 за некэшированный запрос. Суточный предел по умолчанию 50 вызовов.
- Отклик: до 15 с при промахе кэша — поэтому SSE-прогресс обязателен, иначе ожидание выглядит как зависание.
- Доступность: один инстанс, без резервирования. Простой допустим.
- Секреты: только в `.env` на сервере и в GitHub Secrets.
