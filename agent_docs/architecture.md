# Архитектура

## Обзор

Монорепозиторий: одно задание челленджа — один каталог `days/dayN/` — один контейнер. Единственный VPS с Caddy принимает `challenge.zpq.ai` и маршрутизирует префикс пути в контейнер соответствующего дня. Корень домена отдаёт статический лендинг со списком дней.

Образы собираются в GitHub Actions и публикуются в GHCR. Сервер только тянет образ и перезапускает сервис.

## Контекст

Содержание будущих заданий неизвестно, поэтому дни изолированы по стеку, отказу и деплою: день 3 может оказаться на Python, не затронув день 1.

Для дня 1 внешняя зависимость одна — Anthropic Messages API. Публичный адрес держит платный ключ, поэтому контроль расхода — часть архитектуры, а не эксплуатации.

## Ключевые компоненты

```text
                    challenge.zpq.ai

        ┌──────────────────────────────────────┐

        │  handle_path /day1/* → day1:8080     │  ← префикс срезается
        │  handle      /       → /srv/site     │
        └───────┬──────────────────────┬───────┘
                │                      │
                ▼                      ▼
     ┌────────────────────┐   ┌──────────────────┐
     │ контейнер day1     │   │ site/ (статика)  │
     │ ghcr.io/mikekharr/ │   │ список дней      │

```

Каталоги:

```text
days/dayN/     приложение дня: Dockerfile, код, public/
site/          лендинг на корне домена
deploy/        Caddyfile, compose.yml, bootstrap.sh
```

Новый день = каталог + две строки в `Caddyfile` + сервис в `compose.yml` + ссылка на лендинге.
Порядок и детали — `agent_docs/guides/new-day.md`. Ключ Anthropic общий для всех дней
(`deploy/secrets.env` на сервере), заводить его для нового дня не нужно.

- Project-local skills source: `.agents/skills/<name>/SKILL.md`.
- Platform skill mirrors: `.claude/skills/`, `.codex/skills/`, `.cursor/skills/`.

## Потоки данных

### Деплой

1. Ветка `dayN` → PR → CI (синтаксис, тесты, сборка образа, `/healthz`) → мерж в `main`.
2. Workflow определяет изменённые дни по diff.
3. Сборка и публикация `ghcr.io/mikekharr/advent-dayN:<sha>`.
4. На сервере: `git pull`, пин `DAYN_TAG=<sha>` в `deploy/.env`, `docker compose pull`, `up -d`.
5. Проверка живого адреса: лендинг 200, `/dayN/healthz` 200.

Откат — подстановка предыдущего sha в `deploy/.env` и `docker compose up -d dayN`. Пересборка не нужна.

### Запрос дня 1

1. `POST /api/digest { sphere }` — браузер шлёт на `/day1/api/digest`, Caddy срезает префикс.
2. Нормализация и валидация сферы: пусто, >60 символов, управляющие символы — отказ.
3. Проверка лимитов: token bucket на IP, затем суточный предел. **До** вызова API (инвариант I-4).
4. Поиск в кэше по паре (нормализованная сфера, сутки). Попадание — отдать из кэша, API не вызывать.
5. Промах — потоковый вызов Anthropic: `server_tool_use` показывается как «Ищу: <запрос>», `publish_digest` несёт структурированный результат.
6. Валидация по схеме и валидация источников: URL карточки должен быть в выдаче поиска того же ответа, не быть страницей-разделом и не повторять URL другой карточки. Не прошедшая карточка снимается с пояснением в `note`, добор повторным вызовом API запрещён (I-7, I-8; ADR `2026-09-07-1954`).
7. Запись в кэш, отдача карточек. Пустой результат — честное пустое состояние, а не ошибка.

## Технологии и зависимости

| Слой | Выбор | Почему |
|---|---|---|
| Runtime | Node 22 | `node:http`, `fetch`, `node:test`, `node:sqlite` покрывают всё; ноль зависимостей |
| LLM | Anthropic Messages API, `claude-haiku-4-5` | Нужен server-side `web_search`; задача узкая, ставка за токен вдвое ниже, чем у Sonnet 5 (ADR `2026-09-07-1910`, статус «Предложено») |
| Свежесть данных | `web_search_20250305` | Обучающие данные не содержат новостей этой недели. Базовая версия: динамическая фильтрация всё равно недоступна на моделях до 4.6 |
| TLS | Caddy | Сертификат выпускается сам, конфиг в пять строк |
| Хостинг | ReadyIDC VPS-LXS+, Бангкок | Оплата переводом — карточные рельсы не задействованы; ฿267.50/мес, 2 ядра, 4 ГБ, 100 ГБ |
| CI/CD | GitHub Actions | Деплой по push в main; из песочницы агента SSH закрыт |
| Реестр образов | GHCR | Инстанс 1 ГБ не тратит память на сборку; откат — предыдущий тег |
| Маршрутизация | Caddy `handle_path` | Префикс срезается, приложение остаётся запускаемым локально на `/` |

## Нефункциональные требования и ограничения

- Стоимость: измерено спайком 2026-09-07 на одной выборке — **$0.104 и $0.112** за некэшированный дайджест на Haiku 4.5 (вход 55–65K токенов, выход 1.3–1.8K, четыре поиска). Из них $0.04 — поисковые сборы, от модели не зависят. Прежняя оценка $0.085 была занижена: результаты поиска без динамической фильтрации попадают в контекст целиком. Детали замера — ADR `2026-09-07-1954-web-search-strict-json.md`.
- Потолок расхода: `MAX_DAILY_CALLS=50` — предел HTTP-вызовов `/v1/messages` в сутки. Поиски выполняются внутри одного вызова (серверный инструмент), поэтому дайджест — обычно один вызов, в краевых случаях два-три (`pause_turn`; параллельный вызов `web_search` с клиентским инструментом). То есть предел даёт до 50 дайджестов в сутки. Поисковая часть ограничена точно: `MAX_DAILY_CALLS × MAX_SEARCH_USES × $0.01 = $2.00/сут`. Ожидаемая полная загрузка при измеренных $0.112 ≈ **$5.60/сут**; структурный потолок при полном окне контекста ≈ **$12.50/сут**, потому что токеновая часть самим лимитом не ограничена. Потолок в деньгах даёт только биллинг-алерт на стороне Anthropic, его величину задаёт владелец.
- Отклик: измерено 61 с при промахе кэша (спайк 2026-09-07; 23 с у варианта с одним поиском). Прежнее требование «до 15 с» не выполняется. Следствия: SSE-прогресс обязателен — минута тишины неотличима от зависания; таймауты и число одновременных вызовов «в полёте» считать от 60 с, а суточный счётчик инкрементировать до вызова, а не по его завершении (I-4).
- Доступность: один инстанс, без резервирования. Простой допустим.
- Секреты: только на сервере (`deploy/secrets.env` — общий для всех дней) и в GitHub Secrets.
