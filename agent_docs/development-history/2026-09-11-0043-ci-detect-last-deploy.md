# [2026-09-11 00:43] CI: `detect` от последней успешной выкатки

Файл: `agent_docs/development-history/2026-09-11-0043-ci-detect-last-deploy.md`

## Проблема

Очередь `concurrency: deploy-production` держит один ожидающий запуск и
отменяет предыдущий ожидающий. Если docs-мерж приходил сразу за мержем кода,
он отменял ожидающую выкатку кода, а его `detect` смотрел только на
`HEAD^..HEAD` и выкатывал один `atlas`. Все проверки были зелёными, но кода на
проде не оказывалось. Пока это не починили, действовало ручное правило «не
мержить, пока выкатка ждёт» (запись `2026-09-10-1338-atlas-stage-4.md`).

## Что сделано

- **PR #71** (`4888c73`), класс A: `deploy.yml` ссылается на `secrets.*`.
  Гейты: `reviewer` APPROVE и `compliance` БЕЗ ВОЗРАЖЕНИЙ на head `80dce6f`.
  Мержил агент по консенсусу, вердикты записаны в теле squash-коммита.
- Базой diff стал head sha последней успешной push-выкатки `deploy.yml` на
  `main`. Его отдаёт API запусков, выборка идёт постранично и сортируется по
  `updated_at`. Запуски `workflow_dispatch` с `day=` в базу не попадают: они
  выкатывают одну единицу. Если API не ответил, `detect` падает, пустой базы
  не бывает.
- Выбор единиц вынесен в `.github/scripts/deploy-units.sh`. Пустая база даёт
  все единицы с предупреждением. Если база не предок head, `detect` красный:
  откатить прод повтором старого запуска нельзя. Единицы пересекаются с
  каталогами, в которых есть `Dockerfile`, поэтому удалённый каталог сборку не
  валит.
- У `detect` свои права: `contents: read`, `actions: read`, раньше были
  `packages: write` на весь workflow. Checkout идёт с
  `persist-credentials: false`, `GH_TOKEN` виден только шагу выборки.
- `operations.md`, раздел «Атлас проекта»: ручное правило очереди снято.
  Откат прода делает владелец. Агент перезапускает только последний запуск
  выкатки (`gh run rerun <id> --failed`).
- Автор проверил 12 сценариев, в том числе на реальной истории `main`. На
  случае #45/#46 новая логика выкатывает `agents`, `day8` и `router`, а старая
  выкатывала только `atlas`. Таблица — в описании PR.

## Вето compliance

Первый вердикт `compliance` был вето. Его сняли после правок автора, итоговый
вердикт — БЕЗ ВОЗРАЖЕНИЙ на head `80dce6f`. После правок остались:

- откат прода — действие владельца; агент перезапускает только последний
  запуск, а полный повтор старого запуска роняет `detect`;
- наименьшие права у `detect`, токен не виден скрипту репозитория.

Две находки в #71 не чинили:

- **N3** — белый список имён единиц для `workflow_dispatch day=`. Отдельный
  PR, в работе.
- **N4** — окружение `production` в GitHub не ограничено веткой `main`:
  `gh workflow run deploy.yml --ref <ветка>` выкатит код этой ветки. Настройка
  есть только у владельца, пункт в `backlog.md`.
