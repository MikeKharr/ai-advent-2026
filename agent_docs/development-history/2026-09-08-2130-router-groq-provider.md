# [2026-09-08 21:30] Роутер: провайдер Groq и отделение классификаторов от чат-моделей

Файл: `agent_docs/development-history/2026-09-08-2130-router-groq-provider.md`

## Что сделано

Владелец попросил добавить в роутер поставщика Groq, закрепив по умолчанию
модель `meta-llama/llama-prompt-guard-2-22m`, и предусмотреть работу одного
ключа с разными моделями.

- **Адаптер** `router/src/adapters/groq.js` — OpenAI-совместимый
  `POST /openai/v1/chat/completions`. Формы сверены с `console.groq.com`
  2026-09-08: ключ в `Authorization: Bearer`, потолок выхода —
  `max_completion_tokens`, схема — `response_format.json_schema` с
  обязательным `name`, размышления — `reasoning_effort` (при уровне `none`
  не отправляется: модели без его поддержки отвечают 400). Метрики берутся
  из `usage`: `queue_time` — аналог загрузки модели, `prompt_time`,
  `completion_time`.
- **Один ключ, много моделей**: запись провайдера по-прежнему описывает одну
  модель, но `secretEnv` у записей может совпадать. Две записи Groq с разными
  `id`/`model` ходят по одному `GROQ_API_KEY`; ограничение — общая
  `maxConcurrency` у записей одного хоста (ёмкость считается на хост).
  Доказано тестом «один ключ Groq обслуживает две модели».
- **Новая возможность `text_generation`** — отделяет чат-модели от
  классификаторов. Все генеративные классы её требуют; провайдер, который
  текста не порождает, в них не попадает.
- **Новый класс `guard_prompt`** (ярус `cloud-cheap`, требует `prompt_guard`,
  уровень `none` закреплён, 8 токенов ответа) — единственный, куда уходит
  классификатор.

## Почему указанная модель не могла стать провайдером «по умолчанию»

`llama-prompt-guard-2-22m` — классификатор инъекций на 22M параметров
(DeBERTa-xsmall) с окном **512 токенов**; он возвращает метку атаки, а не
текст. Без разделения он оказался бы первым кандидатом яруса `cloud-cheap`
для `summarize`, `translate` и `extract_json` — то есть забирал бы обычные
запросы и портил ответы. Поэтому модель закреплена за собственным классом,
а генеративные классы закрыты возможностью `text_generation`.

Проверено на форме конфигурации: вход длиннее 512 токенов отсекается
возможностью (окно контекста) до вызова, без расхода.

## Цена

На странице модели цена дана только для превью, поэтому в `providers.json`
она задана с запасом вверх — $0.03 за 1M токенов в обе стороны. Завышенная
цена запирает суточный лимит расхода раньше, а не позже: ошибка в безопасную
сторону. Для второй модели примера (`openai/gpt-oss-20b`) взяты официальные
$0.075 / $0.30 за 1M.

## Что изменилось в конфигурации

| Файл | Изменение |
|---|---|
| `providers.json` | запись `groq-prompt-guard`; у Haiku добавлена `text_generation` |
| `providers.local.example.json` | обе записи Groq на одном ключе, включая генеративную |
| `classes.json` | `requires: text_generation` у пяти классов; новый `guard_prompt` |
| `apps.json` | приложению `smoke` разрешён класс `guard_prompt` |

Продовая маршрутизация существующих классов не меняется: классификатор
отсеивается возможностью, генеративной модели Groq в проде нет.

## Тесты

41 зелёный (`node --test test/*.test.js`), было 38. Добавлены три: форма
запроса Groq (`max_completion_tokens`, `response_format`, `reasoning_effort`),
один ключ на две модели, и то, что классификатор не берётся за генеративные
классы и не вызывается вовсе.
