## Зачем

Указание владельца: приложение дёргает API моделью Haiku 4.5. Прикладного кода ещё нет,
поэтому смена ничего не ломает.

Перед правкой сверился с документацией, потому что смена модели тянет за собой форму запроса.
Проверка вскрыла три вещи:

- динамическая фильтрация результатов поиска доступна только моделям 4.6 и новее, поэтому на
  Haiku 4.5 результаты попадают в контекст целиком. Инструмент взят базовый
  `web_search_20250305` — это выбор ради простоты, а не запрет платформы: `web_search_20260318`
  работает и здесь при `allowed_callers: ["direct"]`, просто без фильтрации;
- `output_config.format` возвращает 400 при включённых цитатах, а `web_search` включает цитаты
  всегда. Строгий JSON одним вызовом достигается через strict tool use (`publish_digest` со
  `strict: true`), как и заложено в архитектуре, — это уточняет замысел спайка;
- у Haiku 4.5 ближайший в линейке срок вывода (не ранее 15 октября 2026) и knowledge cutoff
  февраль 2025. Оба факта вынесены в последствия ADR, потому что при постановке задачи их видно
  не было.
