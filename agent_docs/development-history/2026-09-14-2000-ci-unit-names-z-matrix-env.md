# [2026-09-14 20:00] CI: имена единиц через `-z`, выбор тестов как у выкатки, матрица через `env`

Файл: `agent_docs/development-history/2026-09-14-2000-ci-unit-names-z-matrix-env.md`

## Проблема

После #77 осталась находка reviewer и compliance: каталог единицы с `\n`,
`"` или `\` в имени выпадал из списка молча. Git берёт такой путь в кавычки
даже с `core.quotePath=false`
(`2026-09-14-1800-ci-deploy-hardening.md`, «Не чинили»). Каждая доводка
открывала следующую находку, так что вышла цепочка из трёх PR класса A.

## Что сделано

- **PR #84** (`e0dd028`), класс A, reviewer + compliance.
  `deploy-units.sh` и шаг CI «Имена единиц выкатки» читают пути через
  `git ls-tree -z` и `git diff -z`, разбор — `tr '\n\0' '?\n'`. Имя с `"`,
  `\`, табом или `\n` теперь падает на белом списке. Молча оно больше не
  пропускается. `pipefail` действует только внутри подстановки. Автор сам
  записал в «Не чинил» две находки: шаг «Какие дни затронуты» разбирал пути
  без `-z`, и тесты такой единицы на PR молча не бежали, а сбой
  `git ls-tree` в шаге CI давал «ok».
- **PR #87** (`bfa35df`), класс A, reviewer + compliance. Закрыл обе находки
  #84. Выбор тестов на PR разбирает пути как `deploy-units.sh`
  (`agent_docs/заметки.md` → `["atlas"]`, `days/day8/a"b.js` → `["day8"]`).
  Сбой `git diff` и `git ls-tree` в `detect` — теперь `::error::` и красный
  шаг, а не `[]` или «ok». Кроме того, по INFO compliance управляющие символы
  в `::error::` заменяются на `?`.
- **PR #89** (`e976902`), класс A по правилу «сомнение — в сторону старшего»
  (`secrets.*` в `ci.yml` нет). Закрыл находки M1–M3 к #87. Имя из пути —
  недоверенный ввод: в #87 путь `days/x$(touch PWNED)/y.js` исполнялся в job
  `test`. Теперь в матрицу идёт только `[a-z0-9]+` с каталогом единицы в
  дереве, а `matrix.day`, `dir` и `port` попадают в `run:` только через
  `env`. База на push — `git rev-parse -q --verify HEAD^`. В `::error::`
  заменяются только управляющие символы, так что `dé10` снова печатается как
  есть.

## Проверка

Автор #89 работал в изоляции worktree, и сквозные сценарии на синтетических
репозиториях ему недоступны. Стенд прогнали reviewer и compliance
независимо, на head `1341b25`, таблица — в комментарии к PR #89. На main
`PWNED` создавался, на ветке — нет. На 80 последних коммитах main выбор
совпадает с `deploy-units.sh` в 75 случаях. В остальных пяти у атласа нет
`Dockerfile`, и это заявленное отличие. Вердикты: reviewer APPROVE,
compliance PASS.

## Не чинили (INFO)

- В `::error::` не заменяются управляющие символы C1 и U+202E (переворот
  направления текста): `tr '[:cntrl:]'` под `LC_ALL=C` ловит только C0.
  Сторона безопасная: такое имя всё равно роняет шаг.
- `dir=` в `GITHUB_OUTPUT` защищён только фильтром `detect`. Отдельной
  проверки при записи нет.
- Для прогона стендов на macOS нужны локаль UTF-8 и bash ≥4: bash 3.2 не
  разбирает `case pat)` внутри `$(...)`. На runner стоит bash 5, CI это не
  затрагивает.
