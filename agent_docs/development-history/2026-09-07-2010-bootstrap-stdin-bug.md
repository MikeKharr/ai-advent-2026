# [2026-09-07 20:10] apt съел скрипт через stdin

Файл: `agent_docs/development-history/2026-09-07-2010-bootstrap-stdin-bug.md`

## Что случилось

`deploy/bootstrap.sh` запускался так, как было написано в его же заголовке:

```bash
ssh root@<IP> 'bash -s' < deploy/bootstrap.sh
```

Отработало только обновление пакетов. Дальше в выводе:

```text
Configuration file '/etc/cloud/cloud.cfg'
 ==> Modified (by you or by a script) since installation.
*** cloud.cfg (Y/I/N/O/D/Z) [default=N] ?
...
bash: line 24: $'\224\200───...': command not found
```

`dpkg` задал вопрос про conffile и прочитал ответ **со стандартного ввода** — а стандартным вводом был сам скрипт. Он выел середину, после чего bash попытался выполнить обрывок финальной рамки `cat <<EOF` как команду и остановился.

Ни пользователь `advent`, ни UFW, ни fail2ban, ни Docker, ни клон репозитория не выполнились.

## Почему `DEBIAN_FRONTEND=noninteractive` не спас

Эта переменная убирает интерактивные диалоги debconf, но **не управляет вопросами про изменённые conffile** — за них отвечают отдельные опции dpkg. Образ провайдера правил `/etc/cloud/cloud.cfg`, поэтому вопрос возник и без debconf.

## Исправление

1. **Запуск файлом, а не через stdin.** Способ вызова в заголовке скрипта и в инструкциях заменён на:

   ```bash
   scp deploy/bootstrap.sh root@<IP>:/tmp/
   ssh root@<IP> 'bash /tmp/bootstrap.sh'
   ```

   Так stdin свободен, и что бы внутри его ни читало, скрипт не пострадает.

2. **Пояс поверх подтяжек.** Всем командам, способным читать stdin (`apt-get`, `adduser`, `dpkg-reconfigure`), добавлено `</dev/null`.

3. **Conffile-вопросы решаются без человека:**

   ```bash
   APT_OPTS=(-o Dpkg::Options::=--force-confold -o Dpkg::Options::=--force-confdef)
   export DEBIAN_FRONTEND=noninteractive NEEDRESTART_MODE=a
   ```

   `--force-confold` оставляет текущий файл — правильный выбор для образа провайдера, где `cloud.cfg` подогнан под их инфраструктуру.

   `NEEDRESTART_MODE=a` убирает вопрос needrestart о перезапуске служб, который в интерактивном режиме тоже читает stdin.

## Урок

Скрипт, который скармливается интерпретатору через stdin, не должен запускать ничего, что само читает stdin. Это не редкий случай и не про apt: то же самое ломает `ssh` внутри цикла, `read`, любой интерактивный инсталлятор. Правильный вариант по умолчанию — копировать скрипт и запускать файлом.

Ошибка была прямо в заголовке `bootstrap.sh` — то есть я задокументировал неверный способ запуска и сам же ему следовал. Проверить это без реального сервера было нельзя: в песочнице агента исходящий SSH закрыт.
