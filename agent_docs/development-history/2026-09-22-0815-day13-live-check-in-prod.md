Владелец разрешил живую проверку дня 13 в проде с условием минимального
расхода. Проведена **одна** платная прогонка: предел кругов 1, модели по
умолчанию (рабочая `claude-haiku-4-5`, проверяющая `kimi-k2.6`), короткий
вопрос «Одна свежая новость про финтех-стартап», профиль `LiveCheck22`,
запуск `c1df0508-dbbc-44e9-b293-b3f504d78d84`.

## Главное: дефект владельца не воспроизводится

Это **первая живая проверка починки из PR #192 на настоящем вызове модели**.
До неё доказательствами были только тесты и поддельная служба моделей
(`2026-09-22-0625-day13-resume-after-reconnect`).

Сценарий владельца дословно и что увидено:

1. Пауза на этапе 3 «Вызов модели» — через 119 мс после отправки.
2. Вкладка закрыта целиком, паузу не снимали.
3. Новая вкладка, вход в тот же профиль и диалог.
4. **До единого клика:** переписка восстановлена с сервера, состояние
   `paused`, статус «На паузе 0 мин из 60», полоса на том же этапе 3, кнопка
   уже «Продолжить» — зелёная и активная, в мониторе восстановлены все 9
   событий прерванного запуска, предел кругов пережил смену вкладки.
5. «Продолжить» — отказа нет: через 102 мс состояние `running`, дальше этапы
   3→4→5→6 без заминок, `done` на 7,5 с.
6. Запуск продолжился с начала прерванного этапа: в журнале `answer` записан
   как `attempt 2`.

То есть ослепший экран прозрел, а «Запуск уже завершён» на осмысленное
действие не появилось.

## Что ещё сошлось в той же прогонке

- Шесть этапов по порядку; текущий помечен не только цветом — класс `is-now`,
  `aria-current="step"` и скрытая подпись «Этап N из 6»; завершённые —
  `is-past` и галочка.
- Сердцебиение: 8 ударов за 8 секунд активной работы, по одному в секунду, и
  **0 ударов во время паузы**.
- Обрыв вызова модели объяснён в мониторе числами: вход 399 токенов оплачен,
  выход не больше 1024, ответ выброшен; оба числа названы оценкой приложения,
  а не счётом поставщика.
- Мониторинг по каждому этапу с вызовом показывает идентификатор промпта,
  `sha8`, размер промпта, размер контекста и вход; этапы 1 и 6 помечены
  «без вызова модели».
- Журнал выгружается настоящим CSV: `content-type: text/csv; charset=utf-8`,
  `content-disposition: attachment`, 23 колонки, 7 проходов; одна и та же
  попытка записана дважды — `interrupted` и `done`; `pauses` переключается с 0
  на 1 после паузы; `verdict=accepted` только у `verify`; текстов промптов в
  файле нет, только идентификатор, `sha8` и размер.
- Ответ дошёл. Агент отказался выдумывать свежую новость, назвал границу своих
  знаний и предложил, где искать; проверяющая модель дала `accepted`. Ссылок
  на источники нет и быть не должно: у `staged-agent` нет инструмента поиска,
  README дня выводит его из-под инвариантов о карточках новостей.

## Чего проверка не дала

- **Новое правило списания из PR #190 не сверено.** В прогоне не было ни
  одного отказа провайдера — ни 5xx, ни 529, ни неразобранного тела, — поэтому
  сверять оказалось нечего. Разделение исходов `server_error` /
  `bad_response` / `error` по-прежнему подтверждено только тестами роутера.
- **Книга расхода роутера не прочитана:** команда отклонена локальной
  политикой разрешений, расширять разрешения по просьбе агента владелец
  отказался. Единственное, что стоило бы там посмотреть, — как записан
  сознательный обрыв паузой.
