# [2026-09-22 18:30] Второй каталог в закрытом списке серверных команд: `zpq-ai/deploy`

## Решение владельца

Владелец решил расширить закрытый список серверных команд агента на каталог
`~/zpq-ai/deploy` — «на чтение и caddy»: `docker compose ps`,
`docker compose logs`, `docker compose restart caddy`, ровно тот же объём, что
уже есть у адвента. Решение принято 2026-09-23 по часам владельца; имя файла —
по UTC. Основание и разбор — ADR `2026-09-22-1824`.

Повод: после переезда входа, сайта и почты в `MikeKharr/zpq-ai` (ADR
`2026-09-22-0611`) у агента не осталось **ни одной** разрешённой команды против
проекта compose `zpq`. Список с самого начала записан вместе с каталогом
(`cd ai-advent-2026/deploy`), а служб `caddy` и `mail` там больше нет. При этом
адвент публично живёт через вход `zpq`: его поломка краснит живую проверку
выкатки адвента, а посмотреть на неё агент не имел права.

`docker compose restart mail` для `zpq-ai` владелец не решал — не добавлено.

## Что сделано

Ветка `chore/zpq-deploy-in-closed-list`, класс A, защищённые пути:
`.claude/settings.json`, `.agents/skills/day-cycle/SKILL.md`.

- `.claude/settings.json` — две буквальные строки ssh без хвостов:
  `cd zpq-ai/deploy && docker compose ps` и
  `… && docker compose restart caddy`. `logs` в allowlist не попадает, потому
  что содержит переменные части — как и у адвента (ADR `2026-09-11-1230`).
- `.agents/skills/day-cycle/SKILL.md`, фаза 9 — канонические формы и отдельный
  абзац про объём для `cd zpq-ai/deploy`, с явным «`restart mail` там не
  разрешён».
- `agent_docs/operations.md`, раздел «Почтовый сервер и сайт компании» — там
  стояло «список не расширяется и не сокращается»; после этого решения
  утверждение неверно.

**Удалена мёртвая строка** `docker compose restart mail` в
`cd ai-advent-2026/deploy` (ADR `2026-09-18-1839`) — из `.claude/settings.json`
и из описания в скилле. Службы `mail` в этом проекте compose нет с переезда;
команда вернула бы «no such service». Обоснование удаления — в ADR: мёртвой её
сделал переезд, список пересматривал сам владелец, а держать её рядом с
запретом `restart mail` для каталога, где служба реально есть, — прямое
приглашение к ошибочному выводу. ADR `2026-09-18-1839` остаётся в журнале.

## Проверка

Команда `ssh … advent@challenge.zpq.ai 'cd zpq-ai/deploy && docker compose ps'`
исполнена и вернула два контейнера, `zpq-caddy-1` (80/443) и `zpq-mail-1`
(healthy). Этим проверено, что новая строка целится в реальный путь: каталог
`~/zpq-ai/deploy` существует и доступен тому же пользователю `advent` тем же
ключом, проект compose называется `zpq`, служба `caddy` в нём есть.

**Совпадение строки с allowlist исполнением не проверяемо.** В личных
настройках владельца первой записью `permissions.allow` стоит голый `"Bash"`,
поэтому без окна проходит любая команда — в том числе та, которой в проектном
allowlist нет вовсе; тот же прогон прошёл бы и до правки. «Прошло без окна» —
не доказательство разрешения. Это ровно то, что ADR `2026-09-11-1230` записал
в «Последствия» словами «механизма нет»: проектный список держится чтением, а
не механикой. Совпадение строк сверено глазами, посимвольно, с формами
адвента.

`docker compose restart caddy` против `zpq-ai` не запускался: он меняет
состояние прода, нужды в нём не было.

## Уроки

- **Разрешение, привязанное к пути, переживает переезд буквально.** Оно не
  ломается заметно — оно молча перестаёт покрывать то, ради чего выдавалось.
  Переезд каталога стоит считать поводом перечитать список разрешений, а не
  только compose-файлы.
- **Мёртвая строка в allowlist — не безобидный мусор.** Пока она там, соседний
  запрет читается как противоречие, и следующий агент выведет из пары строк
  правило, которого никто не принимал.
- Три места описывают один список: `.claude/settings.json` (исполняемое),
  `/day-cycle` фаза 9 (норма) и `agent_docs/operations.md` (контекст). Правка
  одного без двух других разводит разрешение и описание.
