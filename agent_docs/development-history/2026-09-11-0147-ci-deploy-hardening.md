# [2026-09-11 01:47] CI: доводка выкатки после ревью #73

Файл: `agent_docs/development-history/2026-09-11-0147-ci-deploy-hardening.md`

## Проблема

Ревью #73 оставило три находки
(`2026-09-11-0123-ci-deploy-unit-allowlist.md`, «Не чинили»). Имя новой
единицы проверялось только при выкатке, уже после мержа (compliance). Имена
не из ASCII git брал в кавычки, и такая единица выпадала из списка молча
(reviewer). Шаги SSH в `deploy.yml` подставляли `${{ secrets.* }}` прямо в
текст shell (compliance).

## Что сделано

- **PR #77** (`7e6e6a2`), класс A: workflow CI с `secrets.*` и команда на
  прод-сервере. Гейты: `reviewer` APPROVE и `compliance` БЕЗ ВОЗРАЖЕНИЙ на
  head `34b3a34`. Мержил агент по консенсусу.
- `ci.yml`, job `detect`, новый шаг «Имена единиц выкатки»: если каталог с
  `Dockerfile` (`days/*`, `router`, `agents`, `atlas`) назван вне
  `[a-z0-9]+`, шаг пишет `::error::` с именем каталога и роняет PR. Правило
  то же, что в `.github/scripts/deploy-units.sh`.
- `deploy-units.sh`: `ls-tree` и `diff` идут через
  `git -c core.quotePath=false`. Имя не из ASCII теперь громко падает на
  белом списке.
- `deploy.yml`, шаги «Ключ доступа» и «Выкатка»: `SSH_KEY`, `SSH_HOST`,
  `SSH_PORT` (с тем же `|| 22`) и `SSH_USER` приходят через `env:` шага, а в
  `run:` остаются только `$SSH_*`. Поведение не изменилось. Права jobs и
  токены не менялись.
- `operations.md`, «Атлас проекта»: если push-выкатки встали на имени
  единицы, срочная единица выкатывается через
  `gh workflow run deploy.yml -f day=<единица>`, а чинится переименованием
  каталога.
- Автор прогнал сценарии `deploy-units.sh` и шага CI на синтетических
  деревьях (`dé10`, `Day10`, `day-10`) до и после правки. Таблицы — в
  описании PR.

## Выкатка

Живая выкатка мержа (запуск `34551187022`) прошла: шаги «Ключ доступа»,
«Выкатка» и «Проверка живого сайта» — success. Шаги SSH впервые отработали с
секретами из `env`.

## Не чинили

- Каталог с `\n`, `"` или `\` в имени по-прежнему пропускается молча: git
  берёт такой путь в кавычки даже с `core.quotePath=false`. Сторона
  безопасная, до SSH имя не доходит. Громкую ошибку даст `ls-tree -z` в
  `deploy-units.sh` и в шаге CI. Находка reviewer и compliance к #77,
  заведена в `backlog.md`, Soon (класс A).
- Замечание compliance: выкатка через `day=` — это выход в прод мимо
  обычного пути через мерж. В `operations.md` дописано «с согласия
  владельца» (docs-PR после #77).
