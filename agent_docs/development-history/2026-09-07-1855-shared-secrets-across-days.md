# [2026-09-07 18:55] Один файл секретов на все дни + гайд по новому дню

Файл: `agent_docs/development-history/2026-09-07-1855-shared-secrets-across-days.md`

## Что сделано

- `deploy/secrets.env` — общий файл секретов для всех дней. Сервис дня подключает его
  через `env_file` в `compose.yml` наравне с необязательным `dayN.env`, который теперь
  нужен только для настроек, специфичных для конкретного дня.
- `deploy/put-secrets.sh` — скрипт заведения и ротации ключа: спрашивает ключ скрытым
  вводом, кладёт файл на сервер, ставит `chmod 600`, проверяет результат не показывая
  значение. Локально ключ не сохраняется и в историю shell не попадает.
- `agent_docs/guides/new-day.md` — порядок добавления дня N: каталог, две строки в
  `Caddyfile`, сервис в `compose.yml`, ссылка на лендинге, деплой и откат. Первым пунктом
  зафиксировано, что с секретами для нового дня делать ничего не нужно.
- Ссылки на гайд из `architecture.md` и `index.md`; текст подсказки `bootstrap.sh` и
  `deploy/.env.example` приведены к общему файлу.

## Зачем

Изначально секреты были расписаны по файлу на день (`day1.env`), то есть при каждом новом
задании владельцу пришлось бы повторять процедуру с ключом вручную. Ключ на все дни один,
поэтому файл сделан общим: заведение и ротация — один запуск скрипта, новый день не требует
никаких действий с секретами.

Проверено: `docker compose config` на сервере принимает новый `compose.yml`.
