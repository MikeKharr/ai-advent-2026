# [2026-09-08 19:00] Роутер LLM-провайдеров: реализация по ADR 1748

Файл: `agent_docs/development-history/2026-09-08-1900-llm-router-implemented.md`

## Что сделано

Этап 2 задания — реализация принятого ADR `2026-09-08-1748-llm-router.md`
(владелец: «принято»). Новый каталог `router/` — отдельный сервис, Node 22 без
зависимостей; ADR `2026-09-08-1020` переведён в «Отклонено».

- **Ядро** `src/router.js`: три механизма по ADR — возможность (статичный фильтр,
  несоответствие = отказ), политика (порядок ярусов из реестра классов), здоровье
  (пропуск). Не больше двух вызовов на запрос. Уровень размышлений — только из
  `classes.json`; для закреплённых классов (`extract_json`) override — отказ.
  Неизвестный класс уходит в `other`.
- **Здоровье** `src/health.js`: отрицательный кэш 60 с только для транспортных
  ошибок (`error.cause.code`), предохранитель 3 неудачи → 60 с с одной пробой,
  429 → «занят до» (Retry-After или 10 с), inflight по хосту с синхронным захватом.
- **Адаптеры**: `anthropic` (Messages API; размышления — `budget_tokens` из
  конфигурации провайдера, `max_tokens` его превышает; схема — `output_config`),
  `ollama` — родной `/api/generate` с `think`, `format`, `num_predict`, метриками
  из `eval_count`/`eval_duration`/`load_duration`.
- **Сервисный слой** `src/service.js` + `src/ledger.js`: ключи приложений по
  Bearer, лимиты на приложение (`dailyTokens`/`dailyCostUsd`, без лимита — крах
  на старте), журнал JSONL без промптов на томе, суточные суммы восстанавливаются
  при старте; учитывается каждый вызов провайдера, включая неудачный фолбэк.
  Эндпоинты `/v1/route`, `/v1/spend`, `/v1/metrics`, `/healthz`.
- **Деплой**: сервис `router` в `compose.yml` с томом `router_data` и
  `deploy/router.env`; CI и deploy-workflow обобщены до «единиц» (`days/dayN`
  или `router`), для роутера здоровье проверяется по healthcheck контейнера, а
  не по публичному адресу — адреса у него нет.
- **Документы**: `agent_docs/operations.md` (новый: запуск, добавление
  приложения, подключение self-hosted провайдера), `architecture.md`, `snapshot.md`,
  `backlog.md`, `router/README.md`.

## Отклонения от буквы ADR

- Разделитель ключа кэша — `|`, а не `:`: имена моделей Ollama содержат
  двоеточие (`qwen3.8:27b`), и тест 15 это поймал.
- Ярус `cloud-cheap` в продовой конфигурации пуст: модель одна на все дни
  (`claude-haiku-4-5`), она объявлена как `cloud-frontier`. Классы указывают
  все три яруса, поэтому появление дешёвого облака — правка конфигурации.
- `node:sqlite` не используется: локальный Node 22.12 требует флага, JSONL
  достаточно для журнала с суточными суммами.
- Продовая конфигурация — только облако: ноутбук с сервера не виден до tailnet;
  ноутбучный провайдер — в `providers.local.example.json`.

## Что не сделано и почему

- Дни 1–4 к роутеру не переведены — по правилу владельца о неподдержке
  сданных дней. Первый потребитель — день 5.
- `docker compose config` локально не проверен: docker на машине нет;
  compose и workflows проверит CI на PR.
- `deploy/router.env` на сервере кладёт владелец — секреты в репозиторий не
  попадают. Без файла роутер падает на старте, дни поднимаются как прежде.
