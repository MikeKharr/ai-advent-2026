# [2026-09-11 01:23] CI: белый список имён единиц выкатки

Файл: `agent_docs/development-history/2026-09-11-0123-ci-deploy-unit-allowlist.md`

## Проблема

Имя единицы из `workflow_dispatch day=` уходило в команду на прод-сервере без
проверки: `day="x'; id; echo '"` давал `["x'; id; echo '"]` с rc=0. Список
единиц `${{ needs.detect.outputs.days }}` подставлялся прямо в текст shell.
Находка compliance N3 к #71 (`2026-09-11-0043-ci-detect-last-deploy.md`).

## Что сделано

- **PR #73** (`8135920`), класс A: `deploy.yml` ссылается на `secrets.*` и
  выполняет команду на прод-сервере. Гейты: `reviewer` APPROVE и
  `compliance` БЕЗ ВОЗРАЖЕНИЙ на head `ec082c2`. Мержил агент по консенсусу.
- `.github/scripts/deploy-units.sh`: единица — только имя `^[a-z0-9]+$` с
  `Dockerfile` в дереве `head`. Для `day=` проверяются оба условия, по всей
  строке, так что перевод строки не проходит. В ветке по push по имени
  проверяются все единицы дерева. Нарушение — `::error::` и rc=1, сырое
  значение `day` в лог не выводится.
- `deploy.yml`: список единиц идёт в шаг «Проверка живого сайта» через `env`.
  Перед SSH шаг «Выкатка» ещё раз проверяет весь список строгой регуляркой,
  в удалённую команду попадают только проверенные имена. Права job и токены не
  менялись.
- Сбой `git ls-tree` больше не теряется в конвейере: сначала присваивание,
  потом фильтр.
- `operations.md`, «Очередь выкаток» / «Повтор и откат»: агент перезапускает
  только последний запуск; «пересборка не нужна» — только для sha, на котором
  единица собиралась.
- Автор прогнал десять сценариев `deploy-units.sh` до и после; таблица — в
  описании PR.
