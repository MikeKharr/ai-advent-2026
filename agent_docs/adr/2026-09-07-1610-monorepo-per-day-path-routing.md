# [2026-09-07 16:10] Монорепозиторий по дням и маршрутизация по префиксу пути

## Статус

Принято

## Контекст

Челлендж выдаёт по заданию в день. Владелец задал адреса в продакшене: `challenge.zpq.ai/day1`, `challenge.zpq.ai/day2` и далее — один домен, разделение по префиксу пути.

Содержание будущих заданий неизвестно. День 3 может потребовать Python, день 5 — постоянное соединение, день 7 — вообще статику. Решение о топологии принимается до того, как эти требования станут известны, поэтому цена ошибки — переделка всех уже выложенных дней.

## Решение

Один репозиторий. Каждое задание — каталог `days/dayN/` с собственным `Dockerfile` и собственным контейнером. Имя каталога совпадает с сегментом URL.

Caddy на одном VPS принимает `challenge.zpq.ai` и маршрутизирует:

```text
redir /dayN → /dayN/          голый префикс без слэша
handle_path /dayN/*  → dayN:8080     префикс срезается
handle /             → статический лендинг
```

Образы собираются в GitHub Actions и публикуются в GHCR; VPS только тянет и перезапускает. Тег образа каждого дня пинуется в `deploy/.env` переменной `DAYN_TAG`.

Ветка на день → PR → мерж в `main` → деплой только изменённых дней.

## Обоснование

**Один репозиторий, а не репозиторий на день.** `AGENTS.md`, журнал решений, роли и CI существуют в одном экземпляре. При репозитории на день они копируются десять с лишним раз и немедленно расходятся.

**Контейнер на день, а не одно приложение с маршрутами.** Это прямое следствие неизвестности будущих заданий: изоляция позволяет дню 3 быть на Python, не трогая день 1. Сломанный день не роняет остальные. Расплата — оперативная память: каждый простаивающий Node-контейнер занимает 30–50 МБ, и на инстансе в 1 ГБ это станет ограничением примерно к десятому дню.

**`handle_path` со срезанием префикса, а не приложение, знающее свой префикс.** Приложение видит `/` и остаётся запускаемым локально без всякой обвязки. Расплата — обязательный `<base href="/dayN/">` в HTML и только относительные ссылки. Это самая частая ошибка при маршрутизации по префиксу, поэтому вынесена в README каждого дня.

**Сборка в Actions, а не на VPS.** Инстанс с 1 ГБ памяти, собирающий образ и одновременно обслуживающий трафик, — предсказуемый источник падений. Деплой сводится к `pull` и перезапуску, а откат — к подстановке предыдущего sha.

## Последствия

Положительные:

- новый день добавляется двумя строками в `Caddyfile` и одним сервисом в `compose.yml`;
- дни изолированы по стеку, отказу и деплою;
- деплой затрагивает только изменённые дни;
- откат — смена тега в `deploy/.env`, без пересборки.

Отрицательные:

- потребление памяти растёт линейно по числу дней; на 1 ГБ это упрётся примерно к десятому дню, дальше — тариф выше либо остановка старых дней;
- `Caddyfile` и `compose.yml` правятся вручную при каждом новом дне — шаг, который забудут;
- срезание префикса требует дисциплины с относительными путями, ошибка проявляется только в продакшене;
- один домен и один сервер — общая точка отказа для всех дней сразу.

## Альтернативы рассмотрены

- **Репозиторий на день.** Полная изоляция, но десятикратное дублирование правил и документации.
- **Одно приложение с внутренними маршрутами.** Экономнее по памяти и один деплой, но все дни заперты в одном стеке, а падение одного роняет всё.
- **Поддомен на день** (`day1.challenge.zpq.ai`). Снимает проблему префикса целиком и позволяет абсолютные пути, но владелец задал адреса с префиксом пути.
- **Сборка образов на VPS.** Меньше настройки, но сборка на инстансе в 1 ГБ конкурирует с обслуживанием трафика.
