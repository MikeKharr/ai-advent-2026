### 1. Авторизация — отдельный ключ API (заменяет п. 2.2)

Вход действия — `anthropic_api_key`, секрет — **`ANTHROPIC_API_KEY_AI_REVIEW`**.
`claude_code_oauth_token` не используется.

Почему не токен подписки: его нельзя отозвать точечно — отзыв это выход из
аккаунта на всех устройствах («A revoked token means you signed out
everywhere», `code.claude.com/docs/en/errors`). Для секрета, который читает
workflow, исполняемый из PR, это неприемлемая цена инцидента: отзыв утёкшего
токена выбил бы владельца из его собственного Claude Code.

Почему ключ отдельный от продового: отзыв ключа ревью не трогает прод, а
расход ревью виден в Console отдельной строкой.

Имя секрета — провайдер-первым, как `SSH_*` в этом репозитории: префикс
называет подсистему (`ANTHROPIC_API_KEY`), суффикс — потребителя
(`AI_REVIEW`). Следствия, за которые имя и выбрано: `grep ANTHROPIC_API_KEY`
находит оба ключа, когда проверяешь, где они живут; в `gh secret list` они
стоят рядом; в диффе ключ ревью не спутать с продовым. Имя
`ANTHROPIC_API_KEY` не берётся намеренно.

### 2. Модель и усилие (заменяет п. 2.6)

`--model claude-haiku-5-5`, `--effort medium`, `--max-turns 8`.

Цена: $0.10 за Mtok входа **до 100K токенов в запросе** и $0.50 выше; выход
$0.50 / $2.50. Ступенька на 100K — причина, по которой появился потолок
объёма диффа (п. 3 ниже).

`--effort medium` задан явно, хотя это и есть умолчание `claude-haiku-5-5`:
умолчание — свойство модели, а не нашего файла, и между моделями оно уже
менялось. Ниже (`low`) не берётся сознательно: предмет ревью — расхождения с
инвариантами и действующими ADR, то есть суждение, а `low` документирован для
подагентов и простых задач. Выше не берётся, потому что усилие — первый рычаг
расхода.

**Это отступление от п. 2.6 `2026-10-18-1147`**, который говорил «`--model` не
передаётся: идентификаторы моделей в проекте живут только во фронтматтере
ролей». Пока платила подписка, умолчание действия было бесплатным выбором; с
ключом API каждый запуск — счёт, и цена обязана быть видна в файле, а
умолчание поставщика может смениться вместе с версией действия и подорожать
молча.

**Честная граница отступления.** Правило про идентификаторы моделей держит шаг
«Одна копия» в `docs-guard.yml`, а он читает только `*.md` и только маркеры из
файла `single-source.tsv` в `agent_docs/guides/`. Идентификатор в `*.yml` не
краснеет ни у кого — проверено прогоном. То есть отступление удерживается
только этой записью. Распространять правило на исполняемую конфигурацию —
отдельное решение владельца, здесь оно не принимается.

### 3. Запуск — только по метке (заменяет триггер из п. 2.3)

`on: pull_request: types: [labeled]` плюс условие job
`github.event.label.name == 'ai-review'`. Ни `opened`, ни `ready_for_review`,
ни `synchronize`.

Почему так: ревью стоит денег, и платить решает человек, а не факт открытия
PR. Условие на `github.event.label.name` отличает «повесили именно
`ai-review`» от «повесили какую-нибудь метку», чего `pull_request.labels.*` не
отличает. Поле есть по схеме полезной нагрузки:
`PullRequestLabeledEvent.label: Label`, `Label.name: string`. Рендер страницы
вебхуков в документации GitHub строки `label` в таблице не показывает — это
проверено по схеме, и так и записано, чтобы следующий не считал это
подтверждённым прозой.

**Фильтр `paths` снят.** С запуском по метке он стал бы вторым условием,
которое тихо отменяет уже высказанную просьбу человека: метку повесили, а
ревью не пришло, потому что дифф не задел перечисленные каталоги. Объём входа
держит потолок ниже, и он говорит, почему отказал.

Цена, которую это решение **не** снимает: `pull_request` исполняет файл
workflow из PR, и за секретом теперь стоят деньги проекта. Метка добавляет
человека в цепочку, но не мешает автору PR изменить сам workflow. Смягчение
прежнее: отдельный ключ и точечный отзыв.

### 4. Потолок объёма входа (новое, находка `compliance` Б4)

Шаг перед ревью считает объём диффа и краснеет выше потолка: **2500 строк или
150 КБ**. База — точка расхождения (`git merge-base`), а не голова базовой
ветки: с двумя точками отставшая ветка показывала бы чужие изменения из `main`
как свои (ровно на этом 18.10 покраснел `docs-guard` у PR дня 32).

Откуда числа: 150 КБ кода — порядка 40K токенов; с документацией из поиска и
накоплением по восьми ходам это оставляет запас до ступеньки 100K за запрос.
Выше — не «дороже», а непредсказуемо дороже, и такой PR надо делить.

Краснеет, а не пропускает молча: метку поставил человек, и он должен узнать,
почему ревью не пришло.

### 5. Проверка `RAG_KEY` — белым списком (находка `reviewer` Б3)

Годен только алфавит `A-Za-z0-9+/=_-` (base64 и base64url; base64 советует
`deploy/put-rag-key.sh`). Прежняя проверка была чёрным списком и перечисляла
`"` и `\`, но пропускала одинарную кавычку, табуляцию и возврат каретки —
проверено прогоном на тех значениях. Кто перечислит все опасные символы
заранее, неизвестно, поэтому список белый.

## Обоснование

Все четыре решения владельца смещают одно и то же: **кто платит и может ли он
это заметить**. Ключ API делает расход измеримым и отзываемым точечно; метка
делает запуск намеренным; haiku с явным усилием делает цену ходa
предсказуемой; потолок диффа убирает единственный вход, на котором цена
становится непредсказуемой. Отдельный ADR — чтобы принятая утром запись
осталась тем, что приняли утром.

## Последствия

Положительные:

- расход ревью виден отдельной строкой в Console и не трогает окно подписки
  владельца;
- утёкший ключ ревью отзывается, не выбивая владельца из Claude Code и не
  задевая прод;
- ни один PR не тратит деньги, пока человек не повесил метку;
- объём входа ограничен шагом, который объясняет отказ.

Отрицательные, названные прямо:

- **ревью больше не приходит само.** Про метку надо помнить; забытая метка —
  это молча не состоявшееся ревью, и никакой страж этого не поймает;
- **качество ревью на haiku не измерено.** Дешевле — не значит достаточно;
  первые несколько ревью надо читать глазами и, если находки пустые, вопрос
  модели открывается заново;
- **оценка расхода остаётся оценкой.** Порядок — единицы центов за ревью
  обычного PR (вход накапливается по ходам: каждый следующий запрос несёт всю
  переписку, поэтому восемь ходов стоят заметно больше, чем один, умноженный
  на восемь). Опорное значение проекта ($0.011 за некэшированный дайджест,
  ADR `2026-09-07-2016`) к ревью не применимо — другая работа и другой объём
  входа. Первое настоящее число даёт первый живой запуск; расхождение с
  оценкой вдвое — повод остановиться, а не поднять потолок;
- **метка — это право тратить деньги проекта.** Кто может ставить метки в
  репозитории, тот может запускать расход. Отдельного разграничения здесь не
  вводится.

## Ручные шаги и проверки

Руками владельца, до мержа PR дня 32:

1. `gh secret set ANTHROPIC_API_KEY_AI_REVIEW` — отдельный ключ из Console,
   не продовый. Значение вводится скрытно (память проекта о секретах в
   истории shell).
2. `gh secret set RAG_KEY` — то же значение, что в `deploy/rag.env`.
3. Создать метку `ai-review` в репозитории и повесить её на PR дня 32 — это и
   есть живая проверка.

Что защищало расход до этой записи и куда делось: потолки `--max-turns`,
`timeout-minutes` и `concurrency` из п. 2.6 остаются и усиливаются
(`--max-turns` с 15 до 8); фильтр `paths` как ограничитель объёма **снят
сознательно** и заменён потолком диффа, который сильнее и объясняет отказ.

## Альтернативы рассмотрены

- **Токен подписки `claude setup-token`** — принят утром, отклонён владельцем
  вечером: отзыв = выход из аккаунта на всех устройствах.
- **Один ключ API на прод и ревью** — отзыв ревью ронял бы прод, расход не
  разделить.
- **`claude-sonnet-5-5`** ($2/$10 за Mtok) — предлагался за качество суждения;
  владелец выбрал haiku. Пересмотр — по пустым находкам первых ревью, а не по
  предположению.
- **`--effort low`** — дешевле, но документирован для подагентов и простых
  задач; ревью инвариантов к ним не относится.
- **Запуск на `opened` / `ready_for_review`** — платит факт открытия PR, а не
  человек.
- **`synchronize`** — ревью на каждый коммит, то есть счёт на каждый пуш.
- **`pull_request.labels.*` вместо `github.event.label.name`** — не отличает
  «повесили `ai-review`» от «повесили любую метку на PR, где она уже есть».
- **Фильтр `paths` вместе с меткой** — тихо отменяет просьбу человека.
- **Денилист инструментов вместо `--tools`** — перечисляет известное опасное;
  белый список отсекает и то, что появится в следующей версии CLI.
- **Чёрный список символов в `RAG_KEY`** — был в прежней редакции и пропускал
  одинарную кавычку, табуляцию и возврат каретки.
