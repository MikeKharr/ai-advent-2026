# [2026-09-28 18:20] Поверхность управления инструментами агентов: отдельный API с перечнем операций и отказом по умолчанию, сервер MCP над ним, клиент — код новых дней; единственная преграда — ключ, сеть не закрывается

Файл: `agent_docs/adr/2026-09-28-1820-day15-api-mcp-server-analysis.md`

## Статус

**Принято** владельцем 2026-09-29. Третья редакция того же дня. Решения владельца, под которые
она переписана: (1) **отдельный API для MCP нужен** — «для управления
инструментами агентов — там должен быть принципиально другой подход к
безопасности»; (2) **клиент — приложения новых дней**, код дня, не модель;
(3) **только ключ, сеть не закрывать** — выбрано при показанной развилке с
прямой оговоркой, что требование «с того же сервера» при этом перестаёт
выполняться и что `compliance` скорее всего возразит. Полный OAuth 2.1 по
спецификации MCP владелец отклонил как отдельный большой кусок; (4) **бюджет
— только ограничения роутера**: «я управляю бюджетом всего учебного проекта
через лимиты моделей в консолях поставщиков» — отдельного приложения роутера
и нового `APP_KEY_*` не будет, платные операции платят ключом приложения
`agents`, как день 20. Замысел дословно — в описании PR #249.

**Исходное требование «доступ с того же сервера, снаружи не нужен» снято
самим владельцем:** он заменил сетевое ограничение ключом, зная, что область
доступа расширяется. Это решение, а не пропуск — раздел «Что снято решением
владельца» ниже.

Не оспорено и остаётся: отдельная поверхность, перечень операций, клиент —
код дня, запрет попадания в общий реестр хоста, правка проверяющего промпта
через модель не проектируется.

### Решения владельца при приёмке (2026-09-29)

- **Правка промпта проверяющего шага (`stage.verify.invariants`) — вне перечня
  операций.** Рекомендация архитектора принята: этот промпт задаёт единственную
  проверку ответа, и правка через API её выключала бы. На экране дня 15 правка
  остаётся.
- **Журнал обращений — с текстами, срок хранения 30 суток.** Владелец изменил
  предложенный состав: предлагалось «без текстов», принято «с текстами».
  Следствие, названное прямо: в журнале поверхности оседают тексты сообщений
  посетителей, то есть у него появляется та же чувствительность, что у
  хранилища диалогов, и те же обязанности — не показывать его наружу, не
  выносить в ответы, чистить по сроку. Срок хранения — решение владельца по
  правилу проекта.

## Решение

1. **Поверхность управления — второй слушатель процесса `agents`**
   (`agents/src/control/`, порт 8086, свой ключ `CONTROL_KEY`), не путь
   внутри `/v1` и не обёртка. Данные — SQLite на томе `agents_data`, файл
   базы между контейнерами не делится; у `/v1` разрешение по умолчанию
   «всё под `AGENT_KEY`», и одна поверхность не может иметь два режима
   отказа. Порт виден из всех сетей `agents` — **это и есть вся граница:
   ключ, ничего больше.**
2. **Свойства безопасности — семь, каждое с держателем (I-14). Раз ключ —
   единственная преграда, четыре из них усилены против второй редакции
   (помечены ▲):**
   - *отказ по умолчанию:* диспетчер — таблица операций; путь, метод или имя
     вне таблицы — один 404 без проброса в `/v1`; тест «операция вне перечня
     — 404, обработчик `/v1` не вызван»;
   - *операции перечислением:* закрытый список `agents/src/control/ops.js` —
     имя, вид (чтение/запись), признак «платная», схема аргументов, что под
     ней; новая операция — строка в ADR и PR класса A;
   - *своя проверка каждого аргумента на границе:* сервер MCP — не доверенная
     сторона; `profileId`, `sessionId`, `promptId`, `num`, тексты и билет —
     теми же разборщиками домена (`parsePrompt`, `parseSettings`,
     `checkTicket`) и проверкой принадлежности диалога до хранилища;
     негативный тест на каждую операцию;
   - ▲ *ключ по спецификации и только так:* `Authorization: Bearer <ключ>`;
     ключ в строке адреса или в своём заголовке — 401, значение в журнал не
     попадает (тест: `?key=` и `X-Control-Key` → 401, тело журнала без
     значения); 401 несёт `WWW-Authenticate: Bearer realm="control"` — форма
     обнаружения по спецификации, без OAuth-метаданных; сравнение —
     `timingSafeEqual` по образцу `agents/src/service.js:61`, **с
     держателем**: тест «модуль ключа импортирует `timingSafeEqual` и путь
     сравнения через него» — держит присутствие строки, а не время (честно:
     время тестом не измерить); ключ короче 32 знаков при старте — поверхность
     выключена;
   - ▲ *ключи не пересекаются, совпадение обнуляет:* по прецеденту
     `agents/src/env.js:77-84` — `CONTROL_KEY`, равный `AGENT_KEY` или
     `ROUTER_APP_KEY`, считается **незаданным**: слушатель отвечает 503
     `control_disabled` на всё (не 401 — «выключен» отличим от «чужой ключ»),
     запись `control_key_same_as_*` в журнал, `/healthz` говорит «выключен:
     ключ совпадает». Сервис при этом поднимается: отказывает то, что
     настроено неверно. То же в `mcpagents` для пары `MCPAGENTS_KEY` /
     `CONTROL_KEY`. Тесты на оба;
   - ▲ *свой учёт — кто и какие операции звал, и отказов тоже:* `control_log
     (at, op, outcome, ms, paid, profile_id, remote)` в SQLite `agents`, без
     текстов (I-10; `remote` — адрес соединения, у операций посетителя его
     нет — клиент один); исход `unauthorized` пишется **той же строкой**, что
     успех, с `remote` и без предъявленного значения; строка журнала процесса
     на каждый вызов; срок 30 дней уборкой. **Журнал — не про деньги:**
     расход операций управления виден в сводке роутера по приложению `agents`
     (`admin.js spend`, ADR `2026-09-16-0907`) суммой с днями 6–20; журнал
     держит другое — что через поверхность делали с профилями и кто стучался
     без ключа. Держит тест «отказ и успех дают по строке, значения ключа в
     строке нет»;
   - ▲ *лимитер на неудачные попытки:* окно на адрес соединения — после N
     `unauthorized` за минуту адрес получает 429 до конца окна, до сравнения
     ключа; отдельно от лимитера платных операций (окно на весь ключ и
     `CONTROL_MAX_DAILY_CALLS` до `createRun` и до формулировщика, I-4).
     **Бюджет — вне поверхности и вне репозитория:** потолок приложения
     `agents` у роутера ($10 в сутки, `router/config/apps.json`) плюс лимиты
     моделей в консолях поставщиков; это правило проекта — лимиты на
     приложение, общий потолок на ключ не заводится (решение владельца
     2026-09-08, `architecture.md`), и отдельный потолок поверхности не
     пробел, а следствие правила.
     Честно о цене этого свойства: ключ — 32 случайных байта, перебор
     невозможен при любом лимитере; окно снижает шум и делает залп видимым в
     журнале, защитой оно не является;
   - *свой ответ:* свой JSON из названных полей, не тела `/v1` (образец —
     ADR `2026-09-23-1227`, п. 5); ключей и адресов в ответах нет (тест I-1 по
     образцу дня 16).
3. **Ротация — процедура, не код.** Ключ порождается на сервере агентом по
   образцу `MCP_KEY` (строки закрытого списка `/day-cycle` — часть этого
   ADR): `CONTROL_KEY` → `agents.env` и копия в `mcpagents.env`;
   `MCPAGENTS_KEY` → `mcpagents.env` и копия в `dayN.env` каждого
   дня-клиента. Ротация — повторное порождение с `set -C` снятым **только для
   этой строки списка**, затем `docker compose up -d agents mcpagents dayN`;
   пауза поверхности — секунды, дни 6–15 не задеты. Двух ключей «старый и
   новый» одновременно не держим — гибкость, которую не просили. Повод —
   любое подозрение (I-3) **и** каждая утечка любого `dayN.env`, потому что
   копий станет столько же, сколько дней-клиентов.
4. **Сервер MCP — новая единица `mcpagents` без SDK** (имя условное, в
   глоссарий): копия модуля JSON-RPC `mcpnews/src/rpc.js` плюс
   `resources/list` и `resources/read` (в модуле их нет — проверено). Вход —
   `Authorization: Bearer <MCPAGENTS_KEY>` с тем же модулем ключа, что в п. 2
   (копия, не общий код — единицы не делят модулей). Чтения — **ресурсы**,
   записи — **инструменты**; примитив MCP `prompts` не используется (I-13:
   «MCP навыки» здесь — инструменты и ресурсы). Зовёт
   `http://agents:8086` с `CONTROL_KEY`.
5. **Клиент — код дня, прямым JSON-RPC как консоль дня 16**
   (`days/day16/server.js:145`), не через хост и **не в `mcp-servers.json`**:
   реестр хоста один и без отбора по агенту (`agents/src/mcp/pipeline.js:69-
   85`); запись туда отдала бы операции управления заданию посетителя дня 20
   и планировщику. Держит тест «`mcp-servers.json` не содержит `mcpagents`».
6. **Сеть: никакой новой.** `mcpagents` — в `default`, как дни; правила стража
   `compose-networks.mjs` для него нет **намеренно**: страж, который выглядит
   защитой и ею не служит, хуже отсутствия стража — при следующем возврате к
   теме его приняли бы за границу. Связность `default` даёт и так. Правила
   `mcp`, `cron`, `tools` не меняются. Было: своя сеть `control` с правилом.
7. **Маршрута в `Caddyfile` — нет**, ни к 8086, ни к `mcpagents`. Это не
   противоречит решению владельца: он выбрал ключ как преграду, а не публичный
   адрес как цель; клиент решения — код дня внутри compose, внешнего клиента
   в решении нет. Маршрут — отдельный PR со своими причинами (поадресный
   лимитер, `header_up`, как у `/mcp` дня 16), и поверхность к нему готова:
   ключ — единственная преграда уже сейчас. **Что при этом честно:** без
   маршрута порт достижим только из compose (`expose`), но это не свойство
   проекта — его не держит ничто, и полагаться на него поверхность не вправе.
8. **Перечень операций первого дня** — по списку владельца:

   | Операция | Вид | Платная | Под ней |
   |---|---|---|---|
   | `profiles` | ресурс | нет | `sessions.profiles()` |
   | `profile/{id}` — настройки, `Пn`, промпты профиля | ресурс | нет | `sessions.profile()` |
   | `history/{profileId}/{sessionId}` | ресурс | нет | `sessions.history()` с проверкой принадлежности |
   | `models` | ресурс | нет | `describe().models` |
   | `prompts/{profileId}` — умолчание реестра ⊕ профиль | ресурс | нет | `describe().stages` + `profile().prompts` |
   | `message.send {profileId, sessionId, text, parentId?}` | инструмент | да | `createRun` агента `prompt-agent` |
   | `prompt.set {profileId, promptId, text}`, `prompt.reset` | инструмент | нет | `savePrompt`/`deletePrompt` |
   | `invariant.draft {profileId, text}` | инструмент | да | `invariants.draft` |
   | `invariant.accept {profileId, text, ticket}` | инструмент | нет | `invariants.accept` — ворота билета не обходятся |
   | `invariant.delete {profileId, num}` | инструмент | нет | `deleteInvariant` |
   | `models.set {profileId, model?, reviewModel?}` | инструмент | нет | `saveStagedSettings` под `parseSettings` |

   Нет и не появится «потому что есть»: создание и удаление профиля, очистка,
   голова ветки, CSV, тексты промптов запусков, планировщик. «Выбор профиля» —
   cookie дня, у поверхности его нет. «Редактирование сообщения» — ветка
   `parentId`. Правка инварианта на месте — `delete` + `draft` + `accept`.
9. **День 15 не меняется.** Клиент — новый день, номер по заданию; экран —
   раскладка и `design-review`.

## Что уже есть — карта того, что новый API делает под собой

| Позиция владельца | Сегодня | Где |
|---|---|---|
| просмотр профилей | есть | `GET /v1/profiles` |
| выбор профиля | cookie `day15_pid` дня; у сервиса нет | `days/day15/server.js:32` |
| редактирование сообщения | нет; ветка `parentId` в режиме «Ветки» | `days/day15/public/index.html:5139-5348` |
| редактирование промптов | есть, 5 идентификаторов | `PUT/DELETE /v1/profiles/:id/prompts/:promptId` |
| редактирование инвариантов | заведение через билет и удаление | `POST …/invariants/draft`, `POST …/invariants`, `DELETE …/invariants/:num` |
| текущие промпты и инварианты | есть | `GET /v1/agents` (`describe()`, `staged.js:364`), `GET /v1/profiles/:id` |
| история сообщений | есть | `GET /v1/sessions/:id?profile=` |

Поверхность зовёт не эти ручки по HTTP, а те же функции хранилища и агента
изнутри процесса — иначе `CONTROL_KEY` пришлось бы дополнять `AGENT_KEY`.

## Что снято решением владельца и чем за это платим

При закрытой сети этого не было; теперь возможно, и держит только ключ:

- **Утечка ключа из любого из ~20 контейнеров `default` — полный перечень
  операций.** `MCPAGENTS_KEY` лежит копией в `dayN.env` каждого дня-клиента,
  `CONTROL_KEY` — в двух файлах; любой день, роутер, `caddy`, `atlas` с
  ключом в руках правит промпты и инварианты, ставит `kimi-k3` всем
  профилям и шлёт платные сообщения. При закрытой сети утечка ключа из
  контейнера вне сети не давала ничего.
- **Внутренний шум стал возможен:** любой скомпрометированный контейнер
  щупает 8086 и `mcpagents`; перебор 256-битного ключа невозможен, но
  обрабатывать чужой трафик поверхность теперь обязана — отсюда журнал
  отказов и окно (п. 2), которых закрытая сеть делала ненужными.
- **Путь наружу — две строки `Caddyfile`, и страж их не запретит.** При сети
  публикация требовала бы переноса сетей — красный `compose-networks.mjs`.
  Теперь между поверхностью и интернетом — отсутствие маршрута, которого не
  держит ничто.
- **«С того же сервера» перестало быть свойством проекта.** Держателя нет и
  не будет; документы не должны его обещать — `operations.md` и README дня
  говорят «ключ», не «внутренняя сеть».
- **Время сравнения стало значимым:** соседи по сети больше не доверенные,
  поэтому `timingSafeEqual` получает держатель (п. 2) — у `mcp/src/service.js`
  и `agents/src/service.js` его нет по сей день.
- **Ротация из «на всякий случай» стала обязанностью** (п. 3), и поводов у
  неё столько, сколько копий.
- **Первый путь в проекте, где изоляция — только ключом**, вопреки образцу
  `mcp`/`cron`/`tools` «механизм вместо процедуры»
  (`guides/verification.md`). Это выбор владельца; `compliance` вправе
  возразить, и ответ ему — этот раздел, а не отсутствие раздела.

## Что опасно и почему — для клиента-кода

- **Инъекция из истории снимается на этом пути и возвращается на любом
  другом.** Код дня зовёт инструменты детерминированно, модели текст не
  показывает. Канал появляется, когда день отдаст ресурсы поверхности
  модели; тогда п. 5 и «модель не получает `prompt.set`/`invariant.delete`»
  обязательны. Правка `stage.verify.invariants` через модель не
  проектируется при любом клиенте: это модель, выключающая единственную
  проверку над собой.
- **Клиент-код — анонимный посетитель дня.** Профили открыты; перечень не
  шире экрана дня 15, но дефект кода дня даёт весь перечень — потому
  проверка аргументов на поверхности, перечень короткий.
- **Две поверхности к одним данным** — расхождение проверок молчаливо;
  держит общий модуль разборщиков и тесты на каждую операцию.
- **`models.set` — денежная поверхность, не обход роутера:** явный провайдер
  только внутри ярусов класса (`router/src/router.js:151-168`),
  `dailyCostUsd: 10` действует; `kimi-k3` делает ответ до $0,48 у всякого на
  том же профиле и действует в дне 13 (`days/day15/README.md`). Ответ
  `compliance` на вопрос о бюджете поверхности — «потолок приложения
  `agents`, $10 в сутки, плюс лимиты моделей в консолях поставщика», по
  решению владельца (4); операции управления садят посетителей дней 6–20
  в ту же очередь, что день 20 сегодня.
- **Два слова «инварианты».** Поверхность знает только `Пn`. Инварианты
  продукта `I-n` — git (I-11) и ADR; API к ним не проектируется никому.

## Чем платим

- Два новых ключа и их копии: `CONTROL_KEY` (два файла), `MCPAGENTS_KEY` (по
  файлу на день-клиент); четыре строки закрытого списка; ротация — ещё две.
- Модуль ключа (Bearer-только, постоянное время, минимальная длина,
  обнуление совпадения, журнал отказов, окно на отказы,
  `WWW-Authenticate`) — **дважды**, в `agents` и в `mcpagents`, с тестами
  в обоих: единицы не делят кода.
- Ещё одна единица: семь мест конвейера (ADR `2026-09-28-0736`,
  «Последствия»), тест адреса по образцу `test/mcp-server-urls.test.js`.
- Перечень операций дублируется по форме в `ops.js` и в списке
  инструментов/ресурсов `mcpagents`; сверяет тест равенства имён.
- Ресурсы MCP руками — ~100 строк; клиент дня — руками, второй после дня 16.
- Расход операций управления неотличим в сводке роутера от расхода дней:
  одно приложение `agents`, одна строка `admin.js spend`; кто именно тратил —
  только по `control_log` рядом с журналом роутера, склейка руками.
- `message.send` держит замок диалога до ~16,8 мин при зависшем поставщике.

- **Закрытая сеть compose с правилом стража** — рекомендация двух первых
  редакций; отклонена владельцем при показанной цене.

  рекомендация второй редакции; отклонена владельцем: бюджет проекта живёт в
  консолях поставщиков, внутри — только потолки роутера на приложение.
- **Сеть «для связности» с правилом стража** — правило без защиты; `default`
  связность даёт и так.
- **Обернуть `/v1` в MCP** — отклонено: наследует разрешение по умолчанию.
- **Поверхность отдельной единицей со своим доступом к базе** — SQLite один
  файл на один процесс.

  планировщику.

  ротации — секунды.

  сеть; первый элемент `X-Forwarded-For` — дефект дня 5.
