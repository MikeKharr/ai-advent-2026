# [2026-09-11 12:30] Доступ агента к серверу по ssh: закрытый список вместо подтверждения

Файл: `agent_docs/adr/2026-09-11-1230-ssh-server-access-norm.md`

## Статус

Принято (решение владельца; принятие — мерж PR #115 владельцем:
`.agents/skills/day-cycle/` — защищённый путь).

Сужено по вето compliance к PR #115 (head `8cf9a79`): `exec` в контейнеры
прода и копия строки секрета между env-файлами убраны из списка агента;
список — дословными командами в `/day-cycle`, а не ссылкой на
`operations.md`.

Заменяет `agent_docs/adr/2026-09-10-0426-framework-v2-model-routing.md` в
части правила ssh из поправки compliance («логи — через подтверждение»).
Две точные строки allowlist, классы CI и остальное в ADR `2026-09-10-0426`
в силе.

## Контекст

В `/day-cycle`, фаза 9, стоит: «Логи и всё прочее по ssh — через
подтверждение». Строка пришла из поправки ADR `2026-09-10-0426` после двух
кругов вето compliance на внедрение фреймворка (PR #47;
`agent_docs/development-history/2026-09-10-0427-framework-v2.md`, «Ревью
внедрения» и «Второй круг вето»).

От чего защищало вето — два риска, оба в allowlist `.claude/settings.json`:

1. **Произвольный ssh на прод.** Форма `docker compose *` на сервере
   автоодобряла бы любую команду compose — `up`, `down`, `exec`, — то есть
   изменение прода мимо CI и мимо владельца.
2. **Секреты сервера в транскрипте.** Хвостовой глоб внутри кавычек
   удалённой команды пропускал дописанный `; cat secrets.env`: чтение
   `deploy/*.env` одной автоодобренной командой, нарушение I-1 и I-3.

Итог вето: две точные строки без глобов (`docker compose ps`,
`docker compose restart caddy`); логи из allowlist убраны, потому что
`logs <единица>` без глоба не записать. «Через подтверждение» — не
отдельное решение о логах, а то, что осталось по умолчанию: всё, чего нет в
allowlist, спрашивало владельца. Окно и было механизмом.

Механизм исчез 2026-09-11: у владельца личный `allow: ["Bash"]` (ADR
`2026-09-11-0513`, п. 2; ADR `2026-09-11-1154`). ADR `2026-09-11-0513`
назвал риск прямо — «серверный секрет читается в транскрипт одной командой
без окна … остаётся дисциплиной, а не механизмом» — и отклонил
`deny Bash(cat *.env*)` как ложное ощущение защиты. Строка в `/day-cycle`
при этом не тронута; ADR `2026-09-11-1154` вынес вопрос владельцу и
compliance (`agent_docs/backlog.md`, «Владельцу»). Сейчас строка обещает
окно, которого нет.

## Решение

Формулировка «через подтверждение» заменяется нормой поведения:
**закрытый список того, что агент делает на сервере сам; всё остальное он
не делает — независимо от того, спросит ли Claude Code.**

Агент выполняет по ssh без окна — дословно, в `cd ai-advent-2026/deploy`:

- `docker compose ps`;
- `docker compose logs <единица> --tail N` или с `--since …`;
- `docker compose restart caddy` — после нового маршрута, дословно как в
  `.claude/settings.json`;
- проверки имён без значений: `grep -c '^NAME=' <файл>`,
  `grep -o '^[A-Z_]*=' <файл>`.

Всё остальное запрещено. В частности:

- **любой `exec` в контейнеры прода — без исключений.** Это произвольный
  код в контейнере, где лежат ключи провайдеров; проверка расхода роутера
  (`operations.md`, «Первый запуск на сервере», п. 4) — только владелец;
- всё, что меняет состояние прода: `up`, `down`, `pull`, `restart` других
  единиц, правка файлов, `git` в каталоге сервера, установка пакетов.
  Выкатка — только через `main` и `deploy.yml`; откат — владелец
  (`operations.md`, «Повтор и откат»);
- всё, что печатает значение переменной из `deploy/*.env`: `cat`, `sed`,
  `<`, `grep` с выводом строки, `docker compose config`, `docker inspect`.
  Перечень заведомо неполон — поэтому норма задана списком разрешённого;
- секреты — только руками владельца: новый — через `deploy/put-secrets.sh`
  (без изменений); копия существующей строки между env-файлами сервера —
  тоже владелец, командами из `operations.md` («Сервис агентов и день 6»
  и далее): `grep '^NAME=' a.env >> b.env` для существующего файла, `>` —
  только при создании нового.

Список живёт дословно в `/day-cycle` (защищённый путь): расширить его —
значит открыть PR, который сливает владелец. `operations.md` не защищён и
в список ничего не добавляет: иначе правка класса C разрешала бы агенту
новое действие на проде.

След вместо окна: в уведомлении владельцу после выкатки (фаза 9)
перечисляются серверные команды, если они были.

Правки: одна строка в `.agents/skills/day-cycle/SKILL.md`, фаза 9; в
`.claude/agents/platform.md` («Ограничения этой сессии») устаревшая фраза
«исходящий SSH закрыт» заменена ссылкой на этот список — ssh с машины
владельца открыт, и граница теперь задаётся нормой, не песочницей. В
`operations.md` и `agent-roles.md` правило не упомянуто — там ничего не
меняется. ADR `2026-09-10-0426` не редактируется (I-12).

## Обоснование

- Окна нет и не будет: владелец решил «любые bash-команды без клика» (ADR
  `2026-09-11-1154`). Строка, обещающая окно, не защищает, а вводит в
  заблуждение того, кто читает протокол.
- Список от разрешённого, а не от запрещённого: способов напечатать env
  много (ADR `2026-09-11-0513` назвал четыре), а того, что агенту
  действительно нужно, — `ps`, `logs`, `restart caddy` и проверка имён.
- Границу «состояние прода меняется только через `main`» проект уже держит
  (`.claude/agents/platform.md`, `operations.md`). Норма повторяет её для
  ssh, не вводит новую.

## Последствия

Положительные:

- Протокол говорит правду: что агент делает на сервере, написано, и
  расширяется только владельцем.
- Логи после выкатки читаются без вопроса — единственное, ради чего окно
  и открывалось на практике.

Отрицательные и риски:

- **Механизма нет.** Дрейф агента — `docker compose config` «посмотреть
  порты» — ничем не остановится; утечку ключа в транскрипт заметит только
  тот, кто читает транскрипт, а владелец «команды не очень понимает».
  Страховка та же, что в ADR `2026-09-11-0513`: I-3, ротация при
  подозрении.
- **Логи попадают в транскрипт.** Ключа в них нет (I-1), но ввод
  посетителей может быть; `--tail` ограничивает объём, не содержание.
  Если когда-нибудь включат журнал Caddy, `logs caddy` принесёт в транскрипт
  IP и заголовки посетителей (INFO compliance).
- **Перечень серверных команд в уведомлении** — ещё одна обязанность
  фазы 9, которую легко пропустить; проверить её выполнение можно только
  по транскрипту.
- Проверку расхода роутера и заведение ключей нового дня агент больше не
  делает даже по записанной процедуре: эти шаги ложатся на владельца.
- Норма про `restart caddy` дублирует `operations.md`: при изменении
  процедуры править два места.

## Альтернативы рассмотрены

- **Удалить фразу целиком.** Проще всего, но тогда о доступе агента к
  серверу говорят только две строки allowlist и абзац о риске в ADR
  `2026-09-11-0513`; нигде не сказано, что `logs` можно, а
  `docker compose config` — нет. Отклонено: пустота в этом месте и есть
  дрейф.
- **Оставить как есть с пометкой «механически не держится».** Честно, но
  бесполезно: правило, которое само называет себя мёртвым, учит
  игнорировать правила. Отклонено.
- **Механика: `deny Bash(ssh *)` в проектных настройках плюс обёртка
  `deploy/server.sh ps|logs|restart-caddy` в `allow`.** `deny` сильнее
  личного `allow`, дрейф упрётся в запрет. Цена: скрипт в `deploy/**`
  (класс A, защищённый путь), обход через `/usr/bin/ssh`, `bash -c`,
  `scp`, `rsync -e ssh` — тот же аргумент, по которому ADR
  `2026-09-11-0513` отклонил `deny Bash(cat *.env*)`. Не отклонено —
  отложено: если владелец хочет механизм поверх нормы, это отдельная задача
  по его решению (`AGENTS.md`, «Объём»).
- **Логи без ssh** (`backlog.md`, Later: «Наблюдаемость»). Снимает главную
  причину читать сервер, но не отвечает на вопрос о правиле. Остаётся в
  бэклоге.
