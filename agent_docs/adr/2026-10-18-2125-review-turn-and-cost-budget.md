# [2026-10-18 21:25] Ревью PR: бюджет ходов, потолок стоимости и куда публикуется сводное ревью

Файл: `agent_docs/adr/2026-10-18-2125-review-turn-and-cost-budget.md`

## Статус

**Принято владельцем 2026-10-19.**

Вопрос дословно: «День 32: принимаете новые числа AI-ревью? До 20 шагов вместо
8; потолок — $0.50 на один запуск (обычный ≈ $0.02); комментарий появляется
сразу и дополняется.» Ответ дословно: **«поставь 5$ на один запуск»**.

То есть принято всё предложенное, кроме величины потолка: вместо $0.50
владелец назначил **$5.00 на один запуск**. Числа ходов, порядок публикации и
бюджет чтений приняты как предложены.

**Заменяет п. 2 ADR `2026-10-18-1347`** в части числа ходов (`--max-turns 8` →
`20`) и добавляет потолок стоимости. Модель (`claude-haiku-5-5`), усилие
(`--effort medium`), авторизация отдельным ключом, запуск по метке и правило о
том, кто её ставит, — остаются как приняты; эта запись их не касается.

Отдельной записью, а не правкой `2026-10-18-1347`, — по инварианту **I-12**:
принятые ADR не редактируются, изменение решения несёт новый ADR. Инструкция,
по которой я работал, просила пересчитать стоимость «в ADR 2026-10-18-1347», и
я этого сознательно не сделал: правка принятого ADR — ровно та ошибка, которую
гейт уже снимал в этом же PR.

## Контекст

Живой прогон на `a099c33` после того, как владелец завёл оба секрета, а
оркестратор повесил метку: **прогон 39167342284**.

Что он показал — факты из его журнала, не рассуждения:

| Поле | Значение |
|---|---|
| `subtype` | `error_max_turns` |
| сообщение | `Reached maximum number of turns (8)` |
| `num_turns` | 9 |
| `duration_ms` | 83 622 (84 секунды) |
| `total_cost_usd` | 0.019245485 |
| `permission_denials_count` | 0 |

Что из этого следует:

1. **Ключ, сервер `project` и модель работают.** Ноль отказов по правам —
   значит ни белый список `--tools`, ни путевые deny-правила ничего не
   заблокировали. Деньги списались, модель думала, инструменты отвечали.
2. **Ревью не опубликовано.** Восьми ходов не хватило: модель израсходовала их
   на чтение и поиск.
3. **Запас по времени огромный, а по ходам — нулевой.** 84 секунды против
   `timeout-minutes: 15`. Потолок, который сработал, был не тем, который
   защищает деньги.

**Второй прогон, после правки** — **39168905131** на `2724878`: `success`,
6 ходов, **$0.0165**, ревью опубликовано. То есть обе причины отказа закрыты:
ходов хватило, и сводное ревью нашло, куда публиковаться.

И отдельная причина, найденная при разборе уже не журнала, а исходника
действия: **публиковать сводное ревью было нечем.**

- в agent mode сервер комментариев вообще не поднимается, если в
  `--allowedTools` нет его инструмента:
  `shouldIncludeCommentServer = !isAgentMode || hasGitHubCommentTools`
  (`src/mcp/install-mcp-server.ts:114`);
- даже поднятый `update_claude_comment` падает без `CLAUDE_COMMENT_ID`
  (`src/mcp/github-comment-server.ts:43`), а в agent mode его нет:
  `claudeCommentId: undefined, // No tracking comment in agent mode`
  (`src/modes/agent/index.ts:115`).

То есть промпт требовал сводный комментарий, а инструмента для него не
существовало. Инлайн-замечания были возможны, сводное ревью — нет. Поднятие
числа ходов само по себе эту часть не лечило бы.

## Решение

1. **`--max-turns 20`** вместо 8.
2. **`--max-budget-usd 5.00`** — потолок расхода прогона: «Stop the run once
   estimated spend on API calls reaches this amount» (CLI-справочник).
   Величина — решение владельца (см. «Статус»). `timeout-minutes: 15`
   остаётся. Чем эта величина является и чем не является — ниже, в
   «Обосновании»; коротко: это верх потери за один запуск, а не рабочий
   потолок.
3. **`track_progress: true`** — чтобы сводное ревью было куда публиковать.
   Побочный эффект назван прямо и **полностью** (первая редакция называла
   только первый пункт — находки `reviewer` и `compliance`): это переводит
   действие в tag mode (`src/modes/detector.ts:21`), и tag mode дописывает
   сам, без нашего участия (живой адрес — `src/modes/tag/index.ts`):
   - `Bash(git add:*)`, `Bash(git commit:*)`, обёртку push и
     `Bash(git rm:*)` в `allowedTools`;
   - `--permission-mode acceptEdits`, то есть правки файлов внутри рабочего
     каталога разрешаются без спроса;
   - три инструмента MCP: `mcp__github_ci__get_ci_status`,
     `mcp__github_ci__get_workflow_run_details`,
     `mcp__github_ci__download_job_log`.

   Чем это держится. Оболочку и запись держит **`--tools "Read,Glob,Grep"`**:
   он ограничивает сам набор встроенных инструментов, а `Bash`, `Edit` и
   `Write` в него не входят — поэтому git-команды и `acceptEdits` остаются
   инертными. На инструменты MCP `--tools` **не действует** («The flag
   doesn't affect MCP tools», CLI-справочник), и `permissions` их, скорее
   всего, тоже не держит: сервер поднимается после проверки, которая на
   публичном репозитории отвечает и без `actions: read`
   (`src/mcp/install-mcp-server.ts:34-48`), а предупреждения «Skipping CI
   server installation» в журнале живого прогона нет. Поэтому три
   `mcp__github_ci__*` закрыты явным `--disallowedTools`: deny бьёт allow и
   на инструменты MCP распространяется. Второй контур — `contents: read`:
   пушить всё равно некуда.
4. **`mcp__github_comment__update_claude_comment`** добавлен в
   `--allowedTools`.
5. **Бюджет в промпте**, потому что потолок ходов — это обрыв, а не
   дисциплина: не больше трёх вызовов `project_search` за прогон, не больше
   пяти чтений файлов и только изменённых в этом PR, **сводное ревью
   опубликовать к 12-му ходу** даже при неполном разборе, инлайн-замечания —
   после сводного, на остаток ходов.

Порядок публикации перевёрнут сознательно: раньше промпт говорил «в конце —
сводный комментарий», и именно это потеряло результат. Теперь главное
публикуется первым, а подробности дописываются, если ходы остались.
6. **Токен прогона в рабочем дереве закрыт от чтения.**
   `persist-credentials: false` снимает только заголовок самого
   `actions/checkout`; дальше действие кладёт в тот же `.git/config` свой
   токен (`git remote set-url origin https://x-access-token:$GITHUB_TOKEN@…`,
   `src/github/operations/git-config.ts:130-134`), и в журнале прогона
   39168905131 это видно строкой «✓ Updated remote URL with authentication
   token». `Read` разрешён белым списком, поэтому добавлено deny-правило
   `Read(./.git/**)`. Правило относительное, а не константой пути: каталог
   рабочего дерева у раннера свой. **Честная граница:** путевые правила
   система прав сверяет только для `Read` и `Edit` — правило для `Glob` или
   `Grep` она принимает, но никогда не читает (`docs/en/permissions`),
   поэтому поиск по `.git` этим правилом не закрыт, закрыт только `Read`.
   Триггер не ломается: в tag mode ворота смотрят на trigger phrase, но
   `prompt` снимает проверку целиком («If prompt is provided, always
   trigger», `src/github/validation/trigger.ts:20`), а `labeled` — в списке
   действий, допустимых для `track_progress` (`validateTrackProgressEvent`).

## Обоснование

Восемь ходов были выбраны из осторожности к накоплению входа. Осторожность
вышла дороже отказа: деньги потратились ($0.019), результата нет. Это худший
из возможных исходов — платим и не получаем ничего.

Почему 20, а не 15 и не 40. Измеренному прогону не хватило 8 на чтение плюс
публикацию; промпт теперь требует уложить публикацию в 12, то есть 20 даёт
восемь ходов запаса на инлайн-замечания и на один-два лишних шага модели. 40
не брались: запас сверх восьми ходов ничего не добавляет к гарантии
публикации, а стоимость растёт.

Почему деньги теперь держит потолок стоимости, а не число ходов. Число ходов —
плохая мера расхода: ход бывает дешёвым (один `Read`) и дорогим (поиск с
большим ответом), и накопление входа делает поздние ходы кратно дороже ранних.
Потолок в долларах измеряет ровно то, что мы защищаем.

### Пересчёт стоимости по двум измерениям — и поправка к моей же модели

Теперь есть две точки, и они опровергают модель, которой я оценивал раньше.

| Прогон | Исход | Ходов | Стоимость |
|---|---|---|---|
| 39167342284 | `error_max_turns`, ревью не опубликовано | 9 | $0.0192 |
| 39168905131 | `success`, ревью опубликовано | 6 | $0.0165 |

Шесть ходов стоили почти столько же, сколько девять. Значит стоимость
определяется **не числом ходов, а постоянной частью входа** — диффом,
`CLAUDE.md`/`AGENTS.md`, системной частью, — которая едет в каждом запросе.
Линейная подгонка по двум точкам: около **$0.0009 за ход** плюс постоянные
**$0.011**. Отсюда:

- 20 ходов на диффе такого же размера ≈ **$0.03**;
- 20 ходов на диффе у потолка (2500 строк / 150 КБ, постоянная часть впятеро
  больше) ≈ **$0.07**.

Моя прежняя оценка «$0.09 при квадратичном росте» была **завышена и построена
на неверной модели**: я считал, что накопление переписки доминирует, а данные
говорят, что доминирует постоянная часть. Записываю это прямо, чтобы
следующий не унаследовал ошибку.

**Чем является потолок $5.00 и чем не является.** Пять долларов выше оценки на
20 ходов примерно в 170 раз и выше измеренного прогона примерно в 300 раз. При
таком зазоре он **не страж от разгона внутри прогона**: любой реальный разгон
упрётся сначала в 20 ходов и в 15 минут. Это **объявленный владельцем верх
потери за один запуск** — страховка от неизвестного (смена модели в умолчаниях
действия, распухший дифф, цикл чтений), цена которой названа заранее. Рабочее
значение остаётся **около $0.02**.

Что действительно ограничивает расход, по порядку срабатывания: потолок объёма
диффа (постоянная часть), `--max-turns 20` (переменная часть),
`timeout-minutes: 15`, и запуск только по метке — один запуск на одно решение
человека.

## Последствия

Положительные:

- ревью публикуется: сводный комментарий создаётся **до** работы модели,
  поэтому даже обрыв по ходам или по деньгам оставляет на PR видимый след, а
  не тишину;
- потолок расхода выражен в деньгах, то есть в той величине, которую
  защищаем;
- бюджет чтений и поисков в промпте уменьшает разброс стоимости между
  прогонами.

Отрицательные, названные прямо:

- **запрет на оболочку стал зависеть от одного флага.** В tag mode
  `allowedTools` содержит git-команды, и их недоступность держит `--tools`.
  Уберут `--tools` — вернётся `Bash` с git-подкомандами. Шага CI, который бы
  это ловил, нет; держит ревью диффа;
- **потолок в долларах срабатывает, и это проверено** — но не на нашей
  величине. `compliance` прогнал CLI 2.1.296 с `--max-budget-usd 0.000001`:
  `terminal_reason: "budget_exhausted"`, код возврата **1**, обрыв после
  первого вызова. Отсюда: потолок проверяется **после** завершения вызова,
  поэтому перерасход ограничен стоимостью одного вызова (ровно то, о чём
  предупреждает справочник), и исчерпание **краснит** шаг «Ревью», а не
  завершает его тихо. Срабатывание именно на $5.00 не наблюдалось и не
  будет: раньше сработают ходы и время;
- **$5.00 — это верх потери, а не рабочий потолок.** Зазор к норме
  примерно в 300 раз: если умолчание модели в действии однажды сменится на
  дорогую, потолок остановит прогон не на центах, а на пяти долларах. Поэтому
  модель задана явно (`--model`), и это тот случай, когда явное задание
  дороже стоит, чем выглядит;
- **tag mode — другой режим**, и его умолчания отличаются от agent mode не
  только по Bash. Что именно он добавляет, прочитано по исходнику на `f27be6b`
  и перечислено выше, но `@v1` — плавающий тег, и в следующей версии
  умолчания могут измениться;
- **12-й ход как срок публикации — инструкция, а не механизм.** Модель может
  её не соблюсти; тогда прогон снова закончится обрывом, но теперь на PR
  останется созданный заранее комментарий, по которому это видно;
- **стоимость по-прежнему оценка.** Измерено одно значение на одном диффе.
  Второй прогон даст второе число; расхождение с $0.09 вдвое — повод
  остановиться и разобраться, а не поднять потолок.

## Ручные шаги и проверки

Секреты и метка на месте — владелец завёл `ANTHROPIC_API_KEY_AI_REVIEW` и
`RAG_KEY`, оркестратор повесил метку; оба живых прогона уже состоялись
(39167342284 и 39168905131). Для проверки очередной правки метку нужно
**снять и повесить заново**: новый коммит ревью не запускает.

Что защищало расход до этой записи и куда делось: `--max-turns` остаётся, но
перестаёт быть главным ограничителем денег — его роль занял
`--max-budget-usd`; `timeout-minutes: 15` и `concurrency` по номеру PR не
менялись; потолок объёма диффа (2500 строк / 150 КБ) не менялся.

## Альтернативы рассмотрены

- **Только поднять `--max-turns`, ничего больше** — не лечит вторую причину:
  инструмента для сводного ревью не существовало, и ревью не публиковалось бы
  и на сорока ходах.
- **Отказаться от сводного ревью, оставить только инлайн-замечания** — дешевле
  и без смены режима, но на диффе без удобных якорных строк не публикуется
  ничего, и ревью снова оказывается невидимым.
- **`track_progress` без `--tools`** — tag mode отдал бы модели git-команды в
  оболочке; это прямо запрещено п. 2.5 ADR `2026-10-18-1147`.
- **Поднять потолок ходов до 40 без потолка стоимости** — расход ничем не
  ограничен, кроме времени, а время у нас с 15-кратным запасом.
- **Потолок $0.50**, как предлагалось — отклонён владельцем в пользу $5.00.
  Предлагался как «впятеро выше худшей оценки»; владелец выбрал запас, при
  котором потолок не придётся трогать при росте диффов.
- **Держать деньги только `timeout-minutes`** — время не мера денег:
  измеренный прогон уложился в 84 секунды из 900 и всё равно ничего не дал.
