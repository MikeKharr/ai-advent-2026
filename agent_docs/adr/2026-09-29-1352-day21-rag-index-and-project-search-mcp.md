# [2026-09-29 13:52] День 21: индекс проекта на эмбеддингах Ollama с ноутбука, две стратегии chunking с измеримым сравнением, поиск по проекту как сервер MCP для Claude Code

Файл: `agent_docs/adr/2026-09-29-1352-day21-rag-index-and-project-search-mcp.md`

## Статус

**Принято** владельцем 2026-09-30 в части, не заменённой ADR `2026-09-29-1639` (корпус, две стратегии chunking, мера сравнения, метаданные). Пп. 1, 5, 6 заменены. Развилки владельцу — последний раздел. Задание дня дословно и
замысел владельца — в описании PR этого ADR; здесь не повторяются.

## Решение

1. **Эмбеддинги — локальной моделью через Ollama на ноутбуке владельца,
   модель `bge-m3`.** Ни нового ключа, ни расхода, ни нового секрета. Индекс
   строится и используется там же, где идёт разработка, — на ноутбуке. Прод
   до Ollama не дотягивается надёжно, и это решение с этим не спорит: прод
   в этом дне не клиент (п. 5).
2. **Корпус — то, чем пользуется агент при разработке, а не «всё»:**
   `agent_docs/**/*.md`, `AGENTS.md`, `README.md`, `README.md` единиц; код
   живых единиц — `router/`, `agents/`, `mcp/`, `mcpnews/`, `mcpstore/`,
   `deploy/`, `.github/`, корневой `test/`. **Не берём:** `days/**` (сданные
   дни не поддерживаются — правило владельца 2026-09-08, искать в них нечего),
   `.agents/skills/**` (чужой vendored-набор), `node_modules`, `atlas/dist`,
   `temp/`. Тесты единиц (`*/test/**`) — не берём в первом заходе: 40 тысяч
   строк, которые удвоили бы индекс ради вопросов вида «есть ли тест на X»;
   это развилка владельцу (Р3). Замер: `agent_docs` — 208 файлов, 3,9 МБ;
   код живых единиц без тестов — около 23 тысяч строк, ~1 МБ. Порог задания
   «20–30 страниц» перекрыт на два порядка одной документацией.
3. **Две стратегии chunking, обе с одинаковыми метаданными** `source`
   (путь от корня), `title` (H1 документа или имя файла), `section` (цепочка
   заголовков до чанка, для кода — имя файла), `chunk_id`
   (`<source>#<порядковый>`), плюс `strategy`, `sha256` текста чанка и
   `commit` дерева:
   - *фиксированная*: окно 1500 знаков с перекрытием 200, граница — ближайший
     конец абзаца или строки; заголовки не учитываются намеренно;
   - *структурная*: markdown — по заголовкам (раздел = чанк; раздел длиннее
     3000 знаков режется по абзацам с той же цепочкой заголовков); код —
     файл целиком, если он короче 3000 знаков, иначе по пустым строкам
     верхнего уровня. Чанк несёт цепочку заголовков в тексте, который
     уходит в эмбеддинг: «ADR … › Решение › п. 5 …».
   Источник структуры — **исходный markdown, не `texts.json` атласа**:
   проверено, значения `texts.json` сплющены в одну строку без переводов
   (0 `\n` на 2900 знаков), заголовков в них уже нет. Метаданные документа
   (`type`, `key`, `title`, `file`, `date`) можно брать из `graph.json`
   атласа, но зависимость от сборки атласа не заводится: те же поля читаются
   из фронтматтера и H1 файла прямо.
4. **Мера сравнения — проверяемая, не «на глаз».** Файл
   `rag/eval/queries.json`: 30 вопросов, какие агент задаёт проекту на деле
   («какой потолок у `texts.json`», «где держится I-4», «почему Kimi
   `explicitOnly`»), у каждого — ожидаемые документы (пути) и у части —
   фраза, которая обязана быть в найденном тексте. По каждой стратегии
   считаются: **Recall@5** и **MRR@10** по документам; **доля запросов, где
   фраза-ответ есть в первом чанке**; статистика чанков — число, медиана
   длины, доля чанков, режущих блок кода или список пополам; время сборки
   и число вызовов эмбеддинга. Результат — таблица в записи истории; ничего
   не «проходит» и не «проваливается», разница видна числами. Граница
   меры названа заранее: 30 вопросов пишет человек этого проекта, и они
   отражают его привычки, а не всех будущих клиентов; документный recall
   не видит, обрезан ли ответ внутри чанка, — для этого и введён третий
   показатель по фразам.
5. **Клиент — Claude Code на ноутбуке (владелец и роли `.claude/agents/`
   в нём), сервер — локальный процесс по stdio.** Единица `rag/` без
   runtime-зависимостей и без SDK, как `mcpnews/` (исключение ADR
   `2026-09-23-1227` только для `mcp/`); JSON-RPC своими руками по образцу
   `mcpnews/src/rpc.js`, транспорт stdio вместо HTTP. Подключение — файл
   `.mcp.json` в корне репозитория: `node rag/server.js`. Два инструмента:
   `project.search {query, k, strategy}` — чанки с метаданными и оценкой,
   ответ не больше 8 КБ (потолок хоста `agents/src/mcp/agent.js:41`, чтобы
   тот же сервер годился хосту позже); `project.status` — коммит индекса,
   его возраст, число чанков по стратегиям, доступна ли Ollama. Ключа нет:
   сервер не слушает сеть, читает индекс с диска, за эмбеддингом запроса
   ходит на `localhost:11434`. Ollama недоступна — честный отказ инструмента
   с причиной, не пустой список. В `agents/config/mcp-servers.json` сервер
   **не попадает**: у сервиса `agents` на VPS нет ни доступа к ноутбуку, ни
   потребителя — ни один день не ищет по документам проекта. Запрет ADR
   `2026-09-28-1820`, п. 5, здесь не задействован: это не поверхность
   управления, а чтение публичного репозитория.
6. **Индекс — JSON на диске, не в git, не в выкатке.** `rag/index/<стратегия>.json`:
   чанки с метаданными и векторы `float32` в base64 (оценка: ~3,5 тысячи
   чанков × 1024 измерения ≈ 15 МБ на стратегию). Каталог в `.gitignore`.
   Пересборка — `node rag/build.js`, инкрементальная по `sha256` чанка:
   изменившийся текст переэмбеддится, остальное переносится из старого
   файла; полная пересборка — флаг. Поиск — косинус перебором в памяти:
   3,5 тысячи × 1024 умножений — миллисекунды, ANN не нужен. SQLite
   отклонён строкой в «Альтернативах». Выкатка индекс не трогает: в
   `deploy-units.sh` единица без `Dockerfile` не существует — проверено по
   регулярному выражению списка единиц.
7. **Страницы дня на VPS нет.** Сравнение стратегий — запись
   `development-history`, которую атлас публикует на `challenge.zpq.ai/atlas/`
   сам; на лендинге — карточка дня со ссылкой туда. Отдельная единица
   `days/day21/` со статической таблицей — развилка владельцу (Р4).

## Развилка эмбеддингов

| Вариант | Цена | Что требует от владельца | Годится проду |
|---|---|---|---|
| **A. Ollama на ноутбуке, `bge-m3`** (принят) | 0 денег; 1,2 ГБ на диске; Ollama должна быть запущена во время разработки | `ollama pull bge-m3`; держать Ollama поднятой (сейчас она **не запущена**, см. «Что проверено») | нет: VPS видит ноутбук только через Tailscale, и та **остановлена** на момент записи |
| B. Voyage AI (партнёр Anthropic по эмбеддингам) | новый ключ, новый расход — по документации поставщика $0,02–0,12 за миллион токенов, у части моделей бесплатная квота; за каждый запрос платится эмбеддинг запроса | регистрация, ключ, решение о хранении данных у поставщика (правило владельца), новое место хранения секрета — ключ провайдера мимо роутера или новая возможность `embeddings` в роутере (`router/config/**` — класс A) | да |
| C. Без нейросетевых эмбеддингов (BM25/TF-IDF на чистом Node) | 0 денег, ~100 строк | ничего | да |
| D. Ollama на самом VPS (`embeddinggemma`, 622 МБ) | контейнер и ~1 ГБ памяти на машине 4 ГБ с двумя ядрами; сборка индекса на CPU — десятки минут (оценка, не замер) | ничего руками, но ADR о топологии | да, медленно |

Почему A: единственный, кто пользуется поиском при разработке, сидит на
ноутбуке, и там же живёт Ollama; нулевой расход и нулевой секрет
соответствуют инвариантам I-1–I-6 без единого нового держателя. 128 ГБ
памяти ноутбука (проверено) вмещают `bge-m3` рядом с `qwen3.8:27b`.

Про C прямо: **это не выполнение пункта «генерация эмбеддингов», а подмена.**
Задание ставит FAISS рядом со словом «эмбеддинги» — речь о плотных
векторах модели; частотный вектор формально вектор, но сдать его как
эмбеддинг — обман проверяющего. Как *третья колонка* сравнения и как
*запасной путь*, когда Ollama не поднята, он честен и полезен — развилка Р2.

Про B прямо: это правильный вариант, **если** клиентом станет прод (сервис
`agents` или день на VPS). Такого клиента сегодня нет, а ключ и расход
появились бы сразу. Откладывается до появления потребителя, не отклоняется.

## Что проверено лично и что нет

Живые подтверждения (этот ноутбук, 2026-09-29 13:44–13:52 UTC):

- Ollama не отвечает ни на `127.0.0.1:11434`, ни на `100.77.87.97:11434`;
  `tailscale status` — «Tailscale is stopped». На диске одна модель —
  `qwen3.8:27b`; эмбеддинг-моделей нет. Клиент Ollama 0.33.3.
- `node --version` — 22.12.0: `node:sqlite` без `--experimental-sqlite` даёт
  `ERR_UNKNOWN_BUILTIN_MODULE`; с флагом работает. Единицы на Node 24 —
  `agents`, `mcpstore`. Довод против SQLite для индекса — отсюда.
- `router/config/providers.json` — девять записей, возможности только
  `text_generation`, `json_schema`, `web_search`, `tools`, `prompt_guard`;
  возможности `embeddings` нет, адаптер `ollama.js` ходит только в
  `/api/generate`.
- `.mcp.json` в корне нет; `mcpServers` нет ни в `.claude/settings*.json`,
  ни в `~/.claude.json` — у Claude Code владельца локальных серверов MCP
  сегодня нет.
- Хост инструментов обрезает результат до 8 КБ
  (`agents/src/mcp/agent.js:41`); отбор серверов по агенту —
  `agents/config/agents.json`, поле `servers`, ADR `2026-09-29-0236`, п. 6.
- `texts.json` атласа: 132 документа в локальной сборке от 2026-09-11,
  значения без переводов строк. `graph.json`: узлы с `id`, `type`, `key`,
  `title`, `file`, `date`, `excerpt`. Вход атласа — только `agent_docs`,
  роли, скиллы, деплой (`atlas/atlas.config.json`): кода единиц в атласе нет.
- Медиана длины ADR — 152 строки при 71 файле; заголовков в `agent_docs` —
  2378.
- Список единиц CI и выкатки — явный: `ci.yml` и `deploy-units.sh`
  перечисляют `router|agents|mcpnews|mcpstore|mcp` буквально; новая единица
  без строки там тестов в CI не получает.

Неподтверждённым остаётся всё, что собрано по документации поставщика:
`/api/embed` Ollama и его поля (`model`, `input` списком, `embeddings`,
`prompt_eval_count`); размеры и языки моделей (`bge-m3` 1,2 ГБ, 8K, «100+
языков»; `embeddinggemma` 622 МБ, 300M, 2K; `nomic-embed-text` 274 МБ, 2K);
качество `bge-m3` на русском — заявлено, не замерено; «Anthropic не
предлагает собственной модели эмбеддингов» и рекомендация Voyage — со
страницы платформы; цены Voyage — с её страницы цен, сводка неполная; чтение
`.mcp.json` расширением Claude Code для VS Code — по документации, `claude`
в этой оболочке не на PATH. Скорость эмбеддинга `bge-m3` на этом ноутбуке
не замерялась — первый прогон сборки её и покажет.

## Последствия

Положительные — коротко: задание сдаётся целиком в ограничениях проекта
(chunking, эмбеддинги, локальный индекс с метаданными, измеримое сравнение
двух стратегий); появляется инструмент, которым роли ищут решения и код по
смыслу, а не `grep`.

Чем платим:

- **Инструмент живёт, пока поднята Ollama.** Сейчас она не поднята. Без Р2
  (лексический запасной путь) роль, вызвавшая `project.search` при
  выключенной Ollama, получает отказ — честный, но бесполезный.
- **Индекс стареет молча.** Он не в git и не собирается в CI: после мержа
  чужого PR ищется вчерашний проект, пока не запущен `build.js`.
  `project.status` показывает коммит индекса, но никто не заставляет
  смотреть. Автоматическая пересборка по хуку — сознательно не в этом
  дне: хук — это `.claude/settings.json`, защищённый путь, и отдельное
  решение.
- **Один ноутбук — один индекс.** Второй разработчик или CI ничего не
  ищут; вариант B (Voyage) остаётся единственным путём к общему индексу и
  отложен до потребителя.
- **Новая единица без `Dockerfile` — новая форма в проекте.** `deploy-units.sh`
  её не видит (хорошо), но и `ci.yml` не видит: строка в двух списках —
  правка `.github`, класс A, и это первый прецедент «единица только для
  разработки».
- **Мера сравнения субъективна в основании.** 30 вопросов и их «золото»
  пишет один человек; числа честны только относительно этого набора.
- **Сравнение стоит времени владельца:** заход 2 — на его машине, с его
  Ollama, и оценка длительности эмбеддинга у нас отсутствует.
- **Третья копия протокола MCP.** `mcp/` — SDK, `mcpnews`/`mcpstore` —
  свой JSON-RPC по HTTP, `rag/` — свой по stdio. Три транспорта на четыре
  сервера; долг назван, не закрыт.

## Что этим НЕ решается

- Поиск по проекту у агентов **в проде** (сервис `agents`, дни на VPS):
  ни клиента, ни модели, ни ключа. Потребуется вариант B или D и новый ADR.
- Индекс кода сданных дней и тестов — вне корпуса по решению (Р3).
- RAG как генерация ответа — задание дня 21 индексация; ответ по чанкам
  моделью — следующие дни недели.
- Оценка качества эмбеддингов на русском — только косвенно, через
  метрики п. 4; отдельного бенчмарка моделей нет.
- Свежесть индекса и её принуждение.

## Альтернативы рассмотрены

- **Voyage через роутер** — новая возможность `embeddings`, адаптер, ключ в
  `router.env`: правильно для прода, у которого нет потребителя.
- **Ollama на VPS** — память и CPU машины 4 ГБ на двух ядрах уже держат
  два десятка контейнеров; не замерялось, и без потребителя не нужно.
- **BM25 вместо эмбеддингов** — подмена задания; остаётся как запасной путь (Р2).
- **Сервер в `agents/config/mcp-servers.json` и хост как клиент** — сервис на

- **SQLite для индекса** — на Node 22.12 ноутбука требует флага; поиск всё
  равно перебором в памяти, таблица ничего не добавляет.
- **Индекс в git** — 15 МБ бинарного на стратегию в публичном репозитории при
  каждом изменении документа.
- **`texts.json` атласа как источник корпуса** — структура заголовков в нём
  уже потеряна, кода единиц там нет.
- **`days/day21/` как место кода** — сданные дни замораживаются, а инструмент
  должен жить и меняться.
