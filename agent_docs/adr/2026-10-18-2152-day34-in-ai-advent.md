## Решение

1. **День 34 — в этом репозитории, публично.** Единица `mcpfiles/`:
   локальный stdio-сервер MCP без зависимостей по образцу `mcpgit/` (день
   31) — один файл `server.mjs`, своя копия JSON-RPC ревизии `2025-11-25`,
   корень из `CLAUDE_PROJECT_DIR`. Подключение — третья запись в `.mcp.json`.
2. **Четыре инструмента, три читают, один пишет:** `docs.read` (файл или
   раздел по заголовку, с номерами строк), `docs.search` (подстрока по
   `agent_docs/**/*.md`), `backlog.list` (открытые пункты очереди),
   `backlog.close` (перенос одного пункта в `agent_docs/backlog-closed.md` по
   правилам шапки `agent_docs/backlog.md`: `- [x]` выполнено, `- [~]` снят как
   ошибочный). Больше инструментов не заводится: правка — одна и известна
   заранее.
3. **Воспроизводимость — свойство, а не обещание:** `backlog.close` ищет
   якорь сначала в архиве. Якорь в архиве и пункта в очереди нет — `changed:
   false` без единой записи, то есть второй прогон того же сценария на том же
   дереве даёт пустой `git diff`; якорь в архиве и пункт ещё открыт — отказ,
   потому что это след сбоя между двумя записями, а не повтор. Держатель —
   тест «второй прогон того же сценария на том же дереве даёт пустой git
   diff» (`test/mcpfiles.test.js`).
4. **Две преграды, обе под тестами.** (а) Любой путь из запроса идёт через
   `resolveInRoot`, и все три формы выхода наружу — `..`, абсолютный путь,
   симлинк — закрывает ОДНА проверка: сверка `realpath` пути с `realpath`
   корня (второй, лексической, нет намеренно: та же защита во втором месте
   означала бы, что снятие любой из двух оставляет прогон зелёным, I-14).
   `.git/` и `.env*` закрыты по имени уже РАЗРЕШЁННОГО пути, то есть после
   `realpath` — симлинком их не открыть (I-1, I-3: `.env` на ноутбуке
   существует и несёт ключи). (б) Путь записи из запроса не собирается: имя файла темы сверяется
   с `^[a-z0-9-]+\.md$` и каталогом `agent_docs/backlog/`, второй путь —
   литерал.
5. **Потребитель — project-local skill `/backlog-close`**
   (`.agents/skills/backlog-close/` с зеркалами в `.claude`, `.codex`,
   `.cursor`): сценарий уровня цели «закрыть пункт бэклога по его
   подтверждению» — список открытых пунктов, поиск подтверждения по корпусу,
   чтение названных файлов, перенос с примечанием. Пункт «Владельцу» скилл сам
   не закрывает.
6. **Платных вызовов из кода нет.** Модель — сессия Claude Code владельца;
   ключей, сети и `fetch` у единицы нет вовсе, I-4 к ней неприменим — расход
   нечем совершить.
7. **Карточка и страница недели 31–35 — не здесь.** Страницы по п. 4 ADR
   недели остаются отдельной задачей.

## Обоснование

- **Почему не в `samui-villas`:** день публичный только здесь, а предмет
  («файлы проекта») в этом репозитории богаче, чем в пустом новом. Решение
  владельца 2026-10-19 и совпадает с ценой, названной в п. 3.3 ADR недели.
- **Почему правка одна:** ассистент, умеющий «менять файлы» вообще, — это
  `Edit` в сессии, он уже есть. Ценность здесь в том, что правка знает правила
  очереди проекта и повторный вызов её не удваивает.
- **Почему перенос с исходным текстом:** по нему якорь находится в архиве на
  втором прогоне, то есть сохранение текста — механика воспроизводимости, а не
  вежливость.
- **Почему `agent_docs/` у поиска, а не всё дерево:** область совпадает с
  корпусом индекса дня 21 по смыслу («документы проекта»), а узкая область
  делает выдачу предсказуемой.
