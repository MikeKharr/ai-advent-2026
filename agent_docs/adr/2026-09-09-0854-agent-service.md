# Агент как отдельный сервис: контракт, статусы, монитор

Дата: 2026-09-09

## Статус

владельца на четыре вопроса до старта учтены: агент — отдельный
сервис-контейнер; архив — инструмент агента; монитор показывает только
запросы своего браузера; ADR и макет — до кода.

**Решения владельца по спорным пунктам раскладки** (`agent_docs/design/2026-09-09-0855-day6-monitor-layout.md`):
монитор живёт до перезагрузки страницы и держит пять запусков, долговременная
запись — лента ответов; токен подложки `--overlay` добавляется в корпус;
на узком экране монитор ниже параметров с прокруткой к нему по отправке;
живая область для скринридера — только статусы и ошибки; отмены запуска нет,
статус лишь показывается; группировка событий по запуску; полный системный
промпт публичен — зафиксировано как следствие; кнопка остаётся «Спросить».

## Контекст

День 5 держит всю логику внутри веб-приложения: отбор статей из архива,
сборку промпта, вызов роутера, чистку ссылок. Это работает, но у логики
нет имени и границы: её нельзя вызвать иначе как через страницу дня, нельзя
наблюдать со стороны и нельзя переиспользовать в следующем дне без
копирования.

Задание дня 6: перевести приложение на агентную схему. Агент — отдельная
сущность, логика запроса и ответа к LLM инкапсулирована; у агента есть
монитор состояния с запасом на развитие; страница дня становится
интерфейсом к агенту.

## Решение

### 1. Агент — сервис `agents/`, как роутер

Отдельный каталог верхнего уровня `agents/` и контейнер `agents` в compose,
без публичного адреса. Node 22 без зависимостей (ADR `2026-09-07-1525`).
Внутри — **реестр агентов** и один агент на сегодня: `news-analyst`
(аналитик новостей). Реестр — данные (`agents/config/agents.json`):
идентификатор, имя, версия, назначение, системный промпт, инструменты,
класс задачи роутера, умолчания параметров.

Почему не модуль внутри дня — выбор владельца: следующие дни смогут
переиспользовать агентов, а сервис можно наблюдать отдельно от страницы.

### 2. Архив — инструмент агента

Хранилище статей, обновление лент и отбор под запрос (в дне 5 —
`store.js`, `feeds.js`, `select.js`) переезжают в `agents/src/tools/archive/`
и становятся **первым инструментом** агента. Том `agents_data`. День 5
остаётся как есть со своим архивом (правило владельца о неподдержке
сданных дней); два архива — осознанная цена.

Инструмент — вещь с именем и контрактом (`name`, `describe()`, `run(args)`),
чтобы следующий инструмент добавлялся по образцу, а вызов инструмента был
событием монитора, а не строкой в коде.

### 3. Контракт сервиса — HTTP, node:http, без зависимостей

| Метод и путь | Что |
|---|---|
| `POST /v1/runs` | тело `{ agent, input: { sphere, prompt, model, params } }` → `202 { runId }`; запуск асинхронный |
| `GET /v1/runs/:id/events` | SSE: сначала уже накопленные события запуска, затем живые; завершается терминальным событием |
| `GET /v1/runs/:id` | снимок: статус, события, результат (если есть) |
| `GET /v1/agents` | реестр: имя, версия, назначение, системный промпт, инструменты — для окна передачи |
| `GET /v1/agents/:id/tools/archive` | состояние архива (размер, квота, последнее обновление) — для панели состояния |
| `GET /healthz` | жив ли процесс |

Авторизация — `Authorization: Bearer <ключ>`; ключ один, `AGENT_KEY`,
лежит в `deploy/agents.env` (проверяет сервис) и в `deploy/day6.env`
(предъявляет день). Как у роутера с ключами приложений.

**Почему HTTP.** Контейнеры общаются по сети compose; из транспортов без
зависимостей в Node есть только HTTP (`node:http`) и сырой TCP. WebSocket
на сервере в Node нет — нужна библиотека; gRPC и очереди сообщений — тоже.
Роутер уже говорит по HTTP, и день 6 будет говорить с двумя сервисами
одинаково. Живой поток событий монитора даёт SSE — это тот же HTTP, он
уже работал в днях 1–3 и проходит через Caddy без настройки.

Запуски живут в памяти сервиса: события каждого — в буфере, готовые
запуски удаляются через 10 минут. Долгого хранения нет намеренно: монитор
показывает только запросы своего браузера (решение владельца), и хранит
их браузер, как ленту ответов.

### 4. Модель статусов — с запасом

**Запуск** (`run`) проходит статусы: `queued` → `running` →
`succeeded` | `failed` | `cancelled`. `cancelled` зарезервирован:
отмены в первой версии нет, но статус существует, чтобы её добавление
не меняло контракт.

**Событие** (`event`) — единица монитора:

```text
id          уникальный идентификатор события
runId       запуск
agent       { id, version }
seq         порядковый номер внутри запуска, с единицы
at          метка времени ISO
status      статус запуска в момент события
stage       стадия: received | planning | tool_call | tool_result |
            llm_call | llm_result | guard | warning | error | done
level       info | warn | error
title       одна строка для монитора
detail      подробности одной-двумя строками
data        структурные данные стадии (см. ниже)
durationMs  длительность стадии, если применимо
parentRunId зарезервировано: запуск подагентом
toolCallId  связь tool_call ↔ tool_result
attempt     зарезервировано: номер попытки при повторе
```

`data` по стадиям: у `tool_call` — имя инструмента и аргументы без текстов
статей; у `tool_result` — числа (сколько статей, сколько совпало, размер);
у `llm_call` — провайдер, модель, предел входа, оценка токенов; у
`llm_result` — провайдер, модель, токены, длительность, признак обрезания;
у `guard` — сколько ссылок вырезано; у `error` — код и причина, без
секретов и без текстов.

В событиях **нет текстов**: ни промпта, ни статей, ни ответа. Ответ идёт
отдельным полем результата. Монитор описывает работу, а не содержание.

### 5. День 6 — интерфейс к агенту

Страница дня знает про агента и не знает про роутер, промпты, архив.
`POST /api/answer` создаёт запуск у агента и возвращает `runId`;
`GET /api/runs/:id/events` проксирует поток событий в браузер;
`GET /api/state` собирает модели, пресеты, состояние архива и описание
агента (для окна передачи) — всё это спрашивает у сервиса агента.

Лимитер дня остаётся на дне: он защищает публичный адрес. Суточный
лимит роутера остаётся у роутера: он защищает деньги. Ключ приложения
у роутера — у **агента**, а не у дня: день денег не тратит.

### 6. Монитор — лента над лентой

Новые события сверху, над лентой ответов, только запросы этого браузера.
События приходят по SSE по ходу запуска; монитор — живое окно, а не архив:
в памяти страницы не больше пяти запусков, перезагрузка его очищает,
долговременная запись — лента ответов. Раскладка, состояния и тексты —
по спецификации роли `design`: `agent_docs/design/2026-09-09-0855-day6-monitor-layout.md`.

### 7. Окно передачи

Ссылка на агента в описании открывает диалог с именем, версией,
назначением и системным промптом агента, с кнопкой копирования промпта.
Промпт берётся с сервера (`GET /v1/agents`), а не дублируется в странице:
источник один.

## Обоснование

Граница проходит там, где меняется ответственность: день отвечает за
пользователя (адрес, лимитер, страница), агент — за работу (инструменты,
промпт, модель), роутер — за деньги и провайдеров. Три сервиса, три
ответственности, три ключа.

События без текстов — не осторожность ради осторожности: монитор хранится
в браузере и проксируется через день, и любой текст в нём — лишняя копия
пользовательских данных.

Статусы и стадии названы шире, чем нужно сегодня (`planning`, `attempt`,
`parentRunId`, `cancelled`): владелец просил запас на развитие агентов, и
запас должен быть в контракте, а не в комментариях.

## Последствия

- Три сервиса вместо двух: `router`, `agents`, дни. Ещё один контейнер,
  ещё один ключ, ещё одна единица в CI и деплое (по образцу `router`).
- День 6 не тратит деньги сам и не держит ключа роутера: скомпрометированный
  день — это только его ключ к агенту.
- Два архива статей (у дня 5 и у агента) до тех пор, пока день 5 живёт.
- Ключи `AGENT_KEY` и `APP_KEY_AGENTS` кладутся на сервер **до** мержа —
  урок дня 5, когда роутер лёг из-за отсутствующего ключа.
- Перезапуск сервиса агента обрывает запуски в полёте; день покажет это
  как ошибку запуска. Восстановления нет — и не нужно для этого проекта.

## Альтернативы рассмотрены

- **Агент как модуль внутри дня 6.** Меньше работы, одна граница в коде.
  Отклонено владельцем: нужна переиспользуемость между днями.
- **Архив остаётся у дня, агент только зовёт LLM.** Уже граница, но агент
  тогда ничего не «умеет». Отклонено владельцем.
- **Общий монитор всех запросов на сервере.** Показывал бы чужие запуски;
  даже без текстов это наблюдение за сервисом, а не лента своего запроса.
  Отклонено владельцем.
- **WebSocket для событий.** Нет в ядре Node на серверной стороне —
  зависимость. SSE делает то же в одну сторону, а в другую события не идут.
