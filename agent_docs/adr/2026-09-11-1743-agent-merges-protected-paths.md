# [2026-09-11 17:43] PR с защищёнными путями сливает агент; копию существующего секрета делает агент

Файл: `agent_docs/adr/2026-09-11-1743-agent-merges-protected-paths.md`

PR #122 (head `ba8bb06`) принят владельцем отдельным ответом. Мерж PR с

## Контекст

С ADR `2026-09-11-0513` агент мержит и выкатывает сам, но два действия
остались за владельцем: мерж PR с защищёнными путями и копия строки
секрета между env-файлами сервера (ADR `2026-09-11-1230`, сужение по вето
compliance). На практике оба — механические: владелец получает готовую
команду `gh pr merge … --match-head-commit` или `grep '^NAME=' a.env >>
b.env` и выполняет её, не читая. 2026-09-12 владелец спросил «почему сам
не делаешь?» и на вопрос «делать самому сейчас и впредь» ответил «Да,
сейчас и впредь».

Что при этом терялось: клик владельца был единственным подтверждением,
которое видно с GitHub. Вердикт compliance к PR #96 (в чате; ревью на
GitHub у #96 нет — проверено по API) требовал ручного мержа как
единственного подтверждения решений владельца. Этот ADR меняет ровно это.

Допущение, принятое здесь: «изменения самих правил гейтов и процесса»
владелец отдельно не оговаривал. Принято прочтение: норма меняется только
через ADR, принятие ADR — по-прежнему владелец; мерж PR с принятым ADR —
агентом.

## Решение

1. **PR с защищёнными путями сливает агент-оркестратор** по той же норме
   консенсуса, что и обычные (`agent_docs/guides/agent-roles.md`, «Мерж
   по консенсусу»): явный вердикт каждого гейта класса на head sha,
   `--match-head-commit`, все проверки зелёные, без `--admin`, очередь
   выкатки пуста. **PR с защищёнными путями — всегда класс A**: гейт
   `compliance` обязателен (вето compliance к PR #122).
2. **Копию существующего секрета между env-файлами сервера делает агент —
   по закрытому списку:** копируется только имя `AGENT_KEY`, только из
   `deploy/agents.env`, только в `deploy/dayN.env` единицы, которая ходит
   к сервису агентов. Ключи провайдеров (`ANTHROPIC_API_KEY`, ключ Groq и
   прочие из `router.env`), `ROUTER_ADMIN_KEY` и `APP_KEY_*` агент не
   копирует никуда. Любая другая копия — владелец или новый ADR, который
   принимает владелец. Дословные формы, в `cd ai-advent-2026/deploy`:
   новый файл — `set -C; umask 077; grep '^AGENT_KEY=' agents.env >
   dayN.env; chmod 600 dayN.env` (`set -C` — noclobber: `>` не обрежет
   существующий файл); существующий файл — `umask 077; grep '^AGENT_KEY='
   agents.env >> dayN.env`; проверка — `grep -o '^[A-Z_]*=' dayN.env`,
   имена без значений. Значение не печатается. Формы входят в закрытый
   список серверных команд `/day-cycle` и попадают в перечень команд в
   уведомлении о выкатке (ADR `2026-09-11-1230`).
3. **За владельцем остаются:** принятие ADR — в том числе любого ADR,
   меняющего нормы гейтов и процесса (кто сливает, что класс C, список
   защищённых путей, правила `/day-cycle`, инварианты): такой PR несёт ADR
   со статусом «Предложено», владелец принимает его в чате; после
   принятия статус в PR меняется на «Принято (решение владельца в чате,
   <дата>)», гейты заново подтверждают вердикт на новом head, агент сливает;
   **новые** секреты, которых на сервере ещё нет — `deploy/put-secrets.sh`
   руками владельца; **откат прода**.
4. **След решения владельца** — в чате и в теле squash-коммита: «Мерж
   агентом по консенсусу: <гейты>, head <sha>; по поручению владельца
   (2026-09-12)» для PR, которые до этого ADR сливал владелец.

Правки правил в том же PR: `AGENTS.md` («Автономность»),
`agent_docs/guides/agent-roles.md` («За человеком», п. 6 нормы),
`.agents/skills/day-cycle/SKILL.md` (фаза 9, «Правила оркестрации»),
`agent_docs/operations.md` (копия строки — агент), `agent_docs/glossary.md`
(строка о владельце). Старые ADR не правятся (I-12).

## Обоснование

- Гейт, который владелец проходит копированием команды, не защищает —
  тот же довод, по которому ADR `2026-09-11-0513` снял клик на выкатку.
- Реальное решение владельца — принятие ADR; его норма и оставляет.
  Мерж после принятия — исполнение, не решение.
- Копия строки `grep >>` не показывает значение и уже была описана
  дословно; риск утечки в транскрипт от того, кто набирает команду, не
  зависит.

## Последствия

Положительные:

- Владелец не выполняет команд, которых не читает; цикл до выкатки
  замыкается агентом и для PR с правилами.
- Норма одна для всех PR; ветка «сливает владелец» исчезает из четырёх
  документов.

Отрицательные и риски:

- **GitHub не отличает агента от владельца.** Аккаунт общий; до этого ADR
  «кто нажал мерж» на защищённых путях означало «владелец видел». Теперь
  этого сигнала нет: подтверждение живёт в чате, которого в репозитории
  нет, и в теле коммита, которое пишет сам агент. Внешний читатель не
  сможет проверить, что владелец решение давал.
- **Требование compliance к #96 ослаблено.** Ручной мерж был единственным
  подтверждением решений владельца, независимым от агента; замена — слово
  агента в коммите. Это осознанный обмен, не недосмотр.
- **Агент получает право менять свои же правила** после одной фразы
  владельца в чате. Защита — обязательный ADR и «Предложено» до принятия;
  держится дисциплиной, GitHub её не подкрепляет (CODEOWNERS нет, ADR
  `2026-09-11-0513` отложил).
- **Ошибка в команде копирования ломает прод.** `set -C` не даёт `>`
  обрезать существующий файл, но опечатка в имени файла-источника создаёт
  пустой `dayN.env` без ошибки, и единица падает на старте. Раньше это была
  ошибка владельца в его сессии, теперь — агента без окна; страховка —
  проверка имён после копии и `healthz` при выкатке.
- **Закрытый список копий живёт в трёх местах** (этот ADR, `/day-cycle`,
  `operations.md`): расширение — новый ADR и три правки.
- **Закрытый список ADR `2026-09-11-1230` расширяется** первым же
  решением после его принятия — прецедент для следующих расширений.

## Альтернативы рассмотрены

- **Оставить мерж защищённых путей владельцу, отдать агенту только копию
  секрета.** Отклонено владельцем: «сейчас и впредь» относилось к обоим
  действиям.
- **Отдельная GitHub-личность для агента** (бот или второй аккаунт), чтобы
  мерж владельца и мерж агента различались. Снимает первое отрицательное
  последствие, но требует новый секрет и настройку защиты ветки под две
  личности. Не отклонено — отложено: задача вне списка владельца
  (`AGENTS.md`, «Объём»).
- **Агент заводит и новые секреты** через `put-secrets.sh`. Отклонено:
  значение прошло бы через транскрипт (I-1, I-3).
- **Мерж ADR-PR тоже без принятия владельцем**, по консенсусу гейтов.
  Отклонено: принятие ADR — единственный оставшийся человеческий гейт на
  содержание решений; без него агенты правят свои правила сами.
