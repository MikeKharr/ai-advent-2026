## Решение

1. **Страж зависимостей не сносится, а становится картой «единица →
   точные имена пакетов» в самом шаге `ci.yml`.** Сегодня — одна строка
   `allowed='@modelcontextprotocol/sdk zod'` и жёсткое `unit == mcp/`. Будет:
   `mcp/` → `@modelcontextprotocol/sdk zod`; `rag/` → `faiss-cpu numpy
   packaging`. Шаг по-прежнему читает **каждый** манифест дерева, теперь двух
   форм: `package.json` (три раздела, как сейчас) и `requirements.txt`.
   Манифест единицы, которой нет в карте, с непустыми зависимостями —
   красный; имя вне списка единицы — красный; версия не точная — красный
   (`==x.y.z` и `--hash=sha256:…` у каждой строки pip, `x.y.z` у npm);
   `pyproject.toml`, `Pipfile`, `poetry.lock` — красный как «манифест
   неизвестной формы». **Умолчание остаётся прежним: ноль.** Новая единица
   получает право на пакет только строкой в карте, а карта живёт в `.github/**`
   — защищённый путь, класс A, вето `compliance`. Красная ветвь — приманкой в
   PR; тело шага исполняет `test/deps-step.test.js` по образцу
   `test/secrets-step.test.js` (I-14). `AGENTS.md` меняет одну фразу:
   «Node 22 без runtime-зависимостей; исключения — только единицы и пакеты из
   карты шага „Граница runtime-зависимостей" в `ci.yml`» — список остаётся в
   одном месте.
2. **FAISS приходит через `faiss-cpu` на Python, не через `faiss-node`.**
   Единица `rag/` целиком на Python 3.12: обход корпуса, две стратегии,
   клиент `/api/embed`, `IndexFlatIP` на стратегию (точный перебор; IVF/HNSW
   на 3,5 тысячи векторов только теряют полноту), метаданные чанков — JSON
   рядом с `.faiss`, инкремент по `sha256` чанка. Сервер MCP — тот же
   протокол, что у `mcpnews`, JSON-RPC по HTTP руками на `http.server`,
   без SDK. Образ: `python:3.12-slim` по digest, `pip install
   --only-binary=:all: --require-hashes --no-deps -r requirements.txt` —
   аналог `npm ci --ignore-scripts`: колёса не исполняют `setup.py`, хэши
   прибивают байты. **Почему не `faiss-node`:** последний выпуск 0.5.1 от
   2023-10-15 на FAISS 1.7.4, а бинарник приходит только install-скриптом
   (`prebuild-install … || git clone faiss && cmake`) — ровно тем, что проект
   запрещает `--ignore-scripts`; обходить это ручной распаковкой tar из
   релиза GitHub значит держать чужой двухлетний бинарник руками.
3. **CI учится второму языку — иначе он зелёный, ничего не проверив.**
   Шаг «Синтаксис» для единицы без `.js` и `package.json` сегодня печатает
   notice и проходит; для `rag/` добавляются `python -m py_compile` по `*.py`
   и `python -m unittest discover` в шаге «Тесты» (обе ветви — по наличию
   `requirements.txt`). Строка `rag` — в списках единиц `ci.yml:31,123` и
   `.github/scripts/deploy-units.sh:27,58`. Корпус попадает в образ шагом
   до `docker build` по образцу «Сборка витрины атласа»: копия
   `agent_docs/**`, `AGENTS.md`, `README.md` и кода живых единиц в
   `rag/corpus/` (в `.gitignore`); изменение корпуса включает `rag` в
   затронутые единицы той же регуляркой, что включает `atlas`. Так индекс
   не стареет молча — правка документа доезжает выкаткой; **репозиторий в
   контейнер не монтируется**: рядом с ним на VPS лежат `deploy/*.env`.
4. **Ollama — служба compose на VPS**, `ollama/ollama` по digest, том
   `ollama_data`, сеть `rag` (в ней `caddy`, `rag`, `ollama`; в `default` и
   `tools` их нет — дни и хост инструментов до эмбеддера не дотягиваются).
   Модель тянет `rag` при старте через `/api/pull`, если её нет в `/api/tags`
   — без ручного шага. Пределы — **у обеих новых служб, не у всех**:
   `ollama` — `mem_limit: 2g`, `cpus: 1.0`, `oom_score_adj: 500`; `rag` —
   `mem_limit: 512m`, `cpus: 0.5`, `oom_score_adj: 500`. `cpus: 1.0` — не
   ограничение скорости, а обещание: сборка индекса никогда не займёт оба
   ядра, второе остаётся 26 контейнерам. `oom_score_adj` — при нехватке
   памяти ядро убивает сначала новых жильцов, а не дни. Модель между
   запросами остаётся в памяти на время `OLLAMA_KEEP_ALIVE` (умолчание
   5 минут): в рабочей сессии тёплая, ночью выгружена. Кластер потолков для
   остальных служб (`backlog.md`, «ни у одной службы нет потолка памяти»)
   **не предусловие**: риск, который он закрывает, есть сегодня и не растёт от
   двух ограниченных соседей; растёт только от неограниченных.
5. **Клиент — Claude Code на ноутбуке по HTTPS, `https://challenge.zpq.ai/rag`,
   ключ `RAG_KEY`.** Маршрут в `Caddyfile` по образцу `/mcp` (`header_up
   X-Forwarded-For`, открытый `/rag/healthz` для выкатки). На входе —
   проверка ключа в постоянном времени, лимитер на адрес до `tools/call`, и
   **суточный потолок вызовов эмбеддинга** — то, что здесь стоит денег, это
   не доллары, а ядро общей машины. Ключ — новый секрет: `deploy/rag.env`
   кладёт владелец (`put-secrets.sh`); копия у клиента — в личной
   конфигурации Claude Code владельца, **не в репозитории**: `.mcp.json` в
   корне объявляет URL и `${RAG_KEY}` из окружения. Это первый секрет
   проекта, у которого есть третье место жизни — ноутбук; I-1–I-3 про ключ
   Anthropic и не задеты, но норму «ключ не покидает сервер» ADR
   `2026-09-23-1227` п. 2 этот ключ **нарушает сознательно**: без него клиент
   с ноутбука невозможен, а туннель или Tailscale — то же «должно быть
   поднято», за которое прежний ADR платил Ollama на ноутбуке. В
   `agents/config/mcp-servers.json` сервер **не попадает**: довод ADR
   `2026-09-28-1820` п. 5 — запись в реестре оказывается в руках задания
   посетителя дня 20 и планировщика; здесь это не операции управления, но
   каждый поиск — вызов эмбеддера на общем ядре, и отдать его посетителю —
   отдать ему суточный потолок. Потребителя среди дней нет; появится —
   отдельный ADR.
6. **Индекс живёт в томе `rag_data`**, не в git и не в образе: образ несёт
   корпус, том — векторы по `sha256`; при старте контейнера эмбеддятся только
   чанки, которых в томе нет. Первая полная сборка — один раз, дальше —
   дельта мержа.

## Даёт ли FAISS что-то на этом объёме

Прямо: **нет, кроме соответствия букве задания.** Числа: 3,5 тысячи
векторов × 1024 измерения — 3,6 миллиона умножений на запрос; перебор в
`Float32Array` на Node — единицы миллисекунд, `IndexFlatIP` в C++ — доли
миллисекунды. Разница меньше миллисекунды при пути до Бангкока в сотни. ANN
(IVF, HNSW), ради которого FAISS существует, начинает окупаться на сотнях
тысяч векторов, а на 3,5 тысячах требует обучения и теряет полноту — поэтому
п. 2 берёт точный индекс, то есть тот же перебор, но из C++. Что FAISS
даёт честно: учебный проект видит границу инструмента числами — таблица
сравнения получает колонку «перебор на Node против `IndexFlatIP`» с
миллисекундами, и результат «разницы нет» — результат, а не дефект. Цена —
всё, что ниже в «Последствиях»: второй язык, второй реестр, переписанный
страж, четыре захода класса A.

## Последствия

Положительные — коротко: задание сдаётся буквально (chunking, эмбеддинги,
FAISS, метаданные, измеримое сравнение); индекс один и общий — ищет любой,
у кого есть ключ, а не один ноутбук; свежесть держится выкаткой, а не
памятью; страж становится строже по форме — два манифеста и хэши вместо
одного списка.

Чем платим:

- **Второй язык и второй реестр.** `npm ci` в сборке был первой зависимостью
  от чужого реестра — теперь их две (npm, PyPI), плюс третья на VPS:
  `ollama.com` при `/api/pull`. Роли `backend`/`reviewer` заточены под Node;
  `node --check`, JSDoc, `tsc` для `rag/` не существуют. Правило «единица =
  каталог + Dockerfile» держится, но «единица = Node 22» — больше нет.
- **3,75 ГБ образа ради 1,2 ГБ модели.** Ollama становится самым большим
  предметом на диске машины; первая выкатка тянет его минуты. Р5 — путь
  меньше, но с ручной доставкой модели.
- **Первая сборка — часы, при `bge-m3` под `cpus: 1.0` — до двух суток
  одного ядра.** Дни это не роняет по устройству (второе ядро их), но
  машина эти часы работает на пределе одного ядра, и пока сборка идёт,
  поиск отвечает «индекс строится».
- **Память впритык.** 2 ГБ Ollama + 0,5 ГБ `rag` из 2,5 ГБ доступных
  оставляют дням запас порядка сотен мегабайт; `oom_score_adj` делает
  первыми жертвами новых жильцов — то есть при тесноте ложится сам поиск.
- **Ключ на ноутбуке.** Третье место жизни секрета проекта; утечка отдаёт
  чужим суточный потолок эмбеддера, не деньги — но норма ADR
  `2026-09-23-1227` п. 2 нарушена впервые и сознательно.
- **Каждый мерж документа — пересборка и выкатка `rag`** (минуты CI, рестарт
  контейнера, минуты одного ядра на дельту). Плата за свежесть без
  планировщика.
- **Четвёртая копия протокола MCP:** `mcp/` — SDK, `mcpnews`/`mcpstore` —
  JSON-RPC на Node, `rag/` — JSON-RPC на Python. Долг растёт, не закрывается.
- **Слепое пятно CI между заходами 1 и 2**: пока `py_compile` и `unittest`
  не добавлены, единица на Python проходит «Синтаксис» зелёной без единой
  проверки — заходы 2 и 3 не сдаются порознь.
- **Мера сравнения по-прежнему на 30 вопросах одного человека** (ADR
  `2026-09-29-1352`, п. 4) — переезд этого не лечит.

## Альтернативы рассмотрены

- **Снести страж целиком** — умолчание «можно всё»; ровно то, от чего он
  заведён.
- **Потолок числа пакетов** — число не говорит, что за пакет.
- **Белый список единиц без имён пакетов** — названная раз единица тянет
  что угодно молча.
- **Node-единица, зовущая Python-процесс** — два языка в одной единице.
- **Монтировать репозиторий в контейнер** — рядом лежат `deploy/*.env`.
- **Пересборка контейнером `cron`** — сеть и копия ключа ради того, что
  выкатка делает сама.
- **Туннель SSH или Tailscale вместо ключа** — «должно быть поднято» на
  ноутбуке, за что прежний ADR уже платил.
- **IVF/HNSW** — обучение и потеря полноты на 3,5 тысячах векторов ради
  скорости, которой некуда деваться.
