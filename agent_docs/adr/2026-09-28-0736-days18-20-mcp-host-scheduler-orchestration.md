2. Третий сервер дня 20 — служба дня 16 по её публичному адресу (п. 4);

4. Выключатель планировщика — правка `agents/config/jobs.json` через PR

5. Срок хранения: файлы дня 19 — 30 часов, запуски дня 18 — последние 50

6. Каденция сводки дня 18 — раз в 6 часов, не больше 6 запусков в сутки.

## Решение

1. **Хост — в `agents/`: `src/mcp/client.js` (голый JSON-RPC через
   `fetch`, заголовки как у `days/day16/server.js`, `MCP-Protocol-Version:
   2025-11-25`) и агент `mcp-agent` с циклом:** `initialize` + `tools/list`
   с каждого сервера из `agents/config/mcp-servers.json` → модель через
   роутер с определениями инструментов → блоки `tool_use` → `tools/call` на
   сервер, которому инструмент принадлежит → `tool_result` → повтор. Имя
   инструмента для модели — `<сервер>__<имя с точкой→_>`
   (`mcp__weather_current`): у двух серверов может совпасть имя, а таблица
   соответствия — часть трейса. Потолки: 8 кругов с инструментами, 120 с на
   запуск, `answerTokens` 1024, результат инструмента в контекст — до 8 КБ с
   пометкой об обрезке. `stop_reason: max_tokens` при наличии `tool_use` —
   инструмент **не** исполняется, запуск завершается предупреждением.
   Несколько `tool_use` в одном ответе исполняются по порядку, результаты
   уходят одним сообщением. Недоступный сервер на `tools/list` — событие и
   работа без него, не отказ запуска.
2. **Роутер несёт `tool_use`** (класс A, `router/**`): в `POST /v1/route`
   необязательные `messages[]` (вместо `input`) и `tools[]`
   (`name`/`description`/`input_schema`), в ответе `content[]` как пришёл
   от провайдера и `stopReason: tool_use` без переименования. Новый класс
   `tool_use` в `classes.json`: `tiers: ["cloud-frontier"]`, `requires:
   ["text_generation", "tools"]`, `answerTokens 1024`, `maxAnswerTokens
   2048`. Способность `tools` в реестре уже есть только у `anthropic-haiku`
   (`router/config/providers.json:38`), поэтому другие адаптеры не
   трогаются: выбор отсекает их на стадии возможности. Оценка расхода до
   вызова — по JSON `messages` и `tools`. Учёт в журнале не меняется.
3. **Два новых сервера, две единицы, без SDK и без ключей:** `mcpnews/`
   (порт 8084, Node 22; `news.search {query, days, limit}` по Hacker News
   Algolia с фильтром свежести; `news.summarize {items}` —
   детерминированная выжимка: заголовки по убыванию очков, до 2000
   знаков, в ответе `sha256`) и `mcpstore/` (порт 8085, Node 24 ради
   `node:sqlite`; `file.save {name, content}`, `file.read`, `file.list`;
   том `mcpstore_data`, потолок 64 КБ на файл и 200 файлов, срок 30 часов).
   Каждая единица несёт свою копию модуля JSON-RPC (~150 строк:
   `initialize`, `notifications/initialized` → 202, `ping`, `tools/list`,
   `tools/call` с `isError`, коды `-32700/-32601/-32602`, POST-only, тело до
   64 КБ). Аргументов-адресов нет, хосты зашиты — правило ADR
   `2026-09-23-1227`, п. 5. Сеть compose `tools`: только `agents`,
   `mcpnews`, `mcpstore`; маршрута в `Caddyfile` нет, `caddy` в сети `tools`
   не состоит — держит расширенный `.github/scripts/compose-networks.mjs`.
4. **Третий сервер дня 20 — служба дня 16 по адресу
   `http://challenge.zpq.ai/mcp`:** у `caddy` в сети `default` появляется
   алиас `challenge.zpq.ai` (та же форма, что алиас `advent` в сети `edge`),
   и хост зовёт службу ровно тем адресом, каким её зовёт внешний клиент —
   через блок `/mcp` входа, с `MCP_KEY` и лимитером на адрес контейнера
   `agents`. Сеть `mcp` не расширяется, служба `mcp` и день 16 не
   меняются. `MCP_KEY` в `agents.env` — копия из `mcp.env` по норме ADR
   `2026-09-11-1743`; строка добавляется в закрытый список `/day-cycle` и
   `.claude/settings.json` по образцу строки для `day16.env` (сверка —
   `test/closed-list.test.js`).
5. **Трейс — событие монитора стадии `rpc`:** `data: {server, method,
   request, response, status, ms, clipped}` с телами как есть, потолок 64 КБ
   на тело (как `BODY_LIMIT` консоли дня 16). Правило дня 6 «текстов в
   событиях нет» (ADR `2026-09-09-0854`, п. 4) для этой стадии снимается
   осознанно: тела JSON-RPC и есть предмет показа. Страницы дней 18–20
   получают их через `GET /v1/runs/:id/events` тем же прокси, что день 15.
6. **Планировщик — таймер внутри процесса `agents`** (образец — уборки в
   `agents/server.js`), состояние в `/data/jobs.db` на томе `agents_data`.
   Описание работы — `agents/config/jobs.json`: `enabled`, `everyMinutes:
   360`, `maxRunsPerDay: 6`, агент `mcp-agent`, фиксированный запрос
   сводки (погода трёх городов и свежие новости; прошлая сводка идёт в
   контекст). Тик раз в минуту: срок пришёл, работа не идёт, за сутки UTC
   стартов меньше потолка — запуск; следующий срок — от **планового**, не
   от фактического; пропущенные за простой сроки не догоняются больше
   одного раза. Запуск идёт по отдельному ключу приложения роутера
   `ROUTER_APP_KEY_SCHEDULER` (приложение `scheduler` в `apps.json`: класс
   только `tool_use`, `dailyCostUsd: 0.5`, `dailyTokens: 500000`); без
   ключа планировщик **выключен** и `/healthz` это называет. Выключатель —
   `enabled: false` через PR (выкатка ~5 минут, делает агент); аварийный
   стоп — `docker compose stop agents` руками владельца. Отказ роутера
   `budget_exceeded` — запуск `failed`, следующая попытка на следующем
   сроке, повторов нет.
7. **Сводка — в SQLite и на экран дня 18:** таблица `job_runs` (план,
   старт, финиш, статус, текст сводки, трейс JSON, токены, остаток бюджета
   `budgetLeft` из ответа роутера); хранятся последние 50. Страница: состав
   работы, следующий срок, стартов сегодня из потолка, остаток бюджета,
   лента сводок с раскрываемым трейсом; идущий запуск — по SSE. Почты нет
   и не будет.
8. **День 19 — `pipeline-agent`, цепочка в коде, без модели:**
   `news.search` (`mcpnews`) → `news.summarize` (`mcpnews`) → `file.save`
   (`mcpstore`) → `file.read` (`mcpstore`); хост сверяет `sha256` выжимки с
   `sha256` прочитанного и показывает оба. Порядок задаёт код, данные между
   шагами переносит код; расход модели — ноль. Контраст с днём 20, где
   порядок и данные переносит модель, — предмет показа (проект учебный).
   `taskClass` в реестре становится необязательным для агента без модели.
9. **Три единицы `days/day18..20`** по образцу дня 15: `AGENT_KEY` копией по
   закрытому списку, лимитер дня (5/мин, 30/час на адрес; `MAX_DAILY_CALLS
   50` у дня 20), запись трейса — компонент по правилам консоли дня 16.
   Раскладка — фаза `design` на каждый экран; общая для трёх — одна запись
   в `agent_docs/design/`, если `design` не решит иначе.
10. **Данные и выкатка.** Выкатка — `git reset --hard origin/main` и `docker
    compose up -d` (`deploy.yml`, шаг «Выкатка»); именованных томов она не
    трогает, `rsync --delete` в этом репозитории нет. `jobs.db` не входит в
    `sessions.db`: свой файл, своя уборка, миграции дней 7–15 не задеты.
    Адресов посетителей нет ни в `jobs.db`, ни в `mcpstore` — I-10 не
    задевается; текст запроса посетителя дня 19 живёт в файле 30 часов, как
    переписка дня 7.
11. **Ревизия протокола — `2025-11-25`,** как у клиента дня 16; `2026-07-28`
    не реализуется (долг из `backlog.md` не растёт и не закрывается).

## Проверено лично

- **Роутер не умеет `tool_use`:** `parseBody` требует `input` строкой
  (`router/src/service.js`), адаптер строит одно сообщение `user` и знает
  только `web_search` (`router/src/adapters/anthropic.js:30,48-55`); ответ
  отдаёт склеенный `text`, блоки `tool_use` теряются. Способность `tools`
  есть в `CAPABILITIES` (`router/src/config.js:19`) и у `anthropic-haiku`;
  тест № 9 `router/test/router.test.js:216` показывает, что `requires:
  ['tools']` выбирает Haiku и не зовёт ноутбук.
- **Выкатка не трогает тома:** `deploy.yml`, шаг «Выкатка» — `git fetch`,
  `git reset --hard origin/main`, пин тегов в `.env`, `compose pull`, `up -d
  --remove-orphans`; `rsync` в workflow нет. Тома `router_data`,
  `agents_data`, `day5_data` именованные (`deploy/compose.yml`).
- **`agents` и `mcp` не видят друг друга:** `agents` только в `default`,
  `mcp` и `day16` только в `mcp`, `caddy` в `default`, `mcp`, `edge` с
  алиасом `advent` в `edge` (`deploy/compose.yml`). Вход `zpq` отдаёт весь
  хост `challenge.zpq.ai` во внутренний Caddy (`zpq-ai/deploy/Caddyfile:111-117`),
  поэтому публикация нового пути потребовала бы правки только здесь — и
  не требуется вовсе.
- **`fetch` Node 22.12 не даёт подменить `Host`:** прогон на локальном
  `node:http` — сервер увидел `127.0.0.1:<порт>`, а не подставленное имя.
  Отсюда алиас в DNS compose (п. 4), а не заголовок.
- **Hacker News Algolia:** `search?query=fintech%20startup&tags=story` —
  200, 3,4 с, 5,5 КБ; `search_by_date` с `numericFilters=created_at_i>…`
  в URL-кодировке — 200, 0,47 с, 7,3 КБ, 62 совпадения за неделю; тот же
  фильтр с сырым `>` — 400. Ключа не требует.
- **Планировщик в процессе — есть прецедент:** два `setInterval(...).unref()`
  в `agents/server.js` (уборка запусков и диалогов). Запуски живут в памяти
  10 минут (`RUN_TTL_MINUTES`), события отвергают стадию вне `STAGES`
  (`agents/src/runs.js`) — стадия `rpc` добавляется в контракт, а не
  обходится. Образ `agents` — Node 24, `node:sqlite` без флага.
- **Конвейер для новой единицы — семь мест, не шесть:** `ci.yml` (регэксп
  имён, `detect` дважды, `case` порта), `deploy-units.sh` (регэксп),
  `deploy.yml` (`paths`, список `context`, ожидание `healthy`) **и** шаг
  «Проверка живого сайта», который исключает только `router` и `agents`:
  сервер без публичного `/healthz` уронил бы выкатку. Шаг «Зависимости
  единицы mcp» и страж границы зависимостей новых единиц без
  `dependencies` не касаются.
- **Реестр агентов требует `taskClass`** (`agents/src/registry.js:24`) —
  для `pipeline-agent` без модели поле делается необязательным.
- **Закрытый список** разрешает копию `MCP_KEY` только в `day16.env`
  (`/day-cycle`, фаза 9).

Неподтверждённым остаётся всё, что собрано по документации поставщика:
форма блоков `tool_use`/`tool_result` и обязательность `tool_use_id` (по
образцу `curl/examples.md` актуального справочника API); ограничение имени
инструмента `^[a-zA-Z0-9_-]{1,64}$` — отсюда замена точки; поведение Haiku
4.5 при обрезке `tool_use` по `max_tokens`; условия и пределы Hacker News
Algolia (страница условий не открывалась); детали спецификации MCP для
рукописного сервера (`notifications/initialized` без ответа, `ping`) — по
ревизии `2025-11-25`, живой сверкой станет клиент дня 20 против SDK-службы
дня 16 (п. 4). Синтаксис алиаса в `default` — по прецеденту `edge`, `docker
compose config` локально не запускался (docker в песочнице нет).

## Обоснование

- Свой цикл, а не коннектор Anthropic: маршрутизация и порядок вызовов
  обязаны быть нашим кодом и видимым трейсом (требование владельца);
  коннектор к тому же не дошёл бы до серверов без публичного адреса.
- Нативный `tool_use`, а не JSON-план через `schema`: предмет дней 19–20 —
  протокол инструментов, и эмуляция обесценила бы день 20 («агент сам
  выбирает» превратилось бы в «мы разобрали его JSON»). Цена — PR в
  роутер; JSON-план остаётся запасным путём без правки роутера, если тот
  PR не пройдёт гейты.
- Хост в `agents`, а не новая единица: там уже запуски, SSE, реестр,
  SQLite, Node 24 и клиент роутера; новая единица повторила бы всё это.
- Без SDK в новых серверах: клиенту SDK в `agents` закрыт тем же ADR
  `2026-09-23-1227` (зависимость не должна попасть в контейнер с
  `ROUTER_APP_KEY`), значит клиент рукописный при любом выборе; сервер на
  SDK при рукописном клиенте дал бы две реализации в двух единицах вместо
  трёх копий одного модуля на ~150 строк. Что теряется — сказано в
  «Последствиях».
- Служба дня 16 как третий сервер: единственная независимая (SDK)
  реализация протокола, о которую проверяется наш клиент; без неё обе
  стороны шва — одно прочтение спецификации, и ошибка в нём не найдётся.
- Отдельное приложение `scheduler`: потолок числа запусков ограничивает
  счёт, а не деньги; деньги ограничивает только арифметика `max_tokens`,
  которая меняется при любой настройке. Суточный потолок роутера — одно
  число, переживает перезапуск (журнал на томе, тест «суточные суммы
  восстанавливаются из журнала») и виден отдельной строкой в `/v1/spend`.
  Без ключа — автономного расхода нет вовсе: отказ по устройству.
- Детерминированная выжимка в дне 19: равенство `sha256` на входе и
  выходе цепочки проверяемо тестом; с моделью внутри инструмента
  «корректность передачи данных» проверялась бы на глаз.

## Последствия

Отрицательные:

- **Планировщик живёт в общем сервисе дней 6–15.** Его дефект — падение
  всех этих дней; у контейнера нет предела памяти (`backlog.md`). Выкатка
  `agents` обрывает идущую сводку — запуск помечается `interrupted` при
  старте, повтора нет.
- **Автономный расход на платном ключе появляется впервые.** Потолок $0,5
  в сутки и 6 запусков держат сверху, но ожидание ~$0,05 за запуск — оценка
  до первого замера; каждый новый инструмент в сводке меняет её.
- **Три копии протокола** (два сервера, клиент) плюс консоль дня 16 —
  четыре. Расхождение найдёт только живой прогон против SDK-службы.
- **Выключатель — PR, а не кнопка:** от решения «остановить» до остановки
  ~5 минут с зелёным CI; быстрее — только ssh владельца.
- **Роутер расширяет контракт ради одного провайдера:** `messages`/`tools`
  понимает только адаптер Anthropic; Kimi и Ollama день 20 не увидят.
- **Тела JSON-RPC в событиях** — до 64 КБ на тело, до 16 тел за запуск: в
  памяти `runs` до ~1 МБ на запуск на 10 минут; в `jobs.db` — постоянно
  для 50 запусков (до ~50 МБ в худшем случае, ожидание на порядок меньше).
- **Новости — Hacker News, не стартап-издания:** запрос `startup` даёт шум
  (проверено), сводка дня 18 будет неровной. Архив лент проекта живёт в
  `agents`, и серверу `mcpnews` недоступен без дублирования кода лент.
- **Семь мест конвейера на каждую из пяти новых единиц** (два сервера, три
  дня) правятся руками; ошибка в одном — молчаливый пропуск или красная
  выкатка.
- **Инъекция через результаты инструментов** в дне 20: текст с HN и
  Википедии уходит модели, а модель умеет писать в `mcpstore`. Ущерб
  ограничен построением — файл до 64 КБ в очередь из 200, ни удаления, ни
  адресов, — но подделанная сводка возможна, и страница это скажет.
- **Каденция «раз в 6 часов» держится минутным тиком:** дрейф до минуты,
  после простоя дольше интервала — один догоняющий запуск, остальные
  пропущены навсегда.
- Заменяемый «в части» ADR `2026-09-23-1227` остаётся принятым со строкой,
  которая больше не действует, — прецедент `2026-09-23-1844`.

Положительные: каждый вызов виден и хранится; автономный расход отделён от

## Оценка объёма

Семь PR класса A и один класса C. Работа исполнителей и гейтов по опыту дней
13–16 (2–4 круга на PR класса A): роутер ~3 ч, серверы ~4 ч, `agents` ~4 + 3
ч, три дня ~3–4 ч каждый с раскладкой и `design-review`, документы ~1 ч —
**около 25–30 часов агентов**, две-три сессии календарно. Деньги: живые
прогоны фаз 5–7 — до $0,5 суммарно; планировщик — ожидание $0,1–0,2 в сутки
при потолке $0,5. Каждый из трёх экранов меняет опыт посетителя больше чем
на 40 минут — по `AGENTS.md`, «Объём», это и есть решение владельца, которое
принимается вместе с ADR.

## Альтернативы рассмотрены

- **Коннектор Anthropic (`mcp_servers` + `mcp_toolset`)** — маршрутизация
  уходит поставщику и из трейса; серверы без публичного адреса недостижимы.
- **JSON-план через `schema` вместо `tool_use`** — работает без правки
  роутера и с любым провайдером, но день 20 показывал бы нашу эмуляцию;
  остаётся запасным путём.
- **Планировщик в MCP-сервере (`job.schedule`/`job.result`)** — у сервера
  нет модели, «агент 24/7» получался бы у хоста всё равно; два
  планировщика.
- **Системный cron на VPS** — невидим с экрана, правится только по ssh, и
  ssh-команды вне закрытого списка.
- **Отдельный контейнер планировщика** — повторил бы клиент роутера, SQLite и
  события `agents`.
- **Кнопка «выключить» на странице** — публичный переключатель включает
  обратно любой прохожий.
- **Общее приложение `agents` вместо `scheduler`** — без нового секрета, но
  расход по таймеру сливался бы с расходом дней и не имел бы своей строки.
- **`agents` в сети `mcp`** — снимает изоляцию, ради которой сеть заведена.
- **Заголовок `Host` при обращении к `caddy`** — `fetch` его не подставляет
  (проверено); `node:http` только ради одного сервера — второй клиент.
- **Выжимка моделью внутри `mcpnews`** — ключ роутера у сервера, второй
  контур расхода, непроверяемая передача данных.
- **Одна единица с двумя контейнерами от одного образа** — `docker compose
  pull "$day"` в выкатке тянет по имени службы, совпадающему с единицей.
- **Один экран на три дня** — дни сдаются порознь, у лендинга и прогресса
  строка на день.
- **Расширить исключение по зависимостям на новые единицы** — новый ADR,
  правка стража, два дерева npm в образах, а клиенту SDK всё равно закрыт.
