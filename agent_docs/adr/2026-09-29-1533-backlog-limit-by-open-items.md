# [2026-09-29 15:33] Пределы снимка и бэклога разведены: снимку 300 строк, бэклогу 300 открытых пунктов

Файл: `agent_docs/adr/2026-09-29-1533-backlog-limit-by-open-items.md`

## Статус

Предложено. Направление выбрано владельцем 2026-09-29 в чате из четырёх
вариантов («развести»); число и мера для бэклога — предложение этого ADR.

Заменяет ADR `2026-09-07-1455` в части предела для `agent_docs/backlog.md`
(«≤300 строк» в «Решении» и общий шаг проверки); для `snapshot.md` тот ADR
действует целиком, включая довод о 300 строках.

## Решение

1. `agent_docs/snapshot.md` — предел **300 строк**, без изменений.
2. `agent_docs/backlog.md` — предел **300 открытых пунктов**: открытый пункт —
   строка, начинающаяся с `- [ ]`. Строки не считаются.
3. Третьего файла нет: наблюдения гейтов «Владельцу» остаются в бэклоге.
4. Шаг «Лимит длины файлов состояния (300 строк)» в `docs-guard.yml`
   разделяется на два шага с собственным сообщением каждый — раздел
   «Проверка в CI». Правка `.github/**` — класс B.

## Контекст

Проверено 2026-09-29 по дереву `main` (`8efd2af`):

- `snapshot.md` — 298 строк, `backlog.md` — 297; оба у предела 300.
- В бэклоге 174 открытых пункта, из них **155 «Владельцу»** (89 %);
  вложенных и закрытых (`[x]`, `[~]`) пунктов нет, так что «строка с `- [ ]`»
  описывает файл как есть.
- Рост по `git log`: 09-08 — 35 строк, 15 пунктов, 1 «Владельцу»; 09-22 —
  224 / 132 / 117; 09-29 — 297 / 174 / 155. Средний темп 7,6 пункта в сутки,
  29.09 — 24. Пункты не «Владельцу» — 14 и 19 на тех же датах: очередь работы
  агентов не растёт, растёт реестр находок для владельца.
- Снимок за то же время держится: 280 → 298 → 283 → 298 — роль `docs` ужимает
  прошедшее в записи истории (последний раз — семь блоков, PR #270).
- Сообщение шага «Перенесите закрытое в backlog-closed.md» для снимка
  указывает не то действие: у снимка закрытого нет, его лечат переносом в
  `development-history/`. Имя шага ни один документ не называет —
  переименование каскада по `ci-step-names.mjs` не даст.
- ADR `2026-09-11-0513`, «Последствия»: «Раздел „Владельцу“ в backlog будет
  расти» — предсказано и наступило; закрывает такие пункты владелец.

## Обоснование

Довод ADR `2026-09-07-1455` держится на двух свойствах снимка: его читают
целиком в начале каждой сессии, и его прошедшее **есть где хранить** —
в записях истории. Предел лишь заставляет переносить. У бэклога нет ни того,
ни другого: в список чтения при старте (AGENTS.md, «При начале работы») он
не входит, а у открытого пункта другого хранителя нет — вердикты в PR это
«память процесса, а не подпись» (backlog-closed, пункт от 09-24). Ужать
бэклог можно только сократив пункты, то есть срезав «проверено ДАТА: ЧЕМ»,
которого требует его же шапка. Предел в строках наказывает доказательство.

Мера «открытые пункты» наказывает только накопление, а накопление — это
единственное, о чём предел бэклога может сигналить: реестр «Владельцу»
превращается в сток. Красный шаг тогда — не задача агенту, а остановка:
нести владельцу разбор очереди (AskUserQuestion), а не ужимать и не удалять.

Число 300 — вдвое против 174 сегодня: 2–3 недели при среднем темпе, неделя
при темпе 29.09. Это порог терпимости владельца к неразобранным находкам;
владелец вправе заменить его при принятии.

## Чем платим

- **Стена переезжает, а не исчезает.** Пункты «Владельцу» закрывает только
  владелец, и при темпе 7,6/сут предел встретится через недели. Красный
  шаг блокирует несвязанные PR — ровно как потолок витрины 28–29.09.
- **Ослабление для бэклога.** 300 пунктов при 1,7 строки на пункт — около
  500 строк; файл станет длиннее, чем разрешал `2026-09-07-1455`.
- **Довод «предел важнее, чем кажется» больше не общий.** Для одного из
  двух файлов у него другая мера — это надо объяснять в шапке бэклога.
- Правка `docs-guard.yml` — защищённый путь, PR класса B.

## Что этим НЕ решается

- **Разбор 155 находок.** Вариант «сначала разбор» владелец отклонил;
  реестр остаётся стоком до его решения, предел лишь называет момент.
- **Читаемость очереди агентов.** 19 её пунктов тонут среди «Владельцу»;
  раздельное чтение дал бы третий файл — см. «Альтернативы».
- **Длина одного пункта.** Пункт про `trace.js` — восемь строк прозы в одной
  строке; предел по пунктам этого не ловит. Правила не заводим.
- **Закрытые пункты, забытые в бэклоге.** Шаг их не ищет; правило шапки
  остаётся договорённостью, как и сейчас.

## Проверка в CI

Два шага вместо одного, каждый со своей мерой в имени — читатель списка
проверок видит, что именно красно:

- «Снимок: не больше 300 строк» — `wc -l < agent_docs/snapshot.md`;
  ошибка: `snapshot.md: N строк, предел 300. Прошедшее — в запись
  development-history/, снимок только про текущее состояние`.
- «Бэклог: не больше 300 открытых пунктов» —
  `grep -c '^- \[ \]' agent_docs/backlog.md`; ошибка: `backlog.md: N открытых
  пунктов, предел 300. Не ужимать и не удалять находки — закрывает владелец.
  Остановиться и нести владельцу разбор очереди (ADR 2026-09-29-1533)`.
  Зелёная строка печатает и число «Владельцу» — сигнал накопления виден в
  каждом прогоне без отдельного правила.

Оба шага падают при отсутствии файла, как сейчас. При принятии правятся
шапки `snapshot.md:3`, `backlog.md:3` и две строки дерева в `README.md:38-39`.
Неподтверждённым остаётся всё, что собрано по документации поставщика: форма
аннотации `::error file=…` — по документации GitHub Actions, новый текст
прогоном не проверялся (в текущем шаге та же форма работает).

## Альтернативы рассмотрены

- **Поднять строки бэклога (600, 1000).** Отодвигает стену и сохраняет
  наказание за доказательство: ужимать всё равно придётся «проверено».
- **Третий файл для находок «Владельцу».** Даёт читаемую очередь агентов,
  но стена с тем же вопросом переезжает в новый файл; цена — ещё один файл
  сессии и правка `AGENTS.md:82`, `agent-roles.md`, `dod.md:17`,
  `atomic-documents.md:26` (защищённые пути, класс A). Не сейчас; естественный
  момент — когда владелец заведёт отдельный режим разбора.
- **Предел только на пункты не «Владельцу».** Эта часть не растёт (14 → 19
  за три недели) — правило без проблемы.
- **Снять предел с бэклога совсем.** Честно про актора, но реестр без порога
  никогда не станет поводом остановиться; владелец просил другой предел.
