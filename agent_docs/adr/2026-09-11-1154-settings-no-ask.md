# [2026-09-11 11:54] Разрешения Claude Code: список `ask` пуст, shell-команды не ждут клика владельца

Файл: `agent_docs/adr/2026-09-11-1154-settings-no-ask.md`

## Статус

Принято (решение владельца, 2026-09-11; принятие — мерж PR #112 владельцем).

Заменяет `agent_docs/adr/2026-09-11-0513-sdlc-autonomy.md` в части списка
`ask` в `.claude/settings.json`: список пуст. Остальное в ADR
`2026-09-11-0513` в силе.

## Контекст

ADR `2026-09-11-0513` (внедрение, «Проектный `.claude/settings.json`», и
допущение 2) оставил в `permissions.ask` четыре правила: `git push
--force*`, `git push -f*`, `gh run rerun *`, `gh run cancel *` — каждое
такое действие ждало клика владельца. Владелец 2026-09-11 решил дословно:
«разрешение нужно для bash-команд (любые)» — ни одна shell-команда не
должна ждать его клика. PR #112 (коммит `e286964`) удаляет список `ask`
целиком; `allow` и `deny` (чтение `.env*`, `git diff --no-index`,
`gh pr merge --admin`) не меняются. По I-12 решение принятого ADR
меняется только новым ADR — этим.

## Решение

В проектном `.claude/settings.json` секции `permissions.ask` нет.
Force-push, `gh run rerun` и `gh run cancel` идут по общему `allow` без
подтверждения. `deny` остаётся как есть.

## Обоснование

Клик владельца на каждый force-push и перезапуск CI рвал автономные
прогоны, ради которых принят ADR `2026-09-11-0513`; владелец команды «всё
равно не очень понимает» и решил снять вопрос целиком. Что действительно
должно быть невозможно, держат не правила `ask`, а защита ветки на
GitHub и `deny`.

## Последствия

- Force-push в `main` по-прежнему невозможен: защита ветки GitHub
  (`enforce_admins`, force-push запрещён) — механический контроль, не
  зависящий от настроек Claude Code.
- В собственных ветках агентов force-push идёт без вопроса. Отрицательное:
  ошибочный force-push в чужую ветку никто не остановит; страховка —
  правило «одна задача — одна ветка» и `git ls-remote` перед пушем.
- `gh run rerun` и `gh run cancel` идут без вопроса. Правило
  `operations.md` «агент перезапускает только последний запуск выкатки и
  только упавшие jobs, `gh run rerun <id> --failed`» остаётся нормой
  поведения, но механически больше не держится: полный повтор старого
  запуска — откат прода, который по ADR `2026-09-11-0513` за владельцем, —
  правилами не блокируется.
- Встроенные подтверждения Claude Code для составных команд (`cd` +
  `git`, перенаправления) правилами `permissions` не отключаются; часть
  кликов остаётся вне этого решения.
- Допущение 2 ADR `2026-09-11-0513` («`allow: ["Bash"]` не снимает `ask`
  на `git push --force`») теряет предмет: снимать больше нечего.

  и `gh run cancel` — отклонено владельцем: «любые» bash-команды.
