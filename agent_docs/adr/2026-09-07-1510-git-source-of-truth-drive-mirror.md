# [2026-09-07 15:10] Источник истины — git, Google Drive — витрина

## Статус

Принято

## Контекст

Владелец просил вести протокол действий и решений в Google Drive с версионированием. Шаблон 2030ai держит ADR и историю в репозитории. Два хранилища одних и тех же документов неизбежно расходятся, если не назначить одно главным.

## Решение

Источник истины — git. ADR и записи истории создаются в `agent_docs/adr/` и `agent_docs/development-history/`.

Google Drive, папка «AI advent Dev», — витрина только для чтения. Каждый выложенный файл несёт блок происхождения с путём в репозитории, git sha и временем синхронизации. При расхождении прав git, файл в Drive перевыпускается.

Правила — `agent_docs/guides/drive-sync.md`.

## Обоснование

Решение должно быть доступно агенту во время сессии, попадать в ревью PR вместе с кодом, который оно объясняет, и версионироваться тем же механизмом, что и код. Всё это даёт git и не даёт Drive.

Drive закрывает другую задачу — показать решение человеку, который не открывает репозиторий. Это витрина, и назвать её витриной честнее, чем притворяться, что копия равноправна.

Блок происхождения обязателен: без него через месяц невозможно понять, какая из двух версий свежее.

## Последствия

Положительные:

- одна авторитетная копия, расхождение разрешается механически;
- решения ревьюятся вместе с кодом;
- Drive даёт ссылку, которую можно показать не-разработчику.

Отрицательные:

- синхронизация — ручной шаг, и она будет забываться;
- витрина всегда немного отстаёт от репозитория;
- правка, случайно внесённая в Drive, будет потеряна при перевыпуске.

## Альтернативы рассмотрены

- **Drive как источник истины для решений.** Нативная история ревизий и удобный шеринг, но агент не может прочитать документ во время сессии, и решения отрываются от кода.
- **Только репозиторий, без Drive.** Проще всего и без риска расхождения, но не выполняет прямую просьбу владельца.
