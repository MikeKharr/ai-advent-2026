# [2026-09-11 18:52] Атлас выделяется в отдельный публичный проект `project-atlas` со спецификацией входных данных

Файл: `agent_docs/adr/2026-09-11-1852-project-atlas-extraction.md`

## Статус

Предложено. Принимает владелец.

Решения владельца от 2026-09-12, которые этот ADR не пересматривает: имя
`project-atlas`, каталог `/Users/mike/Projects/project-atlas`; публичный
репозиторий `MikeKharr/project-atlas` создаёт оркестратор по консенсусу
`reviewer` + `compliance`; документы и спецификация — на английском, плюс
`README.ru.md`; интерфейс витрины пока русский; лицензии нет — решает
владелец; история чистая, первый коммит ссылается на sha источника
(`1d882f4`); атлас внутри ai-advent-2026 — `atlas/`, CI, выкатка
`challenge.zpq.ai/atlas/` — не меняется; перевод ai-advent на новый проект —
отдельная задача.

Открытый вопрос владельцу: добавить ключ `language` и словарь `en` — когда?
(спецификация §14, план — вопрос 1). В формате 1 их нет.

Ничего из ADR `2026-09-10-0550`, `2026-09-10-1420` и `2026-09-11-0745` не
отменяется: атлас в этом репозитории продолжает работать по ним. ADR
добавляет второе место жительства кода и контракт входа, по которому его
можно применить к другому репозиторию.

## Контекст

Атлас (ADR `2026-09-10-0550`) написан как пакет `atlas/` этого репозитория и
зашит под его устройство:

- `atlas/lib/sources.js` — список входов константой `INPUTS`:
  `agent_docs/adr`, `days/`, `deploy/compose.yml`,
  `router/config/providers.json`, `.claude/agents`, `.agents/skills`,
  `site/index.html`;
- `atlas/lib/markdown.js` — грамматика цитат с префиксом `agent_docs/` и
  закрытым списком корневых документов;
- `atlas/lib/extract.js` — имена `caddy`, `router`, `site`, префикс образов
  `ghcr.io/`, маска `dayN`, префикс модели `claude-`, русские имена разделов;
- `atlas/overlay.json` — классы гейтов, фазы `/day-cycle`, внешние сервисы;
- `atlas/web/` — адрес репозитория и ссылка на ADR атласа константами.

Владелец хочет тот же инструмент для основного проекта (цель из
`AGENTS.md`: перенести практики в HBK.SG) и для показа снаружи. Для этого
всё проектное должно приходить из описанного входа, а сам код — лежать
отдельно, с чистой историей и своим CI.

Ограничения: ноль зависимостей (ADR `2026-09-07-1525`); граница
публикуемого — явный список входов, I-1…I-3; принятые ADR не правятся
(I-12); объём и мерж — по ADR `2026-09-11-0513`.

## Решение

### 1. Отдельный проект

Код `atlas/` (генератор, витрина, тесты) копируется в
`MikeKharr/project-atlas` на состояние `1d882f4` и дальше живёт там.
Спецификация входа — `docs/input-spec.md` того репозитория, план
переноса — `docs/extraction-plan.md`. Формат входа и выхода — **формат 1**,
определённый так: на checkout ai-advent-2026 `1d882f4` с примером конфига
`examples/ai-advent-2026/` инструмент даёт `graph.json` и `texts.json`
**байт-в-байт равные** `node atlas/build.js` этого репозитория. Это
обязательный критерий приёмки переноса и тест `compat` в CI нового
репозитория (checkout ai-advent-2026 на pinned sha, обе сборки в одном
окружении).

### 2. Что уходит в project-atlas, что остаётся здесь

| В project-atlas (общее) | Остаётся в проекте (специфичное) |
|---|---|
| `build.js`, `lib/*` без литералов проекта, `web/*` без констант репозитория, тесты, раскладка, правило следов, парсер compose, скрытие образцов | `atlas.config.json` — пути, имена сервисов, префикс единиц, реестр образов, адрес репозитория |
| Словарь русских соглашений (`lib/vocab/ru.js`): имена разделов, слова статуса, признаки гейта | `atlas/overlay.json` — классы, фазы, внешние сервисы, исключения; формат не меняется |
| Синтетический второй проект-фикстура для тестов | `atlas/Dockerfile`, `atlas/Caddyfile`, единица деплоя `atlas`, шаги CI и выкатки |

Пример конфига ai-advent-2026 (полная схема — в спецификации):

```json
{
  "format": 1,
  "project": { "name": "AI Advent 2026", "repo": "https://github.com/mikekharr/ai-advent-2026",
               "about": "agent_docs/adr/2026-09-10-0550-project-atlas.md" },
  "docs": { "root": "agent_docs", "adr": "adr", "history": "development-history", "design": "design",
            "guides": "guides", "invariants": "invariants.md",
            "rootDocs": ["agent_docs/architecture.md", "agent_docs/index.md", "agent_docs/glossary.md", "AGENTS.md"] },
  "agents": { "roles": ".claude/agents", "skills": ".agents/skills", "skillsLock": "skills-lock.json", "modelPrefix": "claude-" },
  "units": { "dir": "days", "prefix": "day" },
  "deploy": { "compose": "deploy/compose.yml", "proxy": "caddy", "caddyfile": "deploy/Caddyfile",
              "landing": "site/index.html",
              "static": [{ "name": "site", "dir": "site", "file": "site/index.html",
                           "note": "Лендинг: статика, которую caddy отдаёт из bind-монтирования ../site." }],
              "registry": { "prefix": "ghcr.io/", "external": "ghcr" },
              "providers": { "file": "router/config/providers.json", "service": "router" } },
  "overlay": "atlas/overlay.json"
}
```

Ключевые развилки спецификации, решённые архитектором:

- **Проектные константы — в конфиг, не в overlay.** Иначе пример для
  ai-advent потребовал бы правки `overlay.json` на `1d882f4`, и критерий
  равенства нельзя было бы проверить на нетронутом checkout. Overlay
  остаётся «фактами, которых нет ни в одном файле».
- **Значения для витрины — через `<meta>` в `index.html`, не через
  `graph.json`.** Любое новое поле в `graph.json` ломает равенство.
- **Русские слова грамматики — встроенный словарь `ru`** (модуль констант
  `lib/vocab/ru.js`), единственный в формате 1; ключа `language` в конфиге
  нет. Ключ `language` и словарь `en` — раздел «будущее» спецификации
  (§14): файл, а не смена формата; когда — вопрос владельцу.
- **Тип узла `day` сохраняется** ради равенства; переименование в `unit`
  — формат 2.
- **Необязательный вход, не названный в конфиге, — отсутствует молча;
  названный, но нечитаемый — находка.** Это единственная граница между
  «выключено» и «сломано».
- **Что не читается никогда** — deny-список поверх конфига: `.env*`,
  `*.env`, `temp/`, `logs/`, `data/`, `*.sqlite`, `node_modules/`, `.git/`;
  путь из списка в конфиге — находка. Список проверяется при загрузке
  конфига и повторно при каждом чтении. Пути конфига — по грамматике
  сегментов `^(?!\.{1,2}$)[A-Za-z0-9._-]+$` с расширением по полю.
- **Симлинки не читаются.** При каждом чтении и перечислении — `lstat` по
  каждому компоненту пути от корня; симлинк — находка, путь не читается;
  `realpath` цели обязан лежать под `realpath(root)`.
- **`--out` защищён меткой.** Каталог выхода берётся через `realpath` и
  помечается файлом `.project-atlas`; `site/` и каталоги vault удаляются,
  только если каталог не существует, пуст или несёт метку — иначе отказ;
  пересечение с корнем и входами запрещено в обе стороны.
- **Происхождение — только из своего репозитория:** `sha`, `dirty`, `date`
  читаются, лишь когда `git rev-parse --show-toplevel` равен
  `realpath(root)`; иначе полей нет.
- **Порядок рёбер зафиксирован по коду, а не по таблице:** `depends` и
  `mounts` — по сервисам compose, `cites`/`relies`/`mentions` — по
  документам в порядке цитат (спецификация §4.2). Иначе раскладка и
  равенство расходятся.

### 3. Как ai-advent-2026 будет потреблять атлас — варианты, без реализации

Отдельная задача владельца после публикации. Варианты, чтобы решить один
раз, а не спорить в PR:

1. **Checkout инструмента в CI** — `actions/checkout` с
   `repository: MikeKharr/project-atlas` и `ref: <tag>` в `docs-guard.yml`,
   `ci.yml` и `deploy.yml`; `node project-atlas/build.js --root . --check`.
   Ноль зависимостей, ноль копий кода; цена — три workflow знают о втором
   репозитории и его теге, и обновление тега — PR класса A (workflow с
   `secrets.*`).
2. **Git submodule** `tools/atlas`. Тот же эффект, но submodule требует
   `submodules: true` в каждом checkout и известен неудобством для агентов
   (пустой каталог после обычного clone).
3. **Вендорная копия** `atlas/` синхронизируется из project-atlas скриптом
   (как `.agents/skills` — ADR `2026-09-07-2350`). Просто и прозрачно, но
   это две копии кода и ручной шаг синхронизации; дрейф ловится только
   тестом на равенство.
4. **Оставить свой `atlas/` навсегда.** Ничего не делать; project-atlas
   живёт своей жизнью. Тогда выделение — витрина, а не инструмент, и
   практика в HBK.SG переносится копированием.

Рекомендация архитектора — вариант 1: он единственный без второй копии и
без submodule; цена — класс A на смену тега — честная, потому что версия
инструмента, который пишет публикуемую страницу, и должна проходить через
`compliance`.

### 4. Последствия публикации

Что станет публичным: код `atlas/` уже публичен в этом репозитории —
нового раскрытия кода нет. Новое: спецификация, план, пример конфига (пути
и имена сервисов этого репозитория — они видны в `compose.yml` и так),
синтетическая фикстура. Документы `agent_docs/` в project-atlas **не
копируются**: тесты, которые сегодня берут входы из этого репозитория,
переводятся на фикстуру; тест равенства делает checkout ai-advent-2026 в
CI, а не хранит его тексты.

Риски секретов в текстах и фикстурах и что с ними делается:

- образцы ключей в `lib/texts.js` и в спецификации собраны из кусков и на
  свои же шаблоны не совпадают; скан по всему дереву перед первым коммитом
  — шаг плана, результат — в описание первого PR;
- адрес частной сети из `providers.json` (`100.x`) во входы витрины не
  попадает (`baseUrl` не читается) и в фикстуру не переносится; образец
  маскируется в `texts.json`, как сегодня;
- в новом репозитории — тот же шаг секретов CI, что `docs-guard` здесь, с
  тем же списком образцов;
- тест-страж витрины `secrets.test.js` переезжает и проверяет `dist/site`
  по обоим спискам образцов.

Изменение здесь — только этот ADR (класс C). Ни один инвариант не задет:
входы не расширяются, ключей во входах нет, источник документов не
правится.

## Обоснование

- **Байт-в-байт как определение формата** — самый дешёвый и самый строгий
  критерий: он не требует описывать граф словами, а проверяется `cmp`;
  расхождение показывает первую разошедшуюся строку. Все прочие критерии
  («граф похож», «страница работает») субъективны.
- **Конфиг вместо обхода дерева** — прямое продолжение решения ADR
  `2026-09-10-0550` п. 4: явный список входов как граница публикуемого.
  Конфиг лишь называет этот список; страж чтения остаётся.
- **Минимум конфигурируемого**: только то, что в коде сегодня литерал этого
  репозитория. Ни одного поля «на будущее»; словарь один; тип `day` не
  переименован. Расширение — формат 2, с новым ADR.
- **Отдельный репозиторий, а не пакет внутри этого** — потому что цель —
  применить инструмент к другому проекту и показать его снаружи; внутри
  монорепозитория дня он остаётся «атласом ai-advent».

## Последствия

Положительные:

- инструмент применим к любому репозиторию с похожими соглашениями одним
  файлом конфига; практика переносится в HBK.SG без копирования кода;
- граница публикуемого становится описанной, а не подразумеваемой: спецификация
  называет, что читается, что не читается никогда и что попадает в выход;
- равенство с `1d882f4` даёт переносу механический критерий приёмки.

Отрицательные и риски:

- **Две копии кода на неопределённый срок.** До перевода ai-advent-2026 на
  project-atlas любая правка атласа делается дважды или не делается в одной
  из копий; тест равенства pinned к `1d882f4` и дрейф не заметит. Это
  прямое следствие решения «атлас здесь не трогать».
- **Формат 1 привязан к устройству одного проекта.** Тип `day`, русский
  словарь, форма карточки лендинга, подмножество compose — всё это
  зафиксировано ради равенства; второй реальный проект почти наверняка
  потребует формат 2, и первым же шагом — английский словарь.
- **Конфиг — новая поверхность ошибок.** Опечатка в пути молча выключала бы
  вход; поэтому неизвестный ключ и нечитаемый названный вход — находки, и
  это делает конфиг строгим и многословным (около сорока строк для
  ai-advent).
- **CI нового репозитория зависит от чужого репозитория** (checkout
  ai-advent-2026 на pinned sha в тесте равенства). Если ai-advent станет
  приватным или sha исчезнет, тест сломается; лечится хранением эталонных
  хэшей — но тогда пропадает независимость от часового пояса.
- **Русские сообщения находок и тексты vault** в инструменте с английской
  спецификацией — несоответствие, принятое сознательно (интерфейс пока
  русский); англоязычному пользователю придётся читать русские находки.
- **Витрина без `Dockerfile`** в project-atlas: доставка остаётся заботой
  потребителя, и для HBK.SG её придётся собрать заново.
- **Репозиторий с симлинками среди входов не читается**: каждый симлинк на
  пути входа — находка, не молчаливый пропуск. Для ai-advent-2026 это
  безопасно (зеркала `.claude/skills/*` в список входов не входят); другому
  проекту может потребоваться указать в конфиге реальные пути.
- **Метка `.project-atlas` в каталоге выхода** — лишний файл в `dist/`, и
  первый запуск в уже существующий непустой каталог без метки отказывает:
  придётся очистить его вручную.
- Перевод ai-advent на инструмент — PR класса A по любому из вариантов
  раздела 3, потому что трогает workflow с `secrets.*`.

## Альтернативы рассмотрены

- **Обобщить атлас на месте**, в `atlas/` этого репозитория, и публиковать
  его отсюда. Не даёт чистой истории и отдельного CI; проект-потребитель
  тянул бы весь монорепозиторий. Отклонено владельцем условием «атлас здесь
  не трогать».
- **Обход дерева по маскам** вместо явного списка в конфиге. Проще
  подключать, но граница публикуемого перестаёт быть списком — ровно то,
  от чего ADR `2026-09-10-0550` отказался. Отклонено.
- **Проектные константы в overlay**, конфиг только из путей. Чище по
  смыслу («всё ручное — в одном файле»), но требует правки `overlay.json` на
  `1d882f4` и ломает проверку равенства на нетронутом checkout. Отклонено.
- **Поля проекта в `graph.json`** (`project.name`, `repo`) вместо `<meta>`.
  Естественнее для страницы, но ломает байт-в-байт; отложено до формата 2.
- **Переименовать `day` → `unit` сразу.** Правильнее для общего инструмента,
  но ломает равенство, витрину, vault и тесты одновременно. Отложено до
  формата 2 вместе с переводом ai-advent.
- **Словарь как поля конфига** (каждое слово — ключ). Даёт английский
  сразу, но это полтора десятка регулярных выражений в конфиге каждого
  проекта; выбран встроенный словарь по имени языка.
- **npm-пакет** `project-atlas` для потребления. Противоречит ADR
  `2026-09-07-1525` и гейту ADR `2026-09-08-0205` на стороннее дерево; git
  checkout по тегу даёт то же без реестра. Отклонено.
