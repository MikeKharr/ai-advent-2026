# [2026-09-29 21:39] День 21, заход 4: сервер MCP над индексом и публичный `/rag` — маршрут, ключ, окна и суточный потолок одним изменением

Файл: `agent_docs/adr/2026-09-29-2139-day21-rag-mcp-server-and-public-route.md`

## Статус

**Принято** владельцем 2026-09-30 («запускай»). Развилки выбраны им же:
Р1 — основной путь с живой проверкой подстановки первым шагом; Р2 — (а),
полный объём; Р3 — (а), 500, с прямой оговоркой, что число не измерено;
Р4 — (а), структурная. Исполняет п. 5 ADR `2026-09-29-1639`
(маршрут, ключ, лимитер, суточный потолок, `.mcp.json`, отсутствие сервера
в реестре хоста инструментов) — здесь решается только то, чего тот ADR не
решал, и не повторяется то, что он решил.

## Решение

1. **Поверхность — `POST https://challenge.zpq.ai/rag`**, JSON-RPC 2.0,
   ревизия MCP `2025-11-25`, без сессий. Порядок обработчика читается сверху
   вниз и повторяет `mcp/src/service.js`: `/healthz` открыт → ключ **всегда и
   до чтения тела** → не POST — 405 → тело с потолком 64 КБ → окна лимитера
   **до** `tools/call` → и только теперь RPC. Отказ по ключу и неизвестный
   путь дают побайтно одинаковый пустой 404 — решение владельца по `/mcp`
   (ADR `2026-09-23-1844`, пп. 1–2) переносится сюда без нового обсуждения.
   Сверка ключа — `hmac.compare_digest`. Без `RAG_KEY` процесс не стартует, и
   `rag.env` в `deploy/compose.yml` становится `required: true`.
2. **Два инструмента.** `project.search {query, limit ≤ 10 (5), strategy}` →
   `{index: {commit, strategy, chunks}, results: [{source, title, section,
   score, text}]}`; текст чанка режется до 2000 знаков, весь ответ — до 32 КБ.
   `project.status {}` → состояние сборки, что загружено, остаток суточного
   потолка. Ни адреса, ни заголовков запроса, ни признаков устройства в
   ответах нет.
3. **Умолчание стратегии — структурная, и это выбор без числа.** Мера
   стратегий — заход 5 (ADR `2026-09-29-1352`, п. 4), её ещё не считали на
   живых векторах. Довод умолчания слабый и назван слабым: структурная несёт
   цепочку заголовков в `section`, то есть её результат читается без открытия
   файла. Аргумент `strategy` существует ровно потому, что числа нет: заход 5
   меняет умолчание одной строкой, если число скажет иначе.
4. **Суточный потолок вызовов эмбеддинга живёт в томе, а не в памяти.**
   `RAG_DAILY_EMBEDS` = 500, сутки по UTC, файл `/data/usage.json` — дата и
   число, **без адреса** (I-10). Причина именно в томе: контейнер `rag`
   перезапускается на каждом мерже документа (ADR `2026-09-29-1639`, п. 3),
   и счётчик в памяти обнулялся бы ровно в те дни, когда вокруг больше всего
   работы. Нечитаемый файл читается как ноль и пишется заново: этот потолок
   стережёт ядро общей машины, а не деньги, и остановить поиск из-за битого
   JSON дороже, чем пропустить один день учёта.
5. **Окна на адрес — копия `mcp/src/limits.js` по форме:** минута 10, час 100,
   отдельный счётчик отказов по ключу с одной строкой в журнал за окно.
   Адрес живёт не дольше часа и в журнал не попадает — там число, а не «кто».
6. **Что отдаётся, пока индекса нет, и что — когда он устарел.** `state`
   описывает сборку, новое поле `index` — то, что загружено в память. Сборка
   не удалась, а в томе лежит целая пара файлов — служба ищет по ней и
   называет её `commit`, отличный от `COMMIT` образа. Прямо: **это не починка
   дефекта «сборка не возобновляется»** (он в `agent_docs/backlog.md`, решение
   за владельцем), а то, что делает его последствие переживаемым. Нет ни
   готового индекса, ни целой пары в томе — `isError` с честным текстом и
   **без вызова эмбеддера**.
7. **Конвенция лимитера ADR `2026-09-29-1600` приезжает в `rag` по существу,
   а не по букве.** Таблица маршрутов, окно у каждой записи, `open` с `why`,
   отказ старта на записи без окна — на Python, держит `rag/test/test_serve.py`.
   Корневой `test/limiter-seam-days.test.js` продолжает сканировать `days/`:
   каталога `days/day21/` не существует и не появится (ADR `2026-09-29-1352`,
   п. 7 — страницы дня нет). Одна строка комментария там говорит это прямо,
   иначе принятый владельцем охват «дни 21 и 20» читался бы как невыполненный.
8. **`.mcp.json` в корне репозитория** — `{"mcpServers": {"project": {"type":
   "http", "url": "https://challenge.zpq.ai/rag", "headers": {"Authorization":
   "Bearer ${RAG_KEY}"}}}}`. Подстановка `${VAR}` документацией подтверждена
   не была, поэтому её живая проверка стала первым шагом захода — и
   **подтвердилась** (см. «Что проверено лично», шаг 0 захода 4): переменная
   берётся из окружения процесса в момент подключения. Запасной путь (не
   коммитить `.mcp.json`, сервер только в личной конфигурации владельца)
   не понадобился. Ключ не пишется в файл репозитория ни в каком исходе
   (I-2).
9. **Два долга захода 3 закрываются здесь, потому что их потребитель
   появляется здесь.** Первый — тест на удачный путь `run_build`: переход в
   `ready`, заполненные `strategies`, загруженный индекс; поле `state` до
   этого захода никто не читал, теперь его читает `project.status`. Второй —
   граница `read_commit`: значение из `COMMIT` уходит на открытый `/healthz`
   и пойдёт в каждый результат поиска; годной формой считается 7–40 знаков
   `[0-9a-f]`, иначе `unknown`.

**Проверено исполнением в заходе 4 (шаг 0), 2026-09-30.** Поднят локальный
HTTP-сервер, записывающий полученный заголовок `Authorization`; к нему
подключён сервер MCP той же формы, что в п. 8, через CLI `claude`
(`claude -p … --mcp-config … --strict-mcp-config`). Результат различает
гипотезы: с заданной переменной в журнале сервера `Bearer
VALUE-FROM-ENV-9f3a`, без неё — дословно `Bearer ${PROBE_TOKEN_XYZ}`.
То есть подстановка есть, а сессия без переменной шлёт строку шаблона как
ключ и получает от службы пустой 404. Форма записи HTTP-сервера (`type`,
`url`, `headers`) тем же прогоном подтвердилась рабочей. Третьим прогоном
сервер, объявленный в `.mcp.json` области проекта, соединения к пробному
серверу не дал ни одного — согласуется с «до одобрения не подключается», но
как общее правило поставщика **не подтверждено**: наблюдался один прогон
(сужено ревью к PR #282).

Неподтверждённым остаётся всё прочее, что собрано по документации
поставщика:
одобрение project-scoped сервера при первом запуске и
`claude mcp reset-project-choices`; `claude mcp add --scope user --transport
http`; `MCP_TIMEOUT`; что видит клиент при 401 и блокирует ли это старт
сессии. Проверить исполнением не удалось: CLI `claude` из этой сессии
недоступен. Сюда же: сколько стоит один эмбеддинг запроса на одном ядре VPS —
не мерено, отсюда 500 как начальное число, а не как расчёт; и весь список
`rag/README.md`, «Что остаётся непроверенным после захода 3».

## Последствия

Положительные — коротко: поиск по проекту становится инструментом, который
агент зовёт из этого репозитория, а не отдельной командой; индекс один,
общий и свежеет выкаткой; `rag` перестаёт быть единицей вне конвенции
лимитера; два долга захода 3 закрываются вместе с появлением потребителя.

Чем платим:

- **Индекс отстаёт от рабочего дерева.** Он собран из корпуса, попавшего в
  образ на последней выкатке `main`. Агент на ветке спросит про `main`, а
  получит ответ, который выглядит как ответ про его ветку. Смягчение только
  одно и слабое: `commit` едет в `index` и в `project.status`, то есть
  неверный ответ **можно** отличить от верного, если смотреть.
- **Поиск и сборка делят один слот Ollama** (`OLLAMA_NUM_PARALLEL=1`,
  `deploy/compose.yml`): пока идёт сборка, запрос ждёт батч из шестнадцати
  чанков. На первой сборке это часы.
- **Память процесса растёт.** Метаданные обеих стратегий (7,2 и 6,8 МБ JSON)
  живут загруженными рядом с пиком сборки в 146 МиБ. Потолок 512 МиБ взят с
  запасом втрое от прежнего замера, но замера с загруженным индексом нет.
- **Ключ, который нельзя отозвать быстро.** Смена `RAG_KEY` — скрипт
  владельца, рестарт единицы и правка личной конфигурации на ноутбуке; всё
  три шага руками, два из них — его руками.
- **`.mcp.json` в корне делает инструмент видимым всем ролям и всем сессиям
  в этом каталоге.** Сессия без `RAG_KEY` в окружении будет показывать
  неподключённый сервер — шум в каждом запуске, а не одна ошибка.
- **Потолок 500 — число без замера**, и первый рабочий день его и проверит.
  Промах в меньшую сторону останавливает поиск до полуночи UTC.
- **Счётчик в томе — запись на каждый поиск** и осознанный fail-open на
  битом файле: день учёта теряется молча, в журнале об этом строка.
- **Инструмент конкурирует с `grep`.** На корпусе в 4,8 МБ точный поиск
  мгновенен и точен; эмбеддинги добавляют полноту на перефразировке и
  ничего больше. Обещать «ищет лучше» до чисел захода 5 нечем, и этот ADR
  не обещает.
- **Невозобновляемая сборка остаётся невозобновляемой.** П. 6 делает её
  последствие мягче — это другое, и путать одно с другим здесь запрещено
  прямо.
- **Открытый `/healthz` остаётся открытым** и продолжает отдавать заголовок
  `Server: BaseHTTP/…` (пункт «Владельцу» в `agent_docs/backlog.md`): этот
  заход его не трогает, но добавляет к тому же адресу поверхность с ключом.

## Что этим НЕ решается

- Повтор сборки после единственного отказа — пункт владельца в бэклоге.
- Потолки памяти остальных служб и `Server:` на `/healthz` — там же.
- `rag` в `agents/config/mcp-servers.json` — запрещено ADR `2026-09-29-1639`,
  п. 5; дни и планировщик к индексу не ходят.
- Числа меры стратегий и колонка «перебор на Node против `IndexFlatIP`» —
  заход 5.
- Охват конвенции лимитера для дней 7–11 и 13–15 — осознанно оставлен
  (ADR `2026-09-29-1600`, «Статус»).
- Держатель постоянного времени сверки ключа в `mcp/src/service.js` —
  известное нарушение I-14 в бэклоге; здесь закрывается только `rag`.

## Развилки владельцу

- **Р1. Если `${VAR}` в `.mcp.json` не подставляется:** (а) не коммитить
  `.mcp.json`, сервер только в личной конфигурации *(предложено — ключ и так
  живёт там, а репозиторий остаётся без объявления, которое не работает)*;
  (б) `.mcp.json` с командой-помощником, читающей ключ, — ещё одна
  возможность, которую тоже не удалось подтвердить.
- **Р2. Если пять часов много:** (а) целиком *(предложено)*; (б) без выдачи
  по устаревшему индексу (п. 6), без счётчика отказов (п. 5) и со счётчиком
  суток в памяти (п. 4) — минус около 50 минут и ровно то, что перечислено.
- **Р3. Суточный потолок:** (а) 500 вызовов *(предложено)*; (б) другое число —
  владелец знает, сколько раз в день он ждёт от агента поиск, лучше, чем
  арифметика без замера.
- **Р4. Умолчание стратегии до чисел захода 5:** (а) структурная
  *(предложено)*; (б) фиксированная.

## Альтернативы рассмотрены

- **Ключ значением в `.mcp.json`** — секрет в репозитории, I-2.
- **Переиспользовать `/mcp` службы дня 16** — решение владельца «отдельный
  API для MCP»: ключ дня 16 открывал бы индекс.
- **SDK MCP на Python** — карта зависимостей даёт `rag/` FAISS и его
  спутников; SDK тянет свой набор и потребует правки карты (класс A, вето).
- **Суточный счётчик в памяти** — обнуляется на каждом мерже документа.
- **Дочитывать выдержку из файла корпуса** — `as_meta` уже несёт `text`.
- **BM25 рядом с векторами** — второй индекс ради того, что здесь делает `grep`.
- **Отдать поиск дням и хосту инструментов** — посетитель получил бы суточный
  потолок эмбеддера (ADR `2026-09-29-1639`, п. 5).
- **Разорвать заход на «маршрут с замком» и «инструменты»** — первый сам по
  себе открывает ручку, за которой ничего нет.
