# [2026-09-28 13:02] Перевод на обоих концах цепочки дня 19: единица `mcptranslate` поверх MyMemory

Файл: `agent_docs/adr/2026-09-28-1302-translate-both-ends-mcptranslate.md`

## Статус

**Предложено** 2026-09-28. Записывает решение владельца, принятое в разговоре
2026-09-28 двумя ответами: перевод нужен **в обоих концах** цепочки дня 19 —
запрос посетителя в английский на входе, выжимка на язык посетителя на
выходе; источник — **свой сервер MCP поверх MyMemory**, не готовый чужой.
Принимает владелец.

Дополняет ADR `2026-09-28-0736` в части п. 3 (третий сервер рядом с
`mcpnews` и `mcpstore`) и п. 8 (цепочка дня 19 — шесть шагов вместо
четырёх). Остальное того ADR действует без изменений; это дополнение, не
замена.

## Решение

1. **Единица `mcptranslate`** — по образцу `mcpnews` (ADR `2026-09-28-0736`,
   п. 3): Node 22, `dependencies` пуст, своя копия JSON-RPC, порт 8086,
   `expose` без публикации, только сеть `tools`, маршрута в `Caddyfile` нет,
   ключа нет — поставщик его не требует. Хост зашит:
   `https://api.mymemory.translated.net/get`; правила похода — копия
   `mcpnews/src/net.js`. **Лимитера нет по той же причине, что у соседей:**
   публичного адреса нет, платного API нет, ходит к единице только `agents`.
   Реестр: запись `mcptranslate` / `MCP_TRANSLATE_URL` в
   `agents/config/mcp-servers.json`; страж `compose-networks.mjs` получает
   третье имя в `required`, `allowed` и `only`. Реализация — PR класса A
   (`deploy/**`, `.github/**`).

2. **Один инструмент `text.translate {texts, from, to}`.** `texts` — 1..20
   непустых строк, каждая ≤ 500 байт UTF-8 (предел поставщика на запрос);
   `from`, `to` — `^[a-z]{2}$`, адресных символов нет. Один запрос
   поставщику на строку, последовательно. Ответ — `{texts, from, to,
   chars}`; `chars` — сколько знаков ушло поставщику, чтобы расход квоты был
   виден в трейсе. Отказ — `isError` с `{error, code}`, `code` ∈
   `quota_exhausted` | `provider_failed`. **Первый отказ обрывает вызов
   целиком**, частичного ответа не бывает: иначе выжимка была бы наполовину
   русской.

3. **Цепочка дня 19 — шесть шагов** (`STEPS` в `agents/src/mcp/pipeline.js`):
   1. `text.translate` (`mcptranslate`): запрос → `en` — **только если в
      запросе есть кириллица**; иначе шаг пропускается, в результате
      `queryTranslated: false`;
   2. `news.search` (`mcpnews`) с переведённым запросом; предел 80 знаков
      действует на него, отказ тот же, что сегодня;
   3. `text.translate`: заголовки найденного → `ru`;
   4. `news.summarize` (`mcpnews`) — те же пункты с переведёнными `title`;
      `url` и `points` перевод не трогает;
   5. `file.save`, 6. `file.read` (`mcpstore`) — как сегодня.

   **Сохраняется русская выжимка. Отпечаток сверяет `sha256` текста, который
   вернул `news.summarize`, с `sha256` прочитанного из `mcpstore`** — ровно
   то, что сегодня. Перевод — отдельный инструмент до выжимки, его выход —
   данные следующего шага, как и результат поиска; выжимка остаётся
   детерминированной от своего входа, и на экране показан тот же текст, что
   лежит в хранилище. Результат несёт `query`, `queryEn`, русскую `summary`
   и оба отпечатка.

4. **Исчерпание предела — отдельный исход.** `quota_exhausted` от
   инструмента → `PipelineError` с `reason: 'quota_exhausted'`;
   `provider_failed` → `reason: 'translate_failed'`. Запуск `failed`,
   `paidNothing: true`, страница дня 19 показывает разные сообщения.
   Различие — по коду, который отдаёт сервер, не по тексту. Непереведённый
   текст на экран не уходит ни в одном исходе: цепочка останавливается.
   **Своего счётчика знаков у единицы нет:** он говорил бы «осталось 4910»,
   когда поставщик уже отвечает 429 (см. «Проверено лично»), — неизвестное
   притворялось бы числом. Единственный признак исчерпания — ответ
   поставщика.

5. **Язык посетителя — язык страницы, на которой он читает результат.**
   Обе страницы объявляют `<html lang="ru">` (`days/day18/public/index.html`,
   `days/day19/public/index.html`); в `pipeline.js` — константа
   `VISITOR_LANG = 'ru'`. У плановой работы посетителя нет, но её результат
   читают на странице дня 18 — язык тот же. Поля во входе нет. Язык выхода
   неизвестным быть не может. Язык входа: кириллица есть → пара `ru|en`;
   нет → запрос уходит в поиск как набран, без перевода, и результат это
   говорит. Третий язык не переводится и, скорее всего, даёт «ничего не
   найдено» — тот же честный отказ, что сегодня. `prompt` работы `digest`
   может вернуться к русскому (PR #239 перевёл его на английский, потому
   что переводить было нечем); английский тоже работает — шаг 1
   пропускается, квота не тратится.

6. **Ответ поставщика — недоверенные данные; аналог `safeUrl`** из
   `mcpnews/src/tools.js`:
   - годен только HTTP 200 с `responseStatus === 200` (число); HTTP 429 или
     `responseStatus === 429` → `quota_exhausted`; всё прочее →
     `provider_failed`;
   - читается только `responseData.translatedText`; `matches[]` не читается
     никогда — для «MCP» там лежит медицинский термин;
   - `translatedText` — непустая строка не длиннее 4× исходной в байтах и
     2000 знаков; управляющие символы вырезаются; текст, начинающийся с
     `MYMEMORY WARNING`, — `provider_failed` даже при статусе 200;
   - переведённый текст идёт только в `title` пунктов (`news.summarize`
     режет его до 300 знаков) и на экран через `textContent`
     (`days/day19/public/app.js`, строка 8); в `url` — никогда.

   Перевод, совпавший с исходником («fintech» → «fintech»), — не отказ.

## Проверено лично

Живой прогон с ноутбука 2026-09-28, `curl` к `api.mymemory.translated.net/get`
без ключа:

- удачный ответ: HTTP 200, `responseStatus: 200` (число), `quotaFinished:
  false`, перевод в `responseData.translatedText`; в `matches[]` рядом с
  машинным переводом — записи чужих памятей: для «MCP» одна из них
  «(4-Chl-2-methylphen)acet acid»;
- «протокол MCP» → «mCP protocol»: регистр аббревиатуры сломан;
- исчерпание: HTTP 429, в теле `responseStatus: 429`, `quotaFinished: null`
  (не `true`), `matches: ""` (строка, не массив), а текст «MYMEMORY WARNING:
  YOU USED ALL AVAILABLE FREE TRANSLATIONS FOR TODAY. NEXT AVAILABLE IN
  20 HOURS …» лежит в `responseData.translatedText` — клиент, читающий это
  поле без проверки статуса, показал бы предупреждение как перевод;
- 429 пришёл после четырёх запросов суммарно ~90 знаков. Причина не
  установлена; вероятнее всего, адрес ноутбука делит квоту с кем-то ещё.
  Для собственного адреса VPS не измерено.

По коду: `STEPS` и сверка — `agents/src/mcp/pipeline.js`; вход работы —
`agents/src/mcp/agent.js:442` (`input: { task: job.prompt }`); `MAX_TASK`
дня 19 — 600 знаков при пределе `query` в `news.search` 80 — расхождение
существует сегодня и здесь не меняется; страницы дней 18 и 19 кладут текст
только через `textContent`; страж `compose-networks.mjs` держит
`only: ['mcpnews', 'mcpstore']`.

Неподтверждённым остаётся всё, что собрано по документации поставщика:
5000 знаков в сутки анонимно; предел 500 байт на `q`; `de=<email>` даёт
50 000 знаков в сутки; коды языков в `langpair` — ISO / RFC 3066;
автоопределение языка для `get` не документировано, живая проверка
упёрлась в 429; форма ответа при 429 наблюдалась один раз и контрактом не
объявлена; задержка одного запроса не измерена.

## Контекст

Живая проверка дня 19 в проде (PR #239): цепочка с русским запросом
останавливается на первом шаге — источник `mcpnews` (Hacker News Algolia)
англоязычен. Готовые серверы MCP для перевода зрелые — DeepL
(`github.com/DeepL/deepl-mcp-server`), Lara (`github.com/translated/lara-mcp`),
многопровайдерный `mohammadraufzahed/translate-mcp`, — но все требуют ключа
и несут чужие зависимости: граница «ноль runtime-зависимостей» (ADR
`2026-09-23-1227`, п. 2) и обязательная проверка стороннего кода (ADR
`2026-09-08-0205`). LibreTranslate публичный бесключевой эндпоинт закрыл.
Бесключевым остаётся MyMemory.

## Обоснование

- **Заголовки до выжимки, а не выжимка после чтения:** выжимка до 2000
  знаков с адресами и числами стоила бы ~2000 знаков квоты за прогон (два
  прогона в сутки) и требовала бы резки под 500 байт; заголовки — ~300
  знаков за прогон при `limit` 5, без резки, и показанное совпадает с
  сохранённым.
- **Остановка, а не продолжение по-английски:** частичный перевод даёт
  смешанную выжимку, а на входе продолжать нечем — русский запрос без
  перевода находит пустоту.
- **Язык страницы, а не заголовок браузера:** посетитель русской страницы с
  английским браузером получил бы английскую выжимку; разбор
  `Accept-Language` — механизм, которого никто не просил.
- **Без своего счётчика:** учёт поставщика не наблюдаем снаружи (429 после
  ~90 знаков), локальное число лгало бы увереннее, чем честное «неизвестно».

## Последствия

### Чего это стоит

- **5000 знаков в сутки на всю установку** — квота анонимная, на адрес VPS;
  ~330 знаков за прогон при `limit` 5 → порядка 15 прогонов в сутки, из
  них 6 забирает планировщик. Остатка не видно: узнаём по 429.
- **При исчерпании день 19 перестаёт давать результат вовсе** — не только
  по-русски: цепочка останавливается с `quota_exhausted` до сброса квоты,
  плановые прогоны того же дня падают так же.
- **Ещё один контейнер:** семь мест конвейера (`ci.yml`, `deploy.yml`,
  `compose.yml`), страж сетей, образ в GHCR, четвёртая копия модуля
  JSON-RPC — расхождение найдёт только живой прогон.
- **Ещё один внешний поставщик в цепочке:** сегодня четыре шага зависят от
  одного (HN); теперь от двух — лёг MyMemory, лежит день 19.
- **Цепочка длиннее:** шесть шагов вместо четырёх, до 21 последовательного
  запроса поставщику за прогон (1 + 20 заголовков), задержка не измерена.
- **Инструмент виден и модели дня 20** через общий реестр: её вызов
  `text.translate` на 20 строк по 500 байт тратит квоту суток за один
  круг — и день 19 остаётся без результата. Ограды нет; это тот же класс
  инъекции через результаты инструментов, что назван в ADR
  `2026-09-28-0736`, «Последствия».

### Что этим не решается

- **Качество машинного перевода никто не проверяет.** «Протокол MCP» →
  «mCP protocol» — уже на живом примере; термин, переведённый неудачно,
  уводит поиск не туда, и цепочка честно вернёт не те новости или пустоту.
  Заголовки на экране могут быть искажены так же.
- Кириллица ≠ русский: украинский или болгарский запрос уйдёт как `ru|en`.
- Заголовок не на английском уйдёт как `en|ru` — что вернёт поставщик, не
  проверено.
- Форма ответа 429 может измениться молча; правило про `MYMEMORY WARNING` —
  страховка, не контракт.
- Расхождение `MAX_TASK` 600 и `query` 80 остаётся: длинный русский запрос
  переведётся и упадёт на поиске, как сегодня падает без перевода.

Положительное одно: день 19 отвечает на русский запрос по-русски, и
сверка `sha256` при этом не теряет смысла.

## Альтернативы рассмотрены

- **Готовый сервер MCP (DeepL, Lara, translate-mcp)** — ключ, чужие
  зависимости за границей ADR `2026-09-23-1227`, проверка по ADR
  `2026-09-08-0205`; владелец отклонил.
- **Перевод моделью через роутер (класс `translate`)** — платный ключ; смысл
  дня 19 — нулевой расход модели.
- **Перевод выжимки после `file.read`** — см. «Обоснование», первый пункт.
- **`Accept-Language` как источник языка** — см. «Обоснование», третий
  пункт.
- **Автоопределение языка поставщиком** — для `get` не документировано,
  вживую не проверено.
- **Поле `lang` во входе запуска или в `jobs.json`** — конфигурируемость,
  которой не просили; появится с первой страницей не на русском.
- **`de=<email>` ради 50 000 знаков в сутки** — почтовый адрес в каждом
  запросе к третьей стороне; **владельцу**, если 5000 окажется мало.
- **`ip=<адрес посетителя>` ради квоты на посетителя** — адрес посетителя
  уходит третьей стороне; против духа I-10.
- **Продолжать по-английски с пометкой при отказе перевода** — см.
  «Обоснование», второй пункт.
