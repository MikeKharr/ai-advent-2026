# [2026-10-20 16:21] Ключ выкатки стенда samui-villas — forced command закрытого списка

Файл: `agent_docs/adr/2026-10-20-1621-samui-test-forced-command.md`

## Статус

Предложено. Принимает владелец.

## Контекст

На общей машине появляется четвёртый compose-проект — стенд `samui-test` проекта `MikeKharr/samui-villas` (`~/samui-villas/deploy/test/`, тот же пользователь `advent`). Решение о стенде принято в том репозитории: ADR стенда samui-villas («Стенд `test.velamui.com`, роботы и точки входа стенда и прода», файл `…-stand-robots-entry-points.md` там), П4. Стенд выкатывается **без человека** — на каждый мерж в `main` samui-villas, ключом ssh из GitHub Environment `stand`. Этот ADR samui-villas требует, чтобы ключ стоял в `authorized_keys` строкой `restrict,command="<скрипт закрытого списка>"`, а скрипт жил здесь: машина и пользователь `advent` — этого репозитория (ADR `2026-09-07-1800`, `2026-09-22-0611`, п. 4), и всё, что исполняется от его имени без человека, ревьюится здесь.

Ключ без `command=` — shell `advent` на каждый push чужого репозитория, то есть доступ ко всем проектам машины: `advent`, `zpq` и будущему проду `samui`.

## Решение

1. Скрипт `deploy/samui-test-deploy.sh` — forced command ключа выкатки стенда. Выкатка этого репозитория (`git reset --hard origin/main` в `~/ai-advent-2026`) кладёт его на сервер; публичную часть ключа в `~/.ssh/authorized_keys` кладёт владелец строкой `restrict,command="/home/advent/ai-advent-2026/deploy/samui-test-deploy.sh" ssh-ed25519 …`.
2. **Закрытый список — один проход без выбора:** вход в GHCR, pull образа `ghcr.io/mikekharr/samui-villas` по digest, logout, файлы стенда (`compose.yml`, `Caddyfile`, `smoke.mjs`) из этого образа, `postgres`, миграции, пересев, `app` и `caddy`, дымовая проверка, `ps`. Глаголов нет: присланная строка выбирает только образ.
3. **Снаружи — только digest:** `SSH_ORIGINAL_COMMAND` обязан быть ровно `sha256:<64 hex>`; иначе отказ (код 64) до первого вызова docker. Проект (`-p samui-test`), каталог и файл compose заданы в скрипте.
4. **GHCR — эфемерный `GITHUB_TOKEN`** прогона samui-villas (`packages: read`) первой строкой stdin; вход во временный каталог конфигурации docker, `logout` и удаление сразу после pull. `~/.docker/config.json` пользователя `advent` не трогается; долгоживущего токена на хосте нет.
5. **Чистое окружение:** каждый вызов docker — через `env -i` с фиксированными `PATH` и `HOME`. Compose берёт переменную из окружения процесса раньше, чем из `.env` проекта, и без `env -i` имя из окружения `advent` (ключ модели адвента) подменило бы значение стенда.
6. Держатель — `test/samui-test-deploy.test.js` (шаг «Данные страницы прогресса» в `docs-guard.yml` гоняет `test/*.test.js`): отказы прогоном скрипта, `env -i` и привязка к проекту — по тексту.

Закрытый список **команд агента** (`/day-cycle`, фаза 9; `.claude/settings.json`) этим решением не меняется: ключ выкатки — не агент, его границу держит sshd, а не allowlist харнесса.

## Обоснование

- Forced command, а не shell с договорённостью: sshd подменяет любую присланную команду скриптом, `restrict` снимает проброс портов, агента и pty. Утечка ключа даёт ровно этот проход над `samui-test`, не `advent` и не `zpq`.
- Файлы стенда — из образа, а не из ssh: если бы compose приходил в stdin, ключ решал бы, что исполнить на хосте (`privileged`, сокет Docker), и forced command ничего бы не сужал. Образ собирает и публикует только `main` samui-villas, где compose судит страж `deploy-guard.mjs` (ADR samui-villas, П14).
- Клон samui-villas на сервере не заводится: репозиторий приватный, ключ чтения к нему стал бы ещё одним секретом на хосте — тот же довод, что у выкатки `zpq-ai` («на сервере нет ни клона этого приватного репозитория, ни ключа чтения к нему»).

## Последствия

Положительные:

- Ключ выкатки стенда не даёт shell и не трогает проекты `advent`, `zpq`, `samui`.
- Токен GHCR живёт секунды и не ложится в общую конфигурацию docker пользователя.

Отрицательные и предупреждения:

- **Доверие к compose стоит на образе.** Скрипт исполняет compose из образа с присланным digest; образ в пакете `ghcr.io/mikekharr/samui-villas` может опубликовать не только `main` — любой workflow ветки samui-villas с `packages: write`. Чтобы им воспользоваться, нужны и такой образ, и ключ выкатки (он только в Environment `stand`, политика веток — только `main`). Тома и сети compose называет сам: compose из чужого образа мог бы назвать том прода. Это граница, а не держатель.
- **Изоляция операционная, не защитная:** стенд делит демона Docker с адвентом; root на хосте этот скрипт не сдерживает (та же цена, что у ADR samui-villas, «Последствия»).
- **Связь с раскладкой образа samui-villas:** скрипт ждёт файлы в `/app/deploy/test/` образа. Её перенос там — правка здесь тем же порядком.
- Выкатка адвента пересоздаёт скрипт из `main` при каждом push; правка скрипта — PR класса A здесь (`deploy/**` — защищённый путь).
- Стенд не гейт мержа ни здесь, ни в samui-villas: красная выкатка стенда — issue там, не стоп здесь.

## Альтернативы рассмотрены

- Глаголы `pull`, `up`, `migrate`, `seed`, `ps`, `logs` по отдельности (формулировка П4-а ADR samui-villas) — отклонено в пользу одного прохода: тот же объём, но ssh-команда выбирает только образ, а порядок шагов не может нарушить присылающий.
- Compose и Caddyfile через stdin или `rsync` — отклонено: ключ сам решал бы, что исполняется на хосте.
- Клон приватного samui-villas на сервере с ключом чтения — отклонено: ещё один долгоживущий секрет на общем хосте.
- Загрузка файлов по API GitHub на присланный коммит с проверкой «предок `main`» — сильнее по доверию (compose не зависит от образа), но присылаемых значений два, нужен `curl` с разбором ответа API и токен с `contents: read`; отклонено как сложнее при той же цене утечки ключа (без токена чтения пакета ключ один не вытянет новый образ).
- Скрипт в репозитории samui-villas — отклонено: от имени `advent` исполнялся бы код, который этот репозиторий не ревьюит.
