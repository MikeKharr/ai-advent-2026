# [2026-09-07 15:25] Node 22 без runtime-зависимостей вместо Hono + TypeScript

## Статус

Принято

## Контекст

Изначально выбран стек Node + Hono + vanilla TypeScript. При подготовке выяснилось, что в песочнице агента заблокированы npm и PyPI: `npm install hono` возвращает `403 Forbidden`, `pypi.org` — то же. Установить зависимости невозможно, а значит невозможно запустить и протестировать код перед передачей владельцу.

## Решение

Собрать приложение на Node 22 без единой runtime-зависимости:

| Потребность | Встроенное | Заменяет |
|---|---|---|
| HTTP-сервер и SSE | `node:http` | Hono / Express |
| Вызовы Anthropic API | глобальный `fetch` | `@anthropic-ai/sdk` |
| Тесты | `node:test`, `node:assert` | Vitest / Jest |
| Кэш и суточные счётчики | `node:sqlite` | Redis / better-sqlite3 |
| Загрузка переменных | `process.loadEnvFile()` | dotenv |

Типобезопасность — через JSDoc-аннотации и `checkJs` в `tsconfig.json`, проверка `npx tsc --noEmit` в CI, где сеть доступна.

## Обоснование

Главный аргумент — возможность проверки. При зависимостях агент отдал бы владельцу код, который ни разу не запускался; первый запуск был бы на машине владельца. Без зависимостей агент запускает и тестирует всё до передачи.

Побочные выгоды: образ Docker не ломается при недоступности реестра, отсутствует supply-chain поверхность на сервере с платным API-ключом, и «ноль зависимостей, ~450 строк, без сборки» — более сильное описание для челленджа, чем настройка фреймворка.

Hono на трёх маршрутах экономит порядка тридцати строк роутинга. Это не окупает потерю возможности тестировать.

## Последствия

Положительные:

- код проверен до передачи владельцу;
- нет шага сборки и нет `npm install` в проде;
- меньше поверхность атаки на сервере с ключом.

Отрицательные:

- нет синтаксиса TypeScript, а владелец хотел практики TS для HBK.SG;
- JSDoc многословнее аннотаций типов;
- `node:sqlite` в Node 22 помечен экспериментальным и может измениться;
- ручная работа с `node:http` там, где фреймворк дал бы готовое.

## Альтернативы рассмотрены

- **Hono + TypeScript как планировалось.** Даёт практику TS, но код уезжает владельцу непроверенным.
- **Next.js.** Совпадает со стеком HBK.SG, но избыточен для трёх маршрутов и усугубляет ту же проблему с зависимостями.
- **Python FastAPI.** PyPI заблокирован так же, преимуществ нет.
