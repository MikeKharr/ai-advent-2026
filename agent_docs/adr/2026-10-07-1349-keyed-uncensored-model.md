# [2026-10-07 13:49] Модель без отказов на ноутбуке владельца — доступ только по ключу

Файл: `agent_docs/adr/2026-10-07-1349-keyed-uncensored-model.md`

## Статус

Предложено. Класс будущей реализации — A (`router/config/**` защищённый путь,
ключи и разрешения); гейт `compliance` обязателен, вето — по защите от
злоупотреблений.

Решения владельца 2026-10-07, дословно, в порядке получения:

1. «Для чего ставим модель без цензуры?» → «На сайте, но только для меня».
2. «Какую сборку качать?» → «huihui Q6_K, 22,4 ГБ».
3. Уточнение: «по п2 можно дать для всех (не ограничивать только мной —
   владельцем)».
4. Окончательно: «давайте делать только по ключу, действительно не нужно
   оставлять доступ для всех (хотя модель и доступна публично)».

Дополняет ADR `2026-09-08-1748` (§1 механизмы выбора, §10 ключи приложений),
`2026-09-08-1824` (явный выбор провайдера) и `2026-09-15-1448` (поле
`explicitOnly`); ничего в них не заменяет.

## Решение

Модель `hf.co/huihui-ai/Huihui-Qwen3.8-27B-abliterated-GGUF:Q6_K` подключается
к роутеру вторым провайдером на той же Ollama ноутбука, что `mac-qwen3`, и
достижима **только с ключом доступа**, который выдаёт владелец. Посетитель без
ключа модели не видит ни в одном списке, а подмена `model`/`provider` в запросе
получает отказ **до** обращения к роутеру. Две преграды, каждая со своим тестом:

### 1. Роутер: провайдер виден одному приложению

Запись `mac-qwen3-abliterated` в `router/config/providers.json`: `kind: ollama`,
тот же `baseUrl`, что у `mac-qwen3`, `maxConcurrency: 1`, `explicitOnly: true`,
цена 0, и **новое поле `apps: ["agents"]`** — список идентификаторов приложений
(`router/config/apps.json`), которым провайдера можно назвать по имени.

Проверка — в ветви явного выбора (`router/src/router.js`, `explicit`) и в
`providerLimits`: приложение не из списка получает `refused` со стадией
`policy` и текстом «провайдер доступен не этому приложению», а в `/v1/models`
записи не видит. Сегодня такой границы нет: явный `provider` проверяется
только по ярусам класса (ADR `2026-09-08-1824`, п. 3), и класс `news_answer`
приложения `day5` включает ярус `self-hosted` — без поля `apps` день 5 мог бы
вызвать новую модель прямым `provider`, минуя любой ключ. Поле закрывает это
на стороне роутера, а не в списках страниц.

Общая ёмкость ноутбука уже держится: `router/src/health.js:26` считает
`inflight` по хосту из `baseUrl`, и две записи на одном адресе делят один слот
— две генерации на ноутбуке параллельно не пойдут (проверено по исходнику).

### 2. Сервис агентов: ключ доступа до создания запуска

- Переменная **`MODEL_KEYS`** в `deploy/agents.env`: `имя:значение` через
  запятую (`mike:…,guest1:…`). Имя — метка для журнала и лимита, не секрет;
  значение — 24 случайных байта в base64url, без `:` и `,`.
- Запрос с `model: mac-qwen3-abliterated` обязан нести заголовок
  **`x-model-key`**. Сверка — по свёрткам за постоянное время, форма
  `days/day22/limits.js` (`EVAL_KEY`, ADR `2026-10-05-1130`). **Пустая или
  отсутствующая `MODEL_KEYS` — возможности нет вовсе**: модель не в списке
  никому, любой заголовок, включая пустой, — отказ.
- Без заголовка или с чужим значением — `403` с текстом «модель доступна
  только по ключу», роутер не вызывается. Предъявленное значение не принимает
  ни одна функция журнала (структурный запрет, образец
  `agents/src/control/key.js`).
- Порядок: лимитер дня на адрес → ключ → суточный лимит на ключ → роутер.
  Ключ меняет, **кому** доступна модель, а не что стоит раньше (I-4): бюджет
  приложения `agents` и окна дня остаются как есть.

### 3. Экран

Модель не добавляется в списки `MODELS`/`LAYERED_MODELS` сданных дней: дни
11 и 13–15 кладут переписку в профили, которые открыты любому посетителю
(`invariants.md`, «С дня 11…»), и ответы модели без отказов стали бы читаемы
всем. Экран — отдельная единица по образцу дня 22 («пульт без сессий и
переписки», ADR `2026-10-04-0735`): поле ключа, поле запроса, ответ; модель
одна и зашита, списка нет. Тексты живут только в памяти запусков `agents`
(`runs.js`, TTL 10 минут после завершения) и в браузере. Где именно экран и
помнить ли ключ в браузере — развилки владельцу ниже.

### 4. Лимиты и расход

Деньги — 0 (цена записи), поэтому бюджет приложения `agents` ($10/сутки) этот
трафик не тратит. Бюджет модели — **время ноутбука**: один слот хоста на оба
провайдера, значит запрос держателя ключа задерживает посетителя `mac-qwen3`
на свой дедлайн профиля `laptop`. Поэтому **суточный потолок на ключ — 30
запусков**, в памяти `agents` (сбрасывается перезапуском — та же честная
граница, что у I-5), отказ `429` с датой сброса. Число 30 не измерено.

Память ноутбука: 128 ГиБ (проверено `sysctl`), сборка Q6_K — 22,4 ГБ (карточка
модели), KV-кэш `q8_0` (проверено `launchctl print`). Обе модели в памяти
помещаются; переключение между ними, если Ollama выгрузит одну, стоит
загрузки ~20 с — она уже в дедлайне профиля (ADR `2026-09-08-1748`,
«Таймауты»). `OLLAMA_MAX_LOADED_MODELS` в службе не задан.

### 5. Журнал

Роутер пишет `provider` на каждый вызов и строку учёта без промптов (ADR
`2026-09-08-1748`, п. 8) — без изменений. `agents` добавляет в событие
создания запуска **имя ключа** (`keyName`), значение — никогда. Лог Ollama на
ноутбуке — строки `[GIN] … | адрес | POST "/api/generate"` без тел (проверено
по `/opt/homebrew/var/log/ollama.log`). Итого промпты и ответы держателей
ключа нигде не хранятся дольше 10 минут после завершения запуска.

### 6. Ключи — только руками владельца

Новый секрет на сервере — владелец (`AGENTS.md`, «Автономность»); закрытый
список `/day-cycle` `MODEL_KEYS` не знает и копировать его агенту некуда.
Выдача, отзыв и ротация — правка строки `MODEL_KEYS` в `agents.env` и
`docker compose up -d agents` (перечитывает `env_file`), обе — владелец.
Отзыв одного имени не трогает остальных. Перезапуск теряет незавершённые
запуски всех дней, идущих через `agents`, — цена названа.

### 7. Что проверяет реализация (тест-приманки)

- `router/test`: явный `provider: mac-qwen3-abliterated` от `day5` и `smoke`
  → `refused`/`policy`, адаптер не вызван; от `agents` — вызов уходит;
  `/v1/models` для `day5` записи не содержит. Мутация: убрать проверку `apps`
  — красный.
- `agents/test`: запуск с моделью без заголовка, с пустым, с чужим → `403`,
  роутер не вызван; с верным → роутер вызван с этим `provider`; пустая
  `MODEL_KEYS` + любой заголовок → `403`; 31-й запуск ключа за сутки → `429`.
  Мутации: убрать сверку, убрать ветвь пустой переменной, убрать счётчик —
  каждая красная.
- Живая проверка после выкатки: запрос без ключа с подменённым `model` через
  публичный адрес → отказ; с ключом владельца → ответ с `provider:
  mac-qwen3-abliterated#1` в поле ответа.

## Обоснование

Ключ проверяет сервер, не интерфейс: UI отдаёт только то, что сервис разрешил,
а прямой запрос к API с подменой поля упирается в ту же проверку. Две преграды,
а не одна, потому что они защищают от разного: поле `apps` — от любого другого
приложения роутера (сегодня, в будущем, при ошибке в `agents`), ключ — от
посетителя публичного адреса. Отдельный экран — потому что все существующие
списки моделей живут в сданных днях с хранением переписки.

Довод «модель и так лежит на Hugging Face» ответственности за выдачу с
`zpq.ai` не снимает: там лежат веса, здесь — работающий сервис под доменом
владельца, и каждый ответ исходит от него.

**Проверено лично** 2026-10-07: устройство выбора провайдера, поле
`explicitOnly`, ярусы классов и отсутствие границы «приложение → провайдер»
(`router/src/router.js:146-176`, `router/src/config.js`); общий слот хоста
(`health.js:26,51`); авторизация роутера по ключам приложений без ролей
(`service.js:36-44`); карточка модели: Apache-2.0, база `Qwen/Qwen3.8-27B`,
Q6_K 22,4 ГБ, предупреждения «safety filtering has been significantly
reduced», «Users must ensure their usage complies with local laws»; лицензия
базы — Apache-2.0 без пунктов о допустимом использовании; политика контента
Hugging Face запрещает контент, продвигающий разработку оружия, CSAM и
вредоносный код, — к репозиторию весов, не к развёртыванию; память и
переменные службы Ollama; форма лога Ollama.

Неподтверждённым остаётся всё, что собрано по документации поставщика:
умолчание `OLLAMA_MAX_LOADED_MODELS`, размер `qwen3.8:27b` на диске и реальная
скорость Q6_K на M3 Max — Ollama на ноутбуке в момент проверки не отвечала
(служба не поднимается: Tailscale остановлен, `bind: can't assign requested
address` в логе; это же значит, что `mac-qwen3` посетителям сейчас недоступен —
смежная находка, не часть этого решения). Юридические оценки ниже — не
консультация, а перечень того, что владельцу стоит проверить.

## Последствия

Положительные: модель недостижима без ключа ни из UI, ни прямым запросом, ни
другим приложением роутера; расход денег нулевой; граница держится тестами, а
не внимательностью (I-14).

Отрицательные:

- **Ответственность за выдачу — на владельце домена.** Держатель ключа
  может получить инструкции по оружию, наркотикам, вредоносному коду, тексты
  сексуального характера с участием несовершеннолетних; у модели нет отказов
  по построению, и ни системный промпт, ни фильтр этого не меняют. Ключ
  ограничивает круг людей, не содержание. Выдал ключ — отвечаешь за того, кому
  выдал. Юрисдикции три: сервер в Таиланде (Computer Crime Act), ноутбук там,
  где владелец (сейчас — РФ, законы о запрещённой информации), домен владельца.
  Утечка ключа у приглашённого делает модель публичной до отзыва, а отзыв —
  ручное действие владельца с перезапуском `agents`.
- **Ноутбук — общий ресурс.** 30 запусков на ключ в сутки при `maxConcurrency`
  1 на хост — это до 30 задержек посетителей `mac-qwen3`; второго слота нет.
  Модель на ~22 ГБ плюс KV держит память постоянно при `keep_alive 30m`.
- **Третья копия логики «ключ оператора».** После `EVAL_KEY` дней 22–25 и
  `CONTROL_KEY` это третья реализация сверки ключа из окружения; общий модуль
  не вводится намеренно (дни сданы), и три места ротации — три файла.
- **Ещё один секрет без держателя ротации.** I-3 «ротация при подозрении» для
  `MODEL_KEYS` держится владельцем; никакого напоминания нет.
- **Экран — новая единица выкатки** (Dockerfile, Caddyfile с
  `header_up X-Forwarded-For`, `dayN.env` с копией `AGENT_KEY`): больше 40
  минут работы над опытом посетителя — только по решению владельца.
- **Поле `apps` — вторая ось разрешений рядом с `classes`.** Приложению
  разрешены классы, провайдеру — приложения; читать конфигурацию придётся в два
  файла. Записи без поля ведут себя как прежде (нет поля — нет ограничения),
  так что тихо ничего не меняется, но и забыть поле у новой закрытой модели
  легко.
- **Перезапуск `agents` для отзыва ключа** обрывает запуски всех дней, идущих
  через этот сервис.

## Решения владельцу

1. **Где экран.** Рекомендация — новая единица по образцу дня 22, без
   хранения переписки. Альтернатива — вписать модель в список дня 11 или
   13–15 под ключ: дешевле (образец ADR `2026-09-16-1038`), но ответы лягут в
   открытые профили, читаемые любым посетителем; не рекомендую.
2. **Один ключ или по ключу на человека.** Рекомендация — именованные ключи
   с первого дня (`имя:значение`): отзыв одного не трогает остальных, журнал
   и потолок — по имени. Один общий ключ — частный случай «только владелец»
   (одна запись `mike:…`); формат тот же, менять потом не придётся.
3. **Помнить ли ключ в браузере.** Рекомендация — нет: ключ живёт в памяти
   вкладки, после перезагрузки вводится заново; это цена одной вставки.
   `localStorage` — утечка через любой общий компьютер, без решения не
   делается.
4. **Потолок 30 запусков на ключ в сутки** — подтвердить или назвать своё
   число; измерить не на чем.

## Альтернативы рассмотрены

- **(а) Публично как есть.** Отклонено владельцем (решение 4); и по существу:
  модель без отказов на публичном адресе под доменом владельца — ответственность
  без контроля круга лиц.
- **(б) Публично с мерами.** Системный промпт «не отвечай о…» — не защита:
  отказы сняты на уровне весов, промпт — просьба, которую модель исполняет не
  лучше любой другой, а задание посетитель пишет свободным текстом. Фильтр
  входа/выхода: локальный классификатор — вторая модель на том же ноутбуке и
  второй дедлайн; облачный (`guard_prompt` ловит инъекции, не темы) — платный
  вызов на каждый запрос и отправка текста посетителя поставщику ради модели,
  выбранной за локальность. Лимиты на адрес, предупреждение на экране, журнал
  — не мешают получить запрещённое, только реже и с записью. Ни одна мера не
  закрывает содержание; отклонено.
- **(в) Только владелец** — частный случай решения: одна запись в
  `MODEL_KEYS`.
- **Второй ключ приложения роутера (`agents-keyed`)** вместо поля `apps`:
  роутер различал бы «запуск по ключу» своим секретом. Отклонено: ещё один
  секрет владельцу, а решение, какой ключ предъявить, принимает тот же код
  `agents` — точка отказа не сдвигается.
- **Список разрешённых провайдеров у приложения** (`apps.json`) вместо поля у
  провайдера. Эквивалентно; отклонено, потому что закрытость — свойство
  модели, и читаться она должна в её записи рядом с `explicitOnly`.
- **Отдельный процесс Ollama или отдельный ноутбучный провайдер с другим
  `hostId`.** Дал бы второй слот и параллельные генерации; отклонено: один
  GPU, вторая генерация замедлит обе (комментарий записи `mac-qwen3` в
  `router/config/providers.json`: «модель на 27B занимает машину целиком»).
