# [2026-09-07 23:50] Набор скиллов addyosmani/agent-skills внутри фаз процесса 2030ai

Файл: `agent_docs/adr/2026-09-07-2350-adopt-addyosmani-agent-skills.md`

## Статус

Принято (решение владельца, сессия 2026-09-07)

## Контекст

Проект работает по процессу шаблона 2030ai: AGENTS.md, инварианты, ADR, dev-history,
snapshot, роли агентов, ветки+PR. Владелец поручил установить набор
`addyosmani/agent-skills` (25 скиллов: spec-driven development, planning, incremental
implementation, TDD, code review, debugging и т.д.) и использовать эти скиллы в первую
очередь при разработке спецификаций, кодинге и тестировании — сохранив верхнеуровневый
процесс 2030ai.

## Решение

1. **Установка в репозиторий** по проектной конвенции: канонический источник —
   `.agents/skills/<name>/SKILL.md`, зеркала `.claude/skills`, `.codex/skills`,
   `.cursor/skills` — симлинки. Установлены все 25 скиллов
   (`npx skills add addyosmani/agent-skills`, коммит источника `48cb116`);
   версии зафиксированы в `skills-lock.json`.
2. **Общие чек-листы** из корневого `references/` репозитория-источника скопированы в
   `.agents/references/` — скиллы ссылаются на них как `../../references/*.md`
   (установщик их не переносит, issue addyosmani/agent-skills#361).
3. **Разделение уровней.** Верхнеуровневый процесс не меняется: AGENTS.md, инварианты,
   ADR/dev-history/snapshot, роли (reviewer/compliance), ветки+PR, Conventional Commits.
   Скиллы применяются внутри фаз: спецификация — `spec-driven-development`,
   `planning-and-task-breakdown`; кодинг — `incremental-implementation`,
   `test-driven-development`; ревью — `code-review-and-quality` в дополнение к ролям
   `reviewer`/`compliance`, не вместо них. При конфликте инструкций скилла с правилами
   проекта приоритет за правилами проекта (зафиксировано в AGENTS.md).
4. **Vendored-материал не редактируется.** Файлы под `.agents/` не правятся под проектный
   стиль (правки сломали бы обновление); они исключены из markdownlint
   (`.markdownlint-cli2.jsonc`). Обновление набора — `npx skills update` отдельным PR.

## Обоснование

- Скиллы кодируют операционные практики (как писать спеку, как вести TDD-цикл, по каким
  осям ревьюить), которых в шаблоне 2030ai нет: он задаёт артефакты и роли, а не технику
  выполнения. Слои дополняют друг друга.
- Установка в репозиторий, а не глобально: версионируется, воспроизводима любым агентом
  (Claude Code, Codex, Cursor) и переносима в HBK.SG — что является целью проекта.
- Все 25, а не подмножество: скиллы активируются по контексту задачи и не мешают,
  пока не нужны; выборочная установка сэкономила бы немного места ценой дыр в цикле.

## Последствия

Положительные:

- полный цикл define→plan→build→verify→review доступен как единый набор практик;
- одинаковые практики у всех агентов, работающих с репозиторием;
- обкатка переносимой конфигурации для HBK.SG.

Отрицательные:

- ~25 чужих документов в репозитории (vendoring) и их сопровождение при обновлениях;
- пересечения со своими правилами (их скиллы про git-workflow, ADR, документацию) —
  разруливаются приоритетом правил проекта, но требуют внимательности;
- слэш-команды исходного репозитория (`/spec`, `/build`, …) установщиком не переносятся —
  скиллы активируются по описанию задачи, а не командой.
