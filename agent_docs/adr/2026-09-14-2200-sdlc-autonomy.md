# [2026-09-14 22:00] SDLC: мерж и выкатка по консенсусу гейтов, объём под контролем владельца, витрина Drive упразднена

Файл: `agent_docs/adr/2026-09-14-2200-sdlc-autonomy.md`

## Статус

Предложено. Принимает владелец.

Заменяет `agent_docs/adr/2026-09-07-1510-git-source-of-truth-drive-mirror.md`
в части витрины Google Drive. Часть «источник истины — git» сохраняется и
остаётся в I-11.

Уточняет ADR `2026-09-13-1800`: п. 3 «человеческих гейтов остаётся два» и
п. 5 «деструктивные действия по-прежнему спрашивают» в части `gh pr merge`.
Ярусы моделей, предзагрузка скиллов, классы изменений и вето `compliance`
там в силе.

Записи истории и принятые ADR, упоминающие Drive, не правятся (I-12);
единственная правка старого ADR — строка «Заменено на …» в его статусе,
как уже делалось для `agent_docs/adr/2026-09-07-1954-web-search-strict-json.md`.

## Контекст

Решения владельца от 2026-09-11 — пять, и они не пересматриваются здесь:
витрина Drive упраздняется; команды выполняются без запроса разрешения;
мерж и выкатка идут автономно при консенсусе гейтов; объём работ — под
контролем владельца; окружение `production` и обязательные проверки на
`main` затягиваются так, чтобы красный CI не смержил и агент. ADR фиксирует
их как норму проекта, называет цену и способ внедрения.

Что к этому привело:

- **Человеческий гейт на выкатку стал формальным.** С 2026-09-10 владелец
  просил не спрашивать его про команды и мерж («выполняй, если есть
  консенсус»). Правило автомержа жило только в памяти оркестратора: PR #65,
  пытавшийся записать его в правила проекта, был закрыт без мержа — защита
  среды не дала агентам самим переписать человеческий гейт. 2026-09-11
  владелец сам попросил закрепить автомерж в SDLC («проверка сейчас
  формальная»). Норма ниже — перенос этой памяти в репозиторий.
- **Объём вышел из-под контроля.** За ночь 2026-09-10/11 из 40 PR 16
  выросли из находок ревьюеров, которых владелец не запрашивал; атлас
  пришлось заморозить (PR #91,
  `agent_docs/development-history/2026-09-14-2100-atlas-frozen-load-timeout-code.md`).
  Автономия гейтов без границы объёма превращает каждую находку в PR.
- **Витрина Drive не велась.** Пункт «Синхронизация решений в Google Drive»
  висит в `agent_docs/backlog.md` с первого дня; отрицательное последствие
  из ADR `2026-09-07-1510` («синхронизация — ручной шаг, и она будет
  забываться») сбылось полностью. Публичный репозиторий и атлас
  (`challenge.zpq.ai/atlas/`) закрывают задачу «показать решения человеку
  без кода» лучше устаревшей копии. 2026-09-11 оркестратор отправил витрину
  в корзину Drive (`00-INDEX.md`, `decisions/`, `history/`, `protocol/`);
  посторонние папки владельца в корневой папке «AI advent Dev» не тронуты.
  Всё содержимое витрины целиком есть в git.
- **Разрешения рвали автономные прогоны.** Точечный allowlist в
  `.claude/settings.json` (ADR `2026-09-13-1800`, п. 5) не покрывает
  живую работу: каждая новая форма команды — окно подтверждения владельцу,
  который «команды всё равно не очень понимает». С 2026-09-11 у владельца
  локальный `.claude/settings.local.json` с `allow: ["Bash"]`.
- **GitHub сейчас.** Защита `main` (проверено по API 2026-09-11): PR
  обязателен, обязательная проверка одна — `guard`; ветка должна быть
  актуальна (`strict`); линейная история; force-push запрещён; обход
  администратором не запрещён (`enforce_admins: false`), но `gh pr merge
  --admin` в `deny`. Workflow `ci` и `markdownlint` фильтруют пути: PR вне
  путей их не запускает, а обязательная проверка, которая не отчиталась,
  блокирует мерж навсегда, — поэтому они и не обязательны, и красный `ci`
  сегодня кнопку мержа не запирает. Окружение `production` ограничено
  веткой `main` (политика веток `main`, сделано оркестратором 2026-09-11
  через `gh api`).

Допущения, принятые в этом ADR:

1. Имя файла — по проектным часам репозитория, как у документов, влитых
   сегодня (последний — `2026-09-14-2100`), а не по календарной дате
   решений: иначе ADR встанет раньше `2026-09-13-1800`, которое уточняет.
2. Порядок правил разрешений Claude Code: `deny` сильнее `ask`, `ask`
   сильнее `allow`. Значит `allow: ["Bash"]` не снимает `ask` на
   `git push --force` и `deny` на `gh pr merge --admin`. Проверяется первым
   же force-push: ожидается окно подтверждения.
3. Условие «очередь выкатки пуста» сохранено, как поставил владелец, хотя с
   #71 `detect` считает изменения от последней успешной выкатки и отменённый
   ожидающий запуск — не потеря (`agent_docs/operations.md`, «Очередь
   выкаток»). Условие страхует не корректность, а ожидание.
4. Класс C «сверяет оркестратор по списку файлов» означает: сверяет любой
   экземпляр, кроме автора, — оркестратор по умолчанию.

## Решение

### 1. Витрина Google Drive упраздняется

- Git — единственный источник истины для решений и истории. Витрины нет.
- Убираются правила её поддержки: содержание `agent_docs/guides/drive-sync.md`;
  шаг 5 роли `docs` и слова «витрина в Google Drive» в её описании и
  владении; строка реестра и схема протокола в
  `agent_docs/guides/agent-roles.md`; строка в `agent_docs/index.md`;
  термин «Витрина» и Google Drive в списке внешних сервисов в
  `agent_docs/glossary.md`; открытый пункт в `agent_docs/backlog.md`
  (переносится в `backlog-closed.md` со ссылкой сюда); упоминания в
  `README.md` (структура каталогов и абзац «Источник истины»).
- Инварианты переформулируются без Drive, нумерация I-1…I-12 сохраняется —
  на номера ссылаются документы и атлас: I-3 — «Ключ не передаётся в чат,
  в issue и в PR. Ротация — при любом подозрении на утечку»; I-11 —
  «Источник истины для решений — git».
- **Файл `agent_docs/guides/drive-sync.md` не удаляется, а сводится к
  заглушке** из нескольких строк: витрина упразднена этим ADR, правил нет,
  файл оставлен потому, что на путь ссылаются неизменяемые документы. Это
  единственное отступление от буквы «drive-sync.md убирается», и вот
  почему: проверка `node atlas/build.js --check` — обязательный шаг
  `guard` — падает на любой неразрешённой ссылке; при удалении файла она
  даёт 9 находок (проверено), из них 6 — в документах, которые править
  нельзя: ADR `2026-09-07-1510`, ADR `2026-09-13-2000`, запись истории
  `agent_docs/development-history/2026-09-07-1520-project-bootstrap.md`,
  две спецификации дизайна атласа. Остальные три (роль `docs`, индекс,
  глоссарий) правятся. Альтернативы — править принятые ADR (нарушает I-12)
  или учить атлас терпеть удалённый путь (атлас заморожен, PR #91) — хуже.
- В статус ADR `2026-09-07-1510` добавляется строка «Заменено на
  `agent_docs/adr/2026-09-14-2200-sdlc-autonomy.md` в части витрины Drive».
  Атлас читает такие строки и строит ребро замены.
- Не трогается: комментарии в `atlas/lib/vault.js` о «формате
  `drive-sync.md`» для блока происхождения. Формат живёт в коде vault и
  описан в `atlas/README.md`; атлас заморожен.

### 2. Команды выполняются без запроса разрешения

- У владельца локальный, не коммитимый `.claude/settings.local.json`:
  `"permissions": { "allow": ["Bash"] }`. Файл добавляется в `.gitignore`
  (сейчас он там не перечислен — проверено `git check-ignore`).
- Проектный `.claude/settings.json`: `deny` остаётся целиком (чтение
  `.env*`, `git diff --no-index`, `gh pr merge --admin`); `ask` остаётся для
  `git push --force*`, `git push -f*`, `gh run rerun`, `gh run cancel`;
  `gh pr merge *` из `ask` убирается — мерж по консенсусу (п. 3) больше не
  требует клика.
- Оболочка остаётся bash. Запросы разрешений зависят от правил, а не от
  оболочки, и все команды агентов написаны под bash.
- **Риск назван прямо:** `deny Read(./**/.env)` закрывает инструмент Read, а
  не `cat deploy/.env` в Bash. С `allow: ["Bash"]` серверный секрет
  читается в транскрипт одной командой без окна подтверждения. Это
  остаётся дисциплиной, а не механизмом: I-1…I-3, правило «новый секрет —
  только через `deploy/put-secrets.sh` руками владельца» (ADR
  `2026-09-13-1800`, поправка compliance) и обязанность `compliance` искать
  такие команды в ревью. Правило вида `deny Bash(cat *.env*)` не
  добавляется: оно обходится `sed`, `<`, `docker compose config` и создаёт
  ложное ощущение защиты.

### 3. Мерж и выкатка — автономно при консенсусе гейтов

Строка `AGENTS.md` «Два согласования в этом проекте всегда человеческие:
принятие ADR и продакшн-деплой» заменяется. Человеческими остаются:

- принятие ADR;
- изменения гейтов и правил процесса — любой PR, трогающий защищённые пути
  (ниже), сливает только владелец;
- откат прода.

Не консенсус, а повод остановиться и нести владельцу — как и раньше: вето
`compliance`, два круга перепроверки без снятия блокирующих
(`/day-cycle`, фаза 7), развилки продукта.

**Норма автомержа** (до сих пор — память оркестратора; теперь — правило
проекта):

1. Консенсус — явный вердикт каждого гейта класса на текущем head sha:
   `reviewer` — одобрение, `compliance` — без вето (класс A), `design-review`
   — ГОТОВО (при UI). Вердикт на предыдущий head не считается.
2. Перед мержем `gh pr checks N`: все проверки зелёные, ни одна не ждёт;
   очередь выкатки `deploy-production` пуста; без `--admin`, не через API,
   не push в `main`, не веб-интерфейс.
3. Команда: `gh pr merge N --squash --delete-branch --match-head-commit <sha>`
   с телом «Мерж агентом по консенсусу: <гейты>, head <sha>».
   `--match-head-commit` гарантирует, что сливается ровно проверенный
   коммит, а не то, что успело приехать в ветку.
4. Ветка отстала от `main` (`strict` на защите ветки) — обновить её и
   получить повторное подтверждение гейтов на новом head. Зелёный CI после
   обновления — не замена вердикту.
5. Класс C сверяет не автор, а оркестратор (или другой экземпляр), по
   списку файлов PR: только документы и лендинг; ни кода, ни `deploy/`,
   ни workflow, ни `.claude/`, ни защищённых путей. До делегирования
   единственной независимой проверкой метки «C» был клик владельца.
6. Защищённые пути — никогда не класс C, сливает только владелец:
   `agent_docs/invariants.md`, `.claude/**`, `AGENTS.md`,
   `.agents/skills/day-cycle/`, `agent_docs/guides/agent-roles.md`,
   `.github/**`, `deploy/**`, `router/config/**`.
7. После выкатки — проверка живого адреса и уведомление владельцу
   (сейчас — push-уведомление в приложение Claude). Красный `healthz` —
   следующий PR не сливать, откат решает владелец.

Правило переезжает в `AGENTS.md` (раздел «Автономность»),
`agent_docs/guides/agent-roles.md` (схема и абзац о гейтах),
`.agents/skills/day-cycle/SKILL.md` (фаза 9 и «Правила оркестрации»),
`.claude/agents/platform.md` (граничное правило) и строку о согласованиях
в `agent_docs/glossary.md`.

### 4. Объём — под контролем владельца

- Задача, меняющая опыт посетителя — что он видит, читает или делает:
  экран, тексты, поведение, доступность, — при оценке реализации больше
  40 минут выполняется только по решению владельца. Оценивает оркестратор
  до запуска, по полному объёму, без искусственного дробления на куски
  «до 40 минут».
- Прочие задачи — CI, безопасность, тесты, документы — агенты сами не
  открывают. Разрешено только то, что входит в текущую задачу владельца,
  включая блокирующие находки её PR.
- Находки ревьюеров за рамками PR идут в `agent_docs/backlog.md` с пометкой
  «Владельцу» и в работу не берутся (раздел «Не делаем без решения
  владельца» уже заведён в PR #91).
- Исключение — особый режим: владелец объявляет его явно и с рамками; в
  этих рамках агенты берут задачи сами.

Правило живёт в `AGENTS.md` (раздел «Автономность») и в `/day-cycle`
(фаза 1: оценка объёма — критерий выхода).

### 5. GitHub

- Окружение `production` ограничено веткой `main` — сделано 2026-09-11,
  фиксируется как факт. Выкатка из любой другой ветки невозможна, даже
  через `workflow_dispatch`.
- В `ci.yml` и `markdownlint.yml` снимаются фильтры `paths`; в `ci.yml`
  появляется сводная проверка `ci-ok` — задание, которое выполняется всегда
  (`if: always()`), красное при падении или отмене любого из `detect`,
  `test`, `caddyfile` и зелёное, когда матрица `test` пропущена (единиц не
  затронуто). Стабильное имя нужно потому, что имена заданий матрицы
  (`test (router)`) меняются от PR к PR и обязательными быть не могут.
- Обязательными проверками на `main` становятся `guard`, `ci-ok` и `lint`;
  `strict` сохраняется. Красный CI не смержит и агент: `gh pr merge` без
  `--admin` упрётся в защиту ветки. Порядок обязателен: сначала мерж PR CI
  (проверки начинают отчитываться на каждом PR), потом `gh api` на
  обязательные проверки — иначе каждый PR ждёт проверку, которая не
  запускается.
- Код CI — отдельный PR роли `platform`; `.github/**` — защищённый путь,
  сливает владелец.

## Обоснование

- Гейт, который всегда нажимают «да», не защищает, а маскирует: решение о
  мерже уже заключено в ревью, и норма п. 3 делает это явным — с условиями,
  которые можно проверить по PR (вердикты на head sha, тело squash-коммита).
- Объём не контролируется гейтами качества по построению: ревьюер честно
  находит, автор честно чинит, и каждая находка законна. Границу объёма
  может держать только тот, кто платит за него временем и деньгами, —
  владелец. 16 из 40 PR за ночь — измеренная цена её отсутствия.
- Витрина без синхронизации — второй источник, который врёт молча; это
  ровно то, против чего I-11. Удалить честнее, чем держать.
- `allow: ["Bash"]` вместо роста allowlist: каждая новая форма команды —
  окно тому, кто её не читает. Ценность окна равна нулю, шум — реален.
  Механические запреты (`deny`, `ask`) остаются там, где действие
  необратимо или обходит защиту.
- Обязательные проверки без фильтров путей — единственный способ сделать
  красный CI блокирующим для агента: любой другой контроль — снова
  дисциплина.

## Последствия

Положительные:

- Цикл «ревью → мерж → выкатка → уведомление» идёт без владельца; он
  получает результат, а не вопросы.
- Норма автомержа проверяема по следам в PR и коммитах, а не по памяти
  одной сессии.
- Объём растёт только по решению владельца; backlog «Владельцу» показывает,
  что накопилось, вместо того чтобы это тихо делалось.
- Один источник истины без витрины, которую забывали.

Отрицательные и риски:

- **Владелец больше не читает то, что мержится.** ADR `2026-09-13-1800`
  отклонял ослабление человеческого гейта; для выкатки это решение теперь
  обратное. Несколько агентов могут иметь общее слепое пятно
  (`agent_docs/guides/agent-roles.md`, «Трезвая оценка»), и дефект, который
  они пропустили, оказывается в проде через минуты после мержа. Откат —
  ручной, владельцем.
- **Секреты сервера читаются из shell без окна.** Это принятый риск, не
  недосмотр: единственная защита — дисциплина ролей и ревью `compliance`.
  Утечка ключа в транскрипт останется незамеченной, если её не искать.
- **Защищённые пути держатся правилом, а не GitHub.** Ни CODEOWNERS, ни
  ruleset их не охраняют; агент, слив PR с `.github/**` по консенсусу,
  нарушит ADR, но не упрётся в защиту ветки. Механическое подкрепление —
  отдельная задача, и по п. 4 её открывает владелец, не агент.
- **Нагрузка сдвигается на владельца.** Раздел «Владельцу» в backlog будет
  расти, включая находки по безопасности; оценка «больше 40 минут» —
  суждение оркестратора, оно ошибается в обе стороны, а «без искусственного
  дробления» держится честностью. Задача, которую агент недооценил, будет
  сделана без решения владельца.
- **Условие «очередь пуста» добавляет ожидание** перед каждым мержем во
  время выкатки; корректность оно не повышает (допущение 3).
- **`drive-sync.md` остаётся заглушкой**, а старый ADR получает правку
  статуса. Это цена I-12 и гейта ссылок: чистого удаления не будет.
- **CI дороже и строже.** Каждый PR, включая docs, гоняет `detect`,
  `caddyfile` и `lint`; обязательный `lint` запирает кодовый PR из-за
  markdown-огреха; `ci-ok` — ещё одно задание, которое надо держать в
  согласии со списком заданий workflow. Три PR (этот, процесс, CI) и
  настройка через API сливаются и выполняются последовательно, а PR
  процесса и CI — руками владельца: до их мержа автономный мерж работает
  на одной обязательной проверке `guard`, и условие «все проверки
  зелёные» держится только п. 2 нормы.
- **Не-разработчик теряет витрину** в привычном Drive; взамен — публичный
  GitHub и атлас, что не то же самое для человека без аккаунта GitHub.

4. **Настройки GitHub** — после мержа PR CI, через `gh api`: обязательные

   класса показывает все три проверки.

## Альтернативы рассмотрены

- **Оставить два человеческих гейта и убрать только шум разрешений.**
  Отклонено владельцем: клик на выкатку был формальным, и формальный гейт
  хуже отсутствующего — он создаёт видимость контроля.
- **Автомерж средствами GitHub** (auto-merge, merge queue) вместо
  `gh pr merge` агентом. GitHub мержит по зелёным проверкам, но не знает
  вердиктов агентов; чтобы он их знал, нужна бот-личность с обзорами и
  обязательным одобрением — новая сущность и секрет. Отклонено: норма п. 3
  даёт то же на существующих средствах.
- **Защищённые пути через CODEOWNERS и обязательный обзор владельца.**
  Механический контроль вместо дисциплины, дешёвый в настройке. Не
  отклонено — отложено: это задача вне списка владельца, и по п. 4 её
  открывает он.
- **Витрина Drive с автоматической синхронизацией** из GitHub Actions.
  Требует сервисный аккаунт Google, секрет в CI и зависимость от Drive API
  ради копии того, что уже публично. Отклонено.
- **Оставить папку Drive без поддержки.** Устаревшая копия, выдающая себя
  за витрину, — то, против чего I-11. Отклонено.
- **`bypassPermissions` / `--dangerously-skip-permissions`** вместо
  `allow: ["Bash"]`. Снимает и `deny`, и `ask`: force-push и `--admin` без
  окна. Отклонено: `allow` для Bash даёт ту же тишину, сохраняя запреты.
- **Расширять allowlist по мере появления команд.** Каждая новая форма —
  окно владельцу; после сотни PR список всё равно неполон. Отклонено.
- **Брать находки ревьюеров в работу, если они класса C или «мелкие».**
  Ровно так и получились 16 PR из 40. Отклонено.
- **Сохранить фильтры путей и «пустышку» с тем же именем задания** для
  PR вне путей (документированный приём GitHub). Два workflow с одним
  именем задания хрупки и путают `gh pr checks`; сводное `ci-ok` без
  фильтра проще. Отклонено.
