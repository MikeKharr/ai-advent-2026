# [2026-09-16 05:40] Лимиты роутера в проде: след в журнале вместо расширения закрытого списка серверных команд

Файл: `agent_docs/adr/2026-09-16-0540-router-limits-trace-and-admin-endpoints.md`

## Статус

Принято (владелец, в чате 2026-09-16, на коммите `3d8c579`; PR #147,
класс C — гейты ревью не требуются, механический CI зелёный).

Развилка из двух решений владельца в один день:

1. На вопрос «проверка новых лимитов в проде требует входа в контейнер
   роутера — это мне запрещено, как закрываем условие?» с вариантами «вы
   выполните команду / расширить мой список / считать достаточным код»
   владелец выбрал **«Расширить мой список»**.
2. После находки этого ADR (расход агенту ни разу не был нужен через ручку,
   см. «Контекст») — на вопрос «Вы решили расширить мой список команд.
   Появился вариант дешевле: роутер печатает свои лимиты в журнал при
   старте» с вариантами «Только журнал / Журнал и список / Только список,
   как решили» владелец выбрал **«Только журнал»**.

Второе решение заменяет первое. Закрытый список серверных команд не
расширяется: ADR `2026-09-11-1230` и `2026-09-11-1743` остаются в силе
целиком, включая «любой `exec` в контейнеры прода — без исключений».
Правил процесса этот ADR не меняет.

## Контекст

**Откуда задача.** Гейт `compliance` поставил условием выкатки дня 11: после
выкатки роутера `GET /v1/spend` в проде обязан отдать у приложения `agents`
`limits.dailyCostUsd: 10` и `limits.dailyTokens: 10000000` до первого
запуска дня 11 (PR #146 в `main`). Довод: значение в репозитории и значение
в проде — разные вещи.

Единственный описанный способ дёрнуть ручку — `agent_docs/operations.md`,
«Первый запуск на сервере», п. 4:

```sh
docker compose exec router node -e "fetch('http://127.0.0.1:8081/v1/spend',{headers:{authorization:'Bearer '+process.env.ROUTER_ADMIN_KEY}}).then(r=>r.text()).then(console.log)"
```

Агенту это запрещено: закрытый список серверных команд (ADR
`2026-09-11-1230`, `/day-cycle`, фаза 9) — `docker compose ps`, `logs`,
`restart caddy`, проверки имён и копия `AGENT_KEY`; «любой `exec` в контейнеры
прода — без исключений». Роутер наружу не опубликован (`deploy/compose.yml`:
`expose`, в `Caddyfile` его нет), ключ администратора `ROUTER_ADMIN_KEY`
лежит в `deploy/router.env`, и читать его агент не вправе. Проверить условие
агент не мог ничем. Отсюда первое решение владельца — расширить список.

**Что изменилось после первого решения.** `compliance` снял условие:
«значения в `main` плюс контейнер роутера пересоздан на этом sha и здоров»
строго влечёт, что процесс загрузил именно эту пару. Цепочка, проверенная
по коду:

1. `apps.json` впечён в образ (`router/Dockerfile`, `COPY --chown=app:app . .`);
2. ничем не перекрыт: у сервиса `router` в `compose.yml` единственный том
   `router_data:/data`, монтирования поверх `/app/config` нет;
3. подменить нечем: env-переключатель в `router/server.js` есть только у
   провайдеров (`ROUTER_PROVIDERS`), `apps.json` читается безусловно;
4. тег пинуется на коммит: выкатка пишет `ROUTER_TAG=$SHA` в `deploy/.env`,
   затем `pull` и `up -d`; мутабельного `latest` нет;
5. битая конфигурация не доживает до порта: `validateApps` валит процесс до
   `listen`, выкатка ждёт `healthy`.

Снято не потому, что агент не может выполнить проверку, — невозможность
выполнить контроль не основание его снимать, — а потому, что вывод строгий и
без ручки. Граница названа: замена равноценна, пока верны все пять пунктов.

Тот же гейт заметил: **роутер не оставляет следа о своих лимитах.** Стартовая
запись журнала (`router/server.js`, событие `start`) печатает строки
провайдеров и идентификаторы приложений, но не `limits`.

**Нужна ли ручка агенту на практике.** По записям — ни разу не была нужна:
цена живых проверок дней 9 и 10 считалась по `usage` ответов
(`development-history/2026-09-11-1758-day9-compression-comparison.md`,
«Потрачено»); остаток бюджета приложения роутер отдаёт в каждом ответе
`/v1/route` и в `/v1/models` (`budgetLeft`), сервис агентов его читает
(`agents/src/llm.js`); при инциденте `operations.md` первым называет
`docker compose logs --tail 200 router` — исход и причина каждого обращения
там есть, `/v1/metrics` лишь суммирует их. Расширение списка оказалось бы
платой за удобство, которого никто не просил на практике, и первым `exec` в
разрешённом списке. Эта находка и привела ко второму решению владельца.

**Что не меняется.** Ключ администратора и ключи всех провайдеров лежат в
окружении контейнера `router`; любая проверка обязана держать ключ вне
команды, вне вывода и вне транскрипта. Решение ниже ключа не касается вовсе.

## Решение

В событие `start` в `router/server.js` добавляется одно поле — лимиты по
приложениям, только числа:

```js
limits: Object.fromEntries(config.apps.apps.map((a) => [a.id, a.limits])),
```

Поле `apps` остаётся как есть. `secretEnv` (имя переменной ключа) в запись не
попадает: берутся только `id` и `limits`. Рядом в той же записи — порт,
строки провайдеров (`id#revision (kind, tier)`), идентификаторы приложений и
число неразобранных строк журнала; значений переменных там нет и не
появляется.

Чтение — уже разрешённой командой закрытого списка: `docker compose logs
router --since <время выкатки>` (или `--tail N`). Строка `"event":"start"` с
`"limits":{"agents":{"dailyTokens":10000000,"dailyCostUsd":10},…}` — слово
самого процесса о том, что он загрузил. Оно сильнее цепочки из пяти
пунктов: цепочка — вывод из сборки, и любой пункт может уехать молча
(конфигурация в монтируемый том, переключатель для `apps.json`, тег без
пина); строка в журнале верна независимо от них.

Реализация — один PR класса A (`router/**`, деньги): строка в
`router/server.js` и фраза в `agent_docs/operations.md` («Первый запуск на
сервере»: лимиты видны в стартовой записи журнала; п. 4 с `exec` остаётся
процедурой владельца). Правил процесса, `/day-cycle` и `.claude/settings.json`
изменение не касается.

## Обоснование

- **Лимит — константа образа**, и вопрос «что загружено» отвечается один раз
  при старте. Ручка нужна для того, что меняется, — расхода; для констант
  она избыточна, а её цена — `exec` в контейнер с ключами.
- **Ни одной новой команды на сервере.** `logs` уже в списке; ключ не
  участвует; в транскрипт попадают числа, которые и так лежат в `apps.json`.
- **Расход и метрики покрыты без ручки**: `usage` в ответах, `budgetLeft`
  в каждом ответе роутера, журнал при инциденте. Пока это так, у расширения
  списка нет потребителя.

## Последствия

Положительные:

- Каждая выкатка роутера сама оставляет доказательство действующих потолков;
  условие вида «в проде — $10» проверяется командой из списка, без ключа.
- Закрытый список не тронут; «без исключений» остаётся без исключений.

Отрицательные и риски:

- **Доказательство живёт, пока живёт журнал.** `json-file`, 10 МБ × 3:
  стартовая строка со временем вытесняется. Это след выкатки, а не
  состояние; для «сейчас» по-прежнему нужны либо цепочка, либо ручка
  руками владельца.
- **PR класса A и лишняя выкатка роутера ради одной строки журнала.**
- **Форма события `start` меняется** (новое поле). Разбирающего кода нет,
  но записи истории читают его глазами — пусть знают.
- **Живой расход и метрики агент по-прежнему не читает.** Если появится
  задача, которую `usage`, `budgetLeft` и журнал не покрывают, вопрос о
  списке вернётся; проработанная форма — в альтернативах ниже.

## Альтернативы рассмотрены

### Расширение закрытого списка — отвергнуто владельцем («Только журнал»)

Это первое решение владельца, проработанное до готовой формы. Форма
записана здесь, потому что показывает цену пути; выбирать его не стали.

Разрешаемой формой была бы **не** `docker compose exec router node -e
"<код>"`: это выполнение произвольного кода в контейнере, где лежат все
ключи; разрешить такую форму значит снять запрет, а не сузить его. Форма:

1. **Фиксированный скрипт в образе роутера** — `router/admin.js`, рядом с
   `server.js`: единственный аргумент из закрытого множества `spend` |
   `metrics`, иначе подсказка в stderr и код 2 без запроса; `GET
   http://127.0.0.1:8081/v1/<аргумент>` с `authorization: Bearer
   <process.env.ROUTER_ADMIN_KEY>` — ключ только из окружения процесса; на
   200 — тело в stdout, код 0; иначе статус и тело в stderr, код 1; имена и
   значения переменных не печатаются ни в одной ветке. Тест на поддельном
   сервере: stdout равен телу, значение ключа не появляется в выводе при
   200, 401 и неверном аргументе.
2. **Две точные строки в закрытом списке `/day-cycle`**, в
   `cd ai-advent-2026/deploy`: `docker compose exec -T router node admin.js
   spend` и `… metrics` (`-T` — по ssh без `-t` терминала нет). Канонические
   ssh-строки — в `allow` `.claude/settings.json`, как две существующие.
3. **Формулировка запрета** менялась бы на «`docker compose exec` остаётся
   запрещённой формой; исключение — две строки выше дословно; другой
   аргумент, файл, `node -e`, контейнер, флаги — запрещённый `exec`».

Что при этом было проверено: `ROUTER_ADMIN_KEY` не покидал бы контейнер;
тела ответов — `ledger.report()` (суммы без промптов) плюс `limits` и `left`
(`router/src/service.js`, 163–173) и счётчики с `health.snapshot` по
провайдерам — ни ключей, ни адресов, ни текста пользователей.

Почему отвергнуто:

- **Первый `exec` в закрытом списке.** «Без исключений» превратилось бы в
  «кроме двух строк», и следующее расширение сослалось бы на это как на
  прецедент.
- **Потребителя нет**: расход и метрики покрыты `usage`, `budgetLeft` и
  журналом (см. «Контекст»).
- **Механизма нет**: `node admin.js spend` и `node -e '…'` разделяет одна
  правка, остановит её только читающий транскрипт.
- **Файл с ключом администратора в руках не на защищённом пути**:
  `router/admin.js` — класс A по содержанию, а не по пути.
- **Каждая новая ручка — пять правок**: ADR, скрипт с тестом, `/day-cycle`,
  `.claude/settings.json`, `operations.md`.

Отвергнутые варианты той же формы, для полноты:

- **Точные строки `docker compose exec -T router node -e "…"` дословно.**
  Команда несёт произвольный код и учит, что `node -e` в проде бывает;
  одинарные кавычки кода внутри канонической ssh-строки — дословная строка
  либо не выполнится, либо потребует экранирования, которое никто не сверит
  глазами.
- **Обёртка в `deploy/`** (`deploy/router-admin.sh spend`): защищённый путь,
  но внутри тот же `exec … node -e` с теми же кавычками и без тестов.
- **Опубликовать ручки через Caddy или порт на петле хоста**: ключ
  администратора оказался бы в команде и в транскрипте; без ключа —
  публичная админская ручка.
- **Ручки без авторизации на петле контейнера**: меняет модель авторизации
  роутера ради проверки; в контейнер всё равно нужен `exec`.
- **Одноразовый контейнер `docker compose run --rm router …`**: новый
  контейнер со всеми ключами в окружении, меняет состояние прода.

### Прочие

- **Считать достаточным код в `main`** (цепочка из пяти пунктов, принятая
  `compliance`). Не отклонено — решение делает тот же вывод видимым и
  независимым от пяти условий.
- **Периодическая запись расхода в журнал роутера.** Даёт «сколько
  потрачено» без ручки, но шумит и не по требованию; остаток и так в каждом
  ответе (`budgetLeft`). Отклонено.
