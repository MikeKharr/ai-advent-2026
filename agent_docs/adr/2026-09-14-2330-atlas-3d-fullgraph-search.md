## Контекст

## Решение

### 1. Вид: объём всегда, плоский — флажком под канвой

Страница открывается в объёме в начальной позе ψ₀, θ₀, вписанной по
огибающей. Флажок «Плоский вид» стоит под канвой (на узком экране — в карте),
одно состояние на два экземпляра в DOM, режим не пишется ни в адрес, ни в
хранилище. Флажок «Объём» и строка под ним из блока фильтров уходят; блок
называется «Фильтры по типу». Подробности — раскладка, раздел 1.

Гарантия «ноль пропущенных подписей» остаётся у плоских видов до 40 узлов —
теперь это только виды при включённых фильтрах типов. Полный граф в обоих
режимах подписывает без гарантии (раздел 3).

### 2. Полный граф всегда; выбор — подсветка, не перестройка

- Канва показывает все узлы невыключенных типов и все рёбра между ними.
  Уходят «1 шаг / 2 шага», «Показать весь граф», стартовая цепь «Цикл дня».
  Проход по фазам остаётся в панели фазы; вход в цикл — ссылка на фазу 1 в
  стартовой панели.
- Выбор узла не двигает камеру и не перевписывает вид: выбранный и соседи —
  в полном цвете, рёбра выбранного — цветом семейства, остальные узлы — с
  непрозрачностью 0,7, остальные рёбра — `--line`. Единственное исключение —
  узел за краем канвы: камера сдвигается к нему без смены масштаба.
- Контракт адресов прежний — `#`-фрагмент называет узел. Меняется смысл:
  `#role-compliance` открывает полный граф с выделенным узлом. Старые ссылки
  ведут туда же, куда вели.
- Строка выбранного узла в списке — рамка и `aria-current`, порядок списка
  постоянный; область прокручивается прямым `scrollTop` так, чтобы строка
  встала на треть высоты. Клавиатурный фокус не переносится — правила #72 и
  #75 в силе. Ниже 100rem у списка своя прокрутка (`max-height: 60dvh`).

Цена — подписи. Соседи раньше подписывались в окрестности, вписанной во всю
канву; теперь они стоят среди двух сотен узлов. По замеру раскладки для
настольного поля 704…976 × 499 из 1617 подписей выделения пропадает 169
(10,5 %) в плоском виде и 278 (17,2 %) в объёме; у самых связанных узлов —
до половины: `compliance` в объёме — 22 из 44, ADR `2026-09-13-1800` —
23 из 42. На карте телефона — 27 % при 360 и 34 % при 320. Имена соседей
всегда есть в панели («Ссылается на», «На него ссылаются»), «Крупнее»
расставляет подписи заново на каждом шаге масштаба. Приближать камеру к
окрестности при выборе отклонено: владелец просил именно полный граф. Число
пропущенных подписей при выборе `compliance` на 1280 записывается в описание
PR как точка отсчёта, а не порог.

### 3. Полнотекстовый поиск и контракт `texts.json`

Поиск идёт по заголовкам, ключам и коротким именам с первого знака (как
сейчас, из `graph.json`) и по тексту документов от трёх знаков. Выдача — до
пяти результатов с отрывком вокруг совпадения; все найденные отмечены
кольцом на канве и в списке; выбор и поиск складываются, а не гасят друг
друга. Подробности — раскладка, раздел 4.

Контракт файла — для `backend`:

| Что | Значение |
|---|---|
| Место | `dist/site/texts.json` рядом с `graph.json`; в образ единицы `atlas` попадает той же сборкой |
| Форма | Объект «идентификатор узла → строка текста», ключи в порядке узлов графа; две сборки одного коммита — байт-в-байт |
| Набор | Узлы с файлом из объявленных входов `atlas/lib/sources.js`: ADR, записи истории, раскладки, гайды (включая `AGENTS.md`, `architecture.md`, `index.md`, `glossary.md`), роли, собственные скиллы. **Не входят** 26 вендорных скиллов (`.agents/skills/*`, чужой текст, +380 КБ) и `deploy/compose.yml` у сервисов и томов. Нового чтения с диска нет |
| Обработка | Фронтматтер снят; `#` заголовков, `**`, `` ` ``, `\|` и строки-разделители таблиц, синтаксис ссылок сняты; пробельные символы схлопнуты в пробел |
| Скрытие | Всё, что совпадает с образцами из `atlas/test/secrets.test.js` — префиксы ключей `sk-ant-` и `gsk_`, `BEGIN OPENSSH`, адрес вида `100.x.x.x`, — заменяется на «[скрыто]». По образцу, а не по списку файлов: образцы уже в пяти документах, включая этот |
| Загрузка | Страницей при первом фокусе в поле поиска, один раз за жизнь страницы; срок — та же константа `LOAD_LIMIT_MS` (30 с), без ступени 8 с; при сбое поиск остаётся по заголовкам, кнопка «Загрузить тексты снова» |
| Расхождение сборок | Идентификаторы, которых нет в графе, страница пропускает; узлы без текста ищутся по заголовку |
| Потолок | Раздел 5 |

Почему отдельный файл, а не поле в `graph.json`: первая загрузка страницы —
42 КБ gzip; тексты увеличили бы её в десять раз ради функции, которой многие
посетители не воспользуются. Почему полные тексты, а не индекс: владелец
выбрал «список со сниппетами», а отрывок нельзя показать без текста; индекс
без текста дал бы только имена узлов — то, что есть сейчас.

### 4. Публичность `texts.json`

Витрина начинает отдавать полные тексты 120 документов — то, от чего ADR
`2026-09-13-2000` отказывался в панели. Это не новая утечка, но новая
поверхность, и разница названа прямо:

- **Ничего нового не раскрывается.** Репозиторий публичен; каждый документ
  набора уже читается любым человеком на GitHub. `texts.json` не содержит
  ничего, чего нет в `git`.
- **Поверхность другая.** Витрина живёт на своём адресе, отдаёт тексты
  пакетом одним запросом без контекста GitHub и связана более строгим
  стражем, чем репозиторий: `docs-guard` ищет в репозитории только формы
  настоящего ключа (`sk-ant-` с десятью и более знаками), а
  `atlas/test/secrets.test.js` требует, чтобы в файлах витрины не было даже
  образцов — префиксов и адресов частной сети. Полные тексты этот тест
  провалили бы сразу; скрытие образцов при сборке держит его зелёным без
  правки теста — он проверяет все файлы `dist/site`, значит и `texts.json`.
- **I-3 не задет.** Ключ не может попасть в `texts.json`, потому что его нет
  во входах: набор — явный список путей, `.env`, `deploy/*.env`, логи и тома
  в нём отсутствуют (тест с подложенным маркером). Единственный путь ключа в
  тексты — если владелец сам впишет его в публичный документ; это уже
  нарушение I-2, а не граница витрины (тест «уже не наша граница»).
- **Честная граница скрытия.** Скрываются известные образцы; ключ поставщика
  с другим префиксом, который однажды появится в документах как пример, страж
  не знает. Расширение списка образцов — правка теста и сборки в одном PR.
- **Класс A** для PR с `texts.json`: изменение расширяет публикуемое
  витриной и опирается на страж секретов. Гейты — `reviewer` и `compliance`,
  вето `compliance` действует. Сомнение — в сторону старшего класса (ADR
  `2026-09-13-1800`).
- `noindex` на `/atlas/` остаётся; `texts.json` к тому же грузится только по
  фокусу в поле, но прямым запросом доступен любому — как и `graph.json`.

### 5. Потолки размера

Прежние критерии «`dist/site` ≤ 400 КБ» и «`graph.json` ≤ 250 КБ» (замер
этапа 3, «граница на рост, чтобы ловить скачок»; ADR `2026-09-14-1000`)
исчерпаны без единого сигнала: 398 и 240 КБ до этой задачи. Новые потолки —
три, по файлам, и впервые **механические**: проверка в `guard` (тест или
находка `--check` — решает `backend`), красная при превышении. Числа для
`texts.json` и `graph.json` — решение владельца.

| Файл | Сейчас | Потолок | Что означает |
|---|---:|---:|---|
| `texts.json` сырыми | 1 438 КБ (≈ 387 КБ gzip) | **3 072 КБ** (≈ 830 КБ gzip при нынешнем сжатии 0,27) | Бюджет посетителя: срок 30 с из #86 выдерживается от ≈ 220 кбит/с (сейчас — от 106); при 1,6 Мбит/с — 4,1 с ожидания после фокуса в поле, при 400 кбит/с — 17 с |
| `graph.json` | 240 КБ (42 КБ gzip) | **1 024 КБ** | Первая загрузка страницы: при потолке ≈ 180 КБ gzip — вчетверо больше нынешней |
| Код страницы: `app.js` + `style.css` + `index.html` | 158 КБ | **256 КБ** | Скачок кода: PR 2 добавит поиск, отрывки и подсветку; удвоение — сигнал |

- **Почему потолок кода вместо «`dist/site` без `texts.json`».** Сумма
  «`graph.json` + код» с потолком, который вмещает 1 024 КБ графа, не
  ловит ничего: код — 158 КБ, и его удвоение прячется в запасе графа.
  Потолок на сумму имел смысл, пока `graph.json` держал 250. Потолки по
  файлам ловят каждый свой скачок; общий потолок `dist/site` не нужен —
  он был бы суммой трёх.
- **При превышении — отказ сборки, не усечение.** Усечение делает поиск
  лжецом молча: «ничего не нашлось» там, где текст есть, и произвольный выбор,
  какой документ выбросить. Отказ — красный `guard` на PR, который перешёл
  черту; PR ждёт. Это контроль, который падает закрыто (`agent-roles.md`,
  «Трезвая оценка»).
- **Поднять потолок — обычный PR класса B** (константа в `atlas/`), где
  `reviewer` подтверждает, что рост органический — новые документы, — а не
  скачок: вендорные скиллы в наборе, разметка, не снятая при обработке,
  дубль текста. Нового ADR не нужно: этот ADR задаёт правило, а не число
  навсегда. Альтернатива потолку — сузить набор (самые крупные файлы —
  раскладки: 124 и 72 КБ), и это уже решение владельца.
- **Темп и цена 3 072 КБ.** Средний документ набора — 12 КБ; в рабочий день
  проект добавляет около десятка. Запас 1 634 КБ уходит примерно за три
  недели работы. Цена — у посетителя на медленной сети: на границе потолка
  срок 30 с держится только от ≈ 220 кбит/с (сейчас — от 106), и полоса
  между 106 и 220 кбит/с, где сегодня тексты успевают, перестанет их
  получать — поиск там останется по заголовкам. Потолок не защита от одного
  скачка: вендорные скиллы дали бы +380 КБ и остались бы под ним; скачок
  состава ловит тест на набор узлов (раздел 6, п. 1).

### 6. Реализация — два PR, затем документы

1. **`backend` — PR «контракт `texts.json`», класс A** (`reviewer` +
   `compliance`): сборка файла в `atlas/build.js` и `atlas/lib/`, обработка,
   скрытие образцов, три механических потолка раздела 5 (`texts.json`,
   `graph.json`, код страницы), строка контракта в `atlas/README.md` («Что
   несёт…»), тесты: форма и порядок ключей, набор узлов, отсутствие вендорных
   скиллов и `compose.yml`, «[скрыто]» вместо образцов, детерминизм двух
   сборок, потолки; `atlas/test/secrets.test.js`
   зелёный без правки. Страница файл не читает — UI-гейта нет, PR мержится
   отдельно и первым.
2. **`frontend` — PR «страница», класс B** (`reviewer` + `design-review`),
   строго после мержа п. 1: `atlas/web/app.js`, `index.html`, `style.css` по
   раскладке; `qa` — тесты чистой части (строка вида, нормализация и порядок
   поиска, отрывок, набор выделения, цель прокрутки) до кода или вместе с
   ним. Приёмка — «Что проверит ревью» раскладки, 26 пунктов, в живом Chrome
   в обеих темах; бюджет кадра p95 ≤ 16 мс в двух замерах, включая эмуляцию
   360 × 780 с замедлением ×4.
3. **`docs`** после мержа: запись истории, `snapshot.md`, страница прогресса;
   пункт backlog о дрейфе подписей «2 шага» закрывается — переключателя
   глубины больше нет.

Экземпляры раскладки (#101), реализации и ревью не пересекаются; автор кода
свой код не ревьюит. Мерж — по консенсусу гейтов (ADR `2026-09-14-2200`).

### Развилки — решены владельцем 2026-09-11

1. **Потолок `texts.json`.** Архитектор предлагал 2 048 КБ (≈ 550 КБ gzip,
   срок 30 с от ≈ 150 кбит/с). **Владелец: 3 072 КБ**, при превышении
   сборка падает. Цена пересчитана в разделе 5: срок 30 с — от ≈ 220 кбит/с.
   Усечение отклонено.
2. **Потолок `graph.json`.** Архитектор предлагал 300 КБ вместо
   исчерпанных 250. **Владелец: 1 024 КБ**, проверяется механически в PR 1,
   как и остальные.
3. **Потолок `dist/site` без `texts.json` — 500 КБ** предлагался
   архитектором; после п. 2 он теряет смысл, потому что в нём `graph.json`.
   Заменён потолком кода страницы 256 КБ — следствие п. 2, обоснование в
   разделе 5; отдельного вопроса к владельцу нет.
4. **Обход `Tab` до панели — вне объёма.** Владелец: остаётся в backlog
   «Не делаем без решения владельца» вместе с #80 и новой ценой — 203
   остановки. Раздел ниже.

### Вне объёма: обход `Tab` через список (#80, заморожено)

В двух колонках и на узком экране список «Узлы в этом виде» стоит в DOM до
панели. С полным графом это 203 остановки `Tab` между поиском и панелью
вместо прежних 5–50 в окрестности. Пропуск-ссылка «К панели узла» ведёт в
панель напрямую, шаг ссылкой ставит фокус на `#panel-h` (#75), так что
посетитель, идущий по ссылкам, цены не платит; платит тот, кто идёт по
странице клавишей подряд. Лечит это раскладка #80
(`design/2026-09-14-1700-atlas-tab-order.md`): панель до списка во всех трёх
раскладках. Она заморожена (#91) и в объём этой задачи не входит. Варианты:

- **Реализовать #80** — класс B, `design-review`, свой PR после PR 2. Цена
  названа в её развилках: кто идёт по списку строка за строкой, после шага
  возвращается к нему через панель (медиана 8 нажатий, у `compliance` — 49);
  в трёх колонках список хаба уходит под панель. Взамен — DOM совпадает с
  экраном (WCAG 1.3.2), панель достижима с клавиатуры за десяток остановок
  при любой ширине.
- **Оставить как есть.** Ничего не делается; расхождение DOM и экрана
  остаётся в backlog «Не делаем без решения владельца». Цена растёт с
  графом: сегодня 203 остановки, через месяц — больше.
- **Локальная мера без #80** — список одной остановкой `Tab` с ходом по
  стрелкам (`listbox` или roving `tabindex`) или вторая пропуск-ссылка
  «Пропустить список». Дешевле #80, но вводит паттерн, которого нет в
  корпусе, требует своей раскладки и `design-review`, а расхождения DOM с
  экраном не лечит. Не рекомендуется: полумера с полной ценой гейтов.

Рекомендация архитектора была — решать вместе с #80 и локальную меру не
делать. **Решение владельца 2026-09-11: оставить как есть.** Пункт остаётся
в backlog «Не делаем без решения владельца» вместе с #80, с новой ценой —
203 остановки `Tab` до панели в двух раскладках из трёх.

## Обоснование

- **Заказ, а не находка.** Все четыре пункта — решение владельца по ADR
  `2026-09-14-2200`, п. 4; ADR не спорит с ними, а называет, что они отменяют
  из ADR `2026-09-14-1000` и `2026-09-13-2000`, и цену — подписи и объём
  публикуемого. Отменяемые пункты перечислены точечно, чтобы граф замен в
  атласе был честным: заменяется часть, не документы.
- **Тексты отдельным файлом по фокусу** — единственный способ дать
  полнотекстовый поиск со сниппетами без десятикратного роста первой
  загрузки и без серверной работы (витрина — статика, ADR `2026-09-13-2000`,
  п. 3, 8).
- **Скрытие по образцу, а не по списку файлов** — потому что список устарел
  бы при этом же ADR: образцы называет каждый документ, который описывает
  страж.
- **Класс A** — потому что изменение трогает границу публикуемого, а
  `compliance` — единственный гейт с правом вето на такое.
- **Отказ вместо усечения** — потому что усечённый поиск врёт молча, а
  проект держит контроли, которые падают закрыто; красный `guard` на PR с
  документами — заметная, но честная цена.
- **Механический потолок вместо критерия ревью** — потому что прежние
  критерии 400 и 250 КБ исчерпаны на 398 и 240 без единого сигнала: никто
  не измерял. Потолки по файлам, а не на сумму: сумма с графом в 1 024 КБ не
  замечает удвоения кода.
- **Полный граф без гарантии подписей** — решение владельца; раскладка
  оплачивает его панелью с именами соседей, «Крупнее» и подсказкой «имя узла —
  под указателем».

## Последствия

Положительные:

- владелец получает то, что просил: объём с первой секунды, весь проект в
  кадре, выбор как подсветка, поиск по тексту с отрывками и кольцами на
  схеме;
- первая загрузка страницы не растёт: 42 КБ gzip, тексты — только тем, кто
  ищет;
- потолки становятся проверяемыми в CI, а не в памяти ревьюера;
- страж секретов витрины не ослабляется и не правится — сборка подстраивается
  под него;
- адреса узлов и путь посещений совместимы: старые ссылки открывают тот же
  узел.

Отрицательные и риски:

- **Подписи выделения без гарантии на полном графе:** до половины соседей у
  самых связанных узлов остаются без подписи и в плоском виде тоже. Плоский
  вид перестаёт быть «видом с гарантией» — гарантия остаётся у отфильтрованных
  видов до 40 узлов, то есть у видов, которые посетитель должен сначала
  собрать.
- **Стартовый экран — клубок.** Раскладка этапа 3 от него отказывалась
  («176 узлов ничего не объясняют»); рассказ «как здесь делается работа»
  перестаёт быть первой картинкой, вход в цикл — ссылка в панели.
- **Витрина отдаёт полные тексты 1,4 МБ**, включая черновые формулировки
  раскладок и записей истории, в одном файле одним запросом. Это публичные
  документы, но пакетом их ещё никто не отдавал; скрытие образцов — известные
  формы, не все возможные.
- **Красный `guard` на PR с документами**, когда `texts.json` перерастёт
  потолок: docs-PR класса C ждёт PR класса B с новой константой. При нынешнем
  темпе — примерно через три недели, и потом регулярно; каждый раз это
  решение владельца между бюджетом посетителя и набором.
- **Первый фокус в поле поиска стоит 387 КБ сегодня и до ≈ 830 КБ у
  потолка**, в том числе тем, кто проходит поле клавишей `Tab`. Сегодня
  тексты не успевают за 30 с на сети медленнее ≈ 106 кбит/с, у потолка —
  медленнее ≈ 220 кбит/с; там поиск остаётся по заголовкам — с подсказкой,
  но без текста. Потолок 3 072 КБ вместо 2 048 — это решение владельца о
  том, что полоса 150…220 кбит/с не в бюджете.
- **`graph.json` до 1 024 КБ** — первая загрузка страницы может вырасти с 42
  до ≈ 180 КБ gzip, прежде чем потолок подаст сигнал; критерий этапа 3 «ловить
  скачок» для графа перестаёт действовать, остаётся только рост.
- **Обход `Tab` до панели — 203 остановки** в двух раскладках из трёх;
  владелец оставил как есть вместе с #80. Это существующее расхождение,
  которое полный граф делает в разы дороже, и теперь оно принятое, а не
  отложенное.
- **Два экземпляра флажка «Плоский вид» с одним состоянием** — ещё одно
  место, где два элемента обязаны совпадать; проверяется ревью, не
  механикой.
- **Кадр на телефоне**: 819 линий и 204 круга при вращении с `dpr` 3 —
  бюджет 16 мс проверяется эмуляцией с замедлением ×4, живого телефона в
  стенде нет; рычаг `dpr ≤ 2` во время движения применяется по замеру, а
  не впрок.
- **Заморозка атласа снята для одной задачи**, а объём её — раскладка на
  тысячу строк и два PR кода; риск, что снятие станет нормой, держится
  только правилом п. 4 ADR `2026-09-14-2200`.

## Альтернативы рассмотрены

- **Тексты полем в `graph.json`.** Один запрос, проще код; первая загрузка
  растёт с 42 до ≈ 430 КБ gzip для всех, включая тех, кто не ищет.
  Отклонено.
- **Индекс вместо текстов** (инвертированный или триграммный, собранный при
  сборке). Меньше по размеру только без сниппетов; с позициями и отрывками —
  не меньше текстов, зато второй формат и второй разборщик. Владелец выбрал
  выдачу с отрывками. Отклонено.
- **Поиск по выдержкам, которые уже есть в `graph.json`.** Ничего не
  грузится, но это не полнотекстовый поиск: выдержка — первый абзац
  контекста. Не то, что просили. Отклонено.
- **Серверный поиск** (сервис рядом с витриной). Витрина — статика без
  серверной работы и без расхода (ADR `2026-09-13-2000`, п. 6, 8); сервис ради
  поиска по 120 документам — новая единица деплоя и новая поверхность.
  Отклонено.
- **Усечение `texts.json` при потолке** (выбросить самые старые записи или
  самые крупные раскладки). Поиск молча перестаёт находить; какой документ
  выбросить — произвол сборки. Отклонено; сужение набора — решение владельца,
  не автоматика.
- **Скрывать образцы списком файлов**, а не по образцу. Список устарел бы
  этим же ADR: образцы называет каждый документ о страже. Отклонено.
- **Не скрывать вовсе, а ослабить тест** («репозиторий и так публичный»).
  Тест — граница витрины, принятая ADR `2026-09-13-2000`; ослаблять страж
  ради удобства сборки — то, чего `compliance` не пропустит. Отклонено.
- **Рендер полного текста в панели** — раз тексты всё равно едут на
  страницу. Заманчиво, но это самый большой кусок кода атласа (markdown без
  зависимостей) и не заказ владельца; `texts.json` делает его дешевле в
  будущем, решение — отдельное. Отклонено здесь.
- **Оставить окрестность «1 шаг / 2 шага» как режим рядом с полным графом.**
  Сохранил бы подписи соседей; владелец просил убрать, и два режима вида —
  две картинки для каждого `design-review`. Отклонено.
- **Камера вписывает окрестность при выборе** (развилка 10 раскладки).
  Подписей больше, но граф уже не целиком в кадре — против п. 2 заказа.
  Отклонено.
- **Потолки оставить критерием ревью**, как прежние. Прежние критерии
  исчерпаны незаметно; критерий, который никто не измеряет, не критерий.
  Отклонено.
- **Потолок `texts.json` 2 048 КБ** — предложение архитектора: срок 30 с от
  ≈ 150 кбит/с, запас на одну-две недели. Владелец выбрал 3 072 КБ: реже
  поднимать, дороже посетителю на медленной сети. Отклонено владельцем.
- **Потолок на сумму `dist/site` без `texts.json`** (500 КБ). При
  `graph.json` до 1 024 КБ сумма не замечает удвоения кода страницы; заменён
  потолком кода 256 КБ. Отклонено как следствие решения владельца.
