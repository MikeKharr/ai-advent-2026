# [2026-09-07 23:30] День 2: свободный ответ с параметрами пользователя, ссылки — по белому списку

Файл: `agent_docs/adr/2026-09-07-2330-day2-free-text-params.md`

## Статус

Предложено — ожидает решения владельца

## Контекст

Задание дня 2: поверх решения дня 1 дать пользователю управление параметрами обработки
запроса — формат ответа, число статей с источника (30 по умолчанию), условие завершения
ответа (например, встретилось слово), останов по числу токенов (200 по умолчанию) — и
показать подсчёт токенов; результаты складывать в ленту (запрос, дата-время, параметры,
токены, сам ответ).

День 1 держит достоверность построением (ADR `2026-09-07-2016`): модель возвращает только
номера по строгой JSON-схеме, а ссылки и даты подставляет приложение. Пользовательский
формат ответа со строгой схемой несовместим: формат произвольный, а `stop_sequences`
обрывают JSON на середине, делая его нечитаемым.

## Решение

1. **Ответ — свободный текст.** Строгая схема не применяется. «Формат ответа» уходит
   в промпт как инструкция; «условие завершения» — в `stop_sequences` (до 4, по одной на
   строку); «останов по токенам» — в `max_tokens` (1–2048, по умолчанию 200);
   «статей с источника» — обрезка кандидатов перед моделью (1–50, по умолчанию 30).
2. **Ссылки — по белому списку.** Модель получает список новостей со ссылками (в отличие
   от дня 1) и инструкцию приводить их дословно. Каждый URL в ответе проверяется по списку
   кандидатов; URL не из списка вырезается (`stripUnknownLinks`). Свойство «модель не
   является источником ссылок» дня 1 заменяется на «ссылка в ответе существует в ленте
   издания» — слабее, но проверяемо построчно.
3. **Ответы модели не кэшируются.** Смысл дня — видеть эффект параметров; кэш его прятал бы.
   Кэш лент (30 минут) сохраняется, лимиты дня 1 (I-4, I-5) — без изменений, проверка до
   вызова API. `usage`, `stop_reason` и `stop_sequence` из ответа API отдаются пользователю.
4. **Лента — в localStorage браузера.** Сервер запросы пользователей не хранит (I-10);
   лента персональна и не является общей витриной.

## Обоснование

- Параметры генерации — суть задания; строгая схема им противоречит, а не помогает.
- Белый список ссылок — единственная проверка достоверности, которая переживает произвольный
  формат ответа: она не разбирает текст, а сверяет URL со множеством известных.
- Отказ от кэша ответов не открывает расход: лимиты на IP и суточный предел прежние,
  а `max_tokens` ограничен потолком 2048.

## Последствия

Положительные:

- пользователь видит связь параметров с поведением модели и расходом токенов — цель дня;
- ссылки в ответе гарантированно ведут на статьи из лент изданий;
- инфраструктура дня 1 (ленты, разбор RSS, лимиты) переиспользована без изменений.

Отрицательные:

- **I-8/I-9 держатся промптом, а не построением:** свободный текст может пересказать
  новость неточно или указать дату не из списка. Белый список закрывает только ссылки.
- **Вход дорожает:** список со ссылками при 30 статьях с источника — ~18K входных токенов
  (~$0.02 за запрос на Haiku 4.5) против ~9.5K у дня 1. Потолок расхода держат прежние
  лимиты.
- **Каждый запрос — вызов API:** повтор с теми же параметрами не бесплатен. Это осознанный
  размен, см. Обоснование.
- Промпт-инъекция через поле «формат» возможна, но её область — собственный ответ
  пользователя: чужих данных в контексте нет, ссылки фильтруются, расход ограничен.

## Альтернативы рассмотрены

- **Строгая схема + пост-форматирование на сервере.** Сохраняет гарантии дня 1, но
  «формат ответа» превращается в шаблонизатор, который придётся писать и ограничивать;
  `stop_sequences` всё равно ломают JSON — параметр из задания терял бы смысл.
- **Два вызова: выбор по схеме, затем форматирование.** Честные ссылки и произвольный
  формат, но двойной расход и двойное время на каждый запрос — против сути дня, где
  запросов много и они дешёвые.
- **Лента на сервере (общая).** Проще показать «историю всех», но это хранение запросов
  пользователей (конфликт с I-10) и витрина чужих экспериментов без запроса на то.
