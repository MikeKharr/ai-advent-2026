# Инварианты продукта

Жёсткие ограничения. Нарушение инварианта — баг, а не компромисс. Изменение инварианта требует ADR.

## Секреты

- **I-1.** `ANTHROPIC_API_KEY` никогда не покидает сервер. Ключ не появляется в клиентском JS, в HTML, в ответах API, в логах и в сообщениях об ошибках.
- **I-2.** В репозитории нет реальных секретов. `.env` в `.gitignore`, коммитится только `.env.example` с пустыми значениями.
- **I-3.** Ключ не передаётся в чат, в issue, в PR и в Google Drive. Ротация — при любом подозрении на утечку.

## Расход средств

- **I-4.** Ни один запрос не может вызвать API без прохождения rate limit и суточного лимита. Проверка лимита предшествует вызову, а не следует за ним.
- **I-5.** Суточный лимит `MAX_DAILY_CALLS` — жёсткий. При исчерпании приложение отдаёт кэш и честное сообщение, но не вызывает API.
- **I-6.** У каждого вызова есть `max_uses` для web_search и `max_tokens`. Безлимитных вызовов не бывает.

## Достоверность

- **I-7.** Каждый пункт новостей несёт минимум одну рабочую ссылку на источник. Пункт без источника не показывается.
- **I-8.** Приложение не выдумывает новости, чтобы заполнить три карточки. Если значимых новостей меньше — показывается меньше, с пояснением в поле `note`.
- **I-9.** Дата в карточке — дата события из источника, а не дата запроса.

## Данные пользователя

- **I-10.** Запросы пользователей не хранятся в связке с IP дольше окна rate limit. Кэш ключуется нормализованной сферой, не пользователем.

## Документация

- **I-11.** Источник истины для решений — git. Google Drive — витрина только для чтения; расхождение решается в пользу git.
- **I-12.** Принятые ADR не редактируются. Изменение решения — новый ADR со статусом «Заменяет ...».
