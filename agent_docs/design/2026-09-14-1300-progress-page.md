# Страница прогресса `/progress/` — раскладка до кода

Роль `design` → `frontend`. Основа: `agent_docs/design/corpus.md`,
`agent_docs/invariants.md`, лендинг `site/index.html`, витрина атласа
`atlas/web/` как пример экрана по корпусу и её спецификация
`agent_docs/design/2026-09-13-2100-atlas-page-layout.md`.

Код пишет `frontend`, ревью перед мержем ведёт `design-review` — отдельный
экземпляр, не автор этой спецификации и не автор реализации (ADR
`2026-09-13-1800`). Раскладка до кода обязательна: экран новый (ADR
`2026-09-08-1110`).

## Контекст

Владелец: «страницу с прогрессом веди в challenge.zpq.ai, там же дай ссылки
на работающие приложения, включая атлас». Экран — публичная страница
`challenge.zpq.ai/progress/`: сверху ссылки на работающие приложения, ниже
короткий блок «Сейчас в работе» и журнал PR с целью и итогом каждого. Модель
содержания взята из прототипа, который владелец видел приватно (в репозиторий
он не входит): журнал по дням мержа, фильтр по потокам, тип и класс PR, блок
текущей работы, дни задания. Визуальный язык прототипа не переносится —
сторонние шрифты, восемь своих цветов и цветные плашки типов корпусу
противоречат; экран строится только на токенах корпуса.

Что из этого следует:

1. **Строка PR умещается в три строки текста на десктопе:** итог в одну-две
   (83 знака при полосе 68ch), цель в одну, мета в одну. Карточки для строки
   не нужны — это журнал, а не витрина.
2. **День мержа — до 20 PR.** Группа по дню длинная, поэтому заголовок группы
   несёт число PR, а фильтр — число PR в потоке.
3. **46 PR без класса — не пробел в данных.** Классов до фреймворка v2 не
   было; дописывать их задним числом — выдумывать (I-8 по духу). Строка без
   класса просто не показывает его, а пояснение к классам называет первый PR
   с классом.
4. **Самое длинное слово на 320 px помещается** (≈ 195 px при 16 px против
   288 px колонки), но текст журнала всё равно получает
   `overflow-wrap: anywhere`: следующее длинное слово может прийти с любой
   строкой.

## Проверено до раскладки

- **Доставка.** Caddy отдаёт `site/` целиком (`../site:/srv/site:ro` в
  `deploy/compose.yml`, `file_server` в `handle` по умолчанию), выкатка на
  сервере делает `git reset --hard origin/main`. Каталог `site/progress/`
  доедет без правок деплоя, Caddyfile и compose не меняются.
- **Запрет индексации.** Блок `header` в `deploy/Caddyfile` стоит на уровне
  сайта и накрывает `file_server`, значит `X-Robots-Tag: noindex, …` будет и
  на `/progress/`. Мета-тег `robots` не нужен и не добавляется.
- **Адрес без слэша.** `file_server` сам переводит `/progress` на
  `/progress/`: у каталога есть `index.html`. Отдельного `redir` не нужно.
- **Атлас читает лендинг.** `atlas/lib/extract.js` берёт узлы дней из блоков
  `<a class="day"` в `site/index.html` — из них же даты дней. Новая ссылка на
  лендинге **не должна нести класс `day`**, иначе атлас получит
  несуществующий день. Правка `site/index.html` запускает пересборку и
  выкатку атласа (регулярное выражение `atlas` в `deploy.yml`) — отсюда
  временное правило очереди мержа в `operations.md`, раздел «Атлас проекта».
- **`site/` не единица CI.** Шаги «Синтаксис» и «Тесты» в `ci.yml` идут по
  каталогам единиц (дни, `router`, `agents`, `atlas`); файлы
  `site/progress/*.js` сейчас не проверяет ничто. Обязательная проверка
  `guard` (`docs-guard.yml`) запускается на каждом PR — см. развилку 4.
- **`localStorage` общий на весь домен.** Заняты ключи `day2-feed`,
  `day3-ask-feed`, `day4-feed`, `day5-archive-feed`, `day6-agent-feed`,
  `day6-agent-prompt`, `day7-agent-prompt`, `day8-agent-prompt`. Ключ
  страницы — `progress-stream`, в том же стиле и без пересечений.
- **Тема** — системная, как у дней и атласа: `color-scheme: light dark`, обе
  ветки палитры корпуса. Переключателя нет.

## Файлы

```text
site/progress/index.html   разметка; блок приложений — статичный HTML
site/progress/style.css    токены корпуса и стили экрана
site/progress/app.js       проверка строк, фильтр, отрисовка журнала и «Сейчас в работе»
site/progress/data.js      данные: «Сейчас в работе», потоки, строки PR
```

Структура повторяет `atlas/web/`. Пути к своим файлам — относительные
(`style.css`, `app.js`, `data.js`), `<base>` нет. Ссылки на приложения —
от корня (`/day1/`, `/atlas/`), как на лендинге: эти страницы живут только
на домене, локально их открыть нечем.

**Блок приложений — в разметке, а не в данных.** Это главное, ради чего
страницу открывают, и оно обязано работать без скрипта и без файла данных.
Цена — новый день правит `index.html` одной строкой списка; это делает
`feat`-PR дня, который и так правит лендинг и проходит `design-review`.

Сверху вниз, в порядке важности:

2. **«Работающие приложения»** — восемь дней и атлас. Требование владельца и

5. Подвал: откуда журнал и где исходный код.

просили, а числа по потокам уже стоят на чипах фильтра.

## Раскладка

Одна колонка чтения на всех ширинах. Содержимому не нужно больше 48rem: самая
широкая строка — строка журнала, 4.5rem колонки номера плюс полоса 68ch.
Планшет и десктоп поэтому различаются только полями по краям, а не
раскладкой. Порог один — **36rem** (576 px).

| Что | Ниже 36rem | От 36rem |
|---|---|---|
| Контейнер `.page` | `max-width: 48rem`, `margin-inline: auto` | то же |
| Поля страницы | `padding-block: --s-6`, `padding-inline: --s-4` | `--s-7` / `--s-5` |
| Между секциями и после шапки | `--s-7` | `--s-7` |
| Строка приложения | метка и стрелка первой строкой, текст второй | три колонки: метка, текст, стрелка |
| Строка PR | номер и тип первой строкой, дальше текст во всю ширину | две колонки: номер и тип слева, текст справа |

Колонка метки у приложений и колонка номера у PR — одна ширина, 4.5rem: оба
списка читаются по одной вертикали.

### Шапка

- Ссылка «← AI Advent 2026» → `/`: `--t-sm`, `--fg-mut`, подчёркнута.
  Отступ до `h1` — `--s-4`.
- `h1`: `--t-xl`, `line-height: 1.25`, `letter-spacing: -.01em`, вес 600.
- Подпись: `--t-md`, `--fg-mut`, `max-width: 68ch`, отступ сверху `--s-2`.

### Заголовок секции

`h2` — `--t-lg`, `line-height: 1.4`, вес 600. Рядом, если есть, — вторичная
строка (`--t-sm`, `--fg-mut`): флекс с переносом, `align-items: baseline`,
`justify-content: space-between`, зазор `--s-2 --s-3`. От заголовка до
содержимого — `--s-4`.

### Работающие приложения

`ul` без маркеров, строки через зазор `--s-2`. Каждая строка — одна ссылка
`<a>` на всю строку. Форма повторяет лендинг: отдельные строки в рамке, так
что посетитель с лендинга узнаёт её сразу.

| Свойство | Значение |
|---|---|
| Фон / рамка / радиус | `--surface` / `1px solid --line-ctl` / `--r-md` |
| Внутренние отступы | `--s-3 --s-4` |
| От 36rem | `grid-template-columns: 4.5rem minmax(0,1fr) auto`, `column-gap: --s-4`, `align-items: baseline` |
| Ниже 36rem | области `"label arrow" "text text"`, `row-gap: --s-1` |
| Метка «День 1» | `--t-sm`, `--fg-mut`, `tabular-nums` |
| Текст | `--t-md`, `--fg` |
| Стрелка `→` | `--t-md`, `--fg-mut`, `aria-hidden="true"` |

Почему строки, а не сетка карточек. Дни — пронумерованная
последовательность, и список сохраняет её порядок на любой ширине: сетка 4×2
читается то по строкам, то по столбцам, а на 320 px сжимает текст до трёх-четырёх
строк. Список ещё и одна раскладка вместо трёх наборов колонок.

Рамка `--line-ctl`, а не `--line`: строка — элемент управления, и рамка его
опознаёт (корпус: граница контрола ≥ 3:1). На странице отсюда простой язык:
сильная рамка — можно нажать, тонкая линия — структура.

Карточки-заполнителя «следующий день — впереди», как в прототипе, нет: ссылка
в никуда среди ссылок читается как сломанная, а требование — ссылки на
**работающие** приложения. Когда появится день 9, в список добавится строка.

Под списком, отступ `--s-3`, `--t-sm`, `--fg-mut`, `max-width: 52ch` —
пояснение про роутер и сервис агентов (текст — в разделе «Тексты»).

### Журнал PR

Сверху вниз:

1. Пояснение к журналу — `--t-sm`, `--fg-mut`, `max-width: 68ch`: как читать,
   до какого PR доходит журнал, что такое класс.
2. Фильтр, отступ сверху `--s-4`: подпись «Поток» (`--t-xs`, `uppercase`,
   `--fg-mut`, отступ снизу `--s-2`), под ней ряд чипов.
3. Строка состояния, отступ сверху `--s-3`: `--t-sm`, `--fg-mut`,
   `role="status"`.
4. Группы по дням, отступ сверху `--s-5`.

Журнал лежит на `--bg`, без панели: это длинный документ, и панель на каждую
строку превратила бы его в стену рамок. Панели — у двух коротких блоков выше.

**Группа дня.** `section` с `h3`. Первая группа — без верхнего отступа,
каждая следующая — `margin-top: --s-6`, `border-top: 1px solid --line`,
`padding-top: --s-4`. В строке заголовка — `h3` с датой («10 сентября»,
`--t-md`, вес 600) и число PR (`--t-sm`, `--fg-mut`, `tabular-nums`), флекс
по базовой линии, зазор `--s-2`, отступ снизу `--s-2`.

**Строка PR.** `li` внутри `ul`, `padding-block: --s-3`, строки разделены
`border-top: 1px solid --line`.

| Часть | Значение |
|---|---|
| Номер `#58` | ссылка на `https://github.com/MikeKharr/ai-advent-2026/pull/58`, `--t-sm`, `--fg`, подчёркнута, `tabular-nums`, `aria-label` «PR #58 на GitHub» |
| Тип `docs` | `--t-xs`, моноширинный `ui-monospace, SFMono-Regular, Menlo, monospace`, `--fg-mut` |
| Итог | `--t-md`, `--fg`, `max-width: 68ch`, `overflow-wrap: anywhere` |
| Цель | «Цель: …», `--t-sm`, `--fg-mut`, `max-width: 52ch`, `overflow-wrap: anywhere` |
| Мета | «Атлас · класс C», `--t-xs`, `--fg-mut` |

- От 36rem: `grid-template-columns: 4.5rem minmax(0,1fr)`, `column-gap: --s-4`,
  `row-gap: --s-1`; слева номер и под ним тип, справа итог, цель, мета.
- Ниже 36rem: номер и тип в одну строку (зазор `--s-2`), под ними итог, цель
  и мета во всю ширину, между ними `--s-1`.

Итог стоит первым и без подписи: вопрос посетителя — «что получилось».
Цель — второй строкой с подписью, чтобы две строки не читались как одна
мысль. Поток повторяется в мете всегда, и при фильтре тоже: строка должна
быть понятна и вырезанной из контекста.

Тип — моноширинным словом, как в заголовке PR на GitHub. Четыре цветные
плашки прототипа нарушают два правила корпуса сразу: цвет вне палитры и
цвет, дублирующий текст. Слово «класс» в мете — текстом, без рамки: это
справка, а не элемент управления.

Порядок: группы — от свежего дня к старому, внутри группы — по номеру PR
по убыванию.

### Фильтр по потокам

`div role="group"` с `aria-labelledby` на подпись «Поток». Чипы — `button
type="button"` с `aria-pressed`: «Все» и по одному на поток из файла данных,
в его порядке. В каждом чипе — имя и число PR (`tabular-nums`, тот же цвет,
что имя, зазор `--s-1`).

| Состояние | Фон | Текст | Рамка |
|---|---|---|---|
| Покой | `--surface` | `--fg` | `1px solid --line-ctl` |
| Наведение | `--bg` | `--fg` | `--line-ctl` |
| Выбран (`aria-pressed="true"`) | `--fg` | `--surface` | `--fg` |
| Выбран + наведение | `--fg-mut` | `--surface` | `--fg-mut` |
| Нажатие | без смены цвета, сдвиг на 1 px вниз | | |
| `:focus-visible` | `outline: 2px solid --acc; outline-offset: 2px` | | |
| `[disabled]` | `opacity: .5`, `cursor: default` | | |

Размеры: `inline-flex`, `padding: --s-2 --s-3`, `--t-sm` при `line-height: 1.5`,
радиус `--r-full`. Высота любого чипа — 39 px (21 + 16 + 2); ряд
переносится (`flex-wrap`), зазор `--s-2` по обеим осям.

Выбранный чип — нейтральная инверсия, не `--acc`. Акцент на экране остаётся
один, и это кольцо фокуса: у страницы нет главного действия, выбор потока —
состояние, а не призыв. Выбор несёт не только цвет: строка состояния под
чипами называет его словами.

Чип потока, в котором ноль PR, **не блокируется**: нажатие показывает пустое
состояние со словами, почему пусто. `[disabled]` задан в стилях ради правила
пяти состояний, но в разметке не ставится.

**Запоминание.** Выбор пишется в `localStorage` под ключом `progress-stream`.
Корпус хранение в браузере не запрещает, дни 2–8 им пользуются, данные
остаются в браузере посетителя (I-10 не затронут). Правила:

- чтение и запись — в `try/catch`: заблокированное хранилище или приватный
  режим оставляют фильтр рабочим, просто без памяти;
- неизвестное значение (поток переименовали) → «Все», без ошибки;
- строка состояния всегда говорит «Показано 9 из 58 PR», поэтому
  вернувшийся посетитель с запомненным «Атласом» видит, что показано не всё.

Выбор в адрес страницы не пишется: этого не просили.

## Файл данных `site/progress/data.js`

### Формат

```js
// Данные страницы прогресса. Разметку не трогать: docs-PR итерации правит
// только этот файл. Формат и правила — agent_docs/design/2026-09-14-1300-progress-page.md.
globalThis.PROGRESS = {
  now: {
    updated: '2026-09-10T15:00Z',
    items: [
      { stage: 'разработка', title: 'Атлас: объёмный граф с вращением', text: 'ADR принят (#58): …' },
    ],
  },
  streams: [
    { key: 'days', label: 'Дни задания' },
    { key: 'router', label: 'Роутер и агенты' },
    { key: 'process', label: 'Процесс' },
    { key: 'atlas', label: 'Атлас' },
  ],
  prs: [
    { n: 1, merged: '2026-09-07', type: 'docs', stream: 'process',
      result: 'ADR «Node 22 без зависимостей» принят, снимок состояния актуализирован',
      goal: 'Закрепить главное ограничение стека до первой строки кода' },
    // …
    { n: 47, merged: '2026-09-10', type: 'feat', stream: 'process', cls: 'A',
      result: 'Фреймворк v2: модели по ролям, классы гейтов A/B/C, /day-cycle',
      goal: 'Точнее и дешевле работа агентов' },
  ],
}
```

### Поля

| Поле | Обязательно | Правило |
|---|---|---|
| `prs[].n` | да | целое ≥ 1, уникально; строки по возрастанию, новая — в конец массива |
| `prs[].merged` | да | `YYYY-MM-DD`, дата `mergedAt` по UTC: `gh pr view N --json mergedAt` |
| `prs[].type` | да | `feat`, `fix`, `docs`, `chore`, `test` или `refactor` — префикс **заголовка** PR |
| `prs[].stream` | да | один из `streams[].key` |
| `prs[].cls` | нет | `A`, `B` или `C` из описания PR; только с PR #47, у более ранних поля нет |
| `prs[].result` | да | итог, ≤ 100 знаков: что изменилось, в третьем лице |
| `prs[].goal` | да | цель, ≤ 80 знаков: зачем PR был нужен |
| `streams[]` | да | `{ key, label }`; порядок массива — порядок чипов |
| `now.updated` | да | ISO 8601 в UTC с `Z`; время, когда блок сверен с состоянием |
| `now.items[]` | да, может быть пуст | до 5 пунктов `{ stage, title, text }`: `stage` ≤ 24 знаков, `title` ≤ 100, `text` ≤ 300 |

Почему так:

- **`.js` с `globalThis`, а не `.json`.** Файл подключается обычным
  `<script src="data.js" defer>`: не нужен `fetch`, страница открывается и из
  локального каталога, а проверка в Node читает тот же файл импортом — через
  `globalThis` он виден в обоих окружениях. В JSON ещё и нельзя оставить
  комментарий с правилами над данными.
- **Объекты с именами полей, а не кортежи прототипа.** `result` и `goal` —
  обе строки; в кортеже их можно поменять местами, и ничто этого не заметит.
  Строки добавляются PR класса C, у которых нет ревью, только механический CI.
- **Тип — по заголовку PR, а не по ветке.** Ветки до правила о префиксах
  шли без них (`day6-agent`, `day7-chat`, `docs-day6-prod`), а PR #4 с
  веткой `feat/…` по заголовку — `docs`.
- **Дата — по UTC.** Это `mergedAt` из GitHub как есть: без пересчёта, в
  котором ошибётся ручная правка, и так же, как видит посетитель, перейдя по
  номеру. Поясняется в журнале словами «по дням мержа, UTC» (развилка 1).
- **Строки по возрастанию, новые в конец.** Дифф docs-PR — только добавленные
  строки внизу, без конфликтов в середине массива. Сортирует страница.
- **Потоки — в данных.** Новый поток добавляется строкой в `streams`, без
  правки кода.

### Что можно писать в текст

Страница публичная: в данные попадает только то, что уже публично в
репозитории.

- В текстовых полях нет адресов вообще: ни `://`, ни `www.`, ни IP, ни имён
  частной сети (`ts.net`). Ссылку на PR страница строит сама из номера.
- Нет идентификаторов Google Drive, адресов сервера, путей рабочих каталогов
  и ссылок на приватные артефакты — ни в каком виде.
- Текст — в третьем лице для постороннего читателя, без обращения к
  владельцу («без вашего решения» — нельзя).
- «Сейчас в работе» называет только работу с публичным следом: ветку или PR
  на GitHub, ADR или пункт `backlog.md` в `main`.

По этому правилу из прототипа не переносятся два пункта «Сейчас в работе»:
«Мерж по консенсусу ревью и push о релизах» — такого правила в репозитории
нет, и текст обращён к владельцу — и «Витрина документов в Google Drive
догнала git» — это работа над приватной витриной, которую посетитель открыть
не может.

### Проверка строк на странице

`app.js` проверяет каждую строку по таблице полей (обязательные поля есть,
значения из допустимых, длины в пределах). Строка, не прошедшая проверку,
не рисуется и попадает в счётчик частичного результата. Все тексты
вставляются через `textContent`, никакого `innerHTML` из данных.

### Кто и когда пишет строки

Роль `docs` в конце итерации: строки для всех PR, смерженных после прошлой
записи, и свежий `now` с новым `updated`. Свою собственную строку docs-PR
добавить не может — ни номера до открытия, ни даты мержа до мержа у него
нет, — поэтому журнал всегда отстаёт на последний docs-PR. Страница говорит
об этом прямо: «Журнал доходит до PR #{последний} от {дата}; более поздние —
в списке PR на GitHub».

## Состояния контента

Корпус требует четыре на каждый экран. Блок приложений — статичная разметка,
у него их нет по построению; остальные два блока зависят от `data.js`.

### Работающие приложения

| Состояние | Что на экране |
|---|---|
| Данные | Список в разметке, работает без скрипта и без `data.js` |
| Загрузка, пусто, ошибка, частично | Нет по построению: список в HTML. Упавшее приложение — забота его дня, страница прогресса его здоровье не опрашивает |

### Сейчас в работе

| Состояние | Что на экране |
|---|---|
| Загрузка | «Читаю данные…» в панели, `role="status"` |
| Данные | Пункты; во вторичной строке заголовка — «обновлено 10 сентября, 15:00 UTC» |
| Пусто | `items` пуст: «Сейчас ничего не в работе.» — дата обновления остаётся |
| Частично | Пункт без `text` — только этап и заголовок; пункт без `title` не рисуется |
| Ошибка | Нет `data.js` или в нём ошибка: «Блок не загрузился: файл с данными недоступен.» |
| Без скрипта | Секция скрыта целиком вместе с заголовком: показать нечего, а пустая панель читалась бы как «ничего не в работе». Объяснение одно на оба блока — `noscript` в журнале |

### Журнал PR

| Состояние | Что на экране |
|---|---|
| Загрузка | «Читаю журнал…», `role="status"`; чипов ещё нет |
| Данные | Пояснение, чипы с числами, строка состояния, группы |
| Пусто: поток без PR | «В потоке «{поток}» пока нет PR.» + кнопка «Показать все» |
| Пусто: журнал без строк | «В журнале пока нет строк.» + ссылка «Все PR — на GitHub» |
| Частично | Строки, не прошедшие проверку, не рисуются; под строкой состояния — «{N} строк журнала не показаны: в них не хватает полей.» |
| Ошибка | «Журнал не загрузился: файл с данными недоступен. Все PR — на GitHub.» Слова «на GitHub» — ссылка на список PR |

Признак ошибки один: после выполнения скриптов `globalThis.PROGRESS` нет или
это не объект. Он покрывает и отсутствующий файл, и синтаксическую ошибку в
нём: в обоих случаях переменная не появляется.

Без скрипта: `<noscript><style>` в `head` скрывает класс `.js-only` — его
несут заглушки загрузки журнала и вся секция «Сейчас в работе». Вместо них в
журнале показывается текст `noscript`: «Журнал и блок «Сейчас в работе»
строит скрипт, а он отключён. Все PR — на GitHub.» с ссылкой на список PR.
Блок приложений работает.

После «Показать все» кнопка исчезает вместе с пустым состоянием, поэтому
фокус переходит на чип «Все» — иначе он теряется на `body`.

## Интерактивные элементы: пять состояний

Элементы: ссылка на лендинг, девять строк приложений, чипы фильтра, номера
PR, ссылки в пояснении и в состояниях («на GitHub»), кнопка «Показать все»,
ссылки подвала.

```css
:where(a, button):focus-visible {
  outline: 2px solid var(--acc);
  outline-offset: 2px;
}
```

- **Наведение** — фон на одну ступень: строки приложений и чипы
  `--surface` → `--bg`, выбранный чип `--fg` → `--fg-mut`. У текстовых
  ссылок — цвет подчёркивания не меняется, меняется фон на `--surface`.
  Размеры не меняются нигде.
- **Нажатие** — сдвиг на 1 px вниз (`position: relative; top: 1px`), у всех,
  и у строчных ссылок тоже. Смены фона на `--line` нет: `--fg-mut` на `--line`
  в светлой теме — 4.30:1, ниже порога для текста.
- **`[disabled]`** — `opacity: .5`, `cursor: default`, атрибут в разметке. У
  ссылок состояния нет: ссылка, которой некуда вести, просто не рисуется.
- **Движение** — только `background-color` у чипов и строк, 120 мс;
  `@media (prefers-reduced-motion: reduce)` снимает его полностью.
  Появление строк журнала и смена фильтра не анимируются.

Пять размеров, ровно по лимиту корпуса: `--t-xs` (этап, тип, мета, подпись

## Доступность

- Один `h1`; `h2` — три секции; `h3` — даты групп и пункты «Сейчас в работе».
  Уровни не пропускаются.
- Списки — `ul`/`li`, дата обновления — `<time datetime>`.
- Строка состояния фильтра — `role="status"`: смена потока произносится
  («Показано 9 из 58 PR — поток «Атлас»»), фокус остаётся на чипе.
- Стрелка `→` в строках приложений — `aria-hidden`: имя ссылки — метка и
  текст.
- Имя ссылки номера — «PR #58 на GitHub»: видимый текст `#58` входит в него
  (WCAG 2.5.3).
- Порядок `Tab` совпадает с визуальным: лендинг → приложения → фильтр →
  номера PR → подвал.
- Масштаб 200 % при окне 1280 даёт 640 CSS-пикселей — раскладка от 36rem,
  без горизонтальной прокрутки.

## Что проверит ревью

`design-review` по скиллу `/design-review`, вердикт `ГОТОВО` — условие
мержа. Каждый пункт проверяем числом или действием.

1. **Шкалы.** Грепы скилла по `site/progress/style.css`: отступы только
   `--s-1…--s-8`, значений вне шкалы ноль; `font-size` — ровно пять токенов
   `--t-xs…--t-xl`; радиусы — только `--r-sm`, `--r-md`, `--r-full`.
2. **Палитра.** Цвета — только токены корпуса, обе ветки темы; `#`-значения
   встречаются только в двух блоках `:root`. Новых токенов ноль.
3. **Контраст.** Все пары из таблицы «Цвет и контраст» пересчитаны на обеих
   темах и проходят порог; пары вне таблицы на экране не встречаются.
4. **Один акцент.** `--acc` — ровно в одном правиле: `:focus-visible`.
5. **Пять состояний.** Обход `Tab` от первого элемента до последнего:
   видимое кольцо у каждого; у каждого элемента из списка раздела
   «Интерактивные элементы» заданы наведение и нажатие; нажатие не меняет
   фон под текстом.
6. **Четыре состояния контента воспроизводятся.** Переименовать `data.js` →
   обе ошибки; `prs: []` → пустой журнал; поток без PR в `streams` → пустое
   состояние чипа и «Показать все», фокус после неё на «Все»; строка без
   `goal` → «1 строка журнала не показана…»; `items: []` → «Сейчас ничего
   не в работе.»; скрипты выключены → текст `noscript`, приложения
   открываются.
7. **Фильтр.** Ровно один чип с `aria-pressed="true"`; строка состояния
   совпадает с числом видимых строк; выбор переживает перезагрузку;
   `localStorage.setItem('progress-stream','нет-такого')` → «Все»;
   заблокированное хранилище → фильтр работает без памяти.
8. **Горизонтальной прокрутки нет** при 320, 360, 400, 768, 1024 и 1440 px
   и при масштабе 200 % на 1280: `scrollWidth === clientWidth` у
   `document.documentElement`.
9. **Три ширины.** Ниже 36rem строки приложений и PR сложены (метка и
   стрелка / номер и тип первой строкой); от 36rem — колонки; контейнер не
   шире 48rem.
10. **Ноль сторонних запросов.** Вкладка «Сеть» при открытии страницы:
    `index.html`, `style.css`, `app.js`, `data.js` и браузерный
    `/favicon.ico` — все с того же адреса. Ни шрифтов, ни CDN, ни
    `@import`, ни `url(http…)` в CSS.
11. **Числа не вбиты.** Грепом по `site/progress/index.html` и `app.js` не
    находится ни «58», ни «47», ни «23 PR»; урезанный `data.js` меняет все
    счётчики, «доходит до PR #…» и «классы присваиваются с PR #…».
12. **Даты по UTC.** PR #45 — в группе «9 сентября», #46 — «10 сентября»,
    как `mergedAt` на GitHub. Дата обновления «Сейчас в работе» — с «UTC».
13. **`tabular-nums`** у номеров PR, чисел в чипах, в заголовках групп и у
    даты обновления.
14. **Заголовки:** один `h1`, три `h2`, `h3` — даты и пункты; без пропусков.
