# Дизайн-корпус проекта

Единый визуальный язык страниц челленджа. Действует **с дня 3 и далее**. Дни 1 и 2
остаются как есть: приложения сданных дней не поддерживаются без явного указания
владельца. Решение о пайплайне — ADR `2026-09-08-1110`.

Это рабочий стандарт, а не свод вкусов: каждое правило проверяемо и попадает в ревью
`/design-review`. Правило, которое нельзя проверить, здесь не место.

## Приоритет источников

Метод заимствован у `vercel-labs/eve-design-template` (MIT): решение всегда обосновано
корпусом, а не общим впечатлением.

1. **Инварианты проекта** (`agent_docs/invariants.md`) — выше всего. Дизайн не может
   требовать того, что инвариант запрещает: дорисовать третью карточку ради симметрии
   сетки нельзя (I-8), спрятать источник ради чистоты — нельзя (I-7).
2. **Этот корпус.**
3. **Общая дизайн-рекомендация** — допустима, но помечается префиксом
   `Общая рекомендация:`, чтобы её нельзя было принять за правило проекта.

Конфликт двух правил корпуса равного веса не примиряется самостоятельно: он выносится
владельцу.

## Диагноз, ради которого корпус появился

Замер существующих дней показал разброс без системы: два десятка значений отступов
при отсутствии шкалы, размеры шрифта с разницей в полтора процента, ни одного
`:focus-visible`. Каждое решение принято локально и разумно, системы нет — отсюда
ощущение посредственности. Числа — в ADR `2026-09-08-1110` и записи
`development-history/2026-09-08-1130`.

## Токены

Только эти значения. Число вне шкалы — дефект, а не нюанс.

### Шаг сетки 4px

```css
--s-1: .25rem;  /*  4 */
--s-2: .5rem;   /*  8 */
--s-3: .75rem;  /* 12 */
--s-4: 1rem;    /* 16 */
--s-5: 1.5rem;  /* 24 */
--s-6: 2rem;    /* 32 */
--s-7: 3rem;    /* 48 */
--s-8: 4rem;    /* 64 */
```

Между смысловыми блоками — `--s-5` и больше, внутри блока — `--s-2`/`--s-3`.

### Типографика

```css
--t-xs:  .75rem/1.4;    /* 12 — метки, теги */
--t-sm:  .875rem/1.5;   /* 14 — вторичный текст, подписи */
--t-md:  1rem/1.6;      /* 16 — основной текст */
--t-lg:  1.125rem/1.4;  /* 18 — заголовок карточки */
--t-xl:  1.5rem/1.25;   /* 24 — заголовок экрана */
--t-2xl: 2rem/1.15;     /* 32 — только лендинг */
```

- Не больше **пяти** размеров на экране.
- Базовый размер — `1rem`, не 15px: пользовательская настройка размера шрифта должна
  работать.
- Заголовки от `--t-xl`: `letter-spacing: -.01em`. Служебные подписи: `uppercase`,
  `letter-spacing: .06em`, только `--t-xs`.
- **Числа, которые сравнивают глазами** (токены, счётчики, даты), — обязательно
  `font-variant-numeric: tabular-nums`: иначе колонка чисел «пляшет».
- Шрифт — системный стек. Собственный шрифт допустим только файлом внутри образа;
  подключать шрифт с CDN нельзя: это сторонний запрос с адресом пользователя и
  задержка первого рендера.

### Цвет

```css
:root {
  --bg:         #fbfbfa;  /* фон страницы */
  --surface:    #ffffff;  /* карточка, панель */
  --fg:         #17171a;
  --fg-mut:     #6a6a70;
  --line:       #e6e6e3;  /* разделитель, декоративный */
  --line-ctl:   #8f8f8a;  /* граница элемента управления, ≥3:1 */
  --acc:        #2f6f4f;
  --acc-fg:     #ffffff;
  --danger:     #b3261e;
}
@media (prefers-color-scheme: dark) {
  :root {
    --bg:       #131316;
    --surface:  #1b1b1f;
    --fg:       #ececee;
    --fg-mut:   #9b9ba3;
    --line:     #2a2a30;
    --line-ctl: #6a6a73;
    --acc:      #6fc79c;
    --acc-fg:   #0e1a13;
    --danger:   #f2b8b5;
  }
}
```

- Иерархия строится сменой поверхности (`--bg` → `--surface`) и линией, а не тенью.
  Тень — только у того, что действительно всплывает над контентом.
- Контраст: основной текст ≥ 4.5:1; крупный текст и **граница элемента управления**
  (`--line-ctl`) ≥ 3:1. Декоративный разделитель (`--line`) под это требование
  не попадает: он не несёт смысла и не опознаёт элемент (WCAG 1.4.11).
- Цвет никогда не единственный носитель смысла: рядом текст, значок или подпись.
- Не больше одного акцентного элемента в поле зрения. Два акцента — ни одного.

Палитра проверена 2026-09-08 (WCAG 2.1, обе темы):

| Пара | Светлая | Тёмная | Порог |
|---|---:|---:|---:|
| основной текст / поверхность | 17.9:1 | 14.6:1 | 4.5 |
| вторичный текст / поверхность | 5.4:1 | 6.2:1 | 4.5 |
| акцент / поверхность | 6.0:1 | 8.4:1 | 3.0 |
| текст кнопки / акцент | 6.0:1 | 8.8:1 | 4.5 |
| ошибка / фон | 6.3:1 | 10.9:1 | 4.5 |
| граница контрола / поверхность | 3.3:1 | 3.2:1 | 3.0 |

Меняя любой токен цвета, пересчитать таблицу — иначе правило превращается в лозунг.

### Радиус

```css
--r-sm:   6px;    /* поля ввода, кнопки */
--r-md:   10px;   /* карточки, панели */
--r-full: 999px;  /* теги, чипы */
```

## Состояния интерфейса

### Интерактивные элементы

У каждого — **пять** состояний, без исключений: покой, наведение, нажатие,
`:focus-visible`, `[disabled]`.

- `:focus-visible` — `outline: 2px solid var(--acc); outline-offset: 2px`. На всех
  интерактивных элементах, а не только на полях ввода. Наведение без фокуса — дефект
  доступности: клавиатура остаётся без обратной связи.
- Наведение меняет фон на одну ступень, не размеры: «прыгающая» вёрстка читается как
  сбой.
- Нажатие — сдвиг не больше 1px или смена фона.
- `[disabled]` — `opacity: .5`, `cursor: default` и запрет действия в разметке,
  а не только визуально.

### Состояния контента

Каждый экран определяет **четыре**, иначе он не готов: пусто, загрузка, ошибка,
частичный результат. Пустое состояние — честный текст о том, почему пусто (I-8),
а не пустая область.

### Движение

Только на смену состояния, ≤ 120 мс, и полностью отключается в
`@media (prefers-reduced-motion: reduce)`. Появление контента не анимируется.

## Раскладка и ритм

- Полоса чтения: проза ≤ 68ch, вторичный текст ≤ 52ch.
- Для экрана «работа / настройки / результат» рабочая схема — три колонки
  `1fr 18rem 24rem`: главное слева и шире, настройки узкие, результат достаточно
  широк для текста. Внутренние отступы всех колонок берутся из одной шкалы.
- На узком экране колонки складываются в порядке: работа → настройки → результат.
- Ряды тегов и чипов: одинаковая высота, отступ `--s-2`, перенос допустим — рваные
  ряды с разными зазорами не допустимы.

## Проверка

Ревью экрана — скилл `/design-review`. Он собирает факты (число уникальных значений,
покрытие состояний, контраст) и выдаёт вердикт `ГОТОВО` / `ПРАВКИ` / `ПЕРЕДЕЛАТЬ`.
Замечание без конкретного значения или селектора замечанием не считается.
