Варианты у владельца: уменьшить `SECTION_LIMIT`, считать порог в токенах и упасть при превышении, либо послать `truncate: false` и получить громкий отказ вместо тихой обрезки. Следствие — «идёт» и «встала» неотличимы без журнала контейнера, то есть без команды закрытого списка. Смежное и измеренное 2026-10-05: журнала нет и **внутри** прохода — цикл батчей не пишет ни одной строки, а `run_build` пишет только смену состояния и исключение, поэтому «идёт медленно» и «встала» не различить даже по журналу контейнера. Минимальная правка: строка на батч с секундами и знаками. Проверено 2026-10-05 по `rag/build.py:196-229` (цикл без журнала) и `rag/serve.py:492` (`run_build`).

Задевает I-5: потолок расхода перестаёт быть потолком молча. Варианты — падать, переходить на счёт в памяти до конца суток, либо оставить как есть и признать в README; у них разная цена, выбор за владельцем. Находка `compliance` к PR #282, не блокирующая. - [ ] Владельцу: **шаг преобразования не переносит пробу одиночного доступа дня 30 — самого прямого числа этого дня нет на странице.** `rag/eval/day30_probe.py:320` пишет в сырой вывод поле `provider_probe` (одиночный запрос через прод: 200 за 12,5 с), а `rag/eval/to_page.py`, функция `day30`, собирает только `access`, `burst` и `limits` — поля `provider_probe` в публичном файле нет, и страница рассказывает про параллельность, не показав, что одиночный запрос вообще проходит. Правка — либо шаг преобразования, либо строка спецификации; без прогона GPU, данные уже сняты. Проверено 2026-10-10 по названным строкам.
- [ ] Владельцу: **строка документации `rag/eval/report.py` обещает то, чего прогон не оставляет.** В докстринге сказано: «Её ответы судья читает с ноутбука, а в файл от этой оси попадают только числа» — про тексты сборки без встроенных отказов. Читать их действительно можно только на ноутбуке, но прогон их не сохраняет: после него читать нечего, и обещание даёт неверную картину того, как ставился вердикт по оси сжатия. Это и есть причина, по которой страница дня 29 говорит, что вердикт по этой оси читатель проверить не может. Правка — текст докстринга, либо сохранение текстов вне репозитория (второе задевает вето `compliance` ADR `2026-10-07-1349` и само по себе требует решения). Проверено 2026-10-10 по докстрингу `rag/eval/report.py`.
- [ ] Владельцу: **шаг преобразования не переносит заметки судьи по осям дня 29.** `rag/eval/to_page.py`, функция `day29`: у оси в публичный файл идут `score_avg`, `tps`, `ttft_s`, `mem_mib`, `changed` — заметки судьи (`_judge_note`) переносятся только у дней 26 и 28, у осей их нет вовсе. Поэтому вывод «правило не взяло ни одной оси» читатель видит числом, но не видит, что судья написал про каждую ось. Проверено 2026-10-10 по названным функциям.
- [ ] Владельцу: **счётчики скорости оси `temperature` дня 29 испорчены, и причина не установлена.** У части ответов этой оси прогон записал десятые доли токена в секунду и около трети секунды до первого токена при пяти тысячах токенов промпта — числа несовместимые между собой. Страница их не показывает как результат (`site/day29/verdict.js:35`, `isSuspect`; в колонке «Ток/с» — «нет данных» и слово «счётчик испорчен»), остальные оси не затронуты. Диагноза нет: средние по оси считает `to_page.py` без отсечки, отсечка живёт только на странице. Чинить — повторным прогоном одной оси (GPU), то есть решение владельца. Проверено 2026-10-10: `site/day29/results.json`, ось `temperature`; `site/day29/verdict.js:35`.
- [ ] Владельцу: **правило выбора «после» дня 29 отсекает оси по признакам, которые ось не измеряла.** `site/day29/verdict.js:168` (`afterRule`): `think` не вошёл в «после» из-за +5 % времени при поднявшейся оценке судьи (1,90), а `temperature 0,2` и ось промпта — по признаку `cited`, который ищет путь источника подстрокой и ошибается в обе стороны (та же граница, что названа у дня 22). Итог недели — «правило не взяло ни одной оси» — поэтому зависит от двух порогов и одного ненадёжного признака. Владелец 2026-10-10 решил опубликовать честный итог без нового прогона; правка самого правила — отдельное решение. Проверено 2026-10-10 по `site/day29/verdict.js:168` и оговоркам `site/day29/results.json`.
