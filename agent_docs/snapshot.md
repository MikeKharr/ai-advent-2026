# Снимок текущего состояния

Обновлять в конце каждой итерации. Лимит 300 строк, проверяется в CI.

## Где сейчас работа

Каркас и конвейер деплоя готовы. Прикладного кода нет. Всё упирается в действия владельца: репозиторий, инстанс, DNS, секреты.

## Что готово

- Каркас документации `agent_docs/` и правила `AGENTS.md` по шаблону 2030ai + memory-слой cmit-starter.
- 10 ролей агентов в `.claude/agents/`.
- Топология: `days/dayN/` — контейнер на день, Caddy маршрутизирует `challenge.zpq.ai/dayN`, лендинг на корне.
- `deploy/`: `Caddyfile`, `compose.yml`, идемпотентный `bootstrap.sh`.
- CI: markdownlint, docs-guard, ci (синтаксис, тесты, сборка образа, проверка `/healthz`), валидация `Caddyfile`.
- Деплой: сборка в Actions → GHCR → пин тега на сервере → перезапуск только изменённых дней → проверка живого адреса.
- `days/day1/` — заглушка, запущена и проверена локально.

## Чем заниматься дальше

Прогнать конвейер на заглушке до написания кода: репозиторий → `bootstrap.sh` → DNS → первый деплой → `curl https://challenge.zpq.ai/day1/healthz`. Конвейер, впервые запускаемый вместе с первой реализацией, отлаживается вслепую.

Затем спайк `web_search` + строгий JSON — единственное, что может заставить переделать архитектуру дня 1.
