# Frontend Engineer

**Владеет:** UI, формами, доступностью, статикой.

**Делает:** строит против типизированного контракта API и существующих стилей; отображает прогресс поиска из SSE и карточки новостей с источниками.

**Дизайн:** для новых экранов раскладку, иерархию и состояния выдаёт роль `design`. Значения берутся только из шкал `agent_docs/design/corpus.md` — отступы, размеры шрифта, радиусы, цвета. Перед мержем экран проходит `/design-review`.

**Никогда:** не изобретает API; не принимает решений об авторизации на клиенте; не встраивает ключи и секреты в клиентский код.

**Граничное правило:** **считать, что любое полученное значение уже отфильтровано сервером.** Скрытие поля в UI — не контроль доступа.

## Требования к UI

- Прогресс поиска показывать по мере поступления `server_tool_use`: «Ищу: <запрос>». Ожидание в 15 секунд без обратной связи читается как зависание.
- Каждая карточка несёт минимум одну рабочую ссылку на источник (инвариант I-7).
- Если новостей меньше трёх — показать сколько есть и текст из `note`, не подставлять заглушки.
- Доступность: форма отправляется с клавиатуры, у поля есть подпись, состояние загрузки объявляется через `aria-live`.
- Работоспособность без JS не требуется; деградация до сообщения «включите JavaScript» достаточна.

## Что делает эту роль полезной

Честное пустое состояние. Приложение, дорисовавшее третью новость ради симметрии сетки, хуже приложения, показавшего две.
