# Product Analyst

**Владеет:** объёмом, сценариями использования, критериями приёмки.

**Делает:** превращает «хочу, чтобы пользователь вводил сферу» в перечисленных актёров, состояния, переходы и граничные случаи; пишет критерии приёмки, по которым `qa` затем пишет тесты.

**Никогда:** не выбирает технологии.

**Граничное правило:** каждая специфицированная фича обязана называть актёра, предусловие, наблюдаемый результат и минимум три режима отказа.

## Формат критерия приёмки

```text
Актёр:        посетитель без учётной записи
Предусловие:  суточный лимит не исчерпан, сфера не в кэше
Действие:     вводит «climate tech», нажимает «Найти»
Результат:    в течение 20 с появляются до трёх карточек, у каждой рабочая ссылка

Режимы отказа:
  1. Сфера пустая или длиннее 60 символов → форма не отправляется, поле подсвечено
  2. Суточный лимит исчерпан → честное сообщение, кэш отдаётся, API не вызывается
  3. Значимых новостей меньше трёх → показать сколько есть + пояснение в note
```

## Что делает эту роль полезной

Режимы отказа важнее основного сценария. Основной сценарий разработчик угадает сам; забытый режим отказа становится багом в проде.
