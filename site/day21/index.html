Как это работает

Поиск возвращает не один фрагмент, а несколько — по убыванию близости к вопросу. Модель, которая отвечает, берёт пять верхних и читает их все, а при нужде открывает файлы целиком; здесь это Claude в Claude Code через инструмент project.search. Ответ пишет модель — поиск только подбирает ей материал.

Поэтому главный вопрос меры — попал ли верный документ в эту пятёрку: это и считает Recall@5. Первое место — лучший случай, но не обязательный: если верный документ оказался третьим, модель его всё равно прочитает. MRR@10 добавляет к этому, насколько высоко он стоял.

У стратегий две оси. Первая — как резать документы на фрагменты: по размеру или по структуре. Её и мерил этот прогон. Вторая — как пользоваться найденным: взять k лучших фрагментов или искать агентно, несколькими запросами с чтением файлов. Вторую ось прогон не мерил: он сравнивает нарезку при одинаковом способе поиска.

Задание и корпус

Индексация документов. Возьмите набор документов: README / статьи / код / pdf → текст; минимум 20–30 страниц текста суммарно (или эквивалент в коде).

Реализуйте пайплайн индексации: разбиение на чанки (chunking); генерация эмбеддингов; сохранение индекса (FAISS / SQLite / JSON).

Усиление: добавьте метаданные к каждому чанку (source, title/file, section, chunk_id); сделайте минимум 2 стратегии chunking и сравните их — по фиксированному размеру и по структуре (заголовки/разделы/файлы).

Результат: локальный индекс документов с эмбеддингами + метаданные + сравнение 2 стратегий chunking.

В индекс взят сам проект: документация agent_docs, AGENTS.md, README.md единиц и код живых единиц — читаю результаты прогона…

Не взяты сданные дни, чужие скиллы и зависимости: сданные дни не поддерживаются, искать в них нечего.

Индекс — FAISS IndexFlatIP: точный полный перебор по косинусу. На три с небольшим тысячи фрагментов приближённый поиск не нужен — перебор занимает миллисекунды.

Сто вопросов по одному

Число у каждой стратегии в строке — место верного документа в выдаче поиска по этому вопросу: 1 — он нашёлся первым, от 2 до 10 — ниже (меньше — лучше), «нет» — в первую десятку он не попал. Из этих мест и считаются метрики в «Итоге»: Recall@5 — доля вопросов, где место не дальше пятого; MRR@10 — среднее от 1/место, и «нет» входит в это среднее нулём.
